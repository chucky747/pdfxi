## What was added

| Target | Entry function | Real code driven |
|---|---|---|
| `redaction` | `pdfxi_fuzz_entry::fuzz_redaction` | `pdfxi_edit::apply_redaction` (content removal on real bytes), full `Document::save` + `Document::from_bytes` reparse, `pdfxi_edit::verify_redaction`, `pdfxi_security::sanitize_document_full` and `verify_sanitized` (returns rewritten bytes) |
| `edit` | `pdfxi_fuzz_entry::fuzz_edit` | `pdfxi_edit::content_edit::text_blocks` / `list_objects`, `pdfxi_edit::document_annotations::add_highlight` / `add_text_note` (success and typed rejections), `Document::from_bytes` |

Both use the harness conventions exactly: an 8-line `#![no_main]` file with a
`libfuzzer_sys::fuzz_target!` wrapper around a plain function that bounds the
input to `MAX_FUZZ_INPUT` (16 KiB), counts sub-cases in
`pdfxi_testkit::fuzz::FuzzOutcome`, and never panics. A malformed PDF is a
counted rejection and returns normally.

`fuzz/fuzz_targets/redaction.rs`:

```rust
//! libFuzzer target: redaction removal, full save, verification, and sanitize.
#![no_main]

use libfuzzer_sys::fuzz_target;

fuzz_target!(|data: &[u8]| {
    let _ = pdfxi_fuzz_entry::fuzz_redaction(data);
});
```

`fuzz/fuzz_targets/edit.rs` is the same shape around `fuzz_edit`.

### Why the plain functions are in `fuzz/entry`

The five original entry points live in `crates/pdfxi-testkit/src/fuzz.rs`, which
this task does not own. To keep the same wrapper/outcome shape without editing
another lane's crate, the two new functions live in a `pdfxi-fuzz-entry` member
of the standalone fuzz workspace and reuse `FuzzOutcome` and `MAX_FUZZ_INPUT`
from the testkit. That member has no `libfuzzer-sys` dependency, so its
deterministic runner builds on this host.

## Limits / follow-up

- `cargo fuzz run redaction -- -runs=2000` and `cargo fuzz run edit -- -runs=2000`
  still need a fuzz host (see the blocker file); the 24-hour release run is
  unchanged.
- `add_highlight` intentionally accepts quads outside the media box, so the edit
  target exercises its documented `EmptyQuads` rejection instead of a
  coordinate rejection; other toolset functions (`add_underline`, `add_ink`)
  already have their own bounds checks and are out of this task's scope.
