## 1. What shipped

  - `convert_to_pdf(input: ConvertInput, options: ConvertOptions) -> Result<ConvertedPdf, ConvertError>`
    and `convert_to_pdf_file(input, options, path)`.
  - `ConvertInput` - an ordered list of sources. Constructors:
    `new`, `from_source`, `from_sources`, `with`, `push`, `sources`, `len`,
    `is_empty`, `from_path`, `from_paths`, `from_bytes(name, bytes)`.
  - `ConvertSource` - `Text`, `Markdown`, `Html { markup, base_dir }`,
    `Image { bytes, format }`, with `text`, `markdown`, `html`, `image`,
    `with_name`, `name`, `kind`, `byte_len`.
  - `ConvertSourceKind` - `Text`, `Markdown`, `Html`, `ImagePng`, `ImageJpeg`;
    `label()`, `is_image()`, `Display`.
  - `ConvertOptions` - `page_size`, `margins`, `font_size`, `line_height`,
    `title`; builder + getters + `validate()`; defaults are Letter, 1-inch
    margins, 11 pt, 1.2x.
  - `ConvertedPdf` - `bytes`, `into_bytes`, `page_count`, `page_size`, `title`,
    `parts`, `write_to`; `ConvertedPart` - `name`, `kind`, `first_page`,
    `page_count`.
  - `ConvertError` - `EmptyInput`, `TooManySources { count, limit }`,
    `InputTooLarge { bytes, limit }`, `UnsupportedFormat { format }`,
    `OfficeUnavailable { format, message }`, `NotUtf8 { format }`,
    `Options(CreateError)`, `Source { name, source: CreateError }`,
    `Pdf(pdfxi_core::Error)`, `Io`.
  - Bounds: `CONVERT_MAX_SOURCES = 512`, `CONVERT_MAX_TOTAL_BYTES = 64 MiB`,
    `OFFICE_UNAVAILABLE_MESSAGE`.
- `crates/pdfxi-convert/src/lib.rs` - `pub mod convert_to_pdf`, root
  re-exports, and a module-contract bullet describing the entry point.
- `crates/pdfxi-convert/tests/convert_to_pdf.rs` - 16 integration tests.
- `orchestration/feature-updates/T-0240.toml` - matrix fragment (see section 6).

No dependency, manifest, or feature-flag change. The module reuses
`create::create_from_text`, `create::create_from_markdown`,
`create::create_from_html_with_options`, `create::create_from_image`,
`create::HtmlOptions`, `create::CreateOptions`, `create::PageSize`, and
`create::Margins` unchanged. Assembly is `pdfxi_core::PagePlan::merge` +
`Document::apply_page_plan`, metadata is `Document::set_info`, and the final
bytes come from `Document::save`, so ADR 0010's one-write-path rule holds and
the module adds no second PDF writer. No external converter, no Office process,
no network, no zinc.

## 2. API flow

1. `options.validate()` -> typed `ConvertError::Options` before any layout work.
2. Bound checks: non-empty request, `CONVERT_MAX_SOURCES`, total input bytes.
3. Per source, in request order: `render_source` (creation engine) ->
   `Document::from_bytes` -> `page_count`; the page range is recorded in
   `ConvertedPart`.
4. First rendered document is the merge primary; the rest are
   `PagePlan::merge` extras, so page order equals source order.
5. `Document::from_bytes(merged)` -> `set_info({ title, creator:
   "pdfxi-convert", producer: "PDFXI" })` -> `save()`.
6. `ConvertedPdf` carries the bytes, page count, page size, title, and one
   part per source. `write_to` performs a plain caller-owned write; atomic
   replacement stays with the document session.

A source that fails to render is reported as
`Source { name: "#2 (blank.txt)", source: CreateError::EmptyDocument }`, so a
UI can say which file failed without parsing strings.

## 3. Supported input matrix and fidelity limits

Detection is `extension -> content signature -> text sniff`. Binary signatures
win over a misleading name (a PNG named `.txt` is a PNG); a ZIP container is
classified by its member parts when the name is unknown.

| Input | Extensions | Detection | Result | Fidelity limits |
|---|---|---|---|---|
| Plain text | `.txt`, `.text`, `.log` | extension, or UTF-8 fallback | Flowed text, line breaks preserved | Base-14 Helvetica at 11 pt; WinAnsi/Latin-1; characters outside Latin-1 become `?` |
| Markdown | `.md`, `.markdown`, `.mdown`, `.mkd` | extension only (no content signature) | ATX headings, paragraphs, bullet lists, fenced code | Inline emphasis, links, images, tables, ordered lists, blockquotes emitted literally |
| HTML | `.html`, `.htm`, `.xhtml` | extension, or `<!doctype html`/`<html`/`<head`/`<body`/`<table`/`<p>` prefix | Headings, paragraphs, lists, bold/italic, tables, local PNG/JPEG images | Documented CSS subset only; script/remote URL/traversal rejected with typed errors; images resolve against the source file's directory |
| PNG | `.png` | `\x89PNG\r\n\x1a\n` | One page per image, embedded without re-encoding | Non-interlaced 8-bit grayscale/RGB; alpha, palette, interlaced, other depths rejected |
| JPEG | `.jpg`, `.jpeg`, `.jpe` | `FF D8 FF` | One page per image, embedded verbatim | 8-bit, 1 or 3 components; CMYK and other precisions rejected |
| Office (`.docx`, `.xlsx`, `.pptx`, `.doc`, `.xls`, `.ppt`, `.odt`, `.ods`, `.odp`, `.docm`, `.xlsm`, `.pptm`, ...) | extension, or container parts `word/`, `xl/`, `ppt/` | `ConvertError::OfficeUnavailable { format, message }` | **No conversion in round A**; message: "this build has no Office converter; export the document to PDF or HTML and convert that" |
| PDF, RTF, PostScript, GIF/BMP/TIFF/WebP/SVG, EML/MHTML, CSV, ZIP/RAR/7z, unknown binary | extension or `%PDF-`/`PK` | `ConvertError::UnsupportedFormat { format }` naming the format | Not converted by this entry point |

Page geometry: every page uses `ConvertOptions::page_size` and
`ConvertOptions::margins`; image pages use the embedded `pHYs`/JFIF density for
intrinsic size and are fitted (never enlarged) inside the content area. There is
no per-page auto-rotate, no PDF/A, and no tagging in round A. Output is a
classic-xref PDF 1.x file and is byte-identical for identical input because no
timestamp, ID, or locale value is written.

## 8. Re-verification note (transient workspace breakage)

The full gate run quoted in section 5 was taken at 16:47-16:50 with default and
all features, and was green. About four minutes later `crates/pdfxi-render` was
mid-edit by another lane (a `win_print` print-backend module, `LastWriteTime`
2026-11-20 16:53), so any build that pulls `pdfxi-render` failed to compile
**outside this task's files**:

```text
  --> crates/pdfxi-render/src/lib.rs:122:1
error: could not compile `pdfxi-render` (lib) due to 90 previous errors
```

then, on the next retry:

```text
error[E0308]: `match` arms have incompatible types  (crates/pdfxi-render/src/lib.rs)
error: could not compile `pdfxi-render` (lib) due to 2 previous errors
```

This crate does not own `pdfxi-render`, so nothing was changed there. To prove
the new code independently while that crate settles, the same gates were run
without the renderer dependency:


(The 12-test difference in the lib target is the `renderer`-gated
`page_export` unit tests, which do not exist in a `--no-default-features`
build.) `convert_to_pdf` itself is not feature-gated: it needs only `create` and
`pdfxi-core`, both always present. The integrator's `cargo xtask verify` will
stay red until the render lane finishes that edit.

## 9. What is left

- **Office conversion (round B).** `.docx`/`.xlsx`/`.pptx` need a real reader
  or a Windows-only, feature-gated COM path (`Word.Application` is broken on
  this host; Excel/PowerPoint work). Round B must land behind a non-default
  feature, keep the current `OfficeUnavailable` behaviour when the feature is
  off, and report unsupported constructs instead of faking them. No library
  code shells out to Office until then.
- **Shell task (later, lane `app`).** A Convert tool in
  `crates/pdfxi-app/src/shell/**` that takes a file dialog or drag-and-drop
  paths, calls `ConvertInput::from_paths` + `convert_to_pdf_file`, and shows
  `OfficeUnavailable`/`UnsupportedFormat`/`Source` messages. Drag-and-drop
  parsing, the dialog, and capability reporting belong there; this crate only
  classifies and converts.
- **Not in scope for A-28 round A:** PDF pass-through merging (a `.pdf` input is
  `UnsupportedFormat`), OCR of image-only pages, per-page auto-rotation, tagged
  output, and PDF/A targets. Each is a separate task.
