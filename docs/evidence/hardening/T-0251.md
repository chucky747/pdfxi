Secret handling: the service password is read from the registration file
(`%USERPROFILE%\.local\state\opencode\service.json`), held in a `Secret` that
renders `<redacted>`, and used only to build the HTTP Basic header and the MCP
handshake header. It never appears in this file, in an error, in `Debug`
output, in a request body or in a test transcript. Server error bodies are
capped at 256 characters and passed through `redact()`.

### Licence-gate fix (round A -> round B)

The round-A tree used ureq's `platform-verifier` feature, which pulls
`webpki-root-certs` (CDLA-Permissive-2.0) through
`rustls-platform-verifier`, and `cargo deny check licenses` failed:

```text
error[rejected]: failed to satisfy license requirements
  ┌─ ...\webpki-root-certs-1.0.12\Cargo.toml:26:12
  ├ webpki-root-certs v1.0.12
bans ok, licenses FAILED
```

Fix: drop the `platform-verifier` feature, keep `rustls-no-provider`, and build
the TLS configuration in `crates/pdfxi-assistant/src/http.rs` with
`rustls::crypto::ring` plus roots loaded once from
`rustls_native_certs::load_native_certs()` and passed to
`RootCerts::new_with_certs`. HTTPS support is retained; loopback HTTP never
loads or consults the roots. Current result:

```text
$ cargo deny check
advisories ok, bans ok, licenses ok, sources ok
exit 0
```

## 6. Round B: client-MCP attach

(`crates/pdfxi-assistant/src/mcp.rs`, `tests/mcp.rs`, `tests/mcp_live.rs`)

- Socket: `ws://127.0.0.1:<port>/api/experimental/client-mcp?name=<name>` with
  the same Basic header. `wss` is supported for a remote explicit endpoint with
  rustls + operating-system roots. The name is validated against
  `^[A-Za-z0-9_-]{1,64}$`. `TcpStream::connect_timeout` uses the client connect
  budget and the read timeout uses the MCP idle budget.
- Protocol: `initialize` answered with `protocolVersion` `2025-11-25`,
  `capabilities.tools`, and `serverInfo {name: "pdfxi", version}`;
  `notifications/initialized` marks the handshake complete; `tools/list` is
  answered from `ToolProvider::tools()`; `tools/call` dispatches by name;
  `ping` is answered; unknown methods produce JSON-RPC `-32601`; malformed or
  unknown tool arguments produce `-32602`; requests before `initialize` produce
  `-32002`; tool failures return `isError: true` with redacted text and provider
  errors never escape as a panic.
- Tool set is fixed and read-only: `document_info`, `page_text` (1-based
  integer page), `search` (non-empty query), `selection`, `outline`. There is no
  shell, file, edit or network tool. Tool text is capped at 64 KiB with a
  `[truncated by PDFXI]` marker.
- Loop: stops on close, idle timeout, `max_messages` (default 64) or caller
  cancellation. Report: client name, initialize/initialized flags, tool-list
  request count, advertised names, called names, message count, idle flag.

Offline tests (`tests/mcp.rs`, 3 tests; 7 more unit tests in `mcp.rs`) cover the
handshake response, the read-only tool list, dispatch of `search`/`page_text`,
`-32601`/`-32602`/`-32002`, provider failure `isError`, message cap, idle
timeout and cancellation.

## 7. What MCP proved and what it did not

Proved live: WebSocket upgrade with Basic auth on loopback, frame-level JSON-RPC
with one message per text frame, the pinned protocol version, and lazy
`tools/list` immediately after the initialized notification.

Not proved live: `tools/call` from the service (needs a session that references
the MCP), permission prompts, cancellation through
`POST /api/session/{id}/interrupt`, and the `Permission.Ruleset` shape. Those
belong to the app-side connect task and the security review.

## 9. Host caveat

Rustdoc builds and runs merged doctests from `%TEMP%`. On this host an agent
session cannot execute from the default temp directory, so doctests fail
silently (exit 101, no diagnostic) unless `TEMP` and `TMP` point under
`target/tmp`:

```text
$env:TEMP = (Resolve-Path target/tmp).Path
$env:TMP  = $env:TEMP
```

All gate results above were produced with that setting.

## 10. Known limitations and follow-up

- `Assistant::ask` treats the idle item as the only terminal signal; a turn that
  a future service ends without an idle item hits the bounded wait.
- Cancellation stops local polling and socket reads; it does not yet call
  `POST /api/session/{id}/interrupt`, so the service may finish a turn that the
  UI abandoned. That call and its permission round-trip stay for the app task.
- The event stream is live-only and ends on its idle budget; the caller
  reconnects. Session correlation of events remains unverified.
- Round B serves MCP; it does not yet create the assistant session with a
  `Permission.Ruleset` that allows only these tools. The tool set is restricted
  by construction, but the service-side ruleset is still the enforcement point
  the security review needs.
- `[workspace.dependencies]` was not changed: every new crate is used by
  `pdfxi-assistant` only. The integrator may promote `ureq`, `rustls`,
  `rustls-native-certs`, `tungstenite`, `url`, `base64` and `http` when a second
  crate needs them.
