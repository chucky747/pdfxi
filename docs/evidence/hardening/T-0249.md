## 1. Public API

```rust
impl SigningIdentity {
    pub fn from_pfx(bytes: &[u8], password: &str) -> Result<Self, SecurityError>;
}
```

`from_pfx` calls `pkcs12::import_pfx`, then:

1. parses the recovered key as PKCS#8, falling back to PKCS#1;
2. parses every certificate as X.509 DER;
3. selects the certificate whose RSA public key matches the private key as the
   leaf, carrying the remaining certificates in container order;
4. calls the shared `assemble(key, chain)` also used by `from_pem`, which
   enforces the 2048-bit minimum and the key/certificate match.

`assemble` is private and shared so the two loading paths cannot drift. The
password is passed only to `import_pfx`; it is not stored on the identity,
formatted, or placed in an error.

Typed mappings:

| Condition | Error |
|---|---|
| wrong password or MAC/ciphertext mismatch | `PfxPasswordIncorrect` |
| truncated/misordered container, bad certificate DER | `PfxMalformed(&'static str)` |
| unsupported PBES/MAC algorithm | `PfxUnsupportedAlgorithm(String)` |
| no key bag / no certificate bag | `PfxMissingPrivateKey` / `PfxMissingCertificate` |
| non-RSA or key shorter than 2048 bits | `SigningKeyUnsupported(String)` |
| no certificate matches the private key | `DigitalIdKeyAlgorithmMismatch` |
| recovered key is not PKCS#8/PKCS#1 RSA | `SigningIdentityInvalid(&'static str)` |

## 2. PKCS#12 implementation

New modules under `crates/pdfxi-security/src/pkcs12/`:

- `ber.rs` - bounded BER reader for definite and indefinite lengths,
  constructed `OCTET STRING` flattening, implicit `[0]` octets, and OIDs.
- `kdf.rs` - HMAC, PBKDF2, and the RFC 7292 appendix B.2 KDF.
- `decrypt.rs` - PBES2 (PBKDF2 + AES-128/192/256-CBC), PBES1
  `pbeWithSHAAnd3-KeyTripleDES-CBC` and `pbeWithSHAAnd2-KeyTripleDES-CBC`, and
  the password MAC.
- `mod.rs` - `PFX`, `AuthenticatedSafe`, `SafeContents`, and bag parsing with
  `PfxContents` whose decrypted key is zeroed on drop.

Interop corrections made while validating against the Windows-exported PFX:

1. **RFC 7292 KDF:** `I_j = (I_j + B + 1) mod 2^v` is applied to **every** v-bit
   block of `I` (the `+ 1` matters), and the iteration chain is `H(A_i)`, not
   `H(D || A_i)`. The MAC only exercises one block, so the original portable
   tests did not catch this; the Windows 3DES key bag did.
2. **CMS `encryptedContent`:** it is `[0] IMPLICIT OCTET STRING`, not a
   universal `OCTET STRING`. The parser now accepts the context-specific
   identifier and flattens constructed chunks.
3. **Signer subject:** Windows self-signed identities can carry a serial wider
   than `u64`, which the strict `x509::Certificate` parser rejects. Subject
   display now falls back to parsing the `Name` DER directly, so the identity
   no longer shows `<unparsable subject>`.

No debug output is left in the crate: `eprintln!`, `println!` and `dbg!` are
absent from `crates/pdfxi-security/src/**`. The library is silent.

## 3. Local fixtures and key-material rule

`crates/pdfxi-security/tests/fixtures/pfx/generate.ps1` creates a test root,
intermediate and leaf with Windows `New-SelfSignedCertificate`, then exports:

- `leaf-3des.pfx` via `TripleDES_SHA1` (PBES1 + the PKCS#12 KDF);
- `leaf-aes256.pfx` via `AES256_SHA256` (PBES2 + PBKDF2 + AES-256-CBC).

The public test password is `pdfxi-test-pfx`. The certificates are generated by
Windows, not by PDFXI, so the import path is checked against an independent
encoder. The public `root.pem`, `intermediate.pem`, `leaf.pem` and
`generate.ps1` are intended for the repository. **The `.pfx` files contain
private keys and must never be committed.** They remain untracked local test
inputs; `git ls-files` matches no `.pfx`, `.p12`, or private-key PEM.

## 4. Test split

Portable unit tests (no external keys, default gate):

`pkcs12::ber` - definite/indefinite lengths, nested end-of-contents, constructed
`OCTET STRING`, malformed input, OIDs.

`pkcs12::kdf` - RFC 2202/4231 HMAC vectors, RFC 6070 and RFC 8018 PBKDF2
vectors, KDF determinism/id separation, and tail-aware `B + 1` block addition.

`pkcs12::decrypt` - PBES2 AES-256 synthetic round trip and wrong-password /
truncated-ciphertext mapping; PBES1 3-key and 2-key synthetic round trips;
MAC success, wrong password, modified digest and modified authSafe all map to
`PfxPasswordIncorrect`; 3DES known-answer block.

`pkcs12` - synthetic containers for missing key, missing certificate, bad
version, duplicate key, trailing bytes, and non-PFX bytes.
