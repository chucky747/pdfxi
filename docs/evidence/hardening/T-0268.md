# T-0268 - Redaction form XObject recursion and inline image decoding

- Status: Round A (form XObject recursion) and Round B (inline image decoding)
  implemented and gate-green. No app shell; EDIT-013 stays `library`.
- Lane: author
- Claim: `crates/pdfxi-edit/**`, this evidence file, the T-0268 feature fragment.
- Serves: O-06 (redaction removes content, verified by re-extraction and a byte
  scan) and A-30 (Protect PDF redaction entry point) from
  `docs/design/FEATURE_ACCEPTANCE.md`.
- ADR: 0010 point 5. Redaction is a full rewrite; it is never an incremental
  append that leaves the old operators or form content recoverable.
- Depends on: T-0237 (page content and image pixel removal).

## What changed

T-0237 treated every intersecting `/Subtype /Form` XObject as fail-closed:
`keep_images = false` returned `UnsupportedImage` and `keep_images = true`
returned a `<form XObject ...>` survivor. A mark over form-drawn content
therefore refused the whole request. T-0268 recurses into the form instead.

New public surface, same module (`crates/pdfxi-edit/src/redact_document.rs`):

- `RedactionError::UnsupportedForm { page, object, detail }` - a new typed
  fail-closed error for a form cycle, a depth/visit overflow, an undecodable
  form stream or an unsupported form filter. It is used only when the
  intersecting form cannot be rewritten safely.

Everything else in the T-0237 contract is unchanged: `RedactionMark`,
`RedactionRequest`, `RedactionReport`, `SurvivingSpan`, `apply_redaction`,
`verify_redaction`, image pixel redaction, annotation/link/widget/metadata
removal and the verifier.

## Recursion and transform strategy

1. A `Do` name in the current content stream is resolved through that stream's
   `/Resources /XObject`. `Image` keeps the T-0237 path; `Form` enters the new
   path; any other subtype, a direct object, an unresolvable reference or a
   missing name keeps the existing fail-closed behaviour.
2. The form's painted region is its `/BBox` transformed by
   `form Matrix x current CTM` (the unit square when `/BBox` is absent). If that
   region does not intersect a mark the form is not read or rewritten.
3. Otherwise the form content stream is decoded (no filter or a single
   `FlateDecode` with a direct `/DecodeParms`; anything else is
   `UnsupportedForm`) and `rewrite_content` is called with the composed
   `Matrix x CTM` as the initial CTM. Glyph and image rectangles are therefore
   still computed in page space, so the same mark rectangles that apply to page
   content apply inside the form. Nested `Do` operators compose their own form
   matrix with the current CTM in the same way.
4. A form's own `/Resources` replaces the parent's; a form without `/Resources`
   inherits the parent page's or enclosing form's fonts and XObjects. This
   matches the PDF form-resource rule and lets nested forms use either model.
5. A rewritten form is stored copy-on-write as a new stream object with
   `/Filter`, `/DecodeParms` and `/Length` removed. The page dictionary, the
   original source bytes and the original form bytes are never mutated in
   place. Only `Document::set_object` is called, and only after every page and
   form has been prepared.
6. A form placed from more than one CTM is rewritten cumulatively: the second
   pass starts from the bytes produced by the first pass, so marks from every
   placement accumulate instead of the last placement winning. A shared form
   can therefore lose more content than one placement alone requires; over-
   removal is safe for redaction, silent survival is not.

Limits:

- `MAX_FORM_DEPTH = 16` levels of nesting.
- `MAX_FORM_VISITS = 512` form visits per `apply_redaction` call (repeats
  included).
- An object id already on the active recursion stack is a cycle.
- All three conditions return `UnsupportedForm` before any document mutation.

Removed text runs inside a form are merged into `RedactionReport::removed_runs`
with the owning page index; survivors from an opt-out are merged into
`surviving_spans`. `clean` is computed from the merged survivors, so a form can
no longer be skipped without appearing in the report.

## Fail-closed matrix (Round A)

| Intersecting form | `keep_images = false` | `keep_images = true` |
| --- | --- | --- |
| form with text under the mark | rewritten, text removed, reported | `<form XObject name>` survivor |
| form with an image XObject under the mark | image pixel-redacted, reported | `<form XObject name>` survivor |
| form with nested forms under the mark | recursed, nested content removed | `<form XObject name>` survivor |
| form with no filter or a single `FlateDecode` | recursed | survivor |
| form with another filter or a filter array | `UnsupportedForm` | survivor |
| form cycle | `UnsupportedForm` | survivor |
| form nesting over 16 | `UnsupportedForm` | survivor |
| form visit budget over 512 | `UnsupportedForm` | survivor |
| form not intersecting a mark | untouched | untouched |
| form with vector graphics under the mark | not removed; `clean` stays true (known limit) | `<form XObject name>` survivor |
| form with indirect `/Matrix` or `/BBox` | resolved, then placed as above (Round B fix) | survivor |
| form with malformed `/BBox` | recursed as possibly intersecting, never skipped (Round B fix) | survivor |
| form with present malformed `/Matrix` | `UnsupportedForm` (Round B fix) | survivor |
| intersecting inline image | decoded, refilled and rewritten in place (Round B) | `<inline image>` survivor |

Vector paths under a mark are a known limit: this pass removes text and image
XObjects, exactly as the page pass does. Vector graphics are not removed, and a
form that draws only paths under a mark produces no survivor and leaves
`report.clean` true — exactly the same as page content. Callers must not rely
on `clean` for vector-only content.

## Round B - inline images

### Tokenizer and sample-span rules

`content_edit::tokenize` now attaches an `InlineImage` to each `BI` operator
instead of discarding the object. It retains the direct dictionary key/value
pairs between `BI` and `ID`, the exact sample span, and the offset just past
`EI`. The rules are:

1. Dictionary entries are read with the normal content lexer until the bare
   `ID` operator; keys are names and values are names, numbers, strings, arrays
   or dictionaries. A missing value or a non-name key is a typed
   `MalformedContent` error.
2. The single white-space byte that the spec requires after `ID` is consumed
   and is not part of the samples. `sample_start` is the next byte.
3. For an **unfiltered** image, `/W /H /BPC /CS` give an exact sample length
   (`ceil(W x components x BPC / 8) x H`). That length is authoritative, so a
   binary sample byte sequence that spells ` EI ` cannot be mistaken for the
   terminator. The bytes at the computed end must be white-space followed by
   `EI` and then white-space, a delimiter or end of data.
4. For a **filtered** image (notably `DCTDecode`) the length is not derivable,
   so `EI` is located with the PDF terminator rule: a preceding white-space
   byte and a following white-space byte, delimiter or end of data. A term
   that declares a computable length which does not match the bytes is flagged
   `sample_confident = false` and fails closed.
5. `object_end` is just past `EI`, so `rewrite_content` can replace the whole
   object while leaving every surrounding operator and the page's `q`/`Q`
   untouched. The `BI` operator's own `start`/`end` span is unchanged.

A unit test (`content_edit::tests::tokenizer_keeps_inline_dictionary_and_exact_sample_span`)
places a literal ` EI ` inside 12 bytes of RGB sample data and proves the
dictionary, the 12-byte span and `object_end` are all exact.

### Redaction path and supported formats

An inline image paints into the unit square under the current CTM. For an
image inside a form, `rewrite_content` is entered with the form matrix already
composed into the CTM, so the same page-space mark rectangles apply. When a
mark intersects the placement and `keep_images = false`, the sample bytes are
decoded through the image-XObject helpers (`decode_jpeg`, `decode_stream`,
`flate_params`, `raw_color_layout`, `check_sample_budget`), filled with opaque
black through `invert(ctm)` and `mark_image_region`, and rebuilt as a
deterministic unfiltered `BI /W ... /H ... /BPC 8 /CS ... ID\n<samples>\nEI`
object. `/F`, `/DP` and `/D` are not emitted. Unfiltered output lets a reader
derive the exact data length, so embedded `EI`-like bytes are harmless.

| Format | Inline dictionary | Result |
| --- | --- | --- |
| 8-bit DeviceGray / `/G` | `/BPC 8 /CS /G`, raw | refilled, `/CS /G` |
| 8-bit DeviceRGB / `/RGB` | `/BPC 8 /CS /RGB`, raw | refilled, `/CS /RGB` |
| 8-bit Indexed | `/CS [/Indexed base hival <lookup>]` | palette expanded to RGB, refilled, `/CS /RGB` |
| DCTDecode JPEG | `/F /DCTDecode`, JPEG samples | decoded to RGB, refilled, unfiltered |

### Fail-closed matrix (Round B)

| Intersecting inline image | `keep_images = false` | `keep_images = true` |
| --- | --- | --- |
| Gray/RGB/Indexed/DCTDecode with a clear span | decoded, refilled, rewritten in place | `<inline image>` survivor |
| unsupported filter (`JPXDecode`, CCITTFax, filter array, ...) | `UnsupportedImage` naming the filter | survivor |
| declared length disagrees with the bytes | `UnsupportedImage` ("no clear sample span") | survivor |
| `/D`, `/IM`, raw CMYK, ICCBased, `/BitsPerComponent != 8`, `/ImageMask`, bad `/ColorSpace` | `UnsupportedImage` | survivor |
| placement transform not invertible | `UnsupportedImage` | survivor |
| image outside every mark | untouched byte-for-byte | untouched |
| sample budget over 64 MiB or 100 MP | `ImageLimitExceeded` | survivor |

All failures are raised in phase 1, before `document.set_object` is called, so
an error never leaves a half-written stream or an artifact on disk.

### Reviewer follow-ups: fail-closed geometry

- **Form geometry.** `form_matrix` treats an absent `/Matrix` as identity,
  resolves an indirect one through the effective document, and returns
  `UnsupportedForm` for a present value that is not a finite six-number array.
  `form_bbox` resolves an indirect `/BBox` and returns `None` for an absent or
  malformed one. `form_placement` then returns `None` for unknown geometry,
  which `handle_form_xobject` treats as *possibly intersecting*: it recurses
  instead of skipping. There is no longer any identity/unit-square fallback
  that can hide a form under a mark.
- **Unresolvable XObject placement.** Choice made: conservative fail-closed.
  For a missing resource dictionary, a missing name, a direct object or an
  unreadable reference there is no trustworthy placement, so `handle_xobject`
  ignores the unit-square heuristic and refuses the request whenever the page
  has any mark or the CTM is not invertible. With `keep_images = true` it
  records the usual `<unresolved XObject name>` survivor. A resolved XObject
  still uses its real unit-square placement. This means an unrelated, broken
  `Do` on a marked page can fail the whole request; that is deliberate and
  preferable to silently skipping possibly-marked content.

## Remaining limits

- Inline images with `/F` filters other than `DCTDecode` (and `FlateDecode`,
  which is also decoded) fail closed. Filtered sample spans use the PDF
  terminator rule; a filter whose compressed bytes contain the exact byte
  sequence `white-space EI white-space` cannot be delimited by that rule and
  fails closed or is truncated — length-bearing DCTDecode streams should be
  preferred. Re-encoded output is unfiltered, so this limit does not apply to
  redacted output.
- Inline ICCBased colour spaces cannot reference a profile stream from an
  inline dictionary and therefore fail closed. `/D` (Decode) and `/IM`
  (ImageMask) also fail closed.
- Form content filters are limited to none or one `FlateDecode`. Multi-filter
  chains, LZW and other filters fail closed.
- Form and page vector graphics are not removed, matching the page-content
  pass. A future pass would need path-bbox tracking and a fill/stroke decision.
- `redact_document` still has no UI or CLI entry point. EDIT-013 remains
  `library`; no promotion is claimed.
- T-0257 owns the broader sanitise pass and independent second-reader
  verification.
