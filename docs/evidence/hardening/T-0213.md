# T-0213 - full rewrite save, optimize and page plans for modern PDFs

Date: 2026-11-20
Toolchain: rustc 1.100.0 (0ef1bc386 2026-11-09), cargo 1.100.0 (3acc79c0c 2026-11-05)
Target dirs: `CARGO_TARGET_DIR=target/lanes/core` (lane gates),
`CARGO_TARGET_DIR=target/integration` (integrator re-run)
Task: T-0213, lane `core`, claim `orchestration/claims/T-0213.json` (released)

## 1. What was wrong

`Document::save()`, `Document::optimize()` and `PagePlan::apply()` all routed
through `Document::supported_structure()`, which declined every document whose
document-level parse produced `structure.xref.uses_xref_stream` — and, when the
parse had already failed, it also probed `startxref` with
`parser::looks_like_xref_stream()` and converted that failure into
`Error::UnsupportedState("cross-reference streams are not supported")`.

That single gate covered every cross-reference-stream producer, every hybrid
`/XRefStm` file (which is what Excel 2019 and PowerPoint emit) and every file
whose objects live in an `/ObjStm`. The reader already understood all three, so
the write path could not save, optimize or reorder pages of mainstream output.
The gate was there for a real reason: the full-rewrite writer copied objects as
raw source bytes, so any object compressed inside an object stream would have
been dropped. Removing the gate without changing the writer would have produced
silently truncated documents.

## 2. What changed

`crates/pdfxi-core/src/parser.rs`

- Removed `XrefTable::uses_xref_stream` (the field only existed to feed the
  write gate). `XrefReport.uses_xref_stream` — the public reporting surface — is
  unchanged.
- Added `XrefTable::live_object_numbers()`, which returns every in-use *and*
  `/ObjStm`-compressed object number, sorted. `in_use_entries()` still drives
  the incremental path and still returns type-1 entries only.
- Added `parser::is_structural_stream(&Object)`: true for `/Type /XRef` and
  `/Type /ObjStm` streams. Neither may be copied into a rewritten file, because
  their contents are expanded into standalone indirect objects.
- `object_range()` rustdoc now states that a source object without a terminating
  `endobj` is reported as `Error::UnexpectedToken` rather than silently
  repaired. This is what preserves the malformed-manifest contract now that the
  writer re-serializes parsed values instead of copying bytes.

`crates/pdfxi-core/src/writer.rs`

- `write_xref_section_with_generations()` is the new primitive. Each entry maps
  an object number to `(offset, generation)`, and the generation is written as
  `{generation:05}` in the `n` row. `write_xref_section()` is now a thin wrapper
  that fills generation `0`, so incremental saves and page plans keep their
  previous byte shape.
- `sanitize_trailer()` moved here from `optimizer.rs` (it is now shared by both
  full-rewrite paths). It removes `Size`, `Root`, `Prev`, `Encrypt`, `XRefStm`,
  `Length`, `Filter`, `W`, `Index` and `Type`, so xref-stream-only keys from a
  merged source trailer cannot leak into a classic table.

`crates/pdfxi-core/src/lib.rs`

- `Document::save()` is a full rewrite through the typed reader:
  - every number in `live_object_numbers()` is resolved with
    `parser::object_generation()` + `parser::load_object()`, which expands
    `/ObjStm` members and keeps each object's generation;
  - staged `Document::set_object()` changes overlay the source, and structural
    streams are skipped on both paths;
  - objects are emitted in one pass with
    `writer::serialize_indirect()`, so stream dictionaries keep their filters
    and encoded bytes and only `/Length` is recomputed;
  - the output carries one classic table, one trailer, `startxref` and `%%EOF`,
    and object numbers/generations are preserved so existing references stay
    valid;
  - `sanitize_trailer()` runs before `Size`/`Root` are re-inserted.
- `save()` still validates the physical source first: every in-use entry's
  `object_range()` is resolved before any byte is written, so a source object
  with no `endobj` fails as `Error::UnexpectedToken` instead of being repaired.
- `supported_structure()` lost both xref-stream branches. It keeps the stored
  structural error and keeps
  `Error::UnsupportedState("encrypted documents cannot be saved")`: the writer
  does not encrypt, so an `/Encrypt` source must be decrypted by the session
  layer first.
- Rustdoc for `save()`, `apply_page_plan()`, `optimize()` and
  `supported_structure()` now describes the new contract, including that a full
  rewrite flattens revision history, drops linearization hints and invalidates
  signatures.

`crates/pdfxi-core/src/pages.rs`

- `render()` loads every live object number (object streams included) at its
  real generation, skips structural streams, and continues to copy the source
  page tree's non-selected objects into the new document. Page reorder, delete,
  insert, merge, split and extract therefore work on hybrid and pure stream
  sources.
- Module rustdoc no longer lists xref-stream sources as rejected.

`crates/pdfxi-core/src/optimizer.rs`

- The object pass loads `live_object_numbers()` at their real generations and
  skips structural streams; staged changes are overlaid when
  `id.generation == 0` and the value is not a structural stream.
- The local `sanitize_trailer()` copy was removed in favour of the shared
  `writer::sanitize_trailer()`. Module and function rustdoc updated.
- Compression, renumbering and the cancellation checkpoints are unchanged.

`crates/pdfxi-core/src/xref_tests.rs`

- `xref_stream_parses_page_tree_content_and_decode_parms` previously asserted
  that a full rewrite declined. It now asserts the opposite, concretely: the
  rewrite succeeds, the output contains `\nxref\n`, contains no `/Type /XRef`,
  reparses, keeps one page, and keeps the decoded text `Stream XRef!`. The
  incremental assertions in the same test are untouched.

`crates/pdfxi-core/src/boxes.rs`

- Two tests compared raw bytes (`/CustomKey <6B656570206D65>` and a byte slice
  of the untouched page object). A full rewrite canonicalizes string syntax and
  re-serializes every object, so those assertions were wrong for the new
  contract. They now reparse the output and compare typed values:
  `Document::page_boxes`/`object()` return `Object::String(b"keep me")` and
  `Object::String(b"untouched")`, and the untouched page object compares equal
  as an `Object`, not as bytes. This is a strictly stronger check: it no longer
  depends on whitespace or hexadecimal-vs-literal string syntax.

`crates/pdfxi-core/tests/realworld.rs`

- New helper `assert_classic_table()` reparses a rewrite and asserts: a classic
  `xref` keyword, no `/Type /XRef`, no `/ObjStm`, first section
  `XrefSectionKind::Classic`, and `uses_xref_stream == false`.
- Five new tests, all against the Excel 2019 hybrid fixture unless stated:
  - `full_save_rewrites_hybrid_xref_stream_source_with_classic_table` — 2 pages,
    both page texts identical before and after the rewrite;
  - `full_save_page_plan_can_reverse_hybrid_xref_stream_source` — `reorder([1,0])`
    puts the original page 2 text first and page 1 text second;
  - `full_save_page_plan_can_delete_first_hybrid_page` — `extract([1])` leaves
    one page carrying the original page 2 text;
  - `optimize_rewrites_hybrid_xref_stream_source` — optimized output keeps both
    page texts and reports at least the source object count;
  - `full_save_rewrites_pure_xref_stream_and_object_stream_source` — the
    testkit's pure `/Type /XRef` fixture with `/ObjStm` members rewrites and
    keeps `From ObjStm`.
- `write_pdfium_check_outputs` is `#[ignore]`d: it writes the three artifacts
  used for the external PDFium check (section 5).

Every new assertion fails without the change: before it, `save()`,
`apply_page_plan()` and `optimize()` returned
`Err(Error::UnsupportedState("cross-reference streams are not supported"))` at
the removed gate, so each test stopped at its `.expect(...)`.

## 5. Scope and limitations

- Encrypted sources still return `Error::UnsupportedState`; the writer never
  encrypts. Decryption and a typed password error belong to T-0214.
- A full rewrite is deliberately destructive: one revision, no `/Prev` chain, no
  linearization hints, no `/XRefStm`, no source `/Type /XRef`/`/ObjStm` objects,
  and any digital signature is invalidated. Incremental save remains the
  preservation path.
- Object numbers and generations are preserved, but objects are emitted in
  ascending number order and string syntax is canonicalized to hexadecimal. No
  test may compare rewritten bytes; compare parsed values.
- Compressed objects that were only reachable through an object stream are
  emitted as plain indirect objects, so a rewrite can be larger than the source
  (93 KiB from 92 KiB here). The optimizer's compression pass is the way back
  down.
- The optimizer still sums and rewrites every live object; no benchmark was run
  because the change does not add a pass, it replaces a byte copy with a typed
  load for sources that were previously rejected outright. `cargo xtask bench`
  has no xref-stream corpus entry.
- `write_pdfium_check_outputs` writes into `target/`, which is gitignored; it is
  ignored by default so the fast suite never writes files.
