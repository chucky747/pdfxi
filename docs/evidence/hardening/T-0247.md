## API

In `crates/pdfxi-edit/src/document_annotations.rs`:

- `add_underline(document, page_index, quads, contents, author)`
- `add_strikeout(document, page_index, quads, contents, author)`
- `add_ink(document, page_index, paths, stroke_width, contents, author)`

New limits and constants:

```text
MAX_MARKUP_QUADS = 4096
MAX_INK_PATHS = 256
MAX_INK_POINTS = 8192
MIN_INK_STROKE_WIDTH = 0.1
MAX_INK_STROKE_WIDTH = 32.0
MARKUP_STROKE_COLOR = [0.0, 0.0, 0.0]
MARKUP_STROKE_WIDTH = 1.0
```

New typed errors: `EmptyInk`, `TooManyQuads`, `TooManyInkPaths`,
`TooManyInkPoints`, `InvalidStrokeWidth`, `CoordinateOutsidePage`;
`EmptyQuads` now covers every text-markup kind.

`AnnotationView` gained `kind: Option<AnnotationKind>`, `quads`,
`ink_paths`, `color` and `stroke_width`, read back from the stored
dictionary. `AnnotationKind::from_pdf_name` maps `Underline`, `StrikeOut`,
`Ink` (to `Pencil`), `Square` (to `Rectangle`), `Circle` (to `Oval`),
`Polygon`, `Stamp` and the existing note/highlight names; unknown subtypes
stay `None`.

## Appearance construction

- Underline and strikeout write `/Subtype /Underline` or `/StrikeOut`,
  `/QuadPoints` in the PDF eight-number form, `/Rect` as the union of the
  quads, `/C`, `/CA`, `/F 4`, `/T`, `/M`, `/NM`, `/Contents`, and an indirect
  `/AP /N` form XObject.
- The appearance content strokes one line per quad in the annotation's own
  coordinate system: the underline sits half a stroke width above the bottom
  edge, the strikeout crosses the vertical middle. Each line is emitted as
  `m ... l S` in the markup stroke colour at `MARKUP_STROKE_WIDTH`, with the
  default butt cap (the underline/strikeout stream sets no `J`/`j` operator).
- Ink writes `/Subtype /Ink`, `/InkList` as an array of stroked paths,
  `/BS << /W stroke_width /S /S >>`, `/Rect` as the point bounds expanded by
  half the stroke width plus slack, and an `/AP /N` form XObject that strokes
  every path. A one-point path is emitted as a degenerate round-capped
  `m ... S` subpath; whether a viewer paints that as a dot is viewer-dependent
  and is not asserted by a test. Empty paths are ignored.
- Every appearance is an indirect form XObject with `/BBox [0 0 w h]` taken
  from the annotation `/Rect`, an identity `/Matrix`, empty `/Resources`, and
  content coordinates relative to the rect lower-left corner.
- `/NM` defaults to `pdfxi-underline-<object>`, `pdfxi-strikeout-<object>` or
  `pdfxi-ink-<object>` from the allocated annotation object; XFDF import may
  supply one explicitly.

## Validation and fail-closed rules

Validation runs before any object allocation or `set_object`, so a rejected
input leaves the document byte-identical:

- empty or all-degenerate quads -> `EmptyQuads`;
- more than `MAX_MARKUP_QUADS` -> `TooManyQuads`;
- more than `MAX_INK_PATHS` paths or `MAX_INK_POINTS` total points ->
  `TooManyInkPaths` / `TooManyInkPoints`;
- no path with a point -> `EmptyInk`;
- non-finite point -> `Geometry`;
- quads or points outside the page media box -> `CoordinateOutsidePage`;
- stroke width outside the finite `MIN..=MAX` range -> `InvalidStrokeWidth`;
- missing page or malformed `/Annots` -> the existing typed errors.

Coordinates outside the page media box are rejected, never clamped or silently
shrunk. The ink `/Rect` is the point bounds expanded by half the stroke width
plus `INK_RECT_PADDING = 0.5`, so that rect may extend past the media box edge
by the padding even though every input point is inside the box.

## Compatibility decision

`AnnotationSubtype` was deliberately not extended. `pdfxi-app` matches it in
`shell/comments.rs`: `subtype_label` is exhaustive and `subtype_icon` has a
`_` fallback, so adding variants would break the app lane mid-campaign. The new
kinds are reported through `AnnotationView::kind`, while `subtype_label`
renders them as `Other("<Name>")` and `subtype_icon` falls back to the comment
icon. A later shell task should switch the labels/icons to `view.kind` and then
add enum variants. This is a known integration limit, not a silent fallback.

The plain functions use `ShapeStyle::default()`: opaque black, no interior
fill, 1 pt border. `ShapeStyle` is plain data
(`stroke_color: [f64; 3]`, `fill_color: Option<[f64; 3]>`,
`stroke_width: f32`, `opacity: f64`) and the add functions validate it before
allocating any object.

New limits and constants:

```text
MAX_POLYGON_VERTICES   = 4096
MAX_STAMP_TEXT_CHARS   = 200
ARROW_HEAD_LENGTH      = 8.0
STAMP_COLOR            = [0.75, 0.1, 0.1]
STAMP_NAMES            = 14 standard ISO 32000-1 names
```

New typed errors: `DegenerateLine`, `EmptyShapeRect`, `DegeneratePolygon`,
`TooManyVertices`, `InvalidColorComponent`, `InvalidOpacity`,
`InvalidStampName`, `StampTextTooLong`. Existing `Geometry`,
`CoordinateOutsidePage`, `InvalidStrokeWidth` and `DuplicateId` are reused.

`AnnotationView` gained `line: Option<(Point, Point)>` from `/L`,
`vertices: Vec<Point>` from `/Vertices`, and `stamp_name: Option<String>` from
`/Name`. `kind` reports `Line`, `Rectangle`, `Oval`, `Polygon` and `Stamp`
through the existing `AnnotationKind::from_pdf_name` mapping; `AnnotationSubtype`
is still not extended (see the compatibility decision above).

## Round B appearance construction

- Line: `/Subtype /Line`, `/L [x1 y1 x2 y2]`, `/LE [/None /OpenArrow]`, and an
  `/AP /N` form that strokes the segment with round caps and joints plus two
  arrow legs at 25 degrees back from `to`, each [`ARROW_HEAD_LENGTH`] long.
  `/Rect` is the endpoint bounds expanded by half the stroke width plus the
  arrow length.
- Square: `/Subtype /Square`; the appearance draws `re` and paints with `S`
  (outline) or `B` (outline plus `/IC` fill). `/Rect` is the input rectangle
  expanded by half the stroke width.
- Circle: `/Subtype /Circle`; the appearance draws the inscribed ellipse as
  four cubic Bezier segments (`c` operators, kappa `0.5522847498`) and paints
  with `S` or `B`. `/Rect` is the input rectangle expanded by half the stroke
  width.
- Polygon: `/Subtype /Polygon`, `/Vertices [x1 y1 ...]`, and an appearance that
  moves to the first vertex, lines to the rest, closes with `h`, and paints `S`
  or `B`. `/Rect` is the vertex bounds expanded by half the stroke width.
- `/IC` is written only when `ShapeStyle::fill_color` is `Some` and the shape is
  not a line. Every shape also writes `/C`, `/CA`, `/F 4`, `/BS`, `/T`, `/M`,
  `/NM` (`pdfxi-line-<object>`, `pdfxi-square-<object>`,
  `pdfxi-circle-<object>`, `pdfxi-polygon-<object>`) and `/Contents`.
- Stamp: `/Subtype /Stamp`, canonical `/Name`, exact `/Contents`, `/T`, `/M`,
  `/NM` (`pdfxi-stamp-<object>`), `/C`, `/CA 1`, `/F 4` and an `/AP /N` form
  with a vector border plus a Helvetica label. No external image or embedded
  font is used. The label is mapped to printable ASCII (`?` replaces control
  and non-ASCII characters), escaped with the existing PDF literal escaper, and
  sized to fit the border; `/Contents` keeps the exact Unicode text.
- Every appearance is an indirect form XObject with `/BBox [0 0 w h]` from the
  annotation `/Rect`, an identity `/Matrix`, and content coordinates relative to
  the rect lower-left corner. Shape appearances have empty `/Resources`; the
  stamp appearance carries only `/Font /F1 /Helvetica`.

## Round B validation and fail-closed rules

Validation runs before any object allocation or `set_object`, so a rejected
input leaves the document byte-identical:

- `ShapeStyle`: each stroke and fill component must be finite and in
  `0.0..=1.0` -> `InvalidColorComponent`; opacity must be finite and in
  `0.0..=1.0` -> `InvalidOpacity`; stroke width must be finite and in
  `0.1..=32.0` -> `InvalidStrokeWidth`.
- Line: identical endpoints -> `DegenerateLine`; non-finite point ->
  `Geometry`; an endpoint or the derived `/Rect` outside the media box ->
  `CoordinateOutsidePage`.
- Square/circle: zero width or height -> `EmptyShapeRect`; a corner or the
  derived `/Rect` outside the media box -> `CoordinateOutsidePage`.
- Polygon: more than `MAX_POLYGON_VERTICES` -> `TooManyVertices`; fewer than
  three vertices or near-zero shoelace area -> `DegeneratePolygon`; the same
  point and rect checks as the other shapes.
- Stamp: unknown `/Name` -> `InvalidStampName`; more than
  `MAX_STAMP_TEXT_CHARS` characters -> `StampTextTooLong`; empty rect ->
  `EmptyShapeRect`; rect outside the media box -> `CoordinateOutsidePage`.
  The name is matched case-insensitively and the canonical spelling is written
  (for example input `approved` writes `/Name /Approved`).
- Derived `/Rect` values are normalized by construction (`Rect::new` rejects
  inverted input) and every derived rect, including the half-stroke and arrow
  expansion, must lie inside the page media box. Coordinates are rejected, never
  clamped.

## Limits

- `AnnotationSubtype` is not extended; see the compatibility decision above.
  Shape and stamp subtypes read back as `Other("<Name>")` and are carried by
  `AnnotationView::kind` instead.
- The library does not render annotations itself; proof is PDFium plus the
  stored dictionaries. Render proof relies on PDFium honouring `/AP /N`.
- Line annotations always draw the open arrowhead at `to`; a later UI task can
  expose a no-arrow variant by adding a parameter without changing `/L`.
- `ShapeStyle::fill_color` is ignored for lines, which have no interior.
- Stamp labels are drawn with the standard Helvetica font, so the appearance
  shows printable ASCII only; `/Contents` preserves the exact text.
- No shell entry point was added; the Comments UI already exists and will
  expose the new kinds in a later shell task. No matrix promotion:
  `feature_rows` and `promoted_rows` stay empty, and EDIT/REVIEW rows are
  unchanged.
