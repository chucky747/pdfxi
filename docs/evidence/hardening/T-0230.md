## 1. Why

`pdfxi-edit` had no `pdfxi-core` dependency. Its annotation code
(`annotation.rs`, `pdf/`) was a renderer-agnostic model and dictionary
intermediate, so comments and highlights never reached a real PDF `/Annots`
array and had no appearance stream. ADR 0010 requires every document feature to
mutate the real `pdfxi_core::Document` through the single write path, and
ADR 0012 splits comments into this library task plus a later app-shell task.

Round A delivers the vertical slice on real bytes: notes, highlights, listing,
thread replies, resolve state, update, delete, XFDF import/export, and a full
save/reopen proof. The PDFium independent reopen and the app-shell wiring remain
follow-ups (section 7).

## 3. What is written to the PDF

Every annotation is an indirect object added to the page's `/Annots` array
(preserving an indirect array object when the page has one) and carries:

| Key | Text note | Highlight |
|---|---|---|
| `/Type` | `/Annot` | `/Annot` |
| `/Subtype` | `/Text` | `/Highlight` |
| `/Rect` | `[x, y, x+24, y+24]` | union of the quads, normalized |
| `/QuadPoints` | - | 8 numbers per quad in ISO 32000-1 order (UL, UR, LL, LR) |
| `/Contents` | UTF-16BE/PDFDocEncoding text string | same |
| `/T` | author text string | same |
| `/NM` | caller id (notes), `pdfxi-reply-<n>` (replies), `pdfxi-highlight-<n>` (highlights) | same |
| `/M` | `D:YYYYMMDDHHmmSSZ` (UTC) | same |
| `/C` | `[1 .82 .1]` | `[1 1 0]` |
| `/CA` | `1.0` | `0.5` |
| `/F` | `4` (print) | `4` |
| `/AP` | `<< /N <form XObject> >>` | `<< /N <form XObject> >>` |
| `/IRT` + `/RT /R` | on replies only, pointing at the parent annotation object | - |
| `/State` + `/StateModel /Review` | after `set_state` | after `set_state` |

The `/AP /N` form XObject has `/Type /XObject`, `/Subtype /Form`,
`/FormType 1`, `/BBox`, `/Matrix [1 0 0 1 0 0]`, `/Resources`, and a content
stream. The note form (`BBox [0 0 24 24]`) draws the coloured icon rectangle,
border and three text lines. The highlight form (`BBox` = annotation size)
draws one opaquely filled `re f` per quad inside `q /GS0 gs ... Q`, with an
inline `/ExtGState << /GS0 << /Type /ExtGState /ca 0.5 /CA 0.5 >> >>` resource,
so the markup is translucent even in viewers that ignore annotation `/CA`.

`delete_annotation` removes the `/Annots` entry and overwrites the annotation
object and its indirect `/AP /N` stream with `null`, so a full rewrite does not
retain the comment text. An incremental save necessarily keeps earlier
revisions (ADR 0010 point 3); permanent erasure is the redaction path.

## 4. XFDF

`export_xfdf` writes one `<annot>` element per annotation inside
`<xfdf xmlns="http://ns.adobe.com/xfdf/" xml:space="preserve"><annots>` with
attributes `page`, `subtype`, `rect` (`x0,y0,x1,y1`), `author`, `date`, `id`,
plus `replyto` for a thread reply and `state` for a resolved comment. Contents
is escaped element text. `import_xfdf` uses a small bounded XML scanner (no
regex, no XML dependency): it finds the `<annots>` block, tokenizes `<annot>`
tags with quote-aware tag-end detection, parses quoted attributes, decodes
`&amp; &lt; &gt; &quot; &apos;` and numeric character references, and maps the
fields back onto `add_text_note`, `reply_to`, `add_highlight` and `set_state`.
Date, author and the text-note/highlight id round-trip; the reply relationship
round-trips through `replyto`.

## 5. Write model and a core limitation (follow-up request)

`pdfxi_core::Document` exposes no public accessor for staged changes, and
`Document::object()` reads only the source bytes. To make repeated operations
on one `&mut Document` correct without a private accessor, each operation builds
a current view with `Document::save_incremental()` followed by
`Document::from_bytes()`, then stages its new objects into the caller's
document. This is the same reparse the `pdfxi-document` session performs after
every edit, so the cost matches the session path, but it does serialize the
document once per call.

Preferred round B unblock (core lane, T-02xx): add a public
`Document::effective_object(&self, id) -> Result<Object>` (or a staged-change
iterator) so the library can drop the reparse. Until then the behaviour is
correct and tested, but a batch of N annotations costs N incremental
serializations.
