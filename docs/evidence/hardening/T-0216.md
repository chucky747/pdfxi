# T-0216 - Apply ToUnicode CMaps in page_text for subset fonts

Date: 2026-11-20
Toolchain: rustc 1.100.0, cargo 1.100.0
Target dir: `CARGO_TARGET_DIR=target/lanes/core3`
Task: T-0216, lane `core`, claim `orchestration/claims/T-0216.json`

## 1. What shipped

- `crates/pdfxi-core/src/tounicode.rs` - bounds-checked `/ToUnicode` CMap parser and decoder. Handles `begincodespacerange`, `beginbfchar`, `beginbfrange` with an incremented string destination, `beginbfrange` with an array destination `[<dst> <dst> ...]`, UTF-16BE destinations including surrogate pairs, one- to four-byte source codes, and unmapped codes (U+FFFD, never a panic). Caps: 65,536 mappings, 1,024 code-space ranges, 4-byte codes, 8 pending operands.
- `crates/pdfxi-core/src/content.rs` - `FontMap` plus `extract_text_with_fonts`. The extractor now tracks `Tf` and decodes every `Tj`, `TJ`, `'` and `"` string through the active font's CMap before the existing byte-for-byte fallback. `extract_text` is unchanged in behaviour.
- `crates/pdfxi-core/src/lib.rs` - `Document::page_text` resolves the page's `/Resources /Font` dictionary (inline or indirect), decodes each `/ToUnicode` stream with its `/Filter` chain, and caches the parsed CMap by stream object id in a document-scoped `Arc<Mutex<HashMap<...>>>`. A missing, undecodable or malformed CMap falls back to raw-code decoding instead of failing extraction.
- `crates/pdfxi-core/tests/tounicode_text.rs` - four integration tests: synthetic Type0 font covering bfchar, bfrange increment, bfrange array, surrogate pair and an unmapped code; per-`Tf` font switching; the no-CMap regression on both a synthetic font-only PDF and `pdfxi_testkit::minimal_pdf`; and the real Edge fixture markers.
- `orchestration/feature-updates/T-0216.toml` - matrix fragment for AUTO-010.

## 4. Behaviour and limits

- Precedence is `/ToUnicode` first, then the existing byte decoding. This build still has no WinAnsi/Differences table, so a simple font without `/ToUnicode` keeps the previous Latin-1-style fallback; that is unchanged, not widened.
- Segmentation uses the CMap code space. Without one, the unique mapping width is used, otherwise one byte.
- A destination of odd length is decoded as Latin-1 for compatibility with legacy writers; even lengths are UTF-16BE and may contain surrogate pairs.
- `bfrange` increments the destination as a big-endian integer with carry.
- An unmapped code emits one U+FFFD. Decoding always consumes at least one byte and cannot loop forever.
- Resource lookup covers an inline or indirect `/Resources` on the page and an indirect inherited `/Resources` recorded by the page tree. A direct `/Resources` dictionary on an ancestor `/Pages` node is not captured by the current page-tree builder; that pre-existing limitation is unchanged.
- A malformed `/ToUnicode` stream degrades to raw-code extraction rather than returning an error, so text extraction stays total for hostile input.
