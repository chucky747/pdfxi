## Method

Every row was classified by the code that implements it and by whether an end user can
reach that code:

- **A — end-user reachable.** The row's capability runs on real document bytes through
  the CLI (`crates/pdfxi-cli`) or the GUI (`crates/pdfxi-app`), and a call site exists.
- **B — library only.** Real byte-level implementation over PDF documents or document
  encryption, with tests, but no CLI or GUI caller.
- **C — model / contract / host boundary.** An in-memory model over caller-supplied data,
  a plan, or a host-boundary stub. It cannot itself read or write a complete PDF, or it
  is reachable only with demo/canned data.
- **R — replaced.** The row was already `replaced` and is unchanged.

Dependency edges used for the caller test:

| crate | runtime dependency that can reach document bytes |
| --- | --- |
| `pdfxi-cli` | core, automation, text, convert, accessibility, optional render |
| `pdfxi-app` | `pdfxi-render` only |
| `pdfxi-edit` | none |
| `pdfxi-forms` | `thiserror` only |
| `pdfxi-security` | `pdfxi-core` |
| `pdfxi-standards` | none |
| `pdfxi-automation` | none (CLI executor is `EchoOperations`, `crates/pdfxi-cli/src/action.rs:131`) |

GUI call sites are in `crates/pdfxi-app/src/ui.rs`. The GUI currently installs demo
bookmarks, attachments, layers and links (`ui.rs:960-969`) and feeds find/selection from
`demo_text_pages` (`ui.rs:947-949`), so those rows are C even though a pane is painted.
Split/tile (`ui.rs:2583-2588`, `apply_pane_command` at `1491`), thumbnails
(`thumbnails_ui` at `1722`), zoom (`1404`), rotate (`1414`) and open (`1115`) are real.

## Additional findings

1. **PRINT-002 through PRINT-006 and PRINT-008 have titles that do not match their
   evidence.** The titles claim standards validation, ICC colour management, output
   preview, ink manager, trapping/flattening and droplets; the cited code and notes are
   print imposition planners in `crates/pdfxi-app/src/print.rs`. These rows must be
   retitled or re-implemented; they are `model` here.
2. **Bundled rows.** STD-003 bundles object-stream reading (used by every CLI open) with
   linearization writing (no caller); EXPORT-008 bundles a conformance plan with a
   reachable `--fix` normalizer. Per ADR 0007 these should be split before either half is
   promoted.
3. **Security writer and sanitizer are real but unreachable.** `encrypt_document`,
   `sanitize_document`, `Document::optimize` and the incremental-save plan are genuine
   byte-level work with no CLI or GUI surface. They are `library`, not `model`.
4. **The GUI cannot reach edit/forms/security at all** because `crates/pdfxi-app` depends
   only on `pdfxi-render`.
