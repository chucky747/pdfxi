# T-0257 - Document sanitize and independent verification

- Status: Implemented at library level; hardened for XMP in non-catalog
  locations after second-pass review; claim held for review.
- Lane: security
- Claim: `crates/pdfxi-security/**`, this evidence file, the T-0257 feature
  fragment.
- Serves: O-06 (redaction removes content and is proven by re-extraction and a
  byte scan) and A-30 (Protect PDF redaction entry point).
- ADR: 0010 point 5. Sanitize is a full rewrite; it never appends an incremental
  revision that keeps the removed metadata, attachment, script or thumbnail
  bytes recoverable.
- Dependency: T-0237 owns text-operator removal and the page-level redaction
  API. T-0257 does not duplicate that logic. It runs after removal to sanitize
  the surrounding document and to prove the result independently.

## API

- `SanitizeCategory { DocumentInfo, XmpMetadata, Attachments, JavaScript,
  OptionalContent, Thumbnails }`

- `RemovedSanitizeItem { category, target }`

  unsafe_attachment_names }` with `residuals`, `is_clean`
- `SanitizedPdf { bytes, report }` with `bytes`, `report`, `document`
- `sanitize_document_full(&Document, &SanitizeRequest) -> Result<SanitizedPdf>`
- `sanitize_inventory(&Document) -> Result<BTreeSet<SanitizeCategory>>`
- `verify_sanitized(&[u8], &[&str]) -> Result<SanitizeVerification>`
- `SanitizeSurvivor { kind, category, page, object, secret_index, detail }`
- `SanitizeSurvivorKind { ExtractedText, RawBytes, StreamBytes,
  UnreadableStream, DocumentInfo, XmpMetadata, Attachment, JavaScript,
  OptionalContent, Thumbnail }`
- `SanitizeVerification { clean, survivors, secrets_checked, pages_checked }`
- `is_safe_attachment_name(&str) -> bool`

The module is re-exported at the crate root. The existing SEC-008 types
(`Sanitizer`, `SanitizationCategory`, `HiddenInfoSelection`,
`sanitize_hidden_info`) are reused conceptually for category planning and are
unchanged; T-0257 adds the real-`Document` full-rewrite path and the independent
verifier that T-0237 explicitly deferred.

## Categories removed

| Category | Removal |
| --- | --- |
| `document_info` | The whole trailer `/Info` dictionary is replaced with an empty dictionary through `Document::set_info`. Standard keys and unknown vendor keys are cleared. |
| `xmp_metadata` | Every dictionary's `/Metadata` entry in the reachable object graph (catalog, pages, image/form XObjects, annotations, patterns, and any other dictionary that carries one, including header-discovered objects) is detached and each referenced XMP stream subtree is nulled. A present key counts as XMP regardless of the value type, so direct stream/dictionary values, indirect references, and malformed or unreadable values all fail closed. |
| `attachments` | `/Names /EmbeddedFiles` (direct or indirect name tree), every `/Type /Filespec` or `/Type /EmbeddedFile` object, every dictionary carrying `/EmbeddedFile`, and every `/AF` key are removed. Referenced file-spec, `/EF` and embedded-stream objects are neutralized through the subtree. Catalog `/Collection` is removed. `unsafe_attachment_names` counts names that are not plain file names. |
| `javascript` | Catalog/page/annotation `/AA`, catalog `/OpenAction`, the `/Names /JavaScript` name tree, every `/S /JavaScript` or `/Type /JavaScript` action object, and annotation `/A` entries that resolve to a JavaScript action are removed. `/Next` action chains are neutralized as part of the action subtree. |
| `optional_content` | `/OCProperties`, every `/OC` key, and `/Type /OCG` / `/Type /OCMD` objects are removed when the layers are visible by default (flattened). Default-hidden layers fail closed (see below). |
| `thumbnails` | Page and any other `/Thumb` key is detached and its image subtree is nulled. |

Unsafe attachment names are rejected by the public
`is_safe_attachment_name`: empty, longer than 255 bytes, `.`/`..`, leading or
trailing whitespace, control characters, `/` or `\\` separators, and `:` (drive
letters and alternate data streams). The sanitize pass removes all attachments
regardless of name, but counts unsafe names in the report so a caller can audit
what it found. Names are never written to a report.

`SanitizeReport::removed` is a `BTreeSet`-ordered list of stable targets such as
`Catalog/Metadata`, `Catalog/Names/EmbeddedFiles`,
`Catalog/Names/JavaScript`, `Object/13`, or `Page/7/Thumb`. No target contains
document text, an attachment name, a script body, or a secret.

## Full rewrite and fail-closed rules

1. All work is staged on a clone of the caller's `Document` through
   `Document::set_object` and `Document::set_info`.
2. `Document::save()` performs a full, single-revision rewrite. The module never
   calls `Document::save_incremental`, so no earlier revision retains removed
   bytes.
3. The output is reparsed and the category inventory is re-derived. If a
   selected category survives, a second pass over the reparsed classic
   cross-reference output removes orphan category objects that were not
   reachable from the catalog, then the output is saved again.
4. If a selected category still survives both passes, the function returns
   `SecurityError::SanitizeResidual(category)` and returns no bytes. It never
   returns a partial sanitize as success.
5. If `/OCProperties /D /BaseState` is `OFF` or `/D /OFF` is non-empty, the run
   returns `SecurityError::UnsafeOptionalContent` before writing anything.
   Deleting the properties would make hidden layer content visible instead of
   removing it. Removing layer content needs a content-stream rewrite and is
   not attempted in Round A.
6. Damaged or unsupported sources map to
   `SecurityError::SanitizationCoreFailed`. Encrypted sources are rejected by
   the core writer and must be decrypted through `open_encrypted` first.
7. The source document is never mutated; the caller receives new bytes plus the
   report.

XMP is discovered from every dictionary in the reachable object graph, not only
the catalog: `sanitize_inventory` flags `XmpMetadata` whenever any dictionary
(including a stream dictionary) carries a `/Metadata` key, and the sanitize pass
detaches that key and nulls the referenced subtree. The value is never validated
or decoded, so an indirect reference, a direct stream/dictionary, and a
malformed or unreadable value are all treated as "XMP present". Unreadable
indirect references make `load_graph` fail rather than produce a false clean.

Known limit: an object is treated as an attachment or script only when it is
typed (`/Type /Filespec`, `/Type /EmbeddedFile`, `/S /JavaScript`, `/Type
/JavaScript`) or keyed (`/EmbeddedFile`, `/AF`, `/AA`, `/OpenAction`). An
untyped, unreferenced byte stream that no name tree or file specification
reaches is not detectable as an attachment by any reader either.

## Independent verification

`verify_sanitized` does not call any removal helper. It reparses the saved bytes
and checks four independent surfaces:

1. **Page text re-extraction**: every page's `Document::page_text` is searched
   case-insensitively for each supplied secret. Survivors carry the page index.
2. **Whole-file bytes**: the saved file is searched for each secret as UTF-8,
   catching secrets embedded in dictionaries or stored payloads that are not
   stream objects.
3. **Stream bytes**: every text-candidate stream is searched in stored form and,
   for a single `/FlateDecode` filter, in decompressed form, in UTF-8 and
   UTF-16LE. Fonts, font descriptors, image XObjects, object streams,
   cross-reference streams, embedded-file streams and binary codecs are
   excluded, matching the T-0237 rule that arbitrary binary pairs are not
   extractable text. A text-candidate stream whose filter chain cannot be
   decoded is reported as `UnreadableStream`, so unreadable candidate streams
   fail closed.
4. **Category inventory**: `sanitize_inventory` is re-derived from the saved
   object graph and every one of the six categories must be absent. The
   inventory does not trust the removal report.

`clean` is true only when `survivors` is empty. Survivors never contain secret
text or document content; a secret is identified by its index in the caller's
slice.

## Tests

`crates/pdfxi-security/tests/sanitize_verified.rs` (8 tests):

- `real_fixture_is_sanitized_saved_and_reopens_with_text` on
  `fixtures/realworld/microsoft-excel-2019-sample.pdf`: stages identifying
  `/Info` plus a page-level XMP stream with a secret title, sanitizes, saves a
  full rewrite to `target/lanes/security6/t0257-out/sanitized.pdf`, reopens it,
  asserts `/Info` fields and XMP (catalog and page) are gone, unrelated fixture
  text still extracts, and `verify_sanitized` is clean for three secrets. The
  artifact is written by this test.
- `synthetic_document_loses_all_categories_and_verifies_clean`: one classic
  document with XMP, `/Info` (including a custom key), `/Names /EmbeddedFiles`
  with a `../../etc/passwd` attachment, an embedded-file stream, `/OpenAction`,
  catalog/page/annotation `/AA`, two JavaScript actions, a visible optional
  content layer and a page thumbnail. All six categories are present before,
  absent after, the unrelated page text survives, the two unsafe names are
  counted, and verification with six secrets is clean.
- `xmp_in_image_xobject_and_page_is_inventoried_and_removed`: a classic document
  whose catalog has no `/Metadata` but whose page and image XObject each carry an
  XMP stream with a secret title. The source inventory reports `XmpMetadata`
  from those non-catalog locations (this assertion fails with catalog-only
  detection), sanitize detaches both keys and nulls both streams, the reopened
  bytes/inventory have no XMP, unrelated text survives, and `verify_sanitized`
  is clean.
- `xmp_outside_selected_categories_keeps_inventory_and_verification_dirty`: the
  same document sanitized with only `DocumentInfo` selected leaves the XMP in
  place; the output inventory still reports `XmpMetadata` and the verifier
  reports an `XmpMetadata` survivor, proving the verifier is not always-true and
  detection is not scoped to the caller's request.
- `secret_outside_the_sanitized_categories_makes_verification_dirty`: a secret
  in the page content is not removed by sanitize, so verification is not clean
  and records the page and secret index. This proves the verifier is not
  always-true.
- `default_hidden_optional_content_fails_closed`: a `BaseState /OFF` layer set
  returns `UnsafeOptionalContent` and writes no output.
- `attachment_name_validator_rejects_traversal_and_absolute_paths`.
- `category_identifiers_round_trip`.

`crates/pdfxi-security/tests/sanitize_pdfium.rs` (1 test, `--features pdfium`):

- `pdfium_reopens_sanitized_bytes_and_sees_no_identifying_metadata`: PDFium
  opens the sanitized bytes from memory (the source also carries a page-level XMP
  secret title), sees the same page count, extracts text matching the surviving
  source text, and reports no title or author. `verify_sanitized` is clean for
  the Info title, Info author and XMP title secrets.

## Limits and follow-up

- Default-hidden optional content fails closed. Removing the hidden layer's
  marked-content blocks needs a content-stream rewrite; Round A deliberately
  does not reveal them.
- Visible optional content is flattened by removing `/OCProperties` and `/OC`;
  marked-content operators remain valid and render as ordinary visible content.
- The verifier searches secrets as UTF-8 and UTF-16LE only. It does **not**
  claim UTF-16BE coverage, and it does not join bytes across stream boundaries
  or filter stages: a secret split across two streams, across a filter boundary,
  or encoded in UTF-16BE is outside the current scan and is not asserted here.
  Whole-file UTF-8 scanning still catches a literal secret anywhere in the
  saved bytes, and XMP is independently caught by the category inventory from a
  present `/Metadata` key even when its text encoding is unknown.
- The verifier excludes font programs and image streams from the UTF-16LE scan
  by design, the same false-positive boundary T-0237 documented.
- XMP is detected from the `/Metadata` key on any reachable dictionary, not by
  matching XMP syntax. A dictionary that carries `/Metadata` with a non-XMP value
  is treated as XMP and removed (fail closed); an XMP packet stored somewhere
  other than a dictionary `/Metadata` key is not detected by the inventory and
  is only caught if a supplied secret appears in the scanned surfaces.
- Form values, links, annotations as a class, `PieceInfo` and private app data
  remain the existing SEC-008 `HiddenInfoSelection` scope; T-0257 only adds the
  categories the redaction pair needs. A redaction pipeline can run both APIs.
- No UI or CLI entry point is added. SEC-008 and SEC-009 stay `library`; T-0263
  (Protect/Redact UI) owns the app-level promotion after review.
- `crates/pdfxi-security` now has an optional `pdfium` feature and an optional
  `pdfium-render` dependency used only by the integration test. Default builds
  and the default test suite do not compile it.
