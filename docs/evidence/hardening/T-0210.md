# T-0210 evidence - gate hygiene (round 1: cargo-deny bans, optional rfd)

Date: 2026-11-20. Integrator. Task: T-0210 (Phase 0 of
`docs/campaigns/2026-11-20-feature-acceptance.md`).

This round covers two of the four T-0210 items: the `cargo deny` bans failure and
`rfd` as an optional dependency under `ui`. The automated installer test and ADRs
0010/0011 are still open and are not claimed here.

## 1. `cargo deny` bans: wildcard path dependencies removed

The blocker `orchestration/blockers/cargo-deny-bans.md` recorded 18
`error[wildcard]` findings for intra-workspace path dependencies declared without
a version.

Fix (the strict option from the blocker, no `deny.toml` change):

- `Cargo.toml` gains `[workspace.dependencies]` entries for the workspace crates
  that a member already depends on, each with both `path` and
  `version = "0.1.0"` (the workspace package version).
- Member manifests use `{ workspace = true }`, keeping `optional = true` where it
  applied (`pdfxi-render` in `pdfxi-app`, `pdfxi-convert`, `pdfxi-cli`).
  `pdfxi-convert` keeps `default-features = false` in the workspace entry
  because its only dependent, `pdfxi-cli`, wants the renderer path off.
- `pdfxi-app`, `pdfxi-cli` and `pdfxi-edit` are deliberately absent from
  `[workspace.dependencies]`: nothing depends on them, and cargo's
  `unused_workspace_dependency` lint would warn. They are added with their first
  dependent.

`deny.toml` is unchanged: `wildcards = "deny"` still applies.

    $ cargo deny check
    advisories ok, bans ok, licenses ok, sources ok
    EXIT=0

Warnings left are the pre-existing `warning[license-not-encountered]` notes for
allowed licences that no dependency uses; they are not errors.

`orchestration/blockers/cargo-deny-bans.md` is deleted by this change.

## 2. `rfd` optional under `ui`

`crates/pdfxi-app/Cargo.toml`:

    ui = ["dep:eframe", "dep:egui", "dep:rfd"]
    rfd = { version = "0.15", optional = true }

`rfd` is called only from `crates/pdfxi-app/src/ui.rs` (the `ui`-gated shell,
`rfd::FileDialog` in `open_dialog_ui`), so a build without `ui` no longer links
the picker and no longer emits `unused dependency rfd`.

    $ cargo check -p pdfxi-app
        Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.18s
    EXIT=0
    $ cargo check -p pdfxi-app --features ui,pdfium
        Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.43s
    EXIT=0

Both runs print no `warning:` lines (the earlier `unused workspace dependency`
warnings came from the first draft of the workspace table and are gone).

## Round 2: ADRs 0010/0011 and the automated installer test

Date: 2026-11-20. Same task, same claim.

### ADRs

- `docs/decisions/0010-document-session-and-write-path.md` (accepted): one
  `pdfxi-document` session owning bytes, `Document`, password, dirty state and
  undo/redo; `pdfxi-core` is the only write path; mutations are incremental
  appends followed by a PDFium reload from memory; undo truncates to the previous
  revision; redaction, sanitize, optimize and removing encryption always rewrite and
  never keep earlier revisions; atomic saves with external-change detection;
  per-feature PDFium editing by ADR only.
- `docs/decisions/0011-ai-assistant-through-opencode.md` (proposed, to be confirmed
  by spike T-0250): OpenCode is the backend with the user providers; discovery or
  pairing code; primary design is PDFXI attached as a client MCP server exposing
  read-only document tools, fallback is a small plugin bridging RPC over loopback;
  model picker from the OpenCode list with test model `opencode-go/hy4-flash-free`;
  token in Windows Credential Manager; the assistant session can call only PDFXI
  read-only tools; document text is untrusted tool output; nothing is sent before
  the user asks; the OpenCode routes are experimental and must be pinned.

### Automated installer test

`scripts/test-installer.ps1`, run as `cargo xtask installer-test`. It skips with
exit 0 and a loud SKIPPED banner when ISCC.exe is absent, redirects TEMP/TMP for
child processes to `target/tmp/installer-test/temp`, builds the Smoke-identity
installer (`/DSmoke=1`, separate AppId `{9E1B7C52-...}` and AppName `PDFXI Smoke`),
installs silently to `target/tmp/installer-test/install`, asserts the payload, the
GUI subsystem of `pdfxi-ui.exe`, the HKCU uninstall entry, the desktop shortcut, a
live viewer with `pdfium.dll` loaded from the install directory, then uninstalls and
asserts the directory, the registry key and the shortcuts are gone and that the real
installation and the real desktop shortcut are unchanged (tree fingerprint of path,
size and last-write time; shortcut SHA-256).

`crates/pdfxi-cli/tests/packaging.rs` holds
`installer_test_script_contract`, the test PKG-003 cites; it guards that the script,
the separate smoke identity and the xtask wiring cannot disappear. The test index in
`xtask` scans `crates/` only, so an `xtask` unit test would not satisfy
`cargo xtask features verify`; that is why the contract test lives in `pdfxi-cli`.

Run 1 failed one assertion on a real mismatch (the Inno `DisplayName` is
`AppVerName`, so `PDFXI Smoke 0.1.0`, not `PDFXI Smoke`), which proves the test
fails closed. Run 2, after correcting the expectation:
