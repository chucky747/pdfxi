## 2. Formats implemented and fidelity limits

| Format | Parts | What is written | Fidelity limits |
|---|---|---|---|
| Text (`.txt`) | 1 | Extracted text, line feed between pages | `page_text` only; paragraphs follow the core extractor's line breaks |
| Word (`.docx`) | 1 | One paragraph per extracted line, real `w:br w:type="page"` between pages, source page size/orientation | Text only; no images, vector art, charts, annotations, backgrounds |
| Excel (`.xlsx`) | 1 | One worksheet per source page named `Page N`; one extracted line per row in column A; bounded column widths | Text only; one cell per extractor paragraph; no formulas, charts, images, or numeric inference from text |
| PowerPoint (`.pptx`) | 1 | One slide per source page; `Page N` title shape; body lines flowed into a text box; slide size = first source page aspect | Text only; ends up as generated text boxes (reported as `text_layout_flattened`); no images, charts, or transitions |
| PNG | 1 per page | Renderer raster at `ExportOptions::dpi`, RGBA | Requires `pdfium`; renders `document.save()` bytes, not unsaved in-memory object edits beyond the core serializer |
| JPEG | 1 per page | Baseline JFIF at the requested DPI and quality, white flatten | Requires `pdfium`; 3-channel output, alpha flattened |
| HTML (`.html`) | 1 | `<!DOCTYPE html>`, one `<section class="page" id="page-N">` per page, `<h2>Page N</h2>`, one escaped `<p>` per line, inline `<style>` | Text only; no positioned layout, images, links, or scripts; no external assets |
| RTF (`.rtf`) | 1 | RTF 1.9 header/font/colour tables, `\par` per line, `\page` between pages, signed `\uN?` escapes, ASCII bytes | Text only; no tables/images; layout is not preserved |

Cross-cutting limits (also in the `pdf_export` rustdoc):

- Text order comes from `pdfxi_core::Document::page_text`; a page whose content
  uses only `Tj`/`TJ` yields a single paragraph. That is why each XLSX sheet has
  one row and each DOCX/PPTX body has one block in the fixtures, even though the
  visible page lines are sentences run together.
- No images are embedded inside DOCX/XLSX/PPTX and no charts are synthesized.
- The Office adapters report text-only flattening through
  `ExportedFile::unsupported` rather than silently faking content.
- Image formats are not listed by `ExportFormat::implemented()` without the
  `pdfium` feature and fail with `UnsupportedFormat`.

## 8. Remaining / not verified

- The Office viewers were not automated on this host. XLSX and PPTX were
  validated structurally through Windows OPC and XML parsing; the operator
  should still open the generated files in Excel/PowerPoint for the acceptance
  check. DOCX was opened successfully in round A.
- Geometry-based paragraph reconstruction (so one visual line becomes one
  DOCX/PPTX/XLSX paragraph) remains a separate extraction feature. Without it a
  page is one extractor paragraph.
- Images, charts, and positioned layout inside OOXML are not written and are
  reported or documented as unsupported.
- `EXPORT-001..006` stay `library`; A-27 becomes `verified` only through the
  serialised shell task that exposes this dispatch in the Export card and is
  checked on the installed viewer.
