## 1. Gate now runs the feature-gated tests

Changed `xtask/src/main.rs`:

- `run_feature_tests()` runs, in order:
  - `cargo test -p pdfxi-app --features ui,pdfium`
  - `cargo test -p pdfxi-render --features pdfium`
- `verify()` calls it after `cargo test --workspace`.
- The milestone branch of `goal_verify()` calls it after `cargo test --workspace`.
  The full-goal branch already delegates to `verify()`.
- `require_pdfium()` runs first and fails with an actionable message when the
  native library is missing. It checks the same candidates as
  `pdfxi-render`'s loader: `PDFIUM_PATH`, `%LOCALAPPDATA%\pdfxi\pdfium\bin\pdfium.dll`,
  the workspace root, the current directory, and `PATH`. The failure message
  points at `scripts/fetch-pdfium.ps1` and `PDFIUM_PATH`.
- Clippy already runs with `--workspace --all-targets --all-features -- -D warnings`,
  so the `ui` and `pdfium` features are linted in the same pass. No second clippy
  invocation was added.

Changed `.github/workflows/ci.yml`:

- `windows-gnu` and `windows-msvc` fetch PDFium with
  `pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/fetch-pdfium.ps1`
  before the tests.
- Both Windows jobs run the two feature test commands as separate steps so a
  first-command failure cannot be masked by `$LASTEXITCODE` from a second one.
- The Linux and macOS jobs keep `cargo test --workspace`; PDFium is a Windows
  runtime dependency here and no Linux/macOS library is fetched.

## 2. Cited tests must resolve to a real `#[test]`

`features_verify()` now builds a one-pass `BTreeSet` index of every
`#[test]` function name under `crates/**/*.rs` and resolves each
`docs/features.toml` citation by its final `::` segment. It supports the shapes
actually present in the matrix:

- `ui::tests::name`
- `pdfxi-edit::annotation::tests::name`
- `cli.rs::name`
- bare `name`

Missing symbols fail `cargo xtask features verify` and therefore
`cargo xtask goal-verify`, listing the row id and the raw citation. Entries in a
`tests` array that are not test citations (commands or prose) are reported as a
warning and do not masquerade as missing tests.

- `citation_parser_rejects_non_identifiers` (negative)

## 4. JS wall-clock limit with a real busy loop

Added one test to `crates/pdfxi-automation/src/js/tests.rs`:
`wall_clock_budget_stops_a_real_busy_loop`.

- Runs `var spins = 0; while (true) { spins = spins + 1; }`.
- `max_steps`, `max_loop_iterations`, and `max_total_iterations` are `u64::MAX`
  so only the 20 ms wall-clock budget can stop it.
- Asserts `JsError::WallClockExceeded`, asserts the budget elapsed, and asserts
  total wall time is under one second. No sleeps.
