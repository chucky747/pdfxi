# T-0237 - Redaction content removal on real pages (Round A + B1)

- Status: Round A and image pixel redaction (B1) implemented; library-level only.
- Lane: author
- Claim: `crates/pdfxi-edit/**`, this evidence file, the T-0237 feature fragment.
- Serves: O-06 (redaction removes content, verified by re-extraction and a byte
  scan) and A-30 (Protect PDF redaction entry point) from
  `docs/design/FEATURE_ACCEPTANCE.md`.
- ADR: 0010 point 5. Redaction is a full rewrite; it is never an incremental
  append that leaves the old operators or compressed image bytes recoverable.

## API

New module `crates/pdfxi-edit/src/redact_document.rs`:

- `RedactionMark { page, rect }`
- `RedactionRequest { marks, keep_images, remove_annotations, remove_links, remove_form_fields, remove_metadata }`
- `RedactionReport { marks, removed_runs, removed_annotations, removed_links, removed_fields, surviving_spans, metadata_scrubbed, clean }`
- `apply_redaction(&mut Document, &RedactionRequest) -> Result<RedactionReport, RedactionError>`
- `verify_redaction(&Document, &[&str], &RedactionReport) -> Result<RedactionVerification, RedactionError>`
- `RedactionVerification { clean, survivors, secrets_checked }`
- `Survivor { kind, page, object, stream_offset, detail }`

`RedactionRequest::default().keep_images` is **`false`**: a default request
redacts intersecting image pixels. `true` is an explicit opt-out; intersecting
images are then reported as surviving spans and `clean` is false.

The names `RedactionReport` and `RedactionError` already exist in the older
`redaction` module, so the new types are exported at the crate root as
`DocumentRedactionReport` / `DocumentRedactionError` and remain available by
their exact names under `pdfxi_edit::redact_document::*`.

## Content-rewrite strategy

1. The staged document is reparsed (`save_incremental`, falling back to a full
   `save`) so reads see the caller's pending changes.
2. Each marked page's decoded content is tokenized with the T-0233 lexer.
3. `q`/`Q`, `cm`, `BT`/`ET`, `Tm`/`Td`/`TD`/`T*`, `Tf`, `TL`, `Tc`, `Tw` and
   `Tz` are tracked exactly as `content_edit::text_blocks` tracks them.
4. `Tj`, `TJ`, `'` and `"` are analysed glyph by glyph using the page's real
   `/Font` resources and widths. A glyph is removed when the transformed
   bounding box of its text-space rectangle shares positive area with a mark.
5. The affected operator is replaced, not deleted:
   - kept glyphs are re-emitted as the original encoded bytes inside a `TJ`
     array, separated by numeric adjustments whose magnitude is the advance of
     the removed glyphs (`n = -advance * 1000 / (font_size * horizontal_scale)`);
   - a fully removed operator becomes an adjustment-only `TJ`, so the text
     matrix advances by the same amount and following text does not slide into
     the redacted area;
   - `'` keeps its implicit line move as `T*`; `"` re-emits its word and
     character spacing operands and its line move.
6. The first existing `/Contents` stream object is overwritten with the
   rewritten combined stream. Additional content streams are staged as `null`.
   `Document::save()` writes every live object, so adding a new stream and
   leaving the old one unreferenced would still leak the old bytes. The page
   dictionary is staged once with the new `/Contents`.

### Partial intersections

Partial runs split at glyph boundaries. Test
`partial_intersection_removes_only_the_marked_glyphs` marks the middle of
`ABCDEFGHIJ`; the report says `removed_glyphs: 6, kept_glyphs: 4,
whole: false, fallback: false`, the reopened page extracts `ABCJ`, and neither
the full run nor the removed middle survives verification.

### Fonts, encodings and TJ

- No font is re-encoded. Kept glyphs reuse the original code bytes, so a
  subset, composite or symbol font cannot corrupt surviving text.
- If the font resource is missing, the size or horizontal scale is zero, or an
  advance is non-finite, the whole operator is neutralised and the report marks
  it `whole: true, fallback: true` rather than leaving part of a secret.
- `TJ` numbers are preserved and merged with removal advances. A number between
  two kept pieces still applies.

## Image pixel redaction (B1)

For each `Do` naming an image XObject, the current CTM maps the unit square to
page space. If that placement does not intersect a mark the image is untouched.
If it does:

1. The image dictionary is validated before any pixels are read.
2. The mark rectangle is mapped into the image's normalised [0,1] square through
   the inverse CTM, clamped, and converted to a top-down pixel rectangle
   (`row = (1 - v) * height`).
3. Supported samples are decoded, the covered pixels are filled with opaque
   black (0 samples for DeviceGray/RGB; the palette's black index for Indexed;
   RGB for DCTDecode JPEG), and an optional `/SMask` has its alpha samples set
   to 255 in the same region.
4. The sample buffer is re-encoded as a zlib stream using stored DEFLATE blocks
   (no new dependency). `/Width`, `/Height`, `/ColorSpace`,
   `/BitsPerComponent 8` and `/Filter /FlateDecode` are written;
   `/DecodeParms`, `/Decode` and `/ColorTransform` are removed. The original
   compressed bytes are replaced in the same object, so a full save cannot
   retain them.

Supported at 8 bits per component: **DeviceGray, DeviceRGB, Indexed, and
DCTDecode JPEG** (decoded with the workspace `image` crate, MIT OR Apache-2.0,
already in the lock; converted to RGB and re-encoded as raw Flate). ICCBased
profiles with 1 or 3 components are accepted and filled with 0 samples; a
4-component ICCBased CMYK profile is rejected because zero samples mean no ink,
not black. SMask supports raw/Flate 8-bit grey and DCTDecode (converted to
luma).

Fail-closed matrix when `keep_images = false`:

| Intersecting image | Result |
| --- | --- |
| 8-bit DeviceGray / DeviceRGB / Indexed | redacted |
| DCTDecode JPEG (including CMYK if the crate decodes it) | redacted |
| ICCBased with 1 or 3 components | redacted with 0 samples |
| ICCBased with >4 components | `UnsupportedImage` |
| ICCBased 4-component CMYK | `UnsupportedImage` |
| JPXDecode, CCITTFaxDecode, JBIG2Decode, unknown filters | `UnsupportedImage` |
| Separation, DeviceN, ImageMask, `/Decode`, non-8-bit | `UnsupportedImage` |
| inline image `BI ... ID ... EI` | `UnsupportedImage` (not decoded in B1) |
| > 100 megapixels or > 64 MiB decoded samples | `ImageLimitExceeded` |
| corrupt/inconsistent sample buffers | `UnsupportedImage` |

With `keep_images = true` the same intersecting image is reported in
`RedactionReport::surviving_spans` and `clean` is false; no error is returned.

Every other intersecting `Do` XObject is fail-closed, not silently skipped: a
`/Subtype /Form` stream, a missing resource name, an unresolvable reference, a
direct object and a non-stream object all return `UnsupportedImage` when
`keep_images = false`, and become a `<form XObject name>` or
`<unresolved XObject name>` survivor when `keep_images = true`. Form content is
not recursed in this round, so ignoring it would let `clean` be true while the
form still draws under the mark.

Validation, decoding, filling and re-encoding all happen in a preparation phase
before any page content or image object is staged. An unsupported image
therefore returns `UnsupportedImage` without mutating the document or writing a
half-redacted stream.

## Annotations, fields, links and metadata

- An annotation is removed when its `/Rect` intersects a mark and its class is
  enabled: ordinary annotations by `remove_annotations`, `/Link` by
  `remove_links`, `/Widget` by `remove_form_fields`.
- The annotation object is replaced with `null`; every indirect object reachable
  from `/AP` is also replaced with `null`, so appearance streams do not survive
  in the full rewrite.
- Removed widgets are filtered out of `/AcroForm /Fields`; emptied parent
  fields are nulled; `/AcroForm /CO` drops references to removed fields and
  widgets.
- `remove_metadata` clears `/Info` title, author, subject, keywords, creator and
  producer, and removes the catalog `/Metadata` XMP stream. Broader
  sanitisation (thumbnails, optional content, revision remnants, embedded files,
  independent verification with a second reader) is **deferred to T-0257**.
  T-0237 implements the removal API and its fail-closed verifier; it does not
  duplicate T-0257's sanitise pass.

## Verifier checks

`verify_redaction` performs a full `Document::save()` rewrite, reparses the saved
bytes, and checks three independent surfaces:

1. **Text re-extraction**: every page's `Document::page_text` is searched
   case-insensitively for each secret. Survivors carry `page`.
2. **Raw and decompressed bytes**: the saved file is searched in UTF-8; every
   text-candidate stream is scanned in both stored and Flate-decompressed form
   for UTF-8 and UTF-16LE encodings. Survivors carry the stream object and byte
   offset. Font programs, image streams, object streams and xref streams are
   excluded because arbitrary binary pairs would otherwise produce false
   positives (the fallback font contains the byte pair sequence for `ABCDEFGHIJ`
   as UTF-16 code units). A text-candidate Flate stream that cannot be
   decompressed is reported as `UnreadableStream`, so the result is fail-closed.
3. **Surviving annotations and form fields**: annotation and widget `/Rect`
   values are rechecked against the marks in `RedactionReport`.

Image pixels are verified by the image tests below, not by the secret byte scan
(which excludes image streams by design). `clean` is `true` only when
`survivors` is empty.

`fixtures/realworld/microsoft-excel-2019-sample.pdf`:

- `redacts_text_annotation_and_metadata_then_verifies_clean`: adds
  `SECRET-ALPHA-42` with `add_text_box` and a note with `add_text_note`, redacts
  the containing rectangle, saves a full rewrite, reopens it, asserts the
  secret and the marked sentence are absent, the annotation count dropped,
  unrelated fixture text still extracts, and `verify_redaction` is clean.
  Writes `target/lanes/author3/t0237-out/redacted.pdf`.

  text and annotation count identical.
- `verifier_catches_a_secret_left_outside_the_mark`: an outside

  records page 0 and the secret. This proves the verifier is not always-true.
- `partial_intersection_removes_only_the_marked_glyphs`: split-run proof
  described above.
- `image_pixels_under_a_mark_are_black_and_metadata_is_gone`: places a solid red
  16x16 PNG at `(300,400)-(340,440)`, redacts `(305,405)-(325,425)`, saves and
  reopens, decodes the saved image XObject, and asserts pixel `(6,10)` inside
  the mark is `[0,0,0]` while pixel `(14,2)` outside is `[255,0,0]`. Also sets
  `/Info` title/author and XMP, then asserts all are absent after the save.
  Writes `target/lanes/author3/t0237-out/image-redacted.pdf`.
- `jpeg_image_under_a_mark_is_decoded_refilled_and_flated`: same placement with
  a solid red JPEG. The saved image must be `/FlateDecode`, the inside pixel is
  `[0,0,0]`, and the outside pixel stays red (`r > 200, g < 40, b < 40`).
- `intersecting_jpx_image_fails_closed_without_saving`: a dummy `/JPXDecode`
  image under a mark returns `UnsupportedImage` with `keep_images = false` and
  writes no artifact; with `keep_images = true` it returns a report with
  `clean = false` and an image survivor.
- `form_xobject_under_a_mark_fails_closed`: a `/Subtype /Form` XObject under a
  mark returns `UnsupportedImage` naming the form with `keep_images = false`,
  and a `<form XObject FormDo>` survivor with `keep_images = true`.
- `unresolvable_xobject_under_a_mark_fails_closed`: a `Do` name absent from
  `/Resources /XObject` returns `UnsupportedImage` with `keep_images = false`,
  and an `<unresolved XObject MissingDo>` survivor with `keep_images = true`.

## Limits and follow-up (B2)

- Form XObjects are fail-closed, not silently ignored: an intersecting form,
  missing name or unresolvable XObject returns `UnsupportedImage` with
  `keep_images = false`, and is a survivor with `keep_images = true`. B2 should
  recurse into form content with the form matrix.
- Inline images are fail-closed in B1; B2 should parse their dictionary/sample
  span and redact the same supported formats, or keep the typed error.
- ICCBased and Indexed handling is deliberately narrow (no indirect Indexed
  lookup, no 4-component CMYK fill). These fail closed rather than guess.
- `redact_document` does not expose a UI or CLI entry point. EDIT-013 remains a
  library row; no app promotion is claimed.
- T-0257 owns the broader sanitise pass and independent second-reader
  verification.
