## 1. What shipped

- `crates/pdfxi-forms/Cargo.toml` — added `pdfxi-core.workspace = true`. No root
  `Cargo.toml` edit, no new lockfile package.
- `crates/pdfxi-forms/src/document_form.rs` — new bridge from a parsed
  `pdfxi_core::Document` to the crate's field and appearance model:
  - `read_acroform(&Document) -> Result<AcroFormModel, AcroFormError>` walks
    `/AcroForm /Fields` recursively, inherits `/FT`, `/Ff`, `/V`, `/DV`, `/DA`,
    `/Q` and `/Opt`, concatenates partial `/T` names as `parent.child`, and
    distinguishes terminal fields from non-terminal nodes.
  - `AcroFormModel` exposes `present`, `need_appearances`, `contains_xfa`,
    `has_javascript`, `acroform_object`, and `fields()`, `field(name)`, `len()`,
    `is_empty()`.
  - `FormField` exposes `name`, `kind`, `value`, `default_value`, `options`,
    `flags`, `read_only`, `required`, `alignment`, `default_appearance`,
    `widgets`, `field_object`, with `primary_rect()` / `primary_page()`.
  - `FormWidget` exposes `object`, `rect`, `page`, `on_states`,
    `has_appearance`, with `on_state()`.
  - `set_text`, `set_checkbox`, `set_radio`, `set_choice` write `/V` (leaving
    `/DV` untouched), set widget `/AS`, and regenerate `/AP /N`.
  - `needs_appearances` reads `/NeedAppearances`;
    `regenerate_appearances` rewrites every addressable field appearance and
    clears the flag.
  - `flatten(&mut Document)` paints `/AP /N` into page content, removes widget
    annotations and removes the catalog `/AcroForm`.
  - `export_xfdf(&AcroFormModel) -> String` and
    `import_xfdf(&mut Document, &str) -> Result<usize, AcroFormError>`.
- `crates/pdfxi-forms/src/document_form/tests.rs` — unit tests for `/DA`
  parsing, byte-wise font-token replacement and PDF text-string encoding.
- `crates/pdfxi-forms/tests/real_document_form.rs` — seven end-to-end tests on
  `fixtures/realworld/pdfxi-forms-selfmade.pdf` and a derived radio group.
- `crates/pdfxi-forms/src/lib.rs` — module and re-exports. The crate root exposes
  the document XFDF entry points as `export_xfdf_document` /
  `import_xfdf_document` because `export_xfdf` / `import_xfdf` already denote the
  dependency-free `Form` API. The `document_form` module keeps the requested
  exact names.

No new crate dependency beyond `pdfxi-core`; no UI, no network, no filesystem
access inside the library. The test writes its artifact to
`target/lanes/forms/t0234-out/filled.pdf`.

## 2. Field-kind coverage

| `/FT` | Flags | Kind | Value written | Appearance |
|---|---|---|---|---|
| `Tx` | any | Text | `/V` string (UTF-16BE + BOM for non-ASCII) | `/AP /N` stream from `build_appearance`, `/DA` font/size/colour, `/Q`, clipping |
| `Btn` | neither radio (bit 16) nor pushbutton (bit 17) | Checkbox | `/V` name (on-state or `Off`) | named `/N` states `Off` + the widget on-state; `/AS` matches |
| `Btn` | radio (bit 16) | Radio | `/V` name of the selected option | per-widget named `/N` states `Off` + that widget's on-state; `/AS` per widget |
| `Ch` | any | Choice | `/V` string, cleared by `None` | single-line selected value, `build_appearance` with `COMBO` forced for the collapsed display |
| `Sig` | any | Signature | read-only metadata (no setter) | none |
| `Btn` | pushbutton (bit 17) | Button | no value | none |

Radio groups are returned as one logical field: the field node's `/Kids` are the
widgets, and each widget's `/AP /N` keys (excluding `Off`) are its on-states.
`set_radio` validates the requested name against every widget and writes
`/AS /<name>` only on the matching widget, `Off` elsewhere.

`/Ff` bits 1 and 2 are surfaced as `required` and `read_only`; setters reject
read-only fields with `AcroFormError::ReadOnlyField`.

The committed fixture has text, checkbox and choice fields only. Radio coverage
uses a derived fixture: the test stages a two-widget radio group into the real
fixture through `Document::set_object`, saves and reopens it, then fills it. The
committed `fixtures/**` tree was not modified.

## 3. Appearance strategy and limits

- Text and choice content comes from `crate::build_appearance`. The field `/DA`
  is parsed for font resource name, size and grey/RGB colour; size `0` (auto) is
  derived from the `/Rect` height. The generated `/F1` token is rewritten to the
  `/DA` resource name, and the stream `/Resources /Font` maps that name to an
  existing `/DR /Font` object when present, otherwise to a new base-14 Helvetica
  Type1 object (WinAnsiEncoding). `/Q` maps to left/centre/right alignment;
  text is clipped by the existing layout heuristic.
- Checkbox and radio streams carry the existing box/check/radio vector content.
  Checkboxes rename the library's `On` state to the document's real on-state
  (fixture: `Yes`); radio groups use each widget's own on-state.
- Every appearance stream is a Form XObject with `/BBox [0 0 width height]`,
  `/FormType 1`, optional `/Resources`, and non-empty content.
- `/DV` is never modified.
- Limits, all recorded in module rustdoc:
  - No XFA processing and no JavaScript execution. `/XFA` and JS actions are
    detected and reported via `AcroFormModel`; calculation/validation scripts do
    not run.
  - Embedded font programs are not rasterised; non-ASCII text renders through
    the Helvetica/WinAnsi fallback.
  - Inline (non-indirect) field or widget dictionaries are visible but setters
    return `AcroFormError::UnaddressableField`.
  - Because `pdfxi-core` exposes no staged-change accessor, `read_acroform`
    returns the source snapshot. Mutations of different fields in one session
    are independent and safe; re-reading earlier in-memory writes (including
    flatten of a just-filled document) requires save and reopen, which is the
    ADR 0010 append-then-reload shape. A core staged-view accessor would remove
    this restriction.
  - Flatten composes the widget `/Rect` with the appearance `/BBox`; an
    appearance `/Matrix` other than identity is not composed in round A.
  - Choice fields are rendered as their selected value (collapsed display), not
    as a multi-row list box.

What the integration tests assert:

1. The fixture reads as three fields (`text-field` text, `checkbox-field`
   checkbox, `choice-field` choice) with values, `/Opt` options, rects and page
   0.
2. Setting `filled by test`, ticking the checkbox and selecting `three`, then a
   full save and reopen, preserves all three values; each widget has a non-empty
   `/AP /N` stream with the right `/BBox`; the checkbox has `/V /Yes`,
   `/AS /Yes` and `Yes`/`Off` state streams.
3. XFDF exported from the filled model imports into a fresh copy of the original
   and reproduces the same three values after save and reopen.
4. Flatten reports 3 fields / 3 widgets / 1 page; the reopened file has no
   `/AcroForm`, no widget annotations, two `/Contents` entries, `Fm0 Do`/`Fm2 Do`
   paint operators, and still extracts `Form page`.
5. The derived radio group reads two widgets with on-states `A` and `B`;
   selecting `B` sets the field `/V /B`, widget A `/AS /Off`, widget B `/AS /B`,
   and regenerated state streams for both.
6. Setting `/NeedAppearances true`, saving and reopening reports the flag;
   `regenerate_appearances` clears it and gives every field an `/AP`.
7. Unknown field, wrong kind and invalid choice value return the typed errors.
