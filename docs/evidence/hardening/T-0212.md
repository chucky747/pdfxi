## Round B: what changed in the shell API

T-0220 (lane-app) grew `AppCommand` from 41 to 60 variants and reworked the
compilation surface. The three reported errors came from the pre-fix copy of
the test:

1. `unused import: Path` — the test imported `{Path, PathBuf}` but a helper
   using `Path` was inlined. Removed; the test imports `PathBuf` only.
2. `expected Option<u16>, found Option<i16>` — `Rotation::degrees()` now
   returns `i16` (`crates/pdfxi-app/src/view.rs:115`). The `Snapshot.rotation`
   field is `Option<i16>`.
3. `cannot move AppCommand into an FnMut closure` — `egui::Context::run` takes
   `impl FnMut`, so `app.dispatch(command, ...)` cannot move the captured
   command. The viewport helper dispatches `command.clone()` (the enum is
   `Clone`).

The test surface was then extended for the 19 new commands: 16 are proven
(13 capability-gated commands that set the status line, plus
`toggle-fullscreen`, `set-zoom-percent`, `submit-page-number`) and 3 are
allowlisted because they flip private flags with no public getter
(`toggle-tools`, `toggle-grid`, `show-rail`).

## Harness design: how a command is proven to act

`Snapshot` captures every publicly observable field: tab strip
`(id, title, active)`, page/page count, zoom, rotation, view mode, active tool,
find open/query/options/current index/match count, status, theme preference,
window-control style, error banner, typed error count, close policy, selected
text, thumbnail active page.

`assert_dispatch_acts(label, app, command)`:

1. snapshots the app,
2. calls `PdfxiApp::dispatch(command, None)` — the single public entry point
   every shell control uses,
3. snapshots again and asserts the two differ.

The panic names the command label, the dispatched value, the full before/after
snapshots, and the fix. Prerequisites are created through other commands
(`ZoomIn` before `FitPage`; `GoToPage(2)` before `PreviousPage`;
`SetFindQuery("Page")` before `FindNext`). Find proofs assert
`match_count() > 0` first, so a missing PDFium text extractor fails loudly
instead of passing vacuously.

Viewport commands are proven through a real headless frame:

```rust
let ctx = egui::Context::default();
let output = ctx.run(egui::RawInput::default(), |ctx| {
    app.dispatch(command.clone(), Some(ctx));
});
output.viewport_output[&egui::ViewportId::ROOT].commands
```

Proven: `Caption(Minimize)` → `ViewportCommand::Minimized(true)`,
`Caption(Close)` → `ViewportCommand::Close`, `StartWindowDrag` →
`ViewportCommand::StartDrag`, `ToggleFullscreen` → `Fullscreen(true)`.

Fixtures: `fixtures/multipage-3.pdf` (3 text pages), `multipage-2.pdf`,
`multipage-4.pdf`. `with_three_page_document()` asserts PDFium reported 3
pages, with an actionable message (`run scripts/fetch-pdfium.ps1`), so the gate
cannot silently degrade to no-ops. No absolute paths are used; fixture paths are
resolved from `CARGO_MANIFEST_DIR`.

Completeness guard: `every_app_command_is_proven_or_allowlisted` compares
`all_commands()` labels against `PROVEN_LABELS` + `UNOBSERVABLE_ALLOWLIST`, so a
new `AppCommand` cannot ship without a proof or a documented exemption.
`command_labels_are_stable_unique_and_non_empty` pins all 60 labels and asserts
they are non-empty and unique. `allowlisted_commands_have_a_reason` rejects
empty or vague (<40 chars) reasons.

## Allowlist (5 entries)

Two are the original round-A entries; three were added because T-0220
introduced commands whose state has no public accessor yet.

| label | reason |
|---|---|
| `open-dialog` | sets the private `open_dialog_open` request flag, consumed next frame by `rfd::FileDialog::pick_files()`; no getter, and painting the frame headlessly would block on a modal OS dialog. |
| `copy-selection` | copies `selected_text()` to the clipboard/status only when a selection exists; no public selection setter (canvas drag only), so headless dispatch is the documented no-op. |
| `toggle-tools` | flips private `tools_open` and persists it to shell preferences; no getter, and a headless viewer has no preferences path. Follow-up: add `tools_open()` and move to `PROVEN_LABELS`. |
| `toggle-grid` | flips private `grid_view` used only while painting thumbnails; no getter. Follow-up: add `grid_view()`. |
| `show-rail` | assigns private `active_rail` after a capability check; no getter, and the default headless capability set may reject the item. Follow-up: add `active_rail()`. |

## Static no-dead-controls scanner

`scan_source(source, file)` finds `fn` items by line prefix (`fn `, `pub fn `,
`pub(crate) fn `, `pub(super) fn `, `async` variants), tracks brace depth to the
closing brace (string-literal and `//`-comment aware), and, for every function
whose body contains neither `dispatch(` nor `AppCommand`, flags lines
containing:

`.button(`, `menu_button(`, `selectable_label(`, `selectable_value(`,
`checkbox(`, `add(Button`, `shell_tool_button(`, `shell_icon_button(`,
`title_icon_button(`, `traffic_light(`, `text_edit_singleline(`,
`text_edit_multiline(`, `DragValue`, `.clicked()`.

Allowlists:

- Line level: text fields and `DragValue` (value is dispatched on `.changed()`
  or bound directly).
- Function level: `shell_icon_button`, `shell_tool_button`,
  `title_icon_button`, `traffic_light` — they build and return
  `egui::Response`, and the caller dispatches.
- Body level: functions returning `return TabAction::…` defer the action to the
  caller, which dispatches after the UI closure.

The scanner is itself tested: `scanner_flags_a_dead_button` and
`scanner_flags_a_dead_custom_click_target` feed synthetic snippets and expect
exactly one finding; `scanner_accepts_a_dispatched_button`,
`scanner_accepts_an_allowlisted_text_field`, and
`scanner_accepts_a_deferred_tab_action` expect none. A new dead
`ui.button("X").clicked()` therefore fails both the synthetic test and the
repository scan (`repository_shell_has_no_dead_controls`, which reads every
`src/shell/*.rs` plus `src/ui.rs`).

### Known false-negative shapes (explicit)

1. Any `dispatch(`/`AppCommand` anywhere in the enclosing function exempts every
   control in it; a dead control in a live function passes.
2. New helper wrappers not listed in `CONTROL_PATTERNS` are invisible.
3. `ui.add(open)` where `Button::new` was built earlier is not matched
   (`add(Button` only).
4. A dead control inside an allowlisted function (factory or
   `TabAction`-returning) is exempt.
5. Brace counting ignores raw strings, char literals, and block comments; a
   stray `'{'` can truncate a function and hide its controls.
6. `pub(in …) fn`, `const fn`, and multi-line `pub(crate)` + `fn` declarations
   are not recognized as function starts.
7. `.click()` (not `clicked()`), `double_clicked()`, macro-generated widgets, and
   shell UI outside `src/shell/**` + `src/ui.rs` are not scanned.
8. Only lines starting with `//` are skipped; a trailing comment containing
   `.button(` can produce a false alarm.

### Hardening follow-up

Make the scanner **function-scoped to the control's own response**: require the
`dispatch` to reference the same response binding (e.g. `response` / the
temporary) rather than accepting any `dispatch` in the function. This removes
false-negative shape 1, the largest hole. Also add public getters for the three
allowlisted private flags so those entries can be deleted.

  `theme_preference`. Immediately after `SetThemePreference(Dark)` with no frame
  in between, `ToggleTheme` is a no-op. It is not a dead control (real frames
  repaint `self.theme`), and the test proves it from the default `System`
  preference.

  read-only accessors before the gate can prove them.
