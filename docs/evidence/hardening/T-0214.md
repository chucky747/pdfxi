## 1. What shipped

- `crates/pdfxi-document/src/session.rs` - `DocumentSession`, `DocumentSnapshot`
  and `MAX_REVISIONS`: the single owner of the open document per ADR 0010.
- `crates/pdfxi-document/src/error.rs` - `SessionError`, one typed variant per
  user-facing cause (password, stale file, rewrite boundary, no path, I/O, core,
  security).
- `crates/pdfxi-document/src/atomic.rs` - sibling temporary file, `sync_all`,
  rename; every failure path removes the temporary file and leaves the
  destination unchanged.
- `crates/pdfxi-document/src/identity.rs` - length + mtime + SHA-256 of the first
  and last 4 KiB of a file, captured at load and after every save.
- `crates/pdfxi-document/tests/session.rs` - six integration tests on the real
  `fixtures/realworld/` files.
- `crates/pdfxi-document/src/session.rs` unit tests - two `/Encrypt` detection
  tests.

No new dependency was added. The crate uses the existing `thiserror`,
`pdfxi-core` and `pdfxi-security` entries; SHA-256 comes from the public
`pdfxi_security::crypto::sha::sha256`.

## 3. Behaviour and guarantees

### Open and decryption

- Only the trailing 64 KiB is scanned for a `/Encrypt` name token, and the token
  must not be followed by an ASCII alphanumeric character. `/EncryptMetadata`
  therefore does not mark a document encrypted; `/Encrypt 4 0 R` does.
- An encrypted source is opened through
  `pdfxi_security::open_encrypted(&bytes, Some(password))`. `MissingPassword`
  is mapped to `SessionError::PasswordRequired`, `WrongPassword` to
  `SessionError::WrongPassword`, and every other security failure is wrapped.
  Session bytes are the decrypted plaintext, so `document()`, `bytes()` and page
  text all see plaintext.
- An unencrypted source ignores a supplied password.

### Incremental mutation, undo and redo

- `edit` runs the closure on the parsed document, calls
  `Document::save_incremental()`, records `start_len`, the appended delta and
  the SHA-256 of the bytes before and after, then reparses the appended bytes.
  The returned bytes always start with the previous bytes as an exact prefix.
  A mutation or save error reloads the document from the unchanged session bytes
  and records no revision.
- `undo` pops the newest revision, verifies the SHA-256 of the prefix it is about
  to keep, truncates to `start_len`, and reparses. A mismatch returns
  `RevisionMismatch` and restores the revision.
- `redo` verifies the current bytes against the revision's `before` hash,
  re-appends the stored delta, and reparses.
- History holds at most `MAX_REVISIONS = 50` revisions. Pushing beyond that
  drops the oldest entry and sets the sticky `dropped_oldest_revision()` flag.
  The file bytes are unaffected; only the undo window is bounded.
- `edit_full` calls `Document::save()`, which is a single-revision rewrite. It
  clears both stacks and marks the lineage reset; `undo` at that boundary
  returns `UndoAcrossRewrite`. A subsequent incremental `edit` is undoable back
  to the post-rewrite state, and the next step still reports
  `UndoAcrossRewrite`.
- `revision_count()` is the number of revisions currently available for undo.

### Save, save-as and external change

- `save` writes through a sibling temporary file in the destination directory,
  calls `sync_all`, then renames over the destination. On any failure the
  temporary file is removed and the destination is untouched.
- Before writing, `save` compares length, mtime, and the head/tail hashes with
  the identity captured at open or the previous save. A mismatch returns
  `ExternallyModified { path }`. A missing destination is also reported as
  external modification. `save_forced` skips the comparison;
  `save_as` writes elsewhere without touching the previously opened file.
- Once encrypted saving is wired (T-0238), the password is already retained for
  the future re-encryption call.

### Limits recorded for Round A

- Saving an encrypted session is refused with
  `SessionError::EncryptedSaveUnsupported` from `save`, `save_forced` and
  `save_as`. Decrypted plaintext stays available in memory; writing it out
  would silently remove protection, so it is not offered.
- External-change detection samples 4 KiB at each end, not the whole file. A
  same-length rewrite that preserves both ends, the length and the mtime is not
  detected. Typical appends, truncations and rewrites are.
- A literal `/Encrypt` inside a stream payload in the final 64 KiB is a detected
  false positive. The security layer then reports an invalid encryption
  dictionary instead of the file being treated as plaintext.
- The crate is rendering-free per the core lane boundary. The ADR's "reload
  PDFium from memory" step is the application's job: it reopens
  `session.bytes()` through the renderer after each mutation. No renderer
  dependency is added here.
- `edit_full` intentionally drops history. Redaction, sanitize and optimize must
  use it, and the UI must say the earlier revisions are gone (ADR 0010, point 5).

## 4. Tests

`crates/pdfxi-document/tests/session.rs` (six integration tests):

1. `encrypted_fixture_opens_with_password_and_extracts_text` - opens
   `fixtures/realworld/pdfxi-encrypted-selfmade.pdf` with `pdfxi-test`, asserts
   AES-128, one decrypted page containing `Encrypted selfmade page marker`,
   clean state, and that `save()` returns `EncryptedSaveUnsupported`. Also
   asserts no password (bytes and path) gives `PasswordRequired` and a wrong
   password gives `WrongPassword`.
2. `incremental_edits_undo_and_redo_keep_values_and_page_text` - Excel 2019
   fixture: two Info-title mutations, then undo twice and redo once. Asserts the
   title values at every step, exact page text (both pages, all three manifest
   markers), revision counts, redo availability and dirty state.
3. `failed_atomic_save_leaves_the_original_untouched` - edits a copy and calls
   `save_as` on an existing directory, where the rename cannot replace the
   destination. Asserts a typed I/O error, the original file byte-identical,
   the session path unchanged, and no `.pdfxi-tmp` file left behind.
4. `external_change_is_reported_unless_forced` - appends bytes to the file
   behind the session, asserts `save()` returns `ExternallyModified` with the
   right path, then `save_forced()` succeeds and the file equals
   `session.bytes()`.
5. `full_rewrite_edit_makes_earlier_revisions_non_undoable` - incremental edit,
   then `edit_full`, asserts the new value, `can_undo() == false` and
   `Err(UndoAcrossRewrite)`.
6. `revision_cap_drops_the_oldest_and_reports_it` - 55 edits with
   `MAX_REVISIONS == 50`; asserts the retained count, the sticky flag, exactly
   50 successful undos, `NothingToUndo` after them, and the state at the
   retained boundary (`revision 4`).

Unit tests in `session.rs`:

7. `encrypt_detection_ignores_the_metadata_key`
8. `encrypt_detection_finds_the_trailer_reference`
