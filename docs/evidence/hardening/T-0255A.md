# T-0255A - Real-PDF outline reader and writer bridge

Status: verified library slice. The T-0255 app bookmark pane and properties
dialog remain app-lane work. Claim `T-0255A` stays held.

## Scope

`crates/pdfxi-edit/src/navigation/**` gained a document-backed outline bridge:

- `read_outline(&Document) -> Result<OutlineRead, OutlineReadError>`
- `write_outline(&mut Document, &Outline) -> Result<(), OutlineWriteError>`

No app, orchestration, matrix or git changes. The only orchestration artifact is
the lane fragment `orchestration/feature-updates/T-0255A.toml`.

## Public API

`pdfxi_edit::navigation`:

- `OutlineRead { present: bool, outline: Outline, issues: Vec<OutlineIssue> }`
- `OutlineIssue { object: ObjectId, title: String, reason: OutlineIssueReason }`
- `OutlineIssueReason::{MissingDestination, NonGoToAction, UnresolvedNamedDestination,
  InvalidDestination, DanglingPageReference}`
- `OutlineReadError::{Core, CatalogNotDictionary, MalformedOutlines,
  ItemNotDictionary, MissingTitle, InvalidTitle, Cycle, BrokenParent, BrokenLink,
  ItemBudgetExceeded, DepthLimitExceeded, ReferenceCycle, ReferenceDepthExceeded}`
- `OutlineWriteError::{Core, CatalogNotDictionary, MalformedOutlines,
  InvalidTitle, PageNotFound, NonFiniteDestination, DepthLimitExceeded,
  ItemBudgetExceeded}`
- Bounds: `MAX_OUTLINE_ITEMS = 100_000`, `MAX_OUTLINE_DEPTH = 64`.

## Reader

- Walks catalog `/Outlines` `/First`/`/Next` recursively through
  `pdfxi_core::Document::object`; maps `Document::pages()` `Page::id` to
  zero-based indexes.
- Resolves `/Dest [page_ref /Fit ...]` and `/A << /S /GoTo /D ... >>`, including
  integer page indices (range-checked) and named destinations from catalog
  `/Dests` and `/Names /Dests` (`/Names`, `/Kids`).
- Keeps an item with no resolvable destination as a bookmark with
  `destination: None` plus a typed `OutlineIssue`; it never invents a page.
- Narrows a coordinate to `f32` before checking finiteness, so a finite `f64`
  such as `1e39` is an `OutlineIssue` (`destination coordinate overflows f32`)
  instead of an infinite `FitType`. The negative test stages `1e39` on the real
  PowerPoint outline and asserts the other two items still read with pages 1
  and 2.
- Rejects a cyclic, dangling, wrong-parent or structurally inconsistent tree
  with a typed `OutlineReadError`, bounded by item, depth and reference limits.
- Real fixture `fixtures/realworld/powerpoint-slides.pdf` reads 3 roots with
  titles `Slide 1: Lantern Slide`, `Slide 2: Harbor Slide`,
  `Slide 3: Meadow Slide`, pages `0, 1, 2`, and `/XYZ 0 405 0`.
- `fixtures/realworld/microsoft-excel-2019-sample.pdf` reports no `/Outlines`.

## Writer

- Writes catalog `/Outlines` with `/Type /Outlines`, `/Count`, `/First`,
  `/Last`; each item with `/Title`, `/Parent`, `/First`, `/Last`, `/Count`,
  `/Next`, `/Prev`, `/Dest`, `/C`, `/F` as applicable.
- Destinations use real page references from `Document::pages()`, never new page
  objects; page ids are preserved.
- Reuses an existing indirect outline object id, creates `/Outlines` on first
  add, and preserves unrelated catalog entries.
- Validates titles, page ranges, finite coordinates, depth and item count before
  staging anything. IDs are allocated in pre-order and dictionaries are
  deterministic.
- Repeated writes on one `Document` see the previous staged outline through a
  reparsed incremental view; the source document is not mutated.
- Invalid input is a no-op on bytes: the regression test snapshots
  `document.save()` before an out-of-range page and before a NaN coordinate and
  asserts byte equality after each rejection. A later valid write and a second
  valid write both round-trip.

## Round trip and PDFium

Test `round_trip_edits_real_powerpoint_outline_and_reopens_with_pdfium` on the
PowerPoint fixture:

1. read -> add root `Prelude` (page 0), add child `Slide 1 detail` (page 1),
   close `Slide 1`, rename `Slide 2` to `Harbor Slide (renamed)`, move
   `Slide 3` to root index 1;
2. `write_outline`, full save, reopen with PDFXI;
3. asserts root order `Prelude, Slide 3, Slide 1, Harbor Slide (renamed)`,
   pages `0, 2, 0, 1`, the child title/page, closed `/Count -1`, no `XI_Open`,
   and the `/Parent`/`/Prev` chain;
4. PDFium `PdfiumRenderer::from_bytes` opens the saved bytes, reports 3 pages
   and reads page dimensions for every page.

**Limit:** this workspace's `pdfxi-render` PDFium binding exposes no bookmark
traversal, so PDFium cannot independently read outline titles/pages. PDFium is
the independent file-validity and page-tree check; PDFXI's reader asserts the
outline order, titles and destination pages.

The no-outline test on `microsoft-excel-2019-sample.pdf` adds a bookmark on
page 1, then asserts the new `/Outlines` and that every original catalog key and
page object id is unchanged.
