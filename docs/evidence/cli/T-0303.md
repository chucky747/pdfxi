# T-0303 — document find-and-replace host (`EDIT-003`)

Row promoted: `EDIT-003` (Find and replace text across a document)
`model` -> `verified`.

The row's `find_replace` model matched extracted text and produced an
ordered, non-overlapping plan, but never touched content streams. This task is
the writer: it maps a match to the text run that contains it, rewrites the run,
saves, and re-extracts to prove the edit reached the page.

## 1. Host

```text
pdfxi replace <FILE> --out PATH --find T --replace T
    [--case-sensitive] [--whole-word] [--diacritic-insensitive]
    [--limit N] [--json]
```

- Matching is `pdfxi_edit::find_replace::find_all` with the same literal,
  bounded options as `pdfxi search`.
- A match is accepted only when both scalar offsets lie inside one run of the
  page text model (`pdfxi_edit::text_blocks`). The run is rewritten with
  `pdfxi_edit::replace_run_text`, which reflows the whole block and embeds the
  bundled fallback font when the original font cannot encode the replacement.
- After every replacement the document is written and reparsed, because
  `replace_run_text` stages a new content stream and the in-memory reader still
  reports the pre-edit text. A full save (not an incremental one) keeps a long
  run below the core reader's bounded xref-section chain.
- The final file is written, reopened, and the extracted text is re-searched.
  The report carries `initial_matches`, `replaced`, `remaining`, the per-page
  `rows`, `embedded_font_blocks` and `limit_reached`.
- If matches exist but none is expressible inside one run, the command fails
  instead of writing unchanged bytes. `--limit` (default 1000) bounds the work.

## 2. Evidence

```text
> pdfxi replace fixtures\minimal.pdf --out target\tmp\goodbye.pdf --find "Hello" --replace "Goodbye" --case-sensitive
file: fixtures\minimal.pdf
out:  target\tmp\goodbye.pdf
find: "Hello"  replace: "Goodbye"  case_sensitive: true  whole_word: false  diacritics: false
matches: 1 initial, 1 replaced, 0 remaining
limit: 1000
embedded_font_blocks: 0
bytes: 839

> pdfxi text target\tmp\goodbye.pdf
Goodbye, PDFXI!
```

A real 3-page document:

```text
> pdfxi replace fixtures\realworld\powerpoint-slides.pdf --out target\tmp\slides-replaced.pdf --find "marker" --replace "label" --json
  "pages": 3,
  "initial_matches": 3,
  "replaced": 3,
  "remaining": 0,
  "limit_reached": false,
  "embedded_font_blocks": 3,

> pdfxi text target\tmp\slides-replaced.pdf
Lantern Slide•The lantern slide label is the first landscape page.
Harbor Slide•The harbor slide label is the second landscape page.
Meadow Slide•The meadow slide label is the third and final landscape page.
```

The limit stops a run cleanly:

```text
> pdfxi replace target\tmp\three.pdf --out target\tmp\limited.pdf --find "beta" --replace "BETA" --case-sensitive --limit 1
matches: 2 initial, 1 replaced, 1 remaining
limit: 1 (reached)
embedded_font_blocks: 1

> pdfxi text target\tmp\limited.pdf
BETA beta gamma
```

A 120-line multi-page document replaces all 120 matches and `pdfxi search`
finds exactly 120 `label` hits afterwards. Whole-word matching replaces four
standalone `alpha` words and leaves `alphabet` intact. Replacing `Hello` with
`Grüße` extracts correctly.

## Scope

Matching is literal (no regular expressions), one run at a time. Matches that
span runs and whole-run deletions remain in `remaining` rather than being
reconstructed. Replacing reflows the block, so wrapping and line grouping can
change; text is preserved and re-extractable. There is no undo history and no
GUI dialog; `pdfxi replace` is the user entry point.
