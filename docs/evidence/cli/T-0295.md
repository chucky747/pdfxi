# T-0295 — form creation host (`FORMS-002`)

Row promoted: `FORMS-002` (Create text checkbox radio choice and button fields)
`library` -> `verified`.

The typed builders and `serialize_form_pdf` already produced a loadable
one-page form. There was no user-reachable path, so this task adds one and
verifies the written file by reloading it.

## 1. Hosts

```text
pdfxi form create <OUT> --field KIND:NAME:X,Y,W,H[:OPT1|OPT2] ... [--json]
pdfxi form list <FILE> [--json]
```

`KIND` is `text`, `checkbox`, `radio`, `combo`, `list`, `button` or
`signature`. Options are required for `radio`, `combo` and `list` and refused
for the other kinds. Rectangles are `x,y,width,height` in points and must be
positive and inside the emitted 612x792 page. Names must be unique.

`create` builds each `FieldSpec`, emits `field_dictionary()` and
`widget_annotation()`, calls `serialize_form_pdf`, and then fails closed unless:

- `pdfxi-forms::load_acroform` reads back the same number of fields in the same
  order, and
- `pdfxi-core` parses the bytes and reports exactly one page.

Only then does it write the file. `list` reports the terminal fields of any form
PDF through the same loader, so it works for files this command did not create.

Two runs produce byte-identical files (the integration test asserts equality).

Rejections:

```text
> pdfxi form create out.pdf
error: the following required arguments were not provided: --field ...

> pdfxi form create out.pdf --field "text:name:72,700,200"
Error: a field rectangle needs four comma-separated numbers (x,y,w,h)

> pdfxi form create out.pdf --field "text:name:72,700,200,24" --field "checkbox:name:72,660,14,14"
Error: duplicate field name "name"

> pdfxi form create out.pdf --field "radio:color:72,620,14,14"
Error: a radio field needs at least one option after the rectangle

> pdfxi form create out.pdf --field "text:name:600,700,200,24"
Error: field rectangle 600 700 200 24 is outside the 612x792 page
```

## 3. Tests

```text
> cargo test -p pdfxi-cli --test cli form_
test form_create_writes_typed_fields_and_reloads_them ... ok
test form_create_and_list_reject_bad_input ... ok
test result: ok. 2 passed

> cargo test -p pdfxi-cli --bin pdfxi form
test form::tests::field_descriptions_parse_all_supported_kinds ... ok
test form::tests::field_descriptions_reject_bad_input ... ok
test form::tests::rectangles_validate_geometry ... ok
test result: ok. 3 passed
```

- `form_create_writes_typed_fields_and_reloads_them` creates all seven kinds,
  asserts the text report, the `%PDF-1.7` header, deterministic output, a JSON
  `form list` with the expected names and types in order, and `pdfxi info`
  reporting one page.
- `form_create_and_list_reject_bad_input` covers a missing `--field`, a short
  rectangle, a duplicate name, options on a text field, a radio without
  options, an off-page rectangle, and `form list` on a PDF without an AcroForm
  (`present: false`, zero fields).

## Scope

Text, checkbox, radio, choice (combo and list), push-button and signature fields
are reachable and reload from the written bytes. Creation targets a standalone
one-page document; merging fields into an existing PDF and per-option radio
appearance streams remain outside this row, as the library notes already state.
