# T-0274 — `pdfxi compat`: reachable PDF 1.0–2.0 compatibility report

## What changed

`STD-001` ("PDF 1.0 through 2.0 compatibility") already had a complete library
model in `pdfxi-core::compatibility`: tolerant `%PDF-` header parsing, catalog
`/Version` override, twelve version-gated constructs (`PdfFeature::ALL`), a
deterministic gate report and a token scan. No user could reach any of it.

This task adds the reachable surface:

```text
pdfxi compat <FILE> [--json] [--strict]
```

- Prints the header version, effective version, where the version came from
  (`header` or `catalog`), the header byte offset, whether the version is inside
  1.0–2.0, the stable gate summary, every gate with its minimum version, the
  constructs found by the byte scan, and any compatibility warnings.
- `--json` emits a stable shape: `file`, `header_version`, `effective_version`,
  `source`, `header_offset`, `supported`, `warnings`, `features[]`
  (`feature`, `min_version`, `supported`), `detected[]`.
- `--strict` exits 3 when the file contains a construct its effective version
  does not allow, for scripting.

Docs added to the row: `crates/pdfxi-cli/src/main.rs`,
`crates/pdfxi-cli/tests/cli.rs`.

## Reachable path on a real document

```text
$ pdfxi compat fixtures\realworld\powerpoint-slides.pdf
file: fixtures\realworld\powerpoint-slides.pdf
header_version: 1.7
effective_version: 1.7
source: header
header_offset: 0
supported: yes
gates: effective=1.7 supported=9/12 unsupported=AES-256 encryption(need 2.0),associated files(need 2.0),encrypted metadata(need 2.0)
features:
  transparency: supported
  tagged PDF: supported
  cross-reference streams: supported
  object streams: supported
  optional content: supported
  crypt filters: supported
  3D annotations: supported
  embedded files: supported
  multimedia annotations: supported
  AES-256 encryption: not supported (needs 2.0)
  associated files: not supported (needs 2.0)
  encrypted metadata: not supported (needs 2.0)
detected: transparency, tagged PDF, cross-reference streams, object streams
warnings: none
```

Corpus sweep over the first 80 catalogued fixtures:

```text
files=80 failures=2 unsupported=2
version 1.7: 78
```

The two failures are `binary-garbage.pdf` and `empty.pdf`, the intentionally
unreadable fixtures; `compat` exits non-zero on them by design. Every readable
fixture loads and reports.

JSON shape (truncated after the first feature):

```json
{
  "file": "fixtures\\realworld\\powerpoint-slides.pdf",
  "header_version": "1.7",
  "effective_version": "1.7",
  "source": "header",
  "header_offset": 0,
  "supported": true,
  "warnings": [],
  "features": [
    { "feature": "transparency", "min_version": "1.4", "supported": true }
  ]
}
```

## Tests

```text
cargo test -p pdfxi-cli --test cli
test result: ok. 69 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out
```

Seven new tests cover the reachable path:

- `compat_reports_a_14_document_and_every_gate` — 1.4: `supported=2/12`,
  1.5+ constructs reported as not supported, `detected: none`.
- `compat_reports_a_20_document_as_fully_supported` — 2.0: `supported=12/12`.
- `compat_reports_a_catalog_version_override` — header 1.4 plus catalog
  `/Version /1.7`: effective 1.7, `source: catalog`, warning text, `9/12`.
- `compat_flags_a_version_outside_the_supported_range` — 2.1 is reported
  unsupported with the 1.0–2.0 range warning.
- `compat_strict_exits_three_for_a_construct_beyond_the_version` — a 1.4 file
  containing `/ObjStm` exits 3 and names `object streams`.
- `compat_json_has_stable_fields` — twelve feature entries, typed fields.
- `compat_handles_a_real_world_document` — the real PowerPoint-derived fixture
  loads and reports.

The five pre-existing core tests
(`compatibility::tests::*`) stay in the row's `tests` list.

## Honest scope

- The construct scan is a token-presence heuristic: a token inside a compressed
  or uncompressed stream can be a false positive, as the core documentation
  states. Structural confirmation of each construct belongs to the owning
  reader modules.
- No PDF/A, PDF/X or PDF/UA conformance claim is made here; those are separate
  rows.
- The report runs on the document's bytes; it does not rewrite the file.
