# T-0302 — tagged structure-tree host (`STD-006`)

Row promoted: `STD-006` (Tagged PDF and structure tree)
`model` -> `verified`.

The row built the bounded structure model, canonical projection, validation and
`write_structure_tree`. Its stated host boundary was that overlays and catalog
entries must be merged by a host. This task is that host: it merges the writer's
intermediate into a real document and verifies the saved tree.

## 1. Host

```text
pdfxi structure apply <FILE> --out PATH --tree PATH [--json]
```

The tree is JSON:

```json
{
  "lang": "en-US",
  "nodes": [
    { "id": 1, "role": "Document", "page": 0, "children": [2, 3] },
    { "id": 2, "role": "H1", "page": 0, "bbox": [72, 700, 400, 730], "text": "Hello, PDFXI!" },
    { "id": 3, "role": "P", "page": 0, "bbox": [72, 650, 400, 690], "text": "Tagged structure proof" }
  ],
  "roots": [1]
}
```

- Roles accept model and PDF names (`P`/`Paragraph`, `H1`/`Heading1`,
  `TD`/`TableData`, ...). Any other name is rejected before the document is
  touched.
- `A11yTree::new` enforces unique ids, known children, acyclic roots and reachable
  nodes; `write_structure_tree` enforces `/ActualText`, `/E` and artifact rules.
- The generated objects are remapped to fresh numbers after
  `allocate_object_number`, with placeholder page references resolved to the real
  page objects.
- Catalog entries (`/StructTreeRoot`, `/ParentTree`, `/Lang`, `/MarkInfo`,
  `/ViewerPreferences`) are merged; every page gets `/StructParents` and its
  marked-content overlay appended to `/Contents`.
- After saving, the host reopens the bytes and verifies:
  - catalog `/StructTreeRoot` equals the staged root and `/MarkInfo /Marked` is
    `true`, `/Lang` is present;
  - the root has `/Type /StructTreeRoot` and a `/ParentTree` whose `/Nums` is
    non-empty;
  - every `/StructElem` carries `/S`, `/P` and a `/Pg` that is a real page, the
    role count equals the writer's count, and every role is known;
  - every page carries `/StructParents` and its text is unchanged.
- `certification_claimed` is always `false`.

## 2. Evidence

```text
> pdfxi structure apply fixtures\minimal.pdf --out target\tmp\tagged.pdf --tree target\tmp\tree.json
file: fixtures\minimal.pdf
out:  target\tmp\tagged.pdf
lang: en-US
pages: 1
nodes: 3
struct_elements: 3
generated_objects: 5
struct_tree_root: 6
pages_tagged: 1
roles: Document,H1,P
certification_claimed: false

> pdfxi text target\tmp\tagged.pdf
Hello, PDFXI!

> pdfxi accessibility check target\tmp\tagged.pdf --json
      "code": "UA-0001",
```

Before tagging the same checker reports `PDFUA1.NOT_MARKED`, `PDFUA1.NO_LANG`
and `PDFUA1.NO_STRUCT_TREE_ROOT`; after tagging only the unrelated missing-title
finding remains. Two runs produce byte-identical files (`deterministic=True`).

A three-page `realworld/powerpoint-slides.pdf` with `lang: en-GB` and one
heading or paragraph per page reports `pages: 3`, `pages_tagged: 3` and
`roles: Document,H1,H2,P`.

## Scope

The tag tree is written from a JSON description, not inferred from a layout
engine, and only the structure model's roles are accepted. Overlays are marked
content only; no visual content is added. PDF/UA conformance is not certified,
and the document title is still the caller's responsibility.
