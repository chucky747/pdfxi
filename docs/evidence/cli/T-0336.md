# T-0336 — Media annotation and HTML5 hosts (`MEDIA-001`, `MEDIA-002`)

Rows promoted:

- `MEDIA-001` (Audio and video annotations) `model` -> `verified`.
- `MEDIA-002` (HTML5 media replacement for Flash) `model` -> `verified`.

Both models were complete in `pdfxi_render` with no user surface. This task adds
the `pdfxi media` group: one subcommand reads real `/Sound`, `/Movie` and
`/Screen` annotations and can extract an embedded payload; the other emits the
local-only HTML5 player envelope.

## 1. Host

```text
pdfxi media list <INPUT.pdf> [--extract DIR] [--json]
pdfxi media html5 --source SRC=MIME [--source ...] [--poster SRC]
    [--controls] [--autoplay] [--loop] [--muted] [--width N] [--height N]
    [--out PATH] [--json]
```

- `list` scans every page `/Annots` for `Sound`, `Movie` and `Screen`, reads the
  `/Sound` stream or the `/Movie` file specification, guesses the MIME type from
  the movie file extension when the PDF declares none, reads `/Volume`, and
  validates `MediaDictionary` through `MediaAnnotation`. It prints the active
  rendition, activation, volume, host requirements and plan descriptor.
  `--extract DIR` decodes and writes the embedded payload as
  `<annotation>-<kind>.bin`.
- `html5` validates sources through `Html5Descriptor` (embedded `@name` or
  relative local path), emits the deterministic `<audio>`/`<video>` element and
  wraps it in a complete HTML document with
  `default-src 'none'; media-src 'self'; img-src 'self'` CSP. `--out` writes the
  document; without it stdout receives the element.

## Scope

No playback: the CLI resolves the plan and extracts the stream; a host player
realises it. `/Screen` rendition selection from `/A` is not decoded (the row
reports a primary source and plan), and Movie payloads referenced through an
embedded file specification are reported but not extracted. The HTML5 envelope
is local-only and inert: no remote media, scripting or network access.
