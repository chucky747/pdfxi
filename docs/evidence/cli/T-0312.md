# T-0312 — scan-to-PDF assembly host (`CREATE-007`)

Row promoted: `CREATE-007` (Scan to PDF with TWAIN and WIA)
`model` -> `verified`.

The row validated caller-supplied scan geometry, ordering and the reused
print-capture plan, but produced no PDF. This task is the assembly host.

## 1. Host

```text
pdfxi create scan --out PDF --scan PAGE.png [--scan PAGE.png ...]
    [--dpi 300] [--duplex simplex|front-first|back-first] [--json]
```

- Reads each PNG (real bytes), checks the signature/IHDR and extracts width and
  height without decoding pixels.
- Describes every page as a `ScanSource` with its sheet ordinal, side, DPI and
  `ImageFormat::Png`, then calls `build_scan_plan`.
- Each planned page is embedded with `create_from_image` at the plan's exact
  page size (`width_px / dpi * 72` points) with zero margins.
- Pages are merged in plan order through `PagePlan::merge` and
  `Document::apply_page_plan`.
- The written file is reopened; page count and every page's media box are
  checked against the plan. `--json` reports sheet/side/label/source/format/
  pixel and point sizes, front/back counts and both summaries.
- Duplex pairs consecutive images as front/back of each sheet; an incomplete
  pair or a back image in simplex mode is a typed error.

PNG is the supported scan raster because the model's raster formats and the
image embedder intersect there; a TWAIN/WIA adapter can emit PNG.

## Scope

The device/driver (TWAIN/WIA) is still a host adapter: this command consumes
already-rendered PNG pages. Only PNG is accepted; there is no OCR, deskew,
despeckle, or automatic orientation. Page size comes solely from pixels and DPI.
