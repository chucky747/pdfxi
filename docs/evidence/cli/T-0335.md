# T-0335 — Interactive actions host (`MEDIA-005`)

Row promoted: `MEDIA-005` (Interactive actions and triggers) `model` ->
`verified`.

`pdfxi_render::actions` already owned the `/AA` trigger whitelist and the
typed safe-action plan. It had no host. This task adds `pdfxi interactions`,
which audits the real catalog, page and annotation `/AA` dictionaries.

It also fixes a CLI-wide startup failure found while adding the command: the
clap command tree is one deeply nested builder expression, and at this command
count a debug build exhausted the default 1 MiB main-thread stack even for
`pdfxi --version`. `main` now runs the CLI on a worker thread with a 16 MiB
stack, so adding commands cannot regress startup. A regression test asserts
`pdfxi --version` exits 0.

## 1. Host

```text
pdfxi interactions <INPUT.pdf> [--strict] [--json]
```

- Reads `/AA` from the catalog, every page and every annotation.
- Maps each entry's `/S` kind and `/D` destination: a page reference is resolved
  to its zero-based page index, a name or string becomes a named destination.
- Validates each action independently through `AaActionSet::parse`, so one bad
  action does not hide the rest.
- Accepted actions print their stable code (`goto:0`, `next-page`,
  `toggle-full-screen`, ...); rejected actions print the typed reason.
- `--strict` exits non-zero when anything is rejected. No action executes.

## 2. Evidence

Fixture: catalog `/AA << /PV 6 0 R >>` (GoTo page 0), page `/AA << /E 7 0 R
/X 8 0 R >>` (NextPage, JavaScript), annotation `/AA << /D 10 0 R >>`
(FullScreen).

```text
> pdfxi interactions target\tmp\interactions.pdf

  page 1 annotation 4  D  ToggleFullScreen  ok  toggle-full-screen
EXIT=0

> pdfxi interactions target\tmp\interactions.pdf --strict
```

JSON reports `sites 3, actions 4, accepted 3, rejected 1` with per-row
`status`, `code`/`error` and `target`.

## Scope

Audit and validation only. The command never executes an action, edits `/AA`,
or resolves remote/URI destinations; those are reported as unsupported or
dangerous exactly as the model classifies them. Field-level `/AA` dictionaries
remain covered by `pdfxi form actions`.
