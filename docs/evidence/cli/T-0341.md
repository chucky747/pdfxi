# T-0341 — Browser handoff host (`PLAT-004`)

Row promoted: `PLAT-004` (Browser integration) `model` -> `verified`.

`pdfxi_core::browser_handoff` owned the local-only handoff validation and the
deterministic open/download plan, with a recorded boundary: "no network, no
browser extension, no protocol registration." This task adds the host the model
describes: `pdfxi handoff`.

## 1. Host

```text
pdfxi handoff open <FILE> [--mime TYPE] [--launch] [--json]
pdfxi handoff parse <PATH|file://URL> [--json]
pdfxi handoff link <FILE.html> [--fragment TEXT] [--json]
```

- Relative inputs are made absolute; already rooted paths are passed through
  unchanged so a `..` component is still rejected by the model.
- The file must exist; a missing file is a typed error (the model only checks
  path shape).
- `open` resolves `HandoffRequest` -> `resolve_request` and prints path,
  `file:` URL, decision (`open`/`download`), MIME and summary. The MIME
  allowlist is `text/html`, `text/plain`, `application/pdf`,
  `application/octet-stream`; any declared non-HTML type decides `download`.
- `--launch` spawns the platform opener (`cmd /C start`, `open`, `xdg-open`)
  only after validation.
- `parse` accepts a rooted path or `file:` URL, rejects other schemes and
  traversal, resolves the plan and requires the local file.
- `link` builds the HTML `file:` URL with a validated fragment.

`--launch` was not exercised to avoid opening a browser window in this session;
the launch path uses only the validated `file:` URL.
