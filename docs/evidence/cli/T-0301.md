# T-0301 — CID font embedding host (`STD-004`)

Row promoted: `STD-004` (Font embedding and CID fonts)
`library` -> `verified`.

The row explicitly left two producer steps to a host: wiring the staged font
into page `/Resources` and a content stream. `pdfxi_edit::add_text_box` does
both with the bundled Courier Prime program, and this task exposes it as a CLI
command with post-save verification.

## 1. Host

```text
pdfxi font add-text <FILE> --out PATH --text T --rect x0,y0,x1,y1
    [--page N] [--font-size PT] [--align left|center|right] [--json]
```

- Calls `pdfxi_edit::add_text_box`, which uses
  `pdfxi_core::font::stage_cid_font` to write the five objects: `/Type0`,
  `/CIDFontType2`, `/FontDescriptor`, `/FontFile2` and the `/ToUnicode` CMap,
  plus `/CIDToGIDMap` and CID-keyed `/W` widths.
- Appends a content stream using the page resource, wraps text to the box and
  supports left/center/right alignment.
- Reopens the saved bytes and verifies:
  - the named resource is `/Subtype /Type0`,
  - `/DescendantFonts[0]` is `/CIDFontType2`,
  - the descriptor carries `/FontFile2` (or `/FontFile3`/`FontFile`),
  - the Type0 dictionary has `/ToUnicode`,
  - every inserted word is present in the page text, proving the ToUnicode
    mapping is usable by extraction.
- The bundled font is `crates/pdfxi-edit/assets/CourierPrime-Regular.ttf` under
  the SIL Open Font License 1.1; no system font path is used.

## Scope

The bundled TrueType program is embedded as a full CID font (no binary
subsetting), one font per text box, horizontal text only. Arbitrary caller
font programs and subsetting remain library-level; the host proves the staged
graph is wired into a real page and extractable.
