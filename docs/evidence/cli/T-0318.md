# T-0318 — Watched-folder conversion host (`CREATE-014`)

Row promoted: `CREATE-014` (Watched-folder conversion) `model` -> `verified`.

`pdfxi watch` already polled a folder and persisted markers, but every output
was a byte-for-byte passthrough. This task installs the real in-process
converter, closing the row's recorded "output persistence and CLI/host wiring"
gap.

## 1. Host

```text
pdfxi watch <FOLDER> --out <DIR> [--ext txt ...] [--suffix pdf]
    [--markers SNAPSHOT.json] [--poll-every N] [--ticks N] [--json]
```

`PdfConverter` implements `FolderConverter`:

| Extension | Adapter |
| --- | --- |
| `pdf` | unchanged passthrough |
| `txt` | `create_from_text` |
| `md`, `markdown` | `create_from_markdown` |
| `html`, `htm` | `capture_html_markup` (bounded HTML importer) |
| `png`, `jpg`, `jpeg` | `create_from_image` |

- `WatchedFolderConfig` validates the absolute, traversal-free root, safe
  extensions and budgets; `WatchedFolder` scans real files.
- Processed paths are persisted through `MarkerSnapshot` and skipped on later
  polls; a converter error is a typed per-file failure that stays eligible for
  retry.
- Outputs are written by the host under the canonical output root, which must be
  outside the watched folder; `safe_output` rejects any escaping relative name.

## Scope

The host runs a deterministic number of ticks; it does not install an OS
filesystem watcher or run as a service. There is no OCR, no PS/EPS intake in the
watch path, no duplicate suppression beyond the persisted markers, and no
retry/backoff policy beyond the next poll.
