# T-0299 — line-hunk version diff (`REVIEW-008`)

Row promoted: `REVIEW-008` (Compare two PDFs and summarize changes)
`model` -> `verified`.

`pdfxi_edit::compare` already implemented the bounded text-snapshot diff with
page/line references and Added/Removed/Changed hunks. The CLI had a separate
page-alignment mode; nothing used this model. This task adds a `--hunks` mode
over it.

## 1. Host

```text
pdfxi compare <LEFT> <RIGHT> --hunks [--json] [--fail-on-difference]
```

- Each side is reduced to normalised page text (trimmed, non-empty lines) and
  wrapped in `pdfxi_edit::TextDocument` with zero-based page indices.
- `compare_documents` runs with `CompareOptions::default()` (bounded pages,
  lines, line bytes, diff cells and hunks), matching pages by index.
- Text output prints each hunk with its kind, one-based page, old/new line
  numbers and both texts, then the summary and line counts.
- `--json` emits stable fields: `identical`, `summary` (`added`, `removed`,
  `changed`, `pages_examined`, `hunks`, `old_lines`, `new_lines`) and `hunks`
  (`kind`, `page`, `old_line`, `new_line`, `old_text`, `new_text`).
- `--hunks` conflicts with `--lines`; `--fail-on-difference` still exits
  non-zero when any hunk exists.

## 2. Evidence

Two PDFs created from text with `pdfxi create text`:

```text
> pdfxi compare target\tmp\v1.pdf target\tmp\v2.pdf --hunks
changed  page 1  old 2  new 2
  - bravo
  + BRAVO
changed  page 1  old 4  new 4
  - delta
  + epsilon
added  page 1  old -  new 5
  + extra
summary: added 1, removed 0, changed 2, pages 1, hunks 3
lines: 4 -> 5
identical: false

> pdfxi compare target\tmp\v1.pdf target\tmp\v1.pdf --hunks --json
{
  "identical": true,
  "summary": {
    "added": 0, "removed": 0, "changed": 0,
    "pages_examined": 1, "hunks": 0,
    "old_lines": 4, "new_lines": 4
  },
  "hunks": []
}
```

The comparison is exact about case and whitespace, so `bravo` to `BRAVO` is a
changed hunk.

## 3. Tests

```text
> cargo test -p pdfxi-cli --test cli compare_hunks
test compare_hunks_report_line_changes_with_page_numbers ... ok
test compare_hunks_reference_later_pages ... ok

```

- `compare_hunks_report_line_changes_with_page_numbers` builds both PDFs via
  `create text`, asserts two changed hunks and one added hunk with page/line
  references and both texts, byte-identical repeated JSON, an identical
  self-comparison with zero hunks, exit code `1` under
  `--fail-on-difference`, and rejection of `--hunks --lines`.
- `compare_hunks_reference_later_pages` paginates 120 lines (more than one
  page), changes `line 110`, and asserts a single changed hunk whose page is at
  least 2 with the correct old/new text.

## Scope

The line-hunk model is reachable on real PDF bytes with page/line references
and a bounded, deterministic report. The default `compare` page-alignment mode
remains unchanged; hunk mode matches pages by index, so an inserted page is
reported as added lines rather than re-aligning later pages.
