# T-0350 — Prepress planning host (`PRINT-006`)

Row promoted: `PRINT-006` (Trapping presets and transparency flattening)
`model` -> `verified`.

`pdfxi_render::trapping` already validated trapping presets and flattening
policies and produced a deterministic `TrapPlan`, but no caller read a document
or exposed the plan. This task adds `pdfxi prepress plan`, which resolves the
plan against a real page and reports exactly which features need a native
prepress backend.

## 1. Host

```text
pdfxi prepress plan FILE [--preset NAME] [--trap-width PT] [--black-width PT]
    [--black-color auto|knockout|c,m,y,k] [--join miter|round|bevel]
    [--sliding none|auto|PT] [--dpi N] [--balance vector|balanced|raster]
    [--overprint preserve|simulate|knockout] [--max-depth N] [--json]
```

- The command parses the document and requires at least one page; it reports the
  page count and the first page's media geometry alongside the plan.
- `TrappingPreset::new` validates the preset (name, trap/black widths, black
  colour, join style, sliding policy); `FlattenPolicy::with_max_depth` validates
  DPI and depth; `TrapPlan::build` resolves both and lists backend requirements.
- The report includes `needs_backend_prepress`, the stable `policy_bits`
  encoding and every warning the plan produced.
- Painting traps, sliding-trap geometry, CMYK trap colour transforms,
  overprint simulation and rasterizing transparency are **not** performed here;
  the model documents them as the native prepress backend's responsibility.

## 2. Evidence

```text
> pdfxi prepress plan target\tmp\roomy.pdf

> pdfxi prepress plan target\tmp\roomy.pdf --preset Press --trap-width 0.5 \
    --black-width 2 --black-color 0,0,0,1 --join round --sliding 2.5 \
    --dpi 600 --balance raster --overprint simulate --max-depth 4
input: target\tmp\roomy.pdf  pages: 1  page: 612x792 pt
preset: Press  trap: 0.5 pt  black: 2 pt cmyk(0,0,0,1)  join: round  sliding: limited(2.5)
flatten: 600 dpi  balance: prefer-raster  overprint: simulate  depth: 4  bits: 425
needs-backend-prepress: true  warnings: 4
warning: custom CMYK trap colour requires a backend colour transform
warning: sliding traps require backend geometry analysis of adjacent inks
warning: simulated overprint during flattening requires backend compositing
warning: raster-biased flattening requires a rasterizer at 600 DPI
EXIT=0
```

Rejections:

```text
> prepress plan ... --dpi 10
Error: flattening policy: flatten resolution 10 must be in 72..=2400 DPI

> prepress plan ... --trap-width 0
Error: trapping preset: trap width 0 must be finite, in (0.0..=12] points

> prepress plan ... --preset "   "
Error: trapping preset: trapping preset name must not be empty

> prepress plan ... --black-color 2,0,0,0
Error: trapping preset: trap colour component 'c' must be finite and in 0.0..=1.0, got 2

> prepress plan ... --sliding=-1
Error: trapping preset: sliding distance -1 must be finite and in 0.0..=24 points

> prepress plan ... --max-depth 0
Error: flattening policy: flatten depth 0 must be in 1..=32

> prepress plan ... --join star
Error: --join must be miter, round or bevel

> prepress plan <not a PDF>
Error: parse ...: ...
```

## Scope

Preset/policy validation and plan resolution against a real document. The
module's documented backend boundary still applies: no trap painting, no
sliding-trap geometry, no CMYK transform for a custom trap colour, no overprint
compositing and no rasterization of transparent groups. The host reports those
requirements instead of approximating them. The app-level fit/scaling math on
the same row is unchanged.
