# T-0344 — CMS signature host (`SEC-005`)

Row promoted: `SEC-005` (Sign and certify documents) `library` -> `verified`.

`pdfxi_security::pdf_signature` already produced and verified a real CMS
`SignedData` over a PDF `/ByteRange`, but the row noted "no GUI caller yet".
This task adds the caller: `pdfxi sign create` / `pdfxi sign verify` operate on
real files with a caller-supplied PEM or PKCS#12 identity and fail closed.

## 1. Host

```text
pdfxi sign create FILE --out PATH (--key KEY.pem --cert CERT.pem [--chain CHAIN.pem] | --pfx ID.p12)
    [--password PW] [--page N] [--field NAME] [--reason TEXT] [--location TEXT]
    [--time UNIX] [--reserve BYTES] [--json]
pdfxi sign verify FILE [--json]
```

- `create` loads the identity (PEM key + certificate chain, or a
  password-protected PKCS#12 container), signs an incremental revision with
  `sign_pdf`, and **verifies its own output before writing**; a signature that
  fails the full badge is never persisted.
- `verify` runs `verify_signature` and reports status, signature validity, byte
  match, whole-file coverage, appended bytes, signer subject and SHA-256
  fingerprint, digest, `/SubFilter` and `/ByteRange`. It exits non-zero unless
  the signature is fully valid, and never reports certificate trust as `true`
  when the trust store was not evaluated (`chain_trusted` is `null`).
- Key material and passwords are never printed, logged or embedded in errors.
  The field name defaults to `Signature1`; `--page` is one-based.

Tampering and truncation are reported, not accepted:

```text
> (flip one byte inside the signed range: "(PostScript" -> "(XostScript")
> pdfxi sign verify target\tmp\tampered.pdf --json
"status": "tampered", "fully_valid": false, "signature_valid": true,
"bytes_match": false, "covers_entire_file": true
Error: signature is not fully valid: status tampered (signature true, digest false, whole-file true)
TAMPER_EXIT=1

> (append "% appended after signing")
> pdfxi sign verify target\tmp\appended.pdf --json
"status": "valid", "fully_valid": false, "signature_valid": true,
"bytes_match": true, "covers_entire_file": false, "appended_after_signature": true
Error: signature is not fully valid: status valid (signature true, digest true, whole-file false)
APPEND_EXIT=1

> pdfxi sign verify target\tmp\ps-src.pdf
Error: verify target\tmp\ps-src.pdf: no PDF signature was found
```

Rejections:

```text
> pdfxi sign create ... (no identity)
Error: supply an identity with --key/--cert or with --pfx
> pdfxi sign create ... --page 0
Error: --page is one-based and must be at least 1
> pdfxi sign create ... --page 9
Error: --page 9 is outside target\tmp\ps-src.pdf (the document has 1 page(s))
```

## 3. Tests

```text
> cargo test -p pdfxi-cli sign_
sign_creates_a_cms_signature_and_verifies_it ... ok
sign_rejects_bad_identity_options_and_unsigned_input ... ok
test result: ok. 2 passed
```

The tests generate a fresh self-signed 2048-bit RSA identity at runtime (never
committed), sign a real PDF, assert the JSON report, reparse the signed bytes
with the core reader, verify the signature, then assert that a flipped covered
byte reports `tampered` / `bytes_match: false` and that appended bytes report
`valid` with `covers_entire_file: false`, both exiting non-zero. The second test
covers a missing identity, a `--pfx`/PEM conflict, one-based and out-of-range
pages, an unsigned input and a malformed PEM key.

## Scope

Detached CMS signatures and their structural/cryptographic verification. No
certificate trust, revocation or timestamp evaluation (`SEC-006`/`SEC-007`),
no certification-signature permission enforcement, no long-term validation and
no visible signature appearance beyond the standard invisible widget. A
self-signed test identity is generated only inside the tests.
