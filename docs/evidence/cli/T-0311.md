# T-0311 — plugin execution plan host (`AUTO-008`)

Row promoted: `AUTO-008` (WASM plugin host)
`model` -> `verified`.

The row delivered the manifest/invocation model, typed bounded outputs and a
deterministic non-executing plan; a WASM runtime stayed out of scope. This task
adds the user-facing plan/output surface.

## 1. Hosts

```text
pdfxi plugin plan <MANIFEST> --operation NAME [--grant CAP ...] [--expect TYPE]
    [--max-steps N] [--max-memory-bytes N] [--max-wall-clock-ms N]
    [--max-text-bytes N] [--max-bytes N] [--max-total-bytes N] [--json]

pdfxi plugin output --type TYPE [--text T|--text-len N|--int N|--bool B|--bytes-len N]
    [--expect TYPE] [--plugin-id ID] [--operation NAME]
    [--max-text-bytes N] [--max-bytes N] [--max-total-bytes N] [--json]
```

- `plan` parses a real manifest file (`PluginManifest::parse_json`), registers
  it, builds a deny-by-default `CapabilityGrants` from `--grant`, maps the
  budget flags to `InvocationBudget`, and calls `build_execution_plan`.
- The plan prints the six fixed steps (registration, api_version, capabilities,
  budgets, output_budget, execute) with sorted deny codes and a stable summary.
  It executes no plugin code and performs no I/O beyond reading the manifest.
- A denied plan prints its report and exits `2`.
- `output` builds one `PluginValue` (text, text length, integer, boolean, or
  opaque bytes length), creates `PluginOutput`, and validates type and size
  against `OutputBudget`.

## 2. Evidence

```text
> pdfxi plugin plan target\tmp\plugin.json --operation extract --grant document-text
plugin: text.plugin  Text helper  v1.0.0  api 1
capabilities: document-text
plan: extract  expect text  allowed
  registration: allow
  api_version: allow
  capabilities: allow
  budgets: allow
  output_budget: allow
  execute: allow
```

Without the grant:

```text
> pdfxi plugin plan target\tmp\plugin.json --operation extract
plan: extract  expect text  denied
  registration: allow
  api_version: allow
  capabilities: deny(capability_not_granted)
  budgets: allow
  output_budget: allow
  execute: deny(upstream_denied)
exit code: 2
```

A forbidden manifest capability is rejected:

```text
> pdfxi plugin plan ... (capabilities ["filesystem"])
Error: invalid manifest ...: capability ...
```

Typed outputs:

```text
> pdfxi plugin output --type text --text hello --json
{
  "plugin_id": "host.plugin",
  "operation": "output",
  "ty": "text",
  "expected": "text",
  "encoded_len": 5,
  "value": "hello",
  "summary": "host.plugin\toutput\ttext",
  "valid": true
}

> pdfxi plugin output --type text --text-len 70000
Error: plugin output: plugin text output is 70000 bytes; maximum is 65536

> pdfxi plugin output --type text --text hello --expect int
Error: plugin output: plugin output type 'text' does not match expected type 'int'
```

## 3. Tests

```text
> cargo test -p pdfxi-cli --test cli plugin_
test plugin_plan_reports_capability_and_budget_gates ... ok
test plugin_output_validates_types_and_budgets ... ok
test result: ok. 2 passed
```

- The plan test checks manifest metadata, six ordered steps, all-allow with a
  grant, byte-identical repeated JSON, the denied capability/`upstream_denied`
  codes and exit 2, an over-limit invocation budget, a zero output budget
  denying `invalid_budget`, a forbidden manifest capability, malformed JSON and
  a missing manifest.
- The output test covers text/int/bool/bytes/null values, encoded lengths and
  summaries, type mismatch, oversized text and bytes, empty text, empty plugin
  id and a missing value.

## Scope

No WebAssembly is loaded, compiled, or executed; the plan is the host gate and
the output validator is the ABI boundary. Capabilities are the closed four-item
set; filesystem/network/process names are rejected at parse time.
