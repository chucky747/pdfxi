# T-0330 — System speech host (`ACCESS-005`)

Row promoted: `ACCESS-005` (Read aloud with system speech) `model` ->
`verified`.

The model (`pdfxi_app::read_aloud`) already produced deterministic timed
utterances behind a `SpeechSink` boundary, and its notes recorded that "system
speech is host-implemented". This task implements that host on the existing
`pdfxi read-aloud` command so a user can list real installed voices and hear the
document through Windows `System.Speech`.

## 1. Host

```text
pdfxi read-aloud <INPUT.pdf> [--wpm 180] [--page N] [--seek N]
    [--voice NAME] [--speak] [--json]
pdfxi read-aloud --voices [--json]
```

- `--voices` enumerates `SpeechSynthesizer.GetInstalledVoices()` and prints the
  names (JSON: `{"voices": [...]}`).
- `--speak` joins the planned sentences and calls `Speak` on the synthesizer
  with `--voice` (default: the system voice) and
  `Rate = clamp((wpm - 180) / 20, -10, 10)`.
- The plan itself is unchanged: integer-millisecond start/duration/pause from
  `--wpm`, `--seek` rebases the clock, `--page` filters.
- Voice names are rejected when empty, control-bearing or containing `'`, so a
  hand-typed value cannot inject PowerShell. The text is passed on stdin.
- `--json` now includes `"spoken": true|false`.

## 2. Evidence

```text
> pdfxi read-aloud --voices --json
{
  "voices": [
    "Microsoft David Desktop",
    "Microsoft Zira Desktop"
  ]
}

> pdfxi read-aloud --voices
Microsoft David Desktop
Microsoft Zira Desktop
voices: 2

> pdfxi read-aloud target\tmp\speech.pdf --wpm 400 --speak --voice "Microsoft Zira Desktop"
utterance 0  page 1  0-525 ms  3 words
  Read aloud verification.
total: 1 utterance(s), 525 ms at 400 wpm
spoken: yes (system speech)
EXIT=0 elapsed_ms=1878

> pdfxi read-aloud target\tmp\speech.pdf --wpm 400 --speak --json
"wpm": 400,
"total_duration_ms": 525,
"spoken": true,
EXIT=0
```

The 1.9 s wall time is PowerShell start-up plus real synthesis; no audio is
written to disk and nothing plays without `--speak`.

Rejections:

```text
> pdfxi read-aloud --voices FILE.pdf
error: the argument '--voices' cannot be used with '[FILE]'

> pdfxi read-aloud
Error: pass a PDF file or --voices

> pdfxi read-aloud FILE.pdf --voice "Bad'Voice"
Error: --voice "Bad'Voice" contains a control character or quote
```

## Scope

Windows `System.Speech` only (the command errors on other platforms). Voice
pitch/volume, SSML markup, word highlighting and mid-speech cancellation are not
exposed; the existing `SpeechSink` model still owns playback state for a GUI
host. The plan is still the deterministic queue, not a streaming engine.
