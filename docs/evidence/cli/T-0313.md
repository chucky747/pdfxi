# T-0313 — searchable OCR layer host (`CREATE-008`)

Row promoted: `CREATE-008` (OCR scanned pages to searchable PDF)
`model` -> `verified`.

The row validated caller-supplied OCR results and planned invisible word
positions, but had no writer. This task supplies a JSON-backed engine and writes
the invisible layer over the real image.

## 1. Host

```text
pdfxi create ocr <PAGE.png|jpg> --out PDF --words WORDS.json
    [--dpi 300] [--language TAG] [--json]
```

```json
{ "language": "eng",
  "words": [ { "text": "Hello", "x": 10, "y": 20, "width": 40, "height": 14,
               "confidence": 95 } ] }
```

- Reads the image header for width/height, validates the words JSON, and builds
  a grayscale `OcrImage` (bounded to 64M pixels) for the model.
- `JsonEngine` implements `OcrEngine`, returning the supplied words; the
  pipeline sorts them, filters by the default confidence policy, and maps boxes
  to PDF points.
- Embeds the image at `pixels / dpi * 72` points with zero margins, then appends
  a content stream using `BT 3 Tr … Tj ET` (invisible render mode), a Helvetica
  resource `FOcr`, and each word at its planned position and height.
- Saves, reopens, extracts the page text, and requires every kept word to be
  found. `--json` reports kept/rejected/suspect counts, empty pages, plan
  summary, page size, verified words, extracted characters and bytes.

```text

  "image": "target\\tmp\\ocr-page.png",

  "engine": "json-words",
  "pages": 1,
  "kept": 1,
  "rejected": 1,
  "suspect": 0,
  "empty_pages": [],

  "page_width": 2.0,

> pdfxi text target\tmp\ocr.pdf

> pdfxi info target\tmp\ocr.pdf
```

The low-confidence word is rejected; the saved bytes contain `3 Tr` and
`(Hi) Tj`, proving the layer is invisible.

Rejections:

```text
> ... --words missing.json
Error: read words target\tmp\missing.json

> ... --language " "
Error: ocr pipeline: invalid OCR options: language tags must not be blank

> ... --dpi 0
Error: ocr image: OCR image DPI 0 is outside 1..=2400

> ... word with width -1
Error: ocr pipeline: invalid box on page 0: box must be finite with non-negative extent
```

## 3. Tests

```text
> cargo test -p pdfxi-cli --test cli create_ocr
test create_ocr_overlays_invisible_searchable_text ... ok
test create_ocr_rejects_bad_words_and_inputs ... ok
test result: ok. 2 passed
```

- The first checks the report counters, `3 Tr`/`(Hi) Tj`/`FOcr` bytes, extracted
  `Hi`, and byte-identical repeated output.
- The second checks empty word lists, blank text, a negative box, malformed JSON,
  a blank language tag, DPI 0, an unsupported image extension and a missing
  image.

## Scope

No OCR engine or process is bundled: the words file is the recognition result,
and producing it (Tesseract sidecar or another backend) remains the caller's
adapter. One image page per command, Latin-1 text in the invisible layer, and no
deskew, rotation detection, or language auto-detection.
