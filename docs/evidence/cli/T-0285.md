# T-0285 — `pdfxi optimize`: the optimizer's host boundary

Row promoted: `EDIT-014` (Optimize and compress documents) `library` -> `verified`.

## What ships

The row was at `library`: `Document::optimize(&OptimizeOptions,
&CancellationToken) -> Result<OptimizationResult>` was complete and tested, but
nothing a user could reach ran it. This task adds the CLI host:

```text
pdfxi optimize <FILE> --out <PATH> [--remove-metadata] [--remove-optional] [--no-compress] [--json]
```

- Loads the document, runs the optimizer with a fresh `CancellationToken`, writes
  the standalone result and prints the deterministic report.
- `--out` is required and self-overwrite is refused after canonicalising both
  paths, so a failed run cannot destroy the source. The refusal test also
  re-reads the input and asserts the bytes are unchanged.
- `--remove-metadata` clears `/Info` and the catalog `/Metadata` stream;
  `--remove-optional` clears `/Thumb` and `/PieceInfo`; `--no-compress` keeps
  streams uncompressed. Everything else stays at `OptimizeOptions::default()`
  (dedup, unreachable removal, renumbering, beneficial Flate).
- Text output prints the real signed size change (`-0.7%`), object counts, stream
  and image counters, and every optimizer warning. `--json` emits the same values
  with stable names, including `saved_bytes = bytes_after - bytes_before`.

## Real-document evidence

```text
> pdfxi optimize fixtures\realworld\powerpoint-slides.pdf --out target\tmp\slides-optimized.pdf
file: fixtures\realworld\powerpoint-slides.pdf
out:  target\tmp\slides-optimized.pdf
bytes: 119341 -> 118516 (-0.7%)
objects: 68 -> 65
streams compressed: 1
images passed through: 0
deduplicated: 2
removed: 1
warnings: 10
  object 17: stream already Flate-compressed; left unchanged
  ...

> pdfxi info target\tmp\slides-optimized.pdf
file: target\tmp\slides-optimized.pdf
pdf_version: 1.7
bytes: 118516
pages: 3
```

The optimized file reopens with the same three pages, and the extracted text of
every page is byte-identical to the source:

```text
> pdfxi text source.pdf > src.txt ; pdfxi text optimized.pdf > opt.txt
> Compare-Object (Get-Content src.txt) (Get-Content opt.txt) | Measure-Object
text_diffs=0
```

Metadata removal works on the real fixture, which carries both `/Info` and an
XMP `/Metadata` stream:

```text
> pdfxi optimize fixtures\realworld\powerpoint-slides.pdf --out target\tmp\slides-nometa.pdf --remove-metadata --json
  "bytes_before": 119341,
  "bytes_after": 117445,
  "saved_bytes": -1896,

> Select-String target\tmp\slides-nometa.pdf   (raw scan)
metadata_hits=0     # baseline optimized file: baseline_hits=3
```


`optimize_json_report_is_deterministic_and_consistent` runs the command twice and
asserts the two JSON reports are byte-identical, that `bytes_before` equals the
source file length, that `bytes_after` equals the written file length and that
`objects_after <= objects_before`.

`optimize_remove_metadata_clears_info_and_xmp` first proves the fixture really
carries metadata (`Document::info`/`xmp_metadata`), then asserts both are gone
from the optimized output while the page count is unchanged.

## Scope

Compression remains per stream with a strict no-growth policy, so the whole file
can still grow slightly after renumbering; the report prints the real change
rather than promising a shrink. Image re-encoding ("downsample images") is not
part of the optimizer and is not claimed here.
