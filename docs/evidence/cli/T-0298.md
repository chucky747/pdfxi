# T-0298 — accessibility and PDF/UA checker host (`ACCESS-003`)

Row promoted: `ACCESS-003` (Accessibility and PDF/UA checker)
`model` -> `verified`.

The accessibility crate already had a deterministic rule checker and fix plan,
and `pdfxi-standards` had the PDF/UA-1 profile. Neither was reachable on real
files from the CLI. This task adds one command that runs both and merges the
reports.

## 1. Host

```text
pdfxi accessibility check <FILE> [--title TEXT] [--lang TAG] [--json]
```

- Builds an `A11yTree` from the document's recovered page text (document root,
  one page node per page, one paragraph node per non-empty line) and runs
  `pdfxi_accessibility::checker::check` with the document title, catalog `/Lang`
  and page count. `--title`/`--lang` override those two checker inputs.
- Builds a prioritized `FixPlan` from the findings and prints its steps.
- Runs `pdfxi_conformance`'s byte-level adapter with the `PDF/UA-1` profile,
  which reads the real catalog, `/MarkInfo`, `/StructTreeRoot`, language, title,
  annotations and structure facts through `pdfxi-core`.
- Merges both finding sets, counts errors/warnings, and exits `2` when either
  check reports an error, `0` otherwise. `--json` emits both sources with stable
  `UA-nnnn` / `PDFUA1.*` codes.
- The report always carries `certification_claimed: false` and a scope note,
  because the tree is derived from text and no external validator certifies it.

## 2. Evidence

```text
> pdfxi accessibility check fixtures\minimal.pdf
file: fixtures\minimal.pdf
pages: 1
paragraphs: 1
[error] tree/UA-0001 The document has no title; PDF/UA requires a title in the document information dictionary.
[error] tree/UA-0002 The document has no /Lang entry; assistive technology needs a natural language tag.
[error] pdfua/PDFUA1.NOT_MARKED tagged PDF requires /MarkInfo with /Marked true (Catalog /MarkInfo)
[error] pdfua/PDFUA1.NO_LANG the document language (/Lang) is required (Catalog /Lang)
[error] pdfua/PDFUA1.NO_STRUCT_TREE_ROOT tagged PDF requires a /StructTreeRoot (Catalog /StructTreeRoot)
fix: UA-0002 Set the catalog /Lang entry to a valid language tag such as 'en-US'.
errors: 5
warnings: 0
valid: false
certification_claimed: false
scope: The accessibility tree is derived from recovered page text; the PDF/UA-1 profile checks the file's real catalog and structure. No conformance certification is claimed.
(exit code 2)
```

With checker overrides the two tree findings disappear, the real PDF/UA
structure findings remain:

```text
> pdfxi accessibility check fixtures\minimal.pdf --title "Minimal" --lang en-US
title: Minimal
lang: en-US
[error] pdfua/PDFUA1.NOT_MARKED ...
[error] pdfua/PDFUA1.NO_LANG ...
[error] pdfua/PDFUA1.NO_STRUCT_TREE_ROOT ...
errors: 3
valid: false
(exit code 2)
```

`PDFUA1.NO_LANG` still appears because the profile reads the file's catalog,
which the overrides do not modify.

A form PDF created by `pdfxi form create` is also accepted: it reports one page,
the missing-title finding and the PDF/UA structure errors.

The first test asserts exit code `2`, `valid:false`, the presence of `UA-0001`,
`UA-0002`, `PDFUA1.NO_STRUCT_TREE_ROOT`, at least one `pdfua` finding, a
non-empty fix plan, byte-identical repeated output, override behavior (`UA-*`
metadata findings gone, PDF/UA findings retained), and exit code `1` for a
missing file. The second runs the command on a real generated form PDF.

## Scope

The checker and PDF/UA-1 profile are reachable on real bytes with a fix plan.
The accessibility tree is derived from recovered page text because the
accessibility crate models a tree rather than reading `/StructTreeRoot`; the
file's real structure is checked by the embedded PDF/UA-1 profile. Certificate
authority and veraPDF-style external validation remain out of scope.
