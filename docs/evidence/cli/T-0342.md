# T-0342 — Signature field workflow host (`FORMS-010`)

Row promoted: `FORMS-010` (Electronic signature fields and workflows) `model` ->
`verified`.

The field model, placeholder contract and byte-range planning already existed in
`pdfxi-forms` (with `SignatureLifecycle` and `StructureOnlyVerifier`), but no
host produced or consumed a real file. This task adds `pdfxi signature`:

- `create`: a real one-page PDF with a contract-checked `/FT /Sig` field and a
  `/Contents` placeholder;
- `plan`: the exact `/ByteRange` and byte count a signer must cover;
- `verify`: structure-only verification of caller-supplied signature bytes.

No cryptography is performed; the authenticated-signature path remains with the
security lane.

## 1. Host

```text
pdfxi signature create --out FILE [--field NAME] [--signer NAME] [--reason TEXT]
    [--location TEXT] [--rect x,y,w,h] [--placeholder-bytes N] [--json]
pdfxi signature plan FILE [--json]
pdfxi signature verify FILE --contents HEX [--json]
```

- `create` builds `SignatureField` + `SignaturePlan`, serializes through
  `serialize_form_pdf` (page object 5), sets `/V /Contents` to a zero literal of
  `N` characters and swaps its delimiters to `<...>` in place, so the xref
  offsets are unchanged. It reparses the result, reloads the AcroForm and
  requires the `/Sig` field, then writes it.
- `plan` finds `/Contents <hex>`, calls `plan_byte_range`, validates it and
  reports `[a b c d]`, the covered byte count, placeholder size and the
  `/Filter`/`/SubFilter` read from the file.
- `verify` computes the same plan, reconstructs `signed_bytes`, rejects an
  all-zero placeholder, and runs `StructureOnlyVerifier` on the covered bytes
  and provided hex. It always reports `authenticity: structure-only`.

## 2. Evidence

```text
> pdfxi signature create --out target\tmp\sig.pdf --signer "Ada Lovelace" \
    --reason "Approval" --location "London"
out: target\tmp\sig.pdf  bytes: 9030  field: Signature1  placeholder: 8192 hex chars
signature: Digitally signed by Ada Lovelace; Reason: Approval; Location: London
rect: [72, 72, 240, 48]  reloaded: true
EXIT=0

> pdfxi signature plan target\tmp\sig.pdf
file: target\tmp\sig.pdf
byte-range: [0, 302, 8496, 534]  signed-bytes: 836
placeholder: 8192 hex chars  filter: Adobe.PPKLite  subfilter: adbe.pkcs7.detached
EXIT=0

> pdfxi signature verify target\tmp\sig.pdf --contents deadbeef01020304 --json
"field": "Signature1", "filter": "Adobe.PPKLite",
"subfilter": "adbe.pkcs7.detached",
"valid": true, "authenticity": "structure-only",
"detail": "structure-ok:Adobe.PPKLite:adbe.pkcs7.detached:836:8",
"byte_range": [0, 302, 8496, 534], "contents_bytes": 8
EXIT=0
```

The generated PDF is a real 9,030-byte document that the core reader parses and
reports one page for.

Rejections:

```text
> signature verify ... --contents 0000
Error: --contents is all zero bytes: this is an unsigned placeholder, not a signature

> signature create --rect 600,700,100,100
Error: --rect is outside the 612x792 page

> signature create --placeholder-bytes 1001
Error: signature plan: ... placeholder size 1001 is not an even number of hex digits

> signature plan <plain text PDF>
Error: /Contents placeholder not found

> signature verify <plain PDF> --contents xyz
Error: --contents must be a non-empty hex string
```

## 3. Tests

```text
> cargo test -p pdfxi-cli signature_
signature_create_plans_and_verifies_a_real_field ... ok
signature_create_rejects_bad_rects_and_sizes ... ok
signature_plan_rejects_documents_without_a_placeholder ... ok
test result: ok. 3 passed
```

The first creates and parses the PDF with the core reader, asserts the field,
placeholder size and reload, plans a four-element range with a positive signed
byte count and the expected filter/subfilter, verifies synthetic bytes with
structure-only authenticity, and rejects the zero placeholder. The others cover
off-page/odd-size/bad rectangles and documents without a placeholder.

## Scope

Field creation, byte-range planning and structure-only verification. No
cryptography, hashing, key/certificate handling, timestamping or revocation
(security lane), no byte-range patching of a completed signature into the file
and no workflow UI. `verify` never presents a structure-only result as an
authentic signature.
