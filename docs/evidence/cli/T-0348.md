# T-0348 — Digital-ID catalog host (`SEC-004`)

Row promoted: `SEC-004` (Digital IDs and certificate management) `model` ->
`verified`.

The digital-ID lifecycle (`PrivateKeyPkcs8`, `KeyCertificatePair`,
`DigitalIdLifecycleStore`) was complete but had no caller. This task adds
`pdfxi id`, which validates real PKCS#12 or PEM identities and keeps a
metadata-only catalog.

## 1. Host

```text
pdfxi id inspect --label L (--pfx ID.p12 [--password PW] | --key KEY --cert CERT)
    [--time UNIX] [--json]
pdfxi id import --store FILE --label L (identity) [--time UNIX] [--json]
pdfxi id list --store FILE [--time UNIX] [--json]
pdfxi id remove --store FILE --label L [--json]
```

- `inspect` validates one identity and reports subject, issuer, serial,
  fingerprint, key algorithm OID, validity window and validity at `--time`.
- `import` validates the identity, re-imports it through
  `DigitalIdLifecycleStore`, and writes a **metadata-only** catalog entry
  (label, subject, issuer, serial, SHA-256 fingerprint, key OID, validity
  bounds, import time, source path). The private key is never copied into the
  catalog and never printed. A certificate already catalogued under another
  label is rejected; re-importing the same label replaces the entry.
- `list` shows entries sorted by label with validity recomputed at `--time`; a
  missing catalog file is an empty catalog.
- `remove` deletes one entry and reports the remaining count.
- Labels are bounded and reject control characters and path separators; the
  catalog is bounded to 64 entries, version-checked on load, and written through
  a temporary file.

Identity sources: a password-protected PKCS#12 container (`pkcs12::import_pfx`),
or a PEM/DER PKCS#8 private key plus a PEM/DER certificate. PKCS#8 PEM decoding
is now available to callers as
`pdfxi_security::private_key_der_from_pem`.

> id inspect --label X --pfx ... --key ... --cert ...

The first generates a self-signed RSA identity at runtime (never committed),
inspects it, imports it twice into a fresh catalog, asserts the catalog file has
no `PRIVATE KEY` bytes, lists it as valid and later expired, rejects the same
certificate under another label, removes it and rejects a second removal. The
second covers a missing identity, a `--pfx`/PEM conflict, an unsafe label, a
garbage key and an empty catalog.

## Scope

Identity validation and a metadata catalog. The catalog deliberately stores no
private key: it records where the identity lives and what the certificate says.
This is not a key vault, does not manage OS certificate stores or hardware
tokens, and does not make the catalog confidential — the certificate metadata is
public information. PKCS#12 parsing supports the containers `pkcs12::import_pfx`
accepts; PEM support is PKCS#8 (`PRIVATE KEY`) with a certificate.
