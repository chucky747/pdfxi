# T-0346 — Print-production host (`PRINT-008`)

Row promoted: `PRINT-008` (Droplets hot folders and batch preflight)
`model` -> `verified`.

The droplet runner, hot-folder poller and byte-level preflight already exist
(`pdfxi droplet`, `pdfxi watch`, `pdfxi preflight`). The remaining half of the
row was the print-production planner from `pdfxi_app::print`: marks, bleed,
separations and the output-intent report had no host. This task adds
`pdfxi production`, which resolves a real `ProductionPlan` and applies it to a
document.

## 1. Host

```text
pdfxi production plan INPUT [--bleed V|T,R,B,L] [--marks LIST] [--separation NAME:KIND ...]
    [--intent SUBTYPE|NAME|REGISTRY|INTENT] [--json]
pdfxi production apply INPUT --out PATH [same options] [--json]
```

- `plan` reads page 1's TrimBox and MediaBox, builds
  `ProductionPlan::build(trim, sheet, options)` and reports the resolved mark
  count, bleed rectangle, canonical separations (process inks first), the
  output-intent summary and warnings.
- `apply` rebuilds the plan **per page** (mixed-size documents work), writes the
  resolved `/BleedBox` through `Document::set_page_boxes`, paints the requested
  printer-mark families with the core API, saves, reparses and only then writes
  the output. A page whose sheet leaves no room for the requested marks is a
  typed error instead of a silently clipped mark.
- `--bleed` accepts one value or `T,R,B,L`; the model caps it at 72 pt.
- `--marks` accepts `crop`, `registration`, `colour-bars`, `page-info`, `all` or
  `none`.
- `--separation NAME:process|NAME:spot` is repeatable; with none supplied the
  four process inks are planned.
- `--intent` is at most one intent (`pdfx`, `pdfa` or `iccbased`) with a bounded
  name/registry and a supported rendering intent.
- Droplets, hot folders and batch preflight remain `pdfxi droplet`,
  `pdfxi watch` and `pdfxi preflight`.

The written page carries an explicit `/BleedBox` of `[27 27 585 765]` (the trim
box `[30 30 582 762]` expanded by 3 pt) and the painted `PdfxiMarks` form.

Rejections:

```text
> production plan ... --bleed 100
Error: production plan: invalid geometry: bleed must be within 0..=72 pt

> production plan ... --bleed=-1
Error: --bleed values must be finite and non-negative

> production plan ... --marks sparkle
Error: unknown mark family "sparkle"; expected crop, registration, colour-bars, page-info, all or none

> production plan ... --separation Cyan
Error: separation "Cyan" needs NAME:process or NAME:spot

> production plan ... --intent "pdfx|Name|Registry|sepia"
Error: production plan: invalid output intent: unsupported rendering intent sepia

> production plan ... --intent "bogus|Name|Registry|perceptual"
Error: unknown output-intent subtype "bogus"; expected pdfx, pdfa or iccbased

> production apply <no-bleed-margin PDF> --marks crop
Error: production plan: invalid geometry: crop mark does not fit on the sheet
```

## Scope

Plan resolution and application: explicit `/BleedBox`, painted printer marks,
canonical separations and the output-intent decision. No raster proof, real CMM
ICC validation, trapping, imposition or plate output; those remain separate
rows. The marks painted here are the core printer marks, not the planner's
rectangle list (the list is reported as the resolved plan).
