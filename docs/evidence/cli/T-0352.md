# T-0352 — Presentation-mode host (`VIEW-012`)

Row promoted: `VIEW-012` (Full screen and presentation mode) `model` ->
`verified`.

The row's own boundary note says the model is complete and only the host is
missing: "The host supplies `tick` seconds and commands and translates
`PresentationOutcome`/`FullscreenLayout` into effects." This task supplies that
host headlessly, so presentation mode is reachable without a window.

## 1. Host

```text
pdfxi present FILE [--commands next,prev,...] [--screen WxH] [--fit fit|actual]
    [--duration SEC] [--transition none|fade|push] [--slides PAGES] [--json]
```

- The document is parsed; a document with no pages is rejected. By default every
  page becomes a manual slide in document order. `--slides 1,3,5` selects a
  strictly increasing subsequence; `--duration` and `--transition` apply to
  every slide.
- `--commands` is a comma-separated sequence:
  - `next`, `prev`, `first`, `last`, `auto`, `exit`;
  - `key:space|right|left|home|end|escape|a`, mapped through
    `map_presentation_key`;
  - `gesture:swipe-left|swipe-right|long-press`, mapped through
    `map_presentation_gesture`;
  - `tick:SECONDS`, supplying the clock to `PresentationModel::tick`.
- Every step reports the outcome (`page_changed:<index>`,
  `auto_advance_started`, `finished`, `exited`, …), the active slide index and
  one-based page, the auto-advance state, and the full-screen layout for the
  active page's real media size.
- `--screen` defaults to 1280x720; `--fit` is `fit` (letterboxed uniform scale)
  or `actual` (1:1, centred). The final layout is reported too.

No window, native key/swipe capture, timer thread, slide rendering or animation
is involved; those remain the GUI host's responsibility, exactly as the row
documents.

## 2. Evidence

```text
> pdfxi present target\tmp\pages3.pdf --commands next,next,prev,first,last,key:escape --json
"outcome": "page_changed:1", "page_changed:2", "page_changed:1",
           "page_changed:0", "page_changed:2", "exited"
"final_index": 2, "final_page": 3, "final_state": "exited", "exited": true
(final page 3 is 400x400 on 1280x720: scale 1.8, 720x720 at x=280, y=0)

> pdfxi present target\tmp\pages3.pdf --slides 1,3 --duration 2 --transition fade \
    --commands auto,tick:2.5,tick:2.5
input: target\tmp\pages3.pdf  pages: 3  slides: 2  screen: 1280x720  fit: fit
auto -> auto_advance_started  slide 0 page 1  playing
tick:2.5 -> page_changed:1  slide 1 page 3  playing
tick:2.5 -> finished  slide 1 page 3  finished
final: slide 1  page 3  state: finished  exited: false
layout: x=280 y=0 720x720 scale=1.8
EXIT=0

> pdfxi present target\tmp\roomy.pdf --screen 800x600 --fit actual --commands first
final: slide 0  page 1  state: stopped  exited: false
layout: x=94 y=-96 612x792 scale=1
EXIT=0
```

Rejections:

```text
> present ... --commands sideways
Error: unknown presentation command "sideways"

> present ... --commands key:f13
Error: unknown presentation key "f13"

> present ... --commands gesture:pinch
Error: unknown presentation gesture "pinch"

> present ... --commands tick:x        -> Error: tick value "x" is not a number
> present ... --commands tick:-1       -> Error: tick seconds must be finite and non-negative
> present ... --screen wide            -> Error: --screen "wide" needs WxH
> present ... --screen 0x720           -> Error: --screen needs finite positive dimensions
> present ... --fit stretch            -> Error: unknown fit mode "stretch"
> present ... --transition spin        -> Error: unknown transition "spin"
> present ... --slides 0 / 4           -> Error: --slides page ... is outside 1..=3
> present ... --slides 3,1 / 1,1       -> Error: --slides pages must be strictly increasing
> present <not a PDF>                  -> Error: parse ...
```

then checks keyboard/gesture stepping and exit, the final 400x400 layout at
1280x720 (scale 1.8, 720x720, x 280), a two-slide fade presentation with
`auto` + two 2.5-second ticks that finishes, and 1:1 layout of a 612x792 page on
an 800x600 screen (x 94, y -96). The second covers every typed rejection above
plus a non-PDF input.

## Scope

The complete presentation state machine and layout are now user-reachable from
the CLI on real documents: slide order and subsequences, durations,
transitions, auto-advance with caller-supplied ticks, keyboard and gesture
mapping, exit semantics and full-screen layout. The OS full-screen window,
native event capture, timer thread, slide rendering and animation transitions
remain the GUI host boundary and are not claimed here.
