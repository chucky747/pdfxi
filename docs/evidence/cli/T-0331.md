# T-0331 — ICC colour host (`PRINT-003`)

Row promoted: `PRINT-003` (ICC color management and output intents) `model` ->
`verified`.

`pdfxi_render::color` already owned a bounded ICC parser, an `/OutputIntents`
model and an analytic conversion plan, but nothing exposed it to a user. This
task adds the `pdfxi color` command. (The same matrix row also carries the
booklet imposition model recorded by T-0150; that work and its tests are
unchanged.)

## 1. Dependency decision

`pdfxi-cli` previously pulled `pdfxi-render` only through the optional `pdfium`
feature. `pdfxi-render`'s default feature set is empty and its colour module is
pure Rust, so the dependency is now unconditional and `pdfium` keeps only
`pdfxi-render/pdfium`. No PDFium/native code enters the default CLI build.

## 2. Host

```text
pdfxi color icc <PROFILE.icc> [--json]
pdfxi color intents <INPUT.pdf> [--json]
pdfxi color convert <PROFILE.icc> [--space gray|rgb|cmyk] --values C1,C2,... [--json]
```

- `icc` parses a real profile and reports size, version, CMM, device class,
  data colour space, PCS, rendering intent, tag count, ASCII description, media
  white point and the analytic plan label.
- `intents` reads the catalog `/OutputIntents` array, resolves each entry,
  decodes its `/DestOutputProfile` stream (`/Filter` chain plus `/DecodeParms`),
  builds `OutputIntentSet`, reports set issues and parses the usable intent's
  profile.
- `convert` builds `ConversionPlan::from_profile`, wraps the components in
  `DeviceColor`, and returns PCS XYZ (RGB matrix/TRC), linear luminance (gray
  gamma) or the identity. `needs-backend` profiles return a typed error instead
  of an approximation.
- Components are validated to `0..=1`; unknown spaces and component-count
  mismatches are typed errors.

## 3. Evidence

Fixtures were produced from a synthetic RGB display profile (ADBE, v2.4,
`mntr`/`RGB `/`XYZ `, colourant matrix + gamma 2.2 TRCs, 8 tags) embedded
uncompressed in a one-page PDF as a `GTS_PDFX` intent.

Rejections:

> pdfxi color intents <plain text PDF>

## Scope

One analytic path: RGB matrix/TRC to PCS XYZ, gray gamma to linear luminance,
and identity. Full CMM rendering (LUTs, chromatic adaptation, multi-process
profiles), Lab transforms and CMYK conversion are reported as `needs-backend`
and remain a renderer-backend responsibility. No colour transform is applied to
page content, images or output streams, and no PDF is rewritten.
