# T-0310 — toolset host (`AUTO-007`)

Row promoted: `AUTO-007` (Custom toolsets and commands)
`model` -> `verified`.

The row parsed, validated and ran toolsets at library/API level but had no CLI
group. This task adds `pdfxi toolset` with list, validate, show and run.

## 1. Hosts

```text
pdfxi toolset list <FILE> [--json]
pdfxi toolset validate <FILE> [--json]
pdfxi toolset show <FILE> <ALIAS> [--json]
pdfxi toolset run <FILE> <ALIAS> --input PATH ... [--output-dir DIR] [--json]
```

- `list` reports the toolset name and every alias in sorted order with its
  action file, action name and sorted defaults.
- `validate` reparses the file and calls `Toolset::validate`; dangerous aliases
  (`shell`, `cmd`, `delete`, ...) are rejected before any run.
- `show` prints one alias or fails with the available alias list.
- `run`:
  - resolves a relative action file against the toolset's directory and rejects
    `..`/root components so an alias cannot escape;
  - loads the action, requires the named action to exist, and refuses any action
    containing a `Security` or `CustomCommand` step (mirroring the API);
  - applies the tool's defaults only to steps that lack the key, then delegates
    to the same staging executor and report shape as `action run`.

## 2. Evidence

```text
> pdfxi toolset list target\tmp\tools\tools.json
file: target\tmp\tools\tools.json
name: maintenance
daily	actions.txt	nightly	defaults: target=daily.pdf
danger	actions.txt	unsafe
tools: 2

> pdfxi toolset validate target\tmp\tools\tools.json --json
{
  "file": "target\\tmp\\tools\\tools.json",
  "name": "maintenance",
  "tools": 2,
  "valid": true
}

> pdfxi toolset show target\tmp\tools\tools.json daily --json
{
  "alias": "daily",
  "file": "actions.txt",
  "action": "nightly",
  "defaults": { "target": "daily.pdf" }
}
```

Running `daily` with a real input applies the default export target:

```text
> pdfxi toolset run target\tmp\tools\tools.json daily --input fixtures\minimal.pdf --output-dir target\tmp\tools\out --json
  "action": "nightly",
  "jobs": [{
    "state": "succeeded",
    "outcome": { "steps": [
      { "step_id": "load", "artifact_kind": "bytes", "artifact": "bytes(595)" },
      { "step_id": "save", "artifact_kind": "path",
        "artifact": "target\\tmp\\tools\\out\\daily.pdf" }
    ] }
  }]
```

Guards:


## Scope

`run` uses the existing staging executor: steps are validated and reported but
no PDF is written, matching `action run` and `droplet`. Toolset execution still
cannot launder Security or CustomCommand steps, and filesystem effects remain
the executor's responsibility.
