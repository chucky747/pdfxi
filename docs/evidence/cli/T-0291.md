# T-0291 — bookmark, link and attachment editing (`EDIT-011`)

Row promoted: `EDIT-011` (Bookmarks links and attachments editing)
`model` -> `verified`.

The editing *model* already shipped: `navigation::edit` addresses bookmarks by
`BookmarkPath` and edit verbs, `LinkStore` holds link annotations, and
`NameTree` adds/removes attachments. What was missing was a document writer and
a host. This task adds both.

## 1. Document writers (`pdfxi_edit::navigation`)

```rust
pub fn add_link(document, page_index, &Link) -> Result<StagedLink>
pub fn remove_link(document, page_index, index) -> Result<ObjectId>
pub fn add_attachment(document, name, file_name, description, mime, bytes)
    -> Result<StagedAttachment>
pub fn remove_attachment(document, name) -> Result<()>
```

- `add_link` builds a real `/Link` annotation (`/Rect`, `/H`, `/Border`, `/C`)
  and either `/A << /S /URI /URI ... >>`, `/A << /S /Named /N ... >>` or a
  `/Dest [page_reference /Fit ...]` array using the document's actual page
  object. The rectangle must be non-empty, a URI must not be blank, and a
  destination page or non-finite coordinate is rejected before staging.
- `remove_link` counts `/Link` annotations in page order, removes the selected
  one from a direct or indirect `/Annots` array, and leaves every other
  annotation in place.
- `add_attachment` stages an `/EmbeddedFile` stream (`/Params /Size`) and a
  `/Filespec` (`/F`, `/UF`, `/EF /F`, optional `/Desc`), then inserts it into
  the catalog `/Names /EmbeddedFiles` name tree. Existing entries are kept and
  re-sorted; duplicates are refused; the payload is capped at
  `MAX_ATTACHMENT_BYTES` (64 MiB).
- `remove_attachment` deletes the named tree entry and drops `/Names` when no
  entries remain.
- Writers read the current document through an effective reparse of the staged
  changes and allocate object ids in blocks, so several edits can be chained
  into one `save()`.
- New typed errors (`NavigationWriteError`) cover missing pages, out-of-range
  link indices, empty rectangles/URIs, non-finite coordinates, duplicate or
  missing attachments, oversized payloads and malformed name trees.

## 2. Hosts

```text
pdfxi outline list <FILE> [--json]
pdfxi outline add <FILE> --out PATH --title T --page N [--parent PATH] [--index N]
pdfxi outline rename <FILE> --out PATH --path PATH --title T
pdfxi outline move <FILE> --out PATH --path PATH [--parent PATH] [--index N]
pdfxi outline remove <FILE> --out PATH --path PATH
pdfxi link add <FILE> --out PATH --page N --rect x0,y0,x1,y1
    (--uri URL | --to-page N) [--highlight none|invert|outline|push] [--json]
pdfxi link remove <FILE> --out PATH --page N --index K [--json]
pdfxi attach add <FILE> --out PATH --attachment PATH [--name NAME]
    [--description D] [--mime TYPE] [--json]
pdfxi attach remove <FILE> --out PATH --name NAME [--json]
```

Paths are dotted child indices (`0.1`); page numbers are one-based. Every edit
saves a standalone document and then re-reads it, so the report is evidence from
the file.

## Scope

Bookmarks, links and document-level embedded files are reachable and round-trip
through a full save. The desktop bookmark/link panels remain app-level; the CLI
is the host claimed here. `/Link` borders use the model defaults (no interactive
border editor), and attachment bytes are edited by name rather than streamed.
