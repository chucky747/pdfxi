# T-0292 — incremental update host (`STD-010`)

Row promoted: `STD-010` (Incremental update and digital preservation)
`library` -> `verified`.

The row's notes already describe a working core incremental writer for classic,
hybrid and xref-stream sources, plus the preservation validator. The missing
piece was a user-reachable path. This task adds one.

## 1. Host

```text
pdfxi update <FILE> --out PATH
    [--title T] [--author A] [--subject S] [--keywords K] [--producer P] [--json]
```

At least one information field is required. The command reads the current
`/Info` dictionary, replaces the requested fields, stages it with
`Document::set_info`, calls `Document::save_incremental`, validates the result,
and only then writes `--out`. The report is produced from the validator and from
re-reading the saved bytes.

## 2. Preservation checks

- Classic and plain xref-stream sources are checked with
  `Document::validate_incremental` under
  `PreservationPolicy::minimal().with_page_text(true)`: exact byte prefix,
  `/Prev` chain, page count and every page's text.
- Files that already contain a hybrid `/XRefStm` section (Microsoft Office
  exports are typical) cannot be walked by that chain validator. For those the
  command verifies the exact byte prefix, the page count and every page's text
  directly and reports `xref_chain_verified: false` plus a `note` naming the
  hybrid section. It does not claim the chain check passed.

## 3. Evidence

Classic one-page fixture with full chain validation:

```text
> pdfxi update fixtures\minimal.pdf --out target\tmp\upd-min.pdf --title "Minimal"
file: fixtures\minimal.pdf
out:  target\tmp\upd-min.pdf
preserved_prefix: 595 bytes
appended: 229 bytes
revision: Classic at offset 641 (1 entries)
xref_chain_verified: true
pages: 1
text_pages_verified: 1
title: Minimal
```

Hybrid Excel 2019 fixture (92366 bytes), with the honest fallback:

```text
> pdfxi update fixtures\realworld\microsoft-excel-2019-sample.pdf --out target\tmp\upd1.pdf --title "Incremental report" --author "PDFXI" --json
{
  "file": "fixtures\\realworld\\microsoft-excel-2019-sample.pdf",
  "out": "target\\tmp\\upd1.pdf",
  "preserved_prefix_bytes": 92366,
  "appended_bytes": 514,
  "revisions": [],
  "xref_chain_verified": false,
  "note": "the source already carries a hybrid /XRefStm section that the cross-reference-chain validator does not link; the exact byte prefix, page count and page text were verified instead",
  "page_count": 2,
  "text_pages_verified": 2,
  "title": "Incremental report",
  "author": "PDFXI"
}

> pdfxi update target\tmp\upd1.pdf --out target\tmp\upd2.pdf --subject "Second revision"
preserved_prefix: 92880 bytes
appended: 556 bytes
pages: 2
text_pages_verified: 2
title: Incremental report
```

The second run appends a revision on top of the first output, so revisions
compose. A byte comparison of the source and the saved file confirms the
original 92366 bytes are unchanged.

## 4. Tests

```text
> cargo test -p pdfxi-cli --test cli update
test update_appends_a_validated_incremental_revision ... ok
test update_handles_a_hybrid_xref_source_honestly ... ok
test result: ok. 2 passed
```

- `update_appends_a_validated_incremental_revision` runs on
  `fixtures/minimal.pdf`: asserts `xref_chain_verified: true`, one `Classic`
  revision, one verified text page, the saved title, that the source bytes are
  an exact prefix, and that the output is longer. It also asserts the command
  refuses a call with no information field.
- `update_handles_a_hybrid_xref_source_honestly` runs on the real Excel hybrid
  file: asserts the exact prefix length, a positive appended size,
  `xref_chain_verified: false` with the `XRefStm` note, both pages and both texts
  verified, and that a second incremental save preserves the first output's
  bytes as its prefix.

## Scope

Incremental update and preservation validation are reachable from the CLI for
information edits. Page-content edits still use the full-rewrite page planner;
an incremental page-content host is not claimed here.
