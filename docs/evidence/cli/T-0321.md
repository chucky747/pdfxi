# T-0321 — Action Wizard create/run host (`AUTO-001`)

Row promoted: `AUTO-001` (Action Wizard create edit import export)
`model` -> `verified`.

The action document model existed, but the CLI only staged inputs and never
wrote a PDF or created an action file. This task adds `action create` and
`action run --execute`.

## 1. Host

```text
pdfxi action create <FILE.act> --name NAME --step ID:KIND [--step ...]
    [--param ID:KEY=VALUE ...] [--description TEXT] [--force] [--json]

pdfxi action run <FILE.act> NAME --input FILE.pdf [--output-dir DIR]
    [--execute] [--json]
```

- `action create` parses `ID:KIND` steps (`import`, `convert`, `watermark`,
  `security`, `export`, `custom-command`), attaches `ID:KEY=VALUE` parameters,
  validates the model and writes the tab-delimited file. It refuses an existing
  file unless `--force` is given.
- `action run` keeps the existing staging executor by default. With `--execute`
  it selects `RealOperations`:
  - `import` reads the file, applies the byte budget and requires that
    `pdfxi-core` parses it as a PDF.
  - `watermark` stamps every page with the real overlay used by
    `pdfxi decorate watermark` (72 pt, 15% alpha, 45 degrees, centred, front).
  - `export` writes the artifact beneath `--output-dir` and returns its path.
  - `security` and `custom-command` are refused with typed messages.
- Both modes keep the same `DocumentExecutor`/`BatchQueue` validation, ordering,
  failure isolation and JSON shape. `action list`/`action show` inspect the
  written file.

## Scope

The real path supports PDF import, text watermark and export. It does not
implement conversion to other formats, encryption/permissions, or custom
automation commands; those are refused rather than approximated. `droplet`
keeps staging defaults. Watermark style is fixed to the default centre mark.
