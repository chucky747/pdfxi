# T-0297 — form tab order and action hosts (`FORMS-004`)

Row promoted: `FORMS-004` (Form field actions and tab order)
`model` -> `verified`.

The `taborder` and `actions` models already parsed `/Tabs`, ordered widgets and
applied the safe action whitelist. This task adds hosts that read real form
bytes through the document-form model (rectangles and pages included) and report
both.

## 1. Hosts

```text
pdfxi form tabs <FILE> [--policy rows|columns|structure|annotations]
    [--include-read-only] [--no-wrap] [--json]
pdfxi form actions <FILE> [--json]
```

- `tabs` reads the AcroForm `/Tabs` name (`R`, `C`, `S`, `A`; default `R`),
  builds `TabWidget`s from each field's real widget rectangle and page index,
  applies the requested policy (or the file's), and reports the order plus each
  field's next and previous target. `--include-read-only` stops skipping
  read-only widgets; `--no-wrap` stops at the ends.
- `actions` walks the field and widget dictionaries, parses `/A` and `/AA`
  entries (`K`, `F`, `V`, `C`) into the safe `ResetForm`/`SubmitForm` whitelist
  and lists rejected actions with their subtype and reason. JavaScript and URI
  actions are rejected, never executed.
- Both load through `pdfxi-core` + `pdfxi_forms::read_acroform`, so real widget
  geometry and page numbers are used, not insert order.

## 2. Evidence

A four-widget form created by `pdfxi form create`:

```text
> pdfxi form tabs target\tmp\tabs.pdf
file: target\tmp\tabs.pdf
tabs: R (rows)
1. patient  page 1  rect: 72 700 272 724
2. agree  page 1  rect: 72 660 86 674
3. color  page 1  rect: 72 620 86 634
4. state  page 1  rect: 72 580 272 604
patient -> agree / state
agree -> color / patient
color -> state / agree
state -> patient / color
widgets: 4

> pdfxi form tabs target\tmp\tabs.pdf --policy columns --no-wrap
tabs: C (columns)
1. agree  page 1  rect: 72 660 86 674
2. color  page 1  rect: 72 620 86 634
3. patient  page 1  rect: 72 700 272 724
4. state  page 1  rect: 72 580 272 604
agree -> color / (none)
...
state -> (none) / patient
widgets: 4
```

Both orders read the real rectangles; the columns policy reorders the widgets
and `--no-wrap` yields `(none)` at the ends.

Actions on a two-field form whose field dictionaries were staged with
`/A << /S /ResetForm >>` and `/AA << /K << /S /ResetForm >> /F << /S
/JavaScript >> >>`:

```text
> pdfxi form actions target\lanes\forms\t0297\actions.pdf
file: target\lanes\forms\t0297\actions.pdf
present: true
action: patient [A] ResetForm fields: patient
action: state [K] ResetForm
unsupported: state [F] JavaScript: JavaScript actions are not supported
actions: 2
unsupported_actions: 1

> pdfxi form tabs target\lanes\forms\t0297\actions.pdf
tabs: R (rows)
1. patient  page 1  rect: 72 700 272 724
2. state  page 1  rect: 72 660 272 684
widgets: 2
```

A form-free PDF reports `present: false`, zero actions and zero widgets; an
unknown `--policy` is a typed error.

## Scope

Tab order over real widget geometry/pages and the safe action whitelist are
reachable from the CLI. Actions are reported, not executed; structure-tree order
still requires a caller-supplied structure mapping and is reported only when the
selected policy has no structure data.
