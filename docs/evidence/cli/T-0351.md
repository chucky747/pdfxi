# T-0351 — Policy-based protection host (`SEC-011`)

Row promoted: `SEC-011` (Policy-based protection replacement) `model` ->
`verified`.

`pdfxi_security::policy` validated protection policies, built a deterministic
plan and enforced expiry at a caller-supplied time, but nothing applied a policy
to a document. This task adds `pdfxi protection apply`.

## 1. Host

```text
pdfxi protection apply FILE --out PATH --name NAME --password PW [--owner PW]
    [--handler standard-r2|r3|r4|r6] [--permissions LIST] [--recipient LABEL ...]
    [--expiry UNIX] [--now UNIX] [--watermark] [--watermark-text TEXT] [--json]
```

- Builds `ProtectionPolicy::with_protection_id` from the handler, key length,
  validated permission mask and declared recipients, then attaches expiry and
  the watermark flag.
- `apply_protection_policy(policy, now)` validates the policy and **refuses an
  expired one before any output is written**.
- When `--watermark` is set, a visible diagonal watermark is stamped on every
  page with the existing page-decoration renderer; otherwise the source is
  saved unchanged.
- The prepared document is protected through the standard security handler with
  the policy's permission mask and the requested revision, then reopened with
  the user password and required to match the prepared page count and
  first-page text length (fail closed).
- The report lists the policy, handler, revision, key length, permissions,
  recipients, executed plan actions, evaluation time, expiry decision, watermark
  flag, output size and reopen result.
- Recipient labels are recorded. Wrapping content keys for certificate
  recipients remains a caller-supplied key-wrap backend boundary; the standard
  handler's own user/owner passwords protect the file here.

## 2. Evidence

```text
> pdfxi protection apply target\tmp\ps-src.pdf --out target\tmp\policy-protected.pdf \
    --name Archive --password test-password --owner owner-password --permissions read-only \
    --recipient alice --recipient bob --expiry 2000000000 --now 1700000000
out: target\tmp\policy-protected.pdf  bytes: 1709  policy: Archive  handler: standard-r6  revision: 6  key: 256 bits
permissions: print,accessibility,print-high  recipients: alice,bob  watermark: false
actions: validate_policy,set_permissions,wrap_recipient_keys,check_expiry  evaluated-at: 1700000000  expired: false
pages: 1  first-page chars: 41  reparsed: true
EXIT=0

> (json)
"handler": "standard-r6", "revision": 6, "key_length": 256,
"permissions": [...], "recipients": [...], "actions": [...],
"expired": false, "watermark": false, "reparsed": true

> pdfxi unprotect target\tmp\policy-protected.pdf --out target\tmp\policy-plain.pdf --password test-password
out: target\tmp\policy-plain.pdf  bytes: 1057  pages: 1  first-page chars: 41  encrypted: false
EXIT=0

> pdfxi text target\tmp\policy-plain.pdf
PostScript export line one.
Second line.

> pdfxi protection apply ... --name Draft --watermark --watermark-text DRAFT ... --now 1700000000
actions: validate_policy,set_permissions,wrap_recipient_keys,apply_watermark
pages: 1  first-page chars: 46  reparsed: true
> (unprotect, then text)  -> DRAFT
```

The watermarked run has 46 first-page characters instead of 41 and extracts
`DRAFT` after unprotect, proving the watermark was painted before protection.

Rejections:

```text
> protection apply ... --expiry 1600000000 --now 1700000000
Error: apply policy "Old": protection policy 'Old' has expired
(no output file is written)

> protection apply ... (no recipient)
Error: supply at least one --recipient LABEL

> ... --recipient a --recipient a
Error: protection policy: duplicate protection-policy recipient "a"

> ... --handler rot13
Error: unknown handler "rot13"; expected standard-r2, r3, r4 or r6

> ... --permissions annotate
Error: permission mask: annotation requires modification

> ... --name ""
Error: protection policy: protection policy name must not be empty

> ... --password ""
Error: --password must not be empty

> ... --watermark --watermark-text "  "
Error: --watermark-text must not be empty
```

The first applies a read-only AES-256 policy with expiry and recipients, asserts
the handler/revision/key/permissions/recipients/actions, checks `/Encrypt` is
present, unprotects and compares the extracted text, then repeats with
`--watermark` and asserts `DRAFT` extracts from the unprotected output. The
second proves an expired policy writes nothing and covers the typed rejections
above.

## Scope

A local, policy-driven protection application: permission mask, handler and
revision, caller-clocked expiry, optional visible watermark, and fail-closed
reopen verification. No rights-management server, network, licence call or host
clock read. Recipient labels are declarative; certificate key wrapping is a
key-wrap-provider boundary, not performed here. This is not a guarantee that a
hostile reader honours the permission bits.
