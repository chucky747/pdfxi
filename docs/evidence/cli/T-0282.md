# T-0282 — `pdfxi portfolio`: list and extract a collection

Row promoted: `VIEW-014` (Portfolio) `model` -> `verified`.

## What ships

`pdfxi-core` gains the reader for the feature's host boundary:

- `Document::is_portfolio()` — whether the catalog declares `/Collection`.
- `Document::portfolio_items()` — every `/Names /EmbeddedFiles` entry as a
  `PortfolioItem` with the name-tree key, the `/UF` folder path, the file name,
  `/Desc`, the embedded stream's `/Length`, its `/Subtype` media type and its
  `/Params /ModDate` (falling back to the file specification's `/ModDate`).
- The description/size extraction already used by `attachments()` is factored
  into `spec_description`, `embedded_stream` and `embedded_size` so both readers
  share one implementation.

`pdfxi` gains `portfolio`:

```text
pdfxi portfolio <file> [--json] [--extract <dir>]
```

- text output indents each row by its folder depth and prints size, media type
  and description;
- `--json` emits stable fields (`file`, `collection`, `count`, `files`,
  `extracted`) with no omitted optional key other than null metadata;
- `--extract` recreates the `/UF` folders under the target directory and writes
  the exact decoded stream bytes;
- every path component is validated (`safe_relative_path`) and the joined path
  is checked again for containment (`is_inside`), so `..`, absolute paths, drive
  or device prefixes, `:` alternate-stream markers, backslashes, control
  characters, empty components and over-long components are refused per file
  instead of written. A refused entry is reported and does not abort the rest.

## Real-document evidence

Checked-in fixture `fixtures/authoring/authoring-portfolio.pdf` (1271 bytes):
one page, `/Collection`, and three `/Names /EmbeddedFiles` entries —
`Reports/brief.txt` (text, description), `Reports/2026/q1.pdf` (PDF) and
`notes.txt` (no folder, `/F` only).

```text
> pdfxi portfolio fixtures\authoring\authoring-portfolio.pdf
collection: yes
  brief.txt  size: 11  type: text/plain  description: Quarterly brief
    q1.pdf  size: 20  type: application/pdf
notes.txt  size: 22  type: text/plain
files: 3
```

```text
> pdfxi portfolio fixtures\authoring\authoring-portfolio.pdf --json
{
  "file": "fixtures\\authoring\\authoring-portfolio.pdf",
  "collection": true,
  "count": 3,
  "files": [

      "name": "brief.txt",
      "size": 11,
      "mime": "text/plain",
```

## Scope

The GUI portfolio tree is still drawn by no shell surface; the reachable host is
the CLI, which prints the same tree rows the app model produces (depth-indented)
and performs the byte extraction and file I/O the app model deliberately omits.
This is the same CLI-host pattern used for `VIEW-009` (`attachments --extract`).
