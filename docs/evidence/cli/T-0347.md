# T-0347 — Trust and revocation host (`SEC-007`)

Row promoted: `SEC-007` (Trust manager and revocation checks) `model` ->
`verified`.

`pdfxi_security::TrustManager` already built and validated certificate paths
and evaluated CRLs, but nothing outside the tests could run a decision. This
task adds `pdfxi trust verify`, which evaluates a real leaf against
caller-supplied anchors, intermediates and CRLs with a pinned clock.

## 1. Host

```text
pdfxi trust verify --anchor PATH --leaf PATH [--intermediate PATH ...] [--crl PATH ...]
    [--time UNIX] [--strict] [--json]
```

- `--anchor` accepts a PEM bundle or one DER certificate; every certificate in
  it becomes a trust anchor.
- `--leaf` accepts exactly one PEM or DER certificate; `--intermediate` accepts
  a PEM bundle or one DER certificate and may be repeated.
- `--crl` accepts a DER CRL and may be repeated.
- `--time` pins the evaluation clock (default: current time); `--strict` applies
  `RevocationPolicy::strict()` (presence, freshness and CRL signatures all
  required).
- Evaluation uses `TrustManager` and `RsaPkcs1Verifier`: validity windows, CA
  constraints, `keyCertSign`, path length, critical extensions and every
  signature are checked, then CRLs are matched by issuer.
- The report lists the leaf subject and serial, the anchor/intermediate/CRL
  counts, the typed decision (`no_anchor`, `issuer_unknown`, `revoked:<serial>`,
  `revocation_unknown:<serial>`, `revocation_stale:<serial>`,
  `crl_signature_invalid:<serial>`, …), the validated serial path and the
  per-certificate revocation evidence. An untrusted decision exits non-zero.
- Nothing is fetched over the network; no key material is read or printed.

`Certificate` PEM decoding is now available to callers as
`pdfxi_security::certificates_from_pem`, the same tolerant scanner
`TrustAnchorBundle::from_pem` uses.

## 2. Evidence

```text
> pdfxi trust verify --anchor target\tmp\trust\ca.pem --leaf target\tmp\trust\leaf.pem --time 1700000000
leaf: CN=PDFXI Test Leaf,O=PDFXI  serial: 7  anchors: 1  intermediates: 0  crls: 0
trusted: true  reason: none
chain: [7, 1]  anchor: 1
revocation: serial 7 unknown (crl-issuer none, signature-verified false)
evaluated-at: 1700000000  strict: false
EXIT=0

> ... --json
"trusted": true, "reason": null, "chain_serials": [7, 1], "anchor_serial": 1,
"status": "unknown", "signature_verified": false, "evaluated_at": 1700000000

> ... --crl target\tmp\trust\good.crl --strict --json
"trusted": true, "status": "good", "signature_verified": true, "strict": true
EXIT=0

> ... --crl target\tmp\trust\revoked.crl --strict
trusted: false  reason: revoked:7
revocation: serial 7 revoked (crl-issuer CN=PDFXI Test CA,O=PDFXI, signature-verified true)
Error: certificate chain is not trusted: revoked:7
EXIT=1

> ... --strict          (no CRL supplied)
trusted: false  reason: revocation_unknown:7
EXIT=1

> --anchor target\tmp\trust\other-ca.pem ...
trusted: false  reason: issuer_unknown
EXIT=1
```

The fixtures are a generated 2048-bit root CA (serial 1), a leaf (serial 7)
signed by it, an unrelated root (serial 99), and CRLs with and without serial 7
revoked, signed by the CA. The good CRL verifies under `RsaPkcs1Verifier`; the
revoked CRL's entry wins and the decision is `revoked:7`.

## 3. Tests

```text
> cargo test -p pdfxi-cli trust_
trust_verifies_a_chain_and_revocation ... ok
trust_rejects_bad_inputs ... ok
test result: ok. 2 passed
```

The first generates the CA/leaf/CRLs at runtime (never committed), then asserts:
trusted chain `[7, 1]` with anchor 1 and no CRL; a strict good-CRL run with
`signature_verified: true`; a strict revoked-CRL run that exits 1 with
`revoked:7`, the revocation date and verified signature; a strict run without a
CRL failing `revocation_unknown:7`; and an unrelated anchor failing with a typed
reason. The second covers a missing file, garbage anchors, a leaf file with two
certificates and a malformed CRL.

## Scope

Offline chain building and CRL-based revocation only. No OCSP (a network
protocol), no AIA fetching, no online timestamping and no platform certificate
store; anchors and CRLs are explicit files. Expired/not-yet-valid certificates
are reported rather than ignored, and a trusted decision still only means the
supplied anchor set vouches for the chain.
