# T-0305 — local form distribution host (`FORMS-009`)

Row promoted: `FORMS-009` (Distribute and collect forms locally)
`model` -> `verified`.

The row had an in-memory blank-bundle format and a deterministic response
merger, but no filesystem entry point. This task adds the distribute/collect
pair over real PDF and FDF/XFDF files.

## 1. Hosts

```text
pdfxi form distribute <FILE> --out BUNDLE
    [--form-id ID] [--title T] [--version N] [--json]

pdfxi form collect <FILE> --response [RESPONDENT=]PATH ... [--json]
```

### distribute

- Loads the PDF's terminal AcroForm fields and builds `BlankBundle::from_form`.
- Defaults: `--form-id pdfxi-form`, `--title` from the file stem, version 1.
- Writes the canonical `PDFXI-BUNDLE-1` text (`ID`, `TITLE`, `VERSION`, one
  `FIELD name type required label` line per field), reads it back and requires
  `parse_bundle` to reproduce the same bundle.
- Reports the metadata, field rows (name, type, required) and byte count.

### collect

- Each `--response` is `[RESPONDENT=]PATH`. Without an explicit id the file stem
  is used. FDF is detected by a leading `%FDF`, otherwise XFDF is assumed.
- `merge_responses` accepts and rejects individual documents independently and
  resolves conflicts deterministically (smallest respondent id wins, every
  differing value recorded). Duplicate ids collapse and are reported.
- The merged field names must exist in the PDF; otherwise the command fails
  instead of silently collecting responses for another form.
- Required PDF fields with no merged value are listed as `missing_required`.
- Text and JSON reports are identical under response reordering.

The JSON form carries the same summary plus `fields` (name, value, contributors,
conflict), `conflicts` with every contribution, `duplicates`, `rejected` and
`missing_required`.

## Scope

Distribution is local files only: no email, network, or server. Bundles are the
PDFXI text format, not a PDF portfolio. Collection assumes response field names
match the PDF; no type coercion beyond the forms model's conservative XFDF
mapping. Conflicts are reported but the smallest respondent id wins
automatically; there is no interactive resolution.
