# T-0294 — conformance export host (`EXPORT-008`)

Row promoted: `EXPORT-008` (Export to PDF/A PDF/X and PDF/E)
`library` -> `verified`.

The row's notes name exactly the missing piece: "CLI/UI wiring that selects the
conformance target and writes the normalized bytes to a host-chosen path". The
plan/export engine already lived in `pdfxi-convert::conformance`; this task adds
the host and verifies the written bytes.

## 1. Host

```text
pdfxi export conformance <FILE> --profile PROFILE [--out PATH] [--plan]
    [--policy report|reject] [--output-intent SUBTYPE]
    [--no-normalize-version] [--no-xmp] [--no-output-intent] [--json]
```

- Profiles: `PDF/A-1b`, `PDF/A-2b`, `PDF/A-3b`, `PDF/X-1a`, `PDF/X-4`,
  `PDF/E-1`. Compact lowercase spellings such as `pdfa-2b`, `pdfx-4` and
  `pdfe-1` are accepted (case and separators are ignored).
- `--plan` prints the byte-free `ConformancePlan` (steps, enforced versus
  report-only, minimum version) and writes nothing.
- `--policy report` (default) records forbidden catalog entries as warnings;
  `--policy reject` fails before writing the first one.
- `--output-intent` adds an explicit subtype and is validated against the
  target, so contradictory requests such as PDF/E-1 plus `GTS_PDFA1` fail with a
  typed error.
- The host reopens the normalized bytes with `pdfxi-core` and checks, before
  writing: the page count and every page's text against the source, the header
  version against the target minimum, `/Metadata` when the target requires XMP,
  and `/OutputIntents` when the target requires an output intent.
- The report repeats `certification_claimed: false` and the stable scope note.
  No run claims conformance.


PDF/X-4 and PDF/E-1 runs over real fixtures report `pages_verified: 1`,
`certification_claimed: false`, and PDF/E-1 enforces only `minimum_version`
(no XMP or output intent required by that target). A contradictory request is
a typed error:

```text
> pdfxi export conformance fixtures\minimal.pdf --out x.pdf --profile pdfe-1 --output-intent GTS_PDFA1
Error: normalize fixtures\minimal.pdf: contradictory conformance request:
PDF/E-1 does not use output intents, but subtype GTS_PDFA1 was requested
```

Forbidden-entry policy over a fixture whose catalog carries `/JavaScript`:

```text
> pdfxi export conformance js.pdf --out out.pdf --profile pdfa-1b --policy reject
Error: normalize js.pdf: 'PDF/A-1b' forbids catalog entry /JavaScript; remove it before export

> pdfxi export conformance js.pdf --out out.pdf --profile pdfa-1b --policy report --json
"present_forbidden_entries": ["/JavaScript"]
"certification_claimed": false
```

## Scope

Target selection, plan inspection, normalization and writing are reachable from
the CLI for all six supported profiles. The placeholders still require real XMP
and ICC content, and independent validator confirmation remains a CI oracle;
neither is claimed by the export.
