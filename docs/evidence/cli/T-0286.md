# T-0286 — page-stamp operation and the `pdfxi decorate` host

Rows promoted: `EDIT-008` (Headers, footers and page numbering) and `EDIT-009`
(Watermarks and backgrounds), both `model` -> `verified`.

## 1. The missing writer piece: `PageOperation::Stamp` / `StampPages`

`pdfxi-edit` could already *render* overlay content streams but nothing could put
them into a document. `pdfxi-core/src/pages.rs` now has:

- `StampOverlay { content, fonts, ext_gstates, front }` — an overlay content
  stream plus the resources it names. Fonts are `(placeholder, base font)` and
  graphics states are `(placeholder, alpha)`; the placeholders are the resource
  names the overlay content already uses (`/F1`, `/GS0`).
- `PageOperation::Stamp { target, overlay }` — one overlay for a page set.
- `PageOperation::StampPages { overlays }` — one overlay per selection position,
  which is what a header/footer or Bates renderer produces.

Rendering appends (or prepends, for `front: false`) a new content stream to each
stamped page, so the overlay is ordinary page content: rendered, searched and
extracted like the page's own text. The overlay's fonts and `/ExtGState` entries
are merged into a direct copy of the page's resource dictionary under names the
page does not already use (`F1` on the page becomes `F2` for the overlay), and
the content tokens are rewritten to match. A page that already used `/F1` keeps
its own font and still gets the stamp.

`Document::page_frame(index)` returns the media box and effective rotation, which
is the geometry the overlay renderers need.

## 2. The host: `pdfxi decorate`

```text
pdfxi decorate header-footer <FILE> --out PATH [--header TEXT] [--footer TEXT]
    [--side left|center|right] [--font-size N] [--margin N] [--title T] [--date D] [--json]
pdfxi decorate watermark <FILE> --out PATH --text TEXT [--font-size N]
    [--opacity F] [--rotation D] [--tile] [--json]
```

Header/footer templates accept `{page}`, `{pages}`, `{date}`, `{title}` and
`{filename}`; anything else is literal and an unknown placeholder is a typed
error. Both commands build per-page geometries from `page_frame`, render the
`pdfxi-edit` overlays, turn them into `StampOverlay`s and apply one
`PageOperation::StampPages`.

## 3. Real-document evidence

```text
> pdfxi decorate header-footer fixtures\realworld\powerpoint-slides.pdf --out target\tmp\slides-hf.pdf --header "Quarterly Review" --footer "Page {page} of {pages}"
file: fixtures\realworld\powerpoint-slides.pdf
out:  target\tmp\slides-hf.pdf
pages: 3
stamped: 3
suppressed: 0
font size: 10

> pdfxi text target\tmp\slides-hf.pdf
Lantern Slide•The lantern slide marker is the first landscape page.Quarterly ReviewPage 1 of 3
Harbor Slide•The harbor slide marker is the second landscape page.Quarterly ReviewPage 2 of 3
Meadow Slide•The meadow slide marker is the third and final landscape page.Quarterly ReviewPage 3 of 3
```

The original page text is intact and the header and per-page footer are real
extractable content on every page.

```text
> pdfxi decorate watermark fixtures\realworld\powerpoint-slides.pdf --out target\tmp\slides-wm.pdf --text DRAFT --opacity 0.2 --json
{
  "file": "fixtures\\realworld\\powerpoint-slides.pdf",
  "out": "target\\tmp\\slides-wm.pdf",
  "pages": 3,
  "stamped": 3,
  "suppressed": 0,
  "text": "DRAFT",
  "font_size": 72.0,
  "opacity": 0.2,
  "rotation": 45.0,
  "tile": false
}

> pdfxi text target\tmp\slides-wm.pdf   (page 1)
Lantern Slide•The lantern slide marker is the first landscape page.DRAFT

> raw scan of the output
/Contents [ 6 0 R 69 0 R ]   <- the overlay stream is appended to page content
/ExtGState                   <- the alpha resource is merged into the page
/ca 0.2                      <- the requested opacity is written
```

`--tile` repeats the mark (the integration test asserts more than one `COPY` on
page 1); a tiled mark is the same operation with a grid position.

## 5. Scope

Headers, footers and page numbering cover the six-slot model, token
substitution, margins, alignment, numbering formats, page filters and rotation
(the model's own tests). Watermarks cover text marks, opacity, rotation,
centring, tiling and front placement; vector and image marks and the "behind"
placement are not exposed by the CLI yet, and neither are cover pages or Bates
numbering (`EDIT-010` is next and uses the same `StampPages` operation).
