# T-0278 — `pdfxi links`: link annotations and named destinations

## What changed

`VIEW-011` ("Links and named destinations") had an in-memory authoring model in
`pdfxi-edit` but no reader: nothing could tell a user where a link goes. This
task adds the reading half in `pdfxi-core::links` and a CLI surface.

```text
pdfxi links <FILE> [--json]
```

For every `/Link` annotation it reports the one-based page, the rectangle and
the resolved target:

- `/A << /S /URI /URI (...) >>` — external URI.
- explicit destination (`/Dest [page ...]` or `/A /GoTo`) — destination page.
- named destination (`/Dest (name)` or `/A /GoTo /D (name)`) — resolved through
  the catalog's `/Dests` dictionary and the `/Names /Dests` tree
  (recursively through `/Kids`), reporting the page and the name.
- anything else — `unresolved` with the name or the reason, so a link is never
  silently dropped.

`--json` emits `file`, `count` and one row per link with `page`, `rect`, `kind`,
`dest_page`, `dest_name`, `uri` and `detail`.

Files: `crates/pdfxi-core/src/links.rs` (new reader, two tests),
`crates/pdfxi-cli/src/links.rs` (command), `crates/pdfxi-cli/src/main.rs`,
`crates/pdfxi-cli/tests/cli.rs` (three tests),
`crates/pdfxi-testkit/src/lib.rs` (`annotated_pdf()` fixture builder).

## Real-document run

Checked-in real fixture:

```text
$ pdfxi links fixtures\authoring\authoring-annotations.pdf
page: 1  rect: 72 600 240 620  target: uri https://example.invalid/doc
links: 1
```

Generated-but-valid document with all three target kinds
(`pdfxi_testkit::annotated_pdf()`):

```text
$ pdfxi links annotated.pdf
page: 1  rect: 10 10 100 100  target: page 1
page: 1  rect: 10 120 100 160  target: uri https://example.com
page: 1  rect: 10 170 100 200  target: page 1 (named here)
links: 3
```

## Honest scope

- Reads link annotations and destinations; it does not follow a link in the GUI
  yet, and it does not write or repair link annotations.
- Named destinations are resolved through `/Dests` and `/Names /Dests`
  (including `/Kids`); destinations stored in other action types (JavaScript,
  launches) are reported as unresolved rather than executed.
- Rectangles are reported as stored; no page rotation is applied to them.
- `VIEW-009` (attachments) is **not** covered here: listing attachments works,
  but opening or saving the embedded bytes is still missing, so that row stays
  `model`.
