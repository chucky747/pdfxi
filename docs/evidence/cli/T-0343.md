# T-0343 — Standard security handler host (`SEC-002`)

Row promoted: `SEC-002` (RC4 and AES encryption handlers) `library` -> `verified`.

The AES/RC4/MD5/SHA primitives, the revision 2-6 standard handler and the
encrypting save path already existed in `pdfxi-security` with known-answer
vectors, but nothing in the product wrote or reopened an encrypted file. This
task adds `pdfxi protect` and `pdfxi unprotect`, which exercise the whole stack
on real bytes.

## 1. Host

```text
pdfxi protect FILE --out PATH --password PW [--owner PW] [--method rc4-40|rc4-128|aes-128|aes-256]
    [--permissions all|none|read-only|LIST] [--revision N] [--encrypt-metadata BOOL] [--json]
pdfxi unprotect FILE --out PATH --password PW [--json]
```

- `protect` parses the input, refuses an already encrypted file, builds
  `ProtectOptions`, runs `protect_document`, then **reopens the produced bytes
  with the user password** and requires the same page count and first-page text
  length before writing anything (fail closed).
- `unprotect` runs `remove_protection`, re-parses the plaintext output with the
  core reader, and refuses to write output that still declares `/Encrypt`.
- Permission names map onto `ProtectPermissions`/`Permission`; `read-only`,
  `none`, `all` and comma lists are accepted, and inconsistent grants (for
  example `annotate` without `modify`) are rejected by the typed validator.
- Passwords are only used for key derivation; they are never printed, included
  in JSON, or embedded in an error message.

## 2. Evidence

```text
> pdfxi protect target\tmp\ps-src.pdf --out target\tmp\protected.pdf \
    --password test-password --owner owner-password --permissions read-only
out: target\tmp\protected.pdf  bytes: 1710  method: aes-256  revision: 6  key: 256 bits
permissions: print,accessibility,print-high  owner-password: true  pages: 1  first-page chars: 41
EXIT=0

> pdfxi unprotect target\tmp\protected.pdf --out target\tmp\unprotected.pdf --password test-password
out: target\tmp\unprotected.pdf  bytes: 1057  pages: 1  first-page chars: 41  encrypted: false
EXIT=0

> pdfxi text target\tmp\ps-src.pdf        > pdfxi text target\tmp\unprotected.pdf
PostScript export line one.               PostScript export line one.
Second line.                              Second line.

> pdfxi protect ... --method rc4-40 --json
"method": "rc4-40", "revision": 2, "key_length_bits": 40, "pages": 1
```

The AES-256 output is a real 1,710-byte PDF whose `/Encrypt` dictionary the
handler itself reopens; the round trip preserves the page text exactly.

Rejections:

```text
> unprotect <protected> --password wrong
Error: unprotect ...: the supplied password is incorrect

> protect <already protected> --out ...
Error: <file> is already encrypted; run `pdfxi unprotect` first

> protect <plain> --permissions annotate
Error: ... annotation requires modification

> protect <plain> --method rot13
Error: unknown method "rot13"; expected rc4-40, rc4-128, aes-128 or aes-256
```

## 3. Tests

```text
> cargo test -p pdfxi-cli protect_
protect_and_unprotect_round_trip ... ok
protect_supports_legacy_rc4 ... ok
protect_rejects_encrypted_input_and_bad_options ... ok
test result: ok. 3 passed
```

The round trip test protects a real PDF with AES-256 and an owner password,
asserts method/revision/key length/permission list, checks `/Encrypt` is present
in the bytes, unprotects it, checks `/Encrypt` is gone, and compares the text
extracted by the core reader. The RC4 test repeats the cycle for revision 2.
The rejection test covers double protection, a wrong password, an inconsistent
permission set, an unknown method and an empty password.

## Scope

Standard security handler output only: password-based RC4/AES encryption with
revision 2-6 and the eight standard permission grants. This is not a rights
management system, does not authenticate a certificate identity, and does not
claim a permission bit is enforceable against a malicious reader. Certificate
encryption (`SEC-003`), digital IDs (`SEC-004`), CMS signing (`SEC-005`) and
trust/revocation (`SEC-007`) remain separate rows.
