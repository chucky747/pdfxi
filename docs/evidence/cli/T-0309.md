# T-0309 — watched-folder schedule host (`AUTO-003`)

Row promoted: `AUTO-003` (Droplets and watched folders)
`model` -> `verified`.

The row had a deterministic `PollSchedule`/backoff model and a validated marker
snapshot but no OS-side caller. This task supplies the host half: a real folder,
a persisted marker file, and a bounded number of host ticks.

## 1. Host

```text
pdfxi watch <FOLDER> --out DIR [--markers PATH] [--ext EXT ...] [--suffix EXT]
    [--poll-every N] [--base-ticks N] [--max-ticks N] [--multiplier N]
    [--ticks N] [--json]
```

- Canonicalizes the watched folder and output directory. The output directory is
  created when absent and must be outside the watched folder, otherwise outputs
  would be rescanned.
- Builds a `WatchedFolderConfig` (default extension `pdf`, default suffix `pdf`,
  configurable file/byte/depth bounds stay at the library defaults).
- Loads `--markers` through `MarkerSnapshot::from_json_string` when the file
  exists; invalid snapshots are a typed error.
- Advances `PollSchedule` for `--ticks` host ticks. A poll runs only for a
  `Due` decision; `EveryTicks(n)` and the backoff policy decide the gap. A poll
  with any failed file calls `record_failure`, otherwise `record_success`.
- Converts eligible unmarked files with `PassthroughConverter`, writes them to
  `<out>/<output_name>` after a component check, records converted/skipped/
  unsupported/failed counts, and atomically replaces the marker snapshot.
- No thread, timer, or OS watcher is started. A scheduler (Task Scheduler, cron)
  owns repetition.

## 2. Evidence

```text
> pdfxi watch target\tmp\watched --out target\tmp\watched-out --markers target\tmp\markers.json --json
{
  "extensions": ["pdf"],
  "suffix": "pdf",
  "ticks": 1,
  "polls": 1,
  "decisions": [{ "tick": 1, "decision": "due" }],
  "reports": [{
    "tick": 1, "converted": 2, "skipped": 0, "unsupported": 1, "failed": 0,
    "files": [
      { "relative": "a.pdf", "state": "converted", "output": "a.pdf" },
      { "relative": "b.pdf", "state": "converted", "output": "b.pdf" },
      { "relative": "notes.txt", "state": "unsupported",
        "message": "extension 'txt' is not eligible" }
    ]
  }],
  "written": 2,
  "marker_count": 2
}

> type target\tmp\markers.json
{"paths":["a.pdf","b.pdf"],"version":1}
```

The watched folder held `a.pdf` (595 bytes), `b.pdf` (3 bytes) and
`notes.txt`; the two PDFs were written byte-for-byte to the output directory.

A second run with the same markers:

```text
converted 0, skipped 2, unsupported 1, failed 0
written 0, marker_count 2
```

and the marker file is byte-identical, so processed files are not re-read.

A schedule of three ticks with `--poll-every 2`:

```text
tick 1: wait 1 more
tick 2: due
tick 3: wait 1 more
ticks: 3  polls: 1
interval=every_ticks:2  failures=0  tick=3  polls=1  gap=2
```

## Scope

This is the host *poll* half, not a daemon: no thread, file-system notification
API, or wall clock. The converter is passthrough, so file content is copied, not
transformed; installing a real converter is a separate wiring step. Markers
record successful conversions only, so failed files are retried on the next run.
