# T-0279 — Open and save embedded-file attachments (VIEW-009)

## What changed

`pdfxi attachments` could list attachments but not hand back their bytes, so
`VIEW-009` ("Attachments and embedded files") stayed `model`. This task adds the
missing half:

- `Document::attachment_bytes(name)` in `pdfxi-core::links` finds the file
  specification through `/Names /EmbeddedFiles` or a `/FileAttachment`
  annotation, resolves `/EF /F`, and decodes the embedded stream through its
  `/Filter` chain (Flate, LZW, ASCIIHex, … via the existing core decoder).
  A missing name returns `Error::AttachmentNotFound`.
- `pdfxi attachments <FILE> --extract <DIR>` writes every attachment into the
  directory, sanitising names so a hostile `/F (../../evil.txt)` cannot escape
  (only the final path component is used; `..`, empty names and Windows-reserved
  characters are rejected), and de-duplicates collisions.

```text
pdfxi attachments <FILE> [--json] [--extract DIR]
```

On `--extract`, text output adds `extracted: N files`, and JSON rows carry the
written `path`.

Files: `crates/pdfxi-core/src/links.rs` (bytes + lookup, one test),
`crates/pdfxi-core/src/lib.rs` (`AttachmentNotFound`),
`crates/pdfxi-cli/src/links.rs` (extraction + sanitiser, one unit test),
`crates/pdfxi-cli/src/main.rs`, `crates/pdfxi-cli/tests/cli.rs` (one test).

## Live run

Generated document with one embedded file (`notes.txt`, payload `hello`):

```text
$ pdfxi attachments annotated-demo.pdf --extract target\tmp\extracted
name: notes.txt  size: 5  description: Sample notes
extracted: 1 files
attachments: 1
EXIT=0

$ dir target\tmp\extracted
notes.txt  5 bytes

$ type target\tmp\extracted\notes.txt
hello
```

A hostile name (`../../evil.txt`) resolves to `evil.txt` in the target
directory, and `..`/`""` are rejected; proven by
`attachment_names_cannot_escape_the_target_directory`.

## Tests

```text
cargo test -p pdfxi-core --lib links::
test result: ok. 3 passed

cargo test -p pdfxi-cli --test cli attachments
test result: ok. 2 passed
```

- `attachment_bytes_returns_the_embedded_payload` — payload equals `hello`;
  a missing name returns `AttachmentNotFound`.
- `attachments_report_an_embedded_file` — listing name, size and description.
- `attachments_extract_writes_the_embedded_file` — `--extract` writes
  `notes.txt` with the exact 5 bytes.
- `attachment_names_cannot_escape_the_target_directory` — sanitiser unit test.

## Honest scope

- Extraction writes the decoded payload; it does not preserve the original
  file's timestamps or create the original directory structure (by design, for
  traversal safety).
- Encrypted embedded streams require the document to be decrypted first; an
  encrypted file is rejected by the core decoder rather than silently written.
- Viewing an attachment inside the app is still the CLI path plus the OS
  default handler; the in-app attachments panel is not part of this row.
