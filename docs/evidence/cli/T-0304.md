# T-0304 — reader-enable rights host (`FORMS-008`)

Row promoted: `FORMS-008` (Reader-enable form filling and saving)
`model` -> `verified`.

The row modelled the `/Perms /UR` shape, the fill/save policy and a strict
parser, but nothing wrote it into a document. This task is the writer.

## 1. Host

```text
pdfxi form reader-enable <FILE> --out PATH
    [--rights fill,save] [--reason TEXT] [--placeholder-bytes N] [--json]
```

- Rights accept `fill`/`fill-in`, `save`, `annotate`, `assemble`,
  `copy`/`copy-extract`, `accessibility`/`a11y` or `all`; an unknown name or an
  empty set is rejected before the document is read.
- `ReaderEnablePlan` plus a local `UsageRightsSignature` validates the filter,
  reason and placeholder size (1..=65536), then produces the `/Perms /UR`
  dictionary.
- The host converts the forms value to core objects, preserves any other
  `/Perms` entries, replaces only `/UR`, stages the catalog and saves.
- It reopens the output, converts the catalog back and runs
  `parse_rights_dictionary`, checking that the saved rights and filter match the
  request and reporting `can_fill` / `can_save` from the parsed plan.
- `certified` is always `false`: the filter is PDFXI-local and the `/Contents`
  is a run of ASCII `0` placeholders, not a signature.

Writing `/Perms` exposed a parser gap: a full core save canonicalises strings to
hexadecimal, and `pdfxi_forms::parse_pdf` rejected `<...>` strings. This task
also teaches that parser hexadecimal strings (whitespace and odd-digit padding),
so `form list` still reads a reader-enabled form.

## 2. Evidence

```text
> pdfxi form reader-enable fixtures\minimal.pdf --out target\tmp\reader-enable.pdf --rights fill,save --reason "local trial" --json
{
  "file": "fixtures\\minimal.pdf",
  "out": "target\\tmp\\reader-enable.pdf",
  "pages": 1,
  "rights": ["fill-in", "save"],
  "filter": "PDFXI.ReaderEnable.Local",
  "placeholder_bytes": 4096,
  "reason": "local trial",
  "can_fill": true,
  "can_save": true,
  "certified": false,
  "bytes": 8896
}
```

An existing form keeps its fields:

```text
> pdfxi form create target\tmp\reader-form.pdf --field "text:Name:72,600,168,20"
> pdfxi form reader-enable target\tmp\reader-form.pdf --out target\tmp\reader-form-enabled.pdf --rights all --placeholder-bytes 128
pages: 1
rights: fill-in,save,annotate,assemble,copy-extract,accessibility
filter: PDFXI.ReaderEnable.Local
placeholder_bytes: 128
can_fill: true
can_save: true
certified: false

> pdfxi form list target\tmp\reader-form-enabled.pdf
file: target\tmp\reader-form-enabled.pdf
present: true
Name  [text]
fields: 1
```

A save-only grant denies filling:

```text
> pdfxi form reader-enable target\tmp\reader-form.pdf --out target\tmp\reader-form-save.pdf --rights save --json
  "rights": ["save"],
  "can_fill": false,
  "can_save": true,
```

Bad input is typed:

```text
> pdfxi form reader-enable fixtures\minimal.pdf --out ... --rights fill,teleport
Error: unknown right "teleport"; expected fill, save, annotate, assemble, copy-extract, accessibility or all

> pdfxi form reader-enable fixtures\minimal.pdf --out ... --placeholder-bytes 0
Error: reader-enable plan: placeholder byte count 0 is outside 1..=65536
```

## Scope

The output is local compatibility metadata: no cryptography, no signature, no
Adobe certification, and no enforcement of the rights by this codebase. Other
`/Perms` keys are preserved; only `/UR` is written. Rights are the six local
bits; unknown/foreign rights remain rejected by the parser.
