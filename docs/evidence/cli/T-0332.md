# T-0332 — Accessibility tree, navigation and reflow hosts (`ACCESS-006`, `ACCESS-004`)

Rows promoted:

- `ACCESS-006` (Screen reader and accesskit integration) `model` -> `verified`.
- `ACCESS-004` (Reflow high contrast and keyboard navigation) `model` ->
  `verified`.

Both models were complete and window-free (`pdfxi_app::a11y`,
`pdfxi_app::nav`) with no user surface. This task hosts them on the existing
`pdfxi accessibility` command group and feeds them from real documents.

## 1. Host

```text
pdfxi accessibility tree <INPUT.pdf> [--page N] [--focus REGION]
    [--high-contrast] [--json]
pdfxi accessibility nav [--theme standard|high-contrast] [--tabs N]
    [--reverse] [--json]
pdfxi accessibility layout <INPUT.pdf> [--page N] [--viewport WxH]
    [--font-size PT] [--line-spacing FACTOR] [--margin PT] [--json]
```

- `tree` loads the PDF, reads the real page count, validates the current page,
  maps `--focus` to a `FocusTarget`, builds `AccessibilitySnapshot` and
  `A11yTree::from_snapshot`, and prints every node's AccessKit role name,
  children, focusability, disabled state, plus the focus announcement and the
  well-formed flag.
- `nav` builds the theme tokens, audits all five contrast pairs with
  `contrast_ratio` against AAA (7:1) for high contrast or AA (4.5:1) for
  standard, prints the default Tab ring, simulates N forward or reverse Tabs via
  `FocusOrder::tab`, and lists the shortcut map.
- `layout` reads the page's real media box (`Document::page`) and computes
  `reflow_metrics` for the requested viewport, font size, line spacing and
  margin.

## Scope

The CLI publishes and audits the deterministic trees/palettes/metrics; it does
not open a window, call AccessKit or a platform screen reader, or paint the
high-contrast theme. `ACCESS-004`'s reflow text column remains the existing
`pdfxi reflow` command; `layout` reports the geometry a host uses to place that
column. Keyboard navigation is modelled as the Tab ring plus shortcut map, not
as real OS key events.
