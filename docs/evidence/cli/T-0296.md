# T-0296 — form validation and calculations (`FORMS-003`)

Row promoted: `FORMS-003` (Field properties calculations and validation)
`model` -> `verified`.

The property model, `PropertySet` validation, and `Calculation`/`CalculationPlan`
already existed in `pdfxi-forms`. This task adds hosts that load a real form PDF,
apply typed values, validate it, and evaluate calculations.

## 1. Hosts

```text
pdfxi form validate <FILE> [--set NAME=VALUE] ... [--json]
pdfxi form calculate <FILE> [--set NAME=VALUE] ...
    [--sum|--product|--average|--min|--max TARGET=SRC1,SRC2] ...
    [--decimals N] [--json]
```

- `--set` values are typed from the field: checkboxes take `true`/`false`,
  choice and radio fields take `a|b`, and everything else parses as a number
  when possible and text otherwise. Unknown fields and read-only fields are
  typed errors.
- `validate` builds a `FieldProperties` record per field (type, required,
  read-only, max length, choices) and runs `PropertySet::validate`, which checks
  definitions and current values. It exits `0` when valid, `2` when the form has
  errors (like `preflight`), and `1` for a typed input error.
- `calculate` builds a `CalculationPlan` from the requested steps and applies it
  in dependency order, printing each target's value rounded to `--decimals`
  (default 6, maximum 12). Cycles, missing fields and non-numeric sources are
  typed errors. The evaluation is read-only: no bytes are rewritten.

## 2. Evidence

Form created with the FORMS-002 host, then validated and calculated:

```text
> pdfxi form calculate target\tmp\calc.pdf --set a=3 --set b=4 --sum total=a,b
file: target\tmp\calc.pdf
calculations: 1
decimals: 6
total = 7

> pdfxi form validate target\tmp\calc.pdf --set a=3 --set state=CA
file: target\tmp\calc.pdf
fields: 5
valid: true
errors: 0

> pdfxi form validate target\tmp\calc.pdf --set state=ZZ
file: target\tmp\calc.pdf
fields: 5
valid: false
error: state  field 'state' selects 'ZZ', which is not an allowed choice
errors: 1
(exit code 2)
```

The invalid choice is a real value error from the property model, not a CLI
check. Missing calculation sources and bad checkbox values are typed errors:

```text
> pdfxi form calculate calc.pdf --set a=3 --sum total=a,missing
Error: evaluate calculations: calculation source 'missing' does not exist

> pdfxi form validate calc.pdf --set agree=maybe
Error: checkbox "agree" needs true or false, got "maybe"
```

## Scope

Property/definition validation and calculation evaluation are reachable on real
form bytes. Assignments and calculation results live in memory; persisting them
back into the PDF belongs to the fill/property-writer rows and is not claimed
here.
