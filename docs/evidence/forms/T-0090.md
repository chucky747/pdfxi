## 5. Changes

- `crates/pdfxi-forms/src/taborder.rs` (new): `/Tabs` policy parsing
  (`/R`, `/C`, `/S`, `/A`), deterministic row/column/annotation/structure
  widget ordering, page ordering and subsets, `NavPolicy` hidden/read-only
  skipping and wrap, `TabNavigator` (`Iterator`) traversal.
- `crates/pdfxi-forms/src/actions.rs` (new): `/AA` trigger parsing for
  `K`/`F`/`V`/`C`, `/A` parsing, typed safe whitelist (`ResetForm`,
  `SubmitForm`), typed rejection of JavaScript/URI/Launch/Import/Export and
  unknown subtypes, and a deterministic `ActionPlan` + `ActionReport` with an
  `UnsupportedAction` list.
- `crates/pdfxi-forms/src/lib.rs`: module declarations, public re-exports and
  crate-level rustdoc for both new modules.

## 6. Scope notes

- Tab order is a model over `TabWidget` metadata (page, annotation index,
  rectangle, hidden/read-only flags). Structure order requires the host to
  supply the structure sequence, because this crate has no structure-tree
  adapter; without one it deterministically falls back to annotation order.
- Row/column ordering groups widgets by vertical/horizontal bands with a
  documented 2.0-unit tolerance; ties break on coordinate then field name.
- Actions are boundary models only: no script is executed, no network I/O and
  no field writes are performed by this crate. `javascript:` URIs are reported
  as JavaScript rather than generic URI actions. Submit targets are recorded
  verbatim as strings for a host to interpret.
- No `unwrap`/`expect`/`panic!`/`todo!`/`unimplemented!` in non-test code in
  the new modules; all public items have rustdoc.
