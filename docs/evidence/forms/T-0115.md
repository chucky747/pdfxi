## Scope and safety notes

- No new dependencies; `thiserror` was already a workspace-locked dependency of
  this crate.
- No `unsafe`, no filesystem or network I/O, no OCR.
- No `unwrap`, `expect`, `panic!`, `todo!`, or `unimplemented!` in non-test code
  of the three new modules.
- Reader-enable output is a local compatibility metadata plan with a placeholder
  signature; it is explicitly not Adobe certification and implements no
  cryptography (`ReaderEnablePlan::is_certification()` is always `false`).
- XFDF responses are parsed without a form, so raw values map conservatively to
  text/choice; hosts that know the types can pre-map with
  `XfdfDocument::to_fdf`.
