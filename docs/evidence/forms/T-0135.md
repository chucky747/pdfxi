## Scope and safety notes

- Files changed (all inside the claim): `crates/pdfxi-forms/src/reader_enable.rs`,
  `crates/pdfxi-forms/src/lib.rs`. Reports: this evidence file and
  `orchestration/feature-updates/T-0135.toml`.
- No new dependencies; `thiserror` was already a workspace-locked dependency of
  this crate. No network access and no git writes.
- No `unsafe`, no filesystem or network I/O. No `unwrap`, `expect`, `panic!`,
  `todo!`, or `unimplemented!` in non-test code.
- Local replacement per ADR 0008: the `/Perms /UR` metadata block carries a
  documented, fixed ASCII-`0` placeholder `/Contents` under the PDFXI-local
  filter `PDFXI.ReaderEnable.Local`. `FillSavePolicy` provides allowed operations
  plus explicit form-fill and save flags; `ReaderEnablePlan::can_fill`/`can_save`
  return typed `Permission` decisions. `parse_rights_dictionary` validates an
  existing rights dictionary and rejects malformed structure, foreign filters,
  non-placeholder contents, invalid `/Ff`, and unknown rights with typed
  `ReaderEnableError`s.
- No cryptography and no Adobe certification claim:
  `ReaderEnablePlan::is_certification()` and all report `certified` fields are
  always `false`; foreign filters are actively rejected
  (`ReaderEnableError::NonLocalFilter`).
- `docs/features.toml` and `orchestration/BOARD.md` were not edited; the FORMS-008
  change is delivered only as the feature-update fragment.
