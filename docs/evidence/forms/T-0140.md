## What changed

Owned paths only:

- `crates/pdfxi-forms/src/serialize.rs` (new). Concrete PDF 1.7 serializer and
  bounded reader. `serialize_form_pdf(fields, widgets, page)` promotes each
  `/Kids` widget to an indirect object, rewrites the field `/Kids`, overwrites
  the widget `/P` with the real page reference, wires page `/Annots`, builds the
  `/AcroForm /Fields` array, catalogue, page tree, xref table and trailer.
  Object numbers are deterministic; the caller's page number is reserved and
  bounded by `MAX_OBJECT_NUMBER`. `parse_pdf` reads the result back for the
  round-trip verification of `/T`, `/FT`, `/Rect`, `/P` and `/Annots`.
- `crates/pdfxi-forms/src/properties.rs` (new). `FieldProperties` typed property
  record and `PropertySet` name-sorted container, with definition and value
  validation folded into the existing `ValidationSummary`.
- `crates/pdfxi-forms/src/validation.rs`: three new typed `ValidationError`
  variants (`InvalidName`, `InvalidTooltip`, `ConflictingFlags`) with display,
  field access and stable sort ranks.
- `crates/pdfxi-forms/src/rules.rs`: `Format::check` made `pub(crate)` so the
  property model reuses the existing numeric/currency/date/pattern logic.
- `crates/pdfxi-forms/src/lib.rs`: module declarations, re-exports and crate doc.
- `orchestration/feature-updates/T-0140.toml`, this evidence file.

No `Cargo.toml`, `Cargo.lock`, `docs/features.toml`, `orchestration/BOARD.md`,
`.opencode/**` or `xtask/**` file was edited. No new dependency, no git write,
no network, no `unsafe`, and no `unwrap`/`expect`/`panic!` in non-test code.

- FORMS-002 — `verified`. The previously deferred concrete serialization is now
  emitted and round-trip tested end-to-end inside the crate: emit dictionaries,
  write PDF bytes, parse them back, verify field names/types and widget

  document; merging into an existing host PDF, per-option radio appearance

## Negative and determinism coverage

- `missing_page_reference_is_a_typed_error` — `None` page gives
  `SerializeError::MissingPageReference`.
- `invalid_page_reference_is_rejected` — object 0 and an over-limit number give
  `SerializeError::InvalidPageReference`.
- `duplicate_field_names_are_rejected` — a repeated `/T` is rejected before any
  object is allocated.
- `malformed_field_dictionary_is_rejected` / `empty_field_list_is_rejected` /
  `widget_count_mismatch_is_rejected` — hostile shapes are typed errors.
- `parser_rejects_non_pdf_input` — no header and no `startxref` are rejected.

  `property_set_lists_by_name_deterministically` — repeated emission and
  insertion-order changes produce identical output/listing.
