## Fixes delivered (T-0168 LOW findings)

1. `SignatureLifecycle::verify` now calls `validate_byte_range(document, &plan,
   placeholder)` before `signed_bytes`. The `/Contents` placeholder hex used to
   compute the plan is stored on the lifecycle at `request_sign` time. A plan
   that does not match the document, or a document without the placeholder, is
   rejected with `LifecycleError::ByteRange(ByteRangeError::..)` and leaves the
   workflow state unchanged.
2. `signed_bytes` rejects overlapping/inverted ranges, empty intervals, ranges
   beyond the document and a non-zero first start with distinct typed errors:
   `ByteRangeError::InvalidRangeOrder`, `EmptyRange` and `OutOfBounds`.
3. `VerificationOutcome` and `LifecycleReport` carry an explicit `Authenticity`
   level (`StructureOnly` default vs `Cryptographic`). Rustdoc states that a
   `SignatureStatus::Valid` from `StructureOnlyVerifier` must never be displayed
   as an authentic signature. `LifecycleReport::to_lines` emits
   `lifecycle.authenticity=<level>`.
4. `completed_v` emits `/ByteRange` through a new `PdfValue::Integer(u64)`
   variant instead of `u64 as f64`, so offsets above 2^53 remain exact and never
   become scientific notation. `serialize.rs` writes the integer directly.
