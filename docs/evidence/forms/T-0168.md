# T-0168 - signature workflow closure with security boundary

Lane: `forms`. Target dir: `target/lanes/forms` (via `scripts/env.ps1 -Lane forms`).
Scope: `crates/pdfxi-forms/**` only. FORMS-010 is closed at the **library
level**; cryptographic signing/validation stays with the security lane and the
signature UI stays with the app lane.

## Delivered

- `crates/pdfxi-forms/src/signing.rs` (new):
  - `plan_byte_range(document, placeholder_hex)` computes a deterministic
    `/ByteRange [a b c d]` from serialized PDF bytes containing a unique
    `/Contents` placeholder; `validate_byte_range` checks a supplied plan
    against the document; `signed_bytes` reconstructs the exact covered byte
    concatenation (no hashing). Typed `ByteRangeError` for invalid, missing,
    ambiguous or inconsistent placeholders.
  - `SignatureVerifier` trait — a caller-supplied, crypto-agnostic verification
    boundary — plus `StructureOnlyVerifier`, a deterministic stub that checks
    structure only. Typed `VerificationError` / `VerificationOutcome` /
    `VerificationRequest`. **No cryptography in this crate.**
  - `SignatureLifecycle` state machine
    `create -> sign-request -> attach bytes -> verify -> report`, composing the
    existing `SignatureWorkflow` state machine with a caller-supplied byte-range
    plan and caller-supplied signature bytes. `completed_v` emits the `/V`
    dictionary with `/Contents` (hex of the supplied bytes) and `/ByteRange`.
    `LifecycleReport` / `workflow_transition_lines` give deterministic reports
    containing every state and transition.
- `crates/pdfxi-forms/src/signature.rs`: added `SignatureDictionary::filter()`
  and `subfilter()` accessors needed by the verification request.
- `crates/pdfxi-forms/src/fillworkflow.rs`: `attach_signature` now checks the
  installed `SignatureGuard`, so lock/certification enforcement covers all
  fill/edit paths (`set`, `clear`, `reset_field`, `attach_signature`).
- `crates/pdfxi-forms/src/lib.rs`: module declaration, crate-root exports and
  rustdoc for the new contract.

## Boundary and constraints

- No cryptography: byte ranges are pure arithmetic, `/Contents` bytes are
  hex-encoded verbatim, and the default verifier checks structure only. The
  `SignatureVerifier` trait is the documented seam for `pdfxi-security`.
- No `Cargo.toml`, `Cargo.lock`, `docs/features.toml`, `orchestration/BOARD.md`,
  `xtask/**`, git writes, network access, new dependencies, `unsafe`, or
  non-test `unwrap`/`expect`/`panic!`.
- `cargo xtask goal-verify --milestone M3` reads `docs/features.toml`, which the
  integrator owns; the FORMS-010 `verified` status is delivered as the
  `orchestration/feature-updates/T-0168.toml` fragment for the integrator to
  merge before re-running the gate.
