# T-0021 — PDFium backend proof of concept

Status: verified (task); VIEW-001 and VIEW-002 remain in-progress until the app
canvas, tiling, zoom layout, and printing consume the backend.

## Files

- `crates/pdfxi-render/Cargo.toml` — optional `pdfium-render` 0.9.5 dependency
  and `pdfium` feature; `default = []`.
- `crates/pdfxi-render/src/pdfium_backend.rs` — `PdfiumRenderer` with document
  loading from file or bytes, `Renderer::render_page`, `page_count`, structured
  errors, cancellation, progress, and a process-wide mutex (PDFium is not
  thread-safe).
- `crates/pdfxi-render/tests/pdfium_backend.rs` — integration tests gated on the
  feature.

## Verification

```text
$ . .\scripts\env.ps1 -Lane render
PDFIUM_PATH=C:\Users\cmabr\AppData\Local\pdfxi\pdfium\bin\pdfium.dll
$ cargo test -p pdfxi-render --features pdfium
5 unit passed; 4 integration passed; 0 failed
$ cargo test -p pdfxi-render
5 unit passed; 0 failed
$ cargo clippy -p pdfxi-render --all-targets --features pdfium -- -D warnings
clean
```

The raster test asserts non-zero dimensions, `len == width * height * 4`, a
non-uniform image, and complete progress. Library bind errors, missing files,
malformed documents, invalid scales, out-of-range pages, and cancellation all
return structured errors instead of panicking.

PDFium version: `160.0.8165.0` (pdfium-render default `pdfium_8125` bindings).
