## What changed (crates/pdfxi-render/** only)

All five host-agnostic media models were completed at the library level; no
codec, OS playback, script execution, geometry decoding, or native projection
engine was added.

- `media.rs` (MEDIA-001): `RenditionSelection::PreferredMime` selects the first
  rendition by MIME preference (case-insensitive) with a typed
  `MediaError::PreferredMimeNotFound`; `PlaybackControl::code`,
  `HostRequirement::code`, `MediaSource::descriptor` and
  `PlaybackPlan::descriptor` give the plan a byte-stable identity.
- `html5_media.rs` (MEDIA-002): `Html5Descriptor::descriptor`,
  `MediaCategory::code`, `LocalMediaRef::descriptor`; all control characters
  (NUL, tab, CR, LF, ...) in source/poster references are now rejected as
  `Html5MediaError::UnsafeCharacter` in addition to markup punctuation.
- `three_d.rs` (MEDIA-003): `ThreeDFormat::code`, `ThreeDStreamRef::descriptor`,
  `BackendRequirement::code`, `ThreeDPlan::descriptor`; unknown formats remain
  prefixed/escaped in the descriptor rather than being collapsed.
- `geospatial.rs` (MEDIA-004): `local_to_geo` now rejects points outside the
  declared `/LPTS` rectangle with typed `PointOutsideLocalPoints`; new
  deterministic `viewport_for_geo` with typed `NoViewportForPoint`;
  `Unit::code`, `Projection::code`, `PlanNote::code`,
  `GeospatialPlan::descriptor` keep unsupported projections/unknown units
  explicit.
- `actions.rs` (MEDIA-005): `SafeAction::code` and `ActionPlan::descriptor`
  provide a byte-stable action plan; dangerous/network actions remain typed
  rejections with no script execution.

12 new tests were added across the five rows (3 media, 2 html5_media, 2
three_d, 3 geospatial, 2 actions), covering negative validation, determinism,
byte-stable descriptors and typed unsupported cases.

## Status decision (per ADR 0008)

Each MEDIA row is now a genuinely complete host-agnostic model: bounded and
typed validation, deterministic plans with byte-stable descriptors, typed
unsupported cases, and full rustdoc. Per the task's "verified only if genuinely
complete absent codecs/OS integration" carve-out (and the precedent of
VIEW-001/VIEW-010 being verified for the data model only), the rows are reported
`verified` at library level. The host boundary is explicit in every row note:
no codec decode, no OS media sink, no 3D geometry decode/display, no native
datum/projection math, no script execution, and no PDF object-stream extraction
are performed here.
