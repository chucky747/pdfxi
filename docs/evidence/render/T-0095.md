Status: in-progress for the PRINT-003 feature row. This task delivers a bounded
ICC profile parser, output-intent validation, and a deterministic colour contract
with analytic matrix/TRC and gray-gamma conversion plans. Full ICC/CMM rendering

reported as `in-progress` rather than `verified`.

## Coverage

- Header fields: declared size, CMM, version, device class, data colour space,
  PCS, rendering intent, D50 illuminant, `acsp` signature.
- Tag table lookup by signature, tag payload bounds re-check, `desc` ASCII and
  `wtpt` XYZ queries.
- Truncated profiles, declared sizes above the 16 MiB cap, corrupt signatures,
  out-of-bounds tag offsets, and zero-length tag payloads all produce typed
  errors without panicking.
- Synthetic sRGB-like RGB profile: colourant matrix, gamma TRC, RGB plan;
  gray profile: `kTRC` gamma and gray plan.
- Output-intent parse of all dictionary fields; missing, multiple and
  unsupported-subtype detection via both `issues()` and `validate()`.
- Conversion-plan determinism: parsing and planning the same bytes twice gives
  byte-identical plans and outputs; component-count mismatches are typed.
- `ConversionPlan::NeedsBackend` returns a typed `BackendRequired` error,
  documenting the CMM delegation boundary.

## Notes

Fixed-point encodings limit exactness: `s15Fixed16` resolves to 1/65536 and
`u8Fixed8` gamma to 1/256, so value assertions use tolerances of 1e-4 and 2e-3
respectively. Full ICC rendering (arbitrary LUT tags, parametric curves beyond
a single gamma, chromatic adaptation) remains the responsibility of the native
backend; the analytic plans in this module are the documented handoff point.

## Reviewer fix pass (T-0122)

T-0122 closes three reviewer findings against T-0095 without adding new feature
surface. PRINT-003 stays `in-progress` because full ICC/CMM rendering remains the
renderer backend's responsibility.

- **MEDIUM — `desc` (`textDescriptionType`) layout.** `description()` previously
  read the ASCII byte count at offset 0 and the string at offset 4. A real v2
  `textDescriptionType` is a `desc` signature (4 bytes), a reserved word (4
  bytes), a 4-byte ASCII count (including the terminating NUL), then the ASCII
  string, with optional Unicode/ScriptCode sections after it. The parser now
  validates the `desc` signature, reads the reserved word for bounds coverage,
  reads the count at offset 8 and the string at offset 12, validates the count
  against the tag payload with `checked_add`, strips the trailing NUL, and keeps
  returning typed `ColorError::InvalidTagData` for every malformed case. This
  module has no measurement-type (`meas`) parser, so no related type needed
  adjustment. The `desc_payload` test helper now encodes the real layout; a new
  test builds a complete v2 payload (ASCII + Unicode + ScriptCode) and asserts
  correct decoding plus typed errors for a wrong signature, an over-large count,
  and a maximal (`u32::MAX`) count.
- **LOW — Lab conversion honesty.** `ConversionPlan::from_profile` no longer maps
  Lab source data to `Identity`; Lab now yields `NeedsBackend` with an
  explanatory reason, so `convert` returns `BackendRequired` instead of silently
  passing Lab samples through. XYZ PCS profiles still legitimately map to
  `Identity`. Rustdoc on the `Identity` variant and on `from_profile` was updated,
  and `lab_profile_requires_backend` covers both the Lab rejection and the XYZ
  pass-through.
- **Evidence correction.** The T-0095 heading said 15 colour tests while listing
  16; corrected to 16 above. The T-0095 feature fragment
  (`orchestration/feature-updates/T-0095.toml`) was integrator-consumed into the
  PRINT-003 row of `docs/features.toml` and is no longer present, as expected.
  The T-0122 fragment (`orchestration/feature-updates/T-0122.toml`) was likewise
  integrator-consumed into the PRINT-003 row (features.toml evidence/notes/tests).
  No file in this pass is integrator-owned and was edited directly by this lane.

Test counts: T-0095 baseline 78 unit / 16 colour. This pass adds two tests
