## Reviewer-requested fixes in this round

- **HIGH — zero-dimension panic.** `encode_png` called `data.chunks(row_len)`
  before its zero-width guard; `width == 0` made `row_len == 0` and Rust panicked
  with "chunk size must be non-zero". This was reachable through the public
  `encode_image(0, h, ...)`. Fixed by adding typed
  `ExportError::InvalidDimensions(u32, u32)`, rejecting zero width/height at
  the top of `encode_image`, `encode_png`, `encode_jpeg` and `encode_tiff`, and
  guarding the renderer path in `export_pages` so an empty raster from a
  renderer produces `InvalidDimensions` instead of a panic. The dead zero-width
  `raw.resize` branch was removed. Regression tests cover width=0, height=0,
  empty data with non-zero dimensions, and a zero-dimension renderer.
- **LOW — JPEG/RGBA validation.** `format=Jpeg` with `ColorMode::Rgba` and
  `AlphaPolicy::Flatten` previously passed `validate()` and failed later inside
  `encode_jpeg` after pixels had been rasterized. `validate()` now rejects it
  up front with typed `ExportError::UnsupportedColor("jpg", "rgba")`.
- A direct `BitWriter` byte-stuffing regression test was added so the JPEG
  claims below are backed by a test rather than inspection alone.

## What the JPEG tests actually prove

`jpeg_header_quality_and_markers_are_valid` verifies the marker sequence
`SOI, APP0, DQT, SOF0, DHT, SOS` and the trailing `EOI`, the JFIF APP0 signature
and dots-per-inch density fields, the DQT table contents changing with quality
(quality 10 vs 90), and SOF0 precision, two-byte height/width and component
count (3 for RGB, 1 for grayscale). `jpeg_bit_writer_stuffs_0xff_bytes`
verifies that an `0xFF` byte in the entropy stream is escaped with a following
`0x00`. `jpeg_quality_is_validated` verifies the typed rejection of out-of-range
quality, and `jpeg_rgba_with_flatten_is_rejected_in_validate` verifies early
rejection of JPEG+RGBA.

The entropy-coded scan itself is produced deterministically by a fixed
Huffman/DCT pipeline, but these tests **do not decode the JPEG end-to-end with
an independent decoder**; pixel round-trip through JPEG is therefore not
claimed. PNG pixel round-trip is verified directly through the stored-deflate
IDAT stream, and TIFF strips are verified byte-for-byte at their IFD offsets.

## Summary of implementation

- New `crates/pdfxi-render/src/export.rs` (pure Rust, no new dependencies,
  `#![forbid(unsafe_code)]`, no `unwrap`/`expect`/`panic` in library code;
  zero-dimension inputs now return `ExportError::InvalidDimensions` before any
  row chunking).
- `ImageFormat::{Png, Jpeg, Tiff}`, `ColorMode::{Grayscale, Rgb, Rgba}`,
  `AlphaPolicy::{Preserve, Flatten}`, `FitMode::{Actual, Scale, FitWithin}`,
  `ExportOptions`, `ExportError`, `ExportedImage`, `encode_image`,
  `export_pages`, and `MAX_EXPORT_DPI`/`DEFAULT_EXPORT_DPI`.
- DPI 1..=12000 validated; DPI→scale = `dpi / 72`, reusing the existing
  `print::PrintSpooler` for page ranges, fit-to-box, progress, and cancellation.
- PNG: deterministic stored-deflate stream, IHDR colour types 0/2/6, `pHYs`
  DPI metadata, CRC-32 per chunk.
- JPEG: baseline 4:4:4, documented Annex K quantization/Huffman tables, IJG
  quality scaling, JFIF density, 2-byte SOF0 dimensions, byte stuffing.
- TIFF: little-endian, uncompressed, multi-page IFD chain, `ExtraSamples` for
  RGBA, `XResolution`/`YResolution` rationals; one file for all pages.
- 20 unit tests + 1 PDFium-gated integration smoke test.
- Three bugs were found and fixed across both rounds: a TIFF header first-IFD
  pointer aimed at pixel data, a JPEG SOF0 that wrote 4-byte instead of 2-byte
  dimensions, and the HIGH zero-width PNG chunk panic addressed above.
