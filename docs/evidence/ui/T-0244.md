# T-0244 - Export card and Export command

Status: served for A-27. The Export card, the `Export` command and all eight
targets - text, Word, Excel, PowerPoint, PNG, JPEG, HTML and RTF - are wired,
exercised and tested on the Excel fixture. No feature row is promoted and no
capture is claimed.

Claim: app lane, `crates/pdfxi-app/src/**`, `crates/pdfxi-app/tests/**`, this
file and `orchestration/feature-updates/T-0244.toml`. Target directory
`target/lanes/app9`, features `ui,pdfium`.

## Entry points

`AppCommand::Export` (`label = "export"`) is dispatched by the existing command
bar and Tools row plumbing and by the harness. `handle_export_command` never
exports on its own: with no document it sets `Open a document to export`; with an
open document it opens the Export card and sets
`Export: choose a format, then Export`.

## Export card

`ExportUiState` (`open`, `format`, `jpeg_quality`, `dpi`, `last_path`, `error`,
`progress`) and `ExportChoice` (eight A-27 targets with `label()`, `extension()`,
`to_format()`) live in `crates/pdfxi-app/src/shell/export_card.rs`. The card is
drawn under the Tools panel: a "Convert this PDF to:" ComboBox, a JPEG quality
slider (1..=100) when JPEG is selected, an Export button disabled without a
document, and progress/error/last-export lines. The picker lists only
`ExportFormat::is_implemented()` formats, and a stale selection falls back to the
first implemented choice.

## Export path

`choose_export_path` is the only `rfd` call: a save dialog filtered to the chosen
extension, pre-filled with `<tab stem>.<ext>`. Tests never open it.
`export_document_to` builds `ExportOptions` with the tab title,
`TextPageSelection::All`, the card DPI and JPEG quality, and calls `export_pdf`
once. `export_to_path` writes one part at the chosen path, or every page part as
`<stem>-<part.name>.<ext>`; it creates missing parent directories, records
`last_path`, reports `Exported <n> page(s) to <path>`, maps typed errors to the
card error and `Export failed: ...`, and appends Office unsupported findings to
the success status.

PNG and JPEG work through the app's `pdfium` feature, which forwards
`pdfxi-convert/pdfium`; the picker therefore offers all eight formats and the
tests assert the real PNG/JPEG signatures.

## Limits

- Synchronous export on the UI thread with no cancel (incremental follow-up).
- Office "opens the result" is not re-checked because of the recorded T-0215 COM
  problem.
- PDFium is not involved in the written-output check because the output is not a
  PDF.
- No capture is claimed; T-0262 captures the installed build.

## API notes

`export_pdf`, `ExportFormat`, `ExportOptions`, `ExportedFile` and `ExportedPart`
match the brief. `TextPageSelection` is re-exported at the crate root, not from
`pdf_export`; `ExportFormat::is_implemented()` must be consulted because image
formats are feature-gated at runtime.
