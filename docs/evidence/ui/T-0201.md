# T-0201 - Windows window controls, settings menu, persisted theme and control style

Lane: app. Status: implemented, verified by build/clippy/tests and four screenshots;
reviewer sign-off still pending.

## Scope

- WindowControlStyle { Windows, MacOs }, default Windows on Windows and macOS elsewhere,
  persisted in the user settings file.
- Windows caption buttons (minimize, maximize/restore, close) at the right edge, full
  title-bar height, close hover rgb(0xE8,0x11,0x23) with a white glyph, restore glyph when
  maximized. macOS traffic lights stay at the left.
- Title-bar settings popup (gear): Theme (Light / Dark / Follow system) and Window
  controls (Windows / macOS); changes apply immediately and are saved.
- --controls=windows|macos launch flag alongside --dark / --light; flags override the
  saved settings for that run and are never written back.
- Double-click on the title drag area toggles maximize; no edge resize while maximized.
- Theme and control style persist as TOML at %APPDATA%\PDFXI\settings.toml (resolved from
  the environment; on other platforms the platform configuration root). Missing,
  unreadable, or corrupt files fall back to defaults; unknown keys are ignored; writes are
  atomic (temporary file + rename).
- Light-theme moon glyph redrawn as a clean crescent; new gear and restore icons; the
  tautological design::theme_toggle_round_trips test is deleted.

Not in scope (T-0203): demo tabs, avatar, notifications, canned content.

## Known limitations

- Caption buttons are painted by egui, not the OS non-client area. Windows 11 Snap Layouts
  (the maximize-button hover flyout) is therefore absent, and touch/pen hit-testing follows
  egui rather than the native frame.
- Follow system uses the theme egui/eframe reports for the platform; when nothing is
  reported (for example before the first frame) it falls back to Light. There is no
  explicit repaint request on an OS theme change; the existing event-driven repaint is
  relied on.
- Only explicit user choices are saved. A launch flag changes the effective theme/controls
  for that run but never Settings on disk; if the user then changes one setting, only that
  field is written.
- The four screenshots still show T-0203 demo content (named tabs, avatar, notifications,
  proposal page). This task deliberately does not remove it.
- No installer or desktop-shortcut refresh was performed: packaging (T-0202) owns that work
  and is in progress in the same workspace. The capture binary is the lane build at
  target/lanes/app/release/pdfxi-ui.exe.
- The settings write path is covered by unit tests with a temporary directory; no test
  touches the real per-user settings file.
