# T-0203 - honest shell

Lane: app. Status: implemented and verified by gates plus five captures.

Claim: T-0203 was implemented under the T-0201 claim by orchestrator decision,
because T-0201 and T-0203 own the same `crates/pdfxi-app/src/**` paths; there was
no separate T-0203 claim file.

## What was removed

- Fake startup tabs; the app now starts on the empty Home state.
- The painted business-proposal page, demo thumbnails, demo text and all demo
  installers for layers, bookmarks, attachments and links.
- The left rail (Home/Files/Recent/Starred/Shared/Pages/Comments/AI), the fake pages
  panel, the right Tools panel, the AI assistant card and canned answers, the comment
  thread, cloud storage, avatar, notifications, help and export card.
- Edit/Comment/Highlight/Sign/Organize/Export, Undo/Redo, tool and view rows.
- The plan-only Print dialog and every print method/field in the shell (print.rs stays as
  a tested library module with no UI caller).
- Split/tile pane shortcuts and helpers, plus the layer/bookmark/attachment/link row
  helpers in ui.rs; the model modules outside ui.rs are unchanged.
- The demo fixture helper is now `test_fixture_path`, test-only.

## What remains (all reachable on a real PDF)

Open via the native picker (rfd) with multi-select, drag-and-drop, and Ctrl+O/CLI path;
tabs with activation and close; real page thumbnails; continuous canvas with real rasters;
scroll, zoom, fit page/width, actual size, rotate view; find over real extracted text with
per-span highlight boxes; theme and window-control settings; Windows/macOS caption buttons;
dismissible open-error banner.

## Honest limitations

- Find covers only pages whose text has been extracted: the first 8 pages on open, then
  two pages per frame. Very large documents become fully searchable progressively.
- Password detection is still a lowercase "password" string match because pdfium-render
  does not expose a typed load-time password error.
- The native file picker was not verified interactively in this environment.
- Page sizes come from the new Renderer::page_size API; a page whose size cannot be read
  shows an error banner and the canvas does not invent a Letter page.
- Print is removed; panes are removed; no interactive screenshot of the settings popup.
- The window-control screenshots for T-0201 now point at the t0203 captures.


## Round 5 polish (orchestrator review findings)

- Pages are centred horizontally in the canvas when narrower than the viewport; the same
  pad is applied to hit-testing, selection and find highlights. Wider pages still scroll
  left-aligned.
- The floating page/zoom pill is sized to its content and centred on the canvas.
- Page rasters render at zoom x pixels_per_point and are keyed by that device scale, so
  text is crisp at 133% display scaling and a DPI change requests fresh rasters.
- The gear is now a ring with six separated teeth and a wide centre hole at the Find
  magnifier stroke weight.
- Thumbnail tiles and their labels are centred in the panel.
