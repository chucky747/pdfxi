# T-0252 - OpenCode Connect screen and model picker (Round A)

- Status: Round A connection screen, discovery, explicit-endpoint pairing and
  model picker implemented. The assistant chat panel is T-0253.
- Lane: app
- Claim: `crates/pdfxi-app/**`, this evidence file, the T-0252 fragment.
- Serves: A-16 (connection half) and the AI Assistant entry points in A-06.
- ADR: 0011. The app uses the T-0251 client; it does not reimplement HTTP.

## What is real

- `Capability::AssistantConnect` is always on, so the Connect screen is
  reachable; `Capability::AiAssistant` is added **only** while the probe has a
  usable connected service and removed on disconnect/error. No conversation
  control is drawn before a connection exists.
- Three real entries, one command: the command-bar "AI Assistant", the Tools
  panel row and the rail item all dispatch `AppCommand::AiAssistant`, which
  opens the Connect panel. The command has a stable label `ai-assistant`.
- The panel renders five states: `Disconnected`, `Checking`, `Connected`
  (service version, provider count and model count), `Incompatible` (a version
  outside `2.3.x`), and `Unreachable` (redacted T-0251 error text).
- Connected state shows the real service URL (no credentials), the OpenCode
  version, provider labels and the model rows. The model list is clickable;
  the selected model is highlighted. The default and acceptance model is
  `opencode-go/hy4-flash-free`.
- Reconnect, Disconnect and "Pair and check" are real buttons. Pairing uses the
  T-0251 explicit-endpoint path with the code as the endpoint credential; the
  code stays in memory, is moved into the worker and cleared from the form.
  The T-0251 client has no `POST /api/pair` handshake, and the panel states
  that limit instead of pretending otherwise.
- The model and the last successful endpoint are persisted in settings (no
  password, token or pairing code); a settings round-trip test proves the
  defaults and the no-credential rule.

## What is sent

Only `GET /api/info`, `GET /api/provider` and `GET /api/model` during a probe.
No session create, prompt, document text, page text or tool call is sent by
this task. The panel says "This screen sends no document text." An incompatible
service is refused after `/api/info`, before the provider/model routes.

## Tests

`crates/pdfxi-app/src/shell/assistant_connect.rs`:

- `connect_lists_models_and_selects_the_acceptance_default` — a loopback stub
  answers the three routes; the probe records exactly those paths, Basic auth
  on each, two providers, two models and the acceptance default.
- `unreachable_service_is_reported_and_not_usable` — closed port -> Unreachable,
  capability off.
- `incompatible_service_is_refused_before_models_are_requested` — `2.4.0`
  returns `Incompatible` and no provider/model request.
- `dispatch_opens_the_assistant_panel_without_network_io` — the command opens the
  panel headlessly.
- `model_choice_prefers_the_saved_model_then_the_acceptance_model`.
- `pair_with_code_uses_the_explicit_endpoint_and_clears_the_code`.
- `disconnect_returns_to_disconnected_and_keeps_the_remembered_model`.
- `app_persists_the_model_and_endpoint_but_never_the_password`.

`settings::tests::assistant_model_and_endpoint_round_trip_without_credentials`
proves the settings file contains neither password, token nor credential text.

## Limits / Round B (T-0253)

- No assistant chat, streaming answer, summary, insights, citations or stop
  control; that is T-0253.
- `docs/book/src/privacy.md` still says the assistant panel is inert and that the
  AI Assistant command is unavailable; that is now false for the Connect screen
  and must be replaced in T-0253/T-0261.
- No native OpenCode pairing handshake in the T-0251 client; the explicit
  endpoint + code path is used and labelled as such.
- The model picker lists enabled chat models from the service; a model can be
  selected and remembered, but changing it does not create a conversation yet.
- No document text is read or sent by this screen.
