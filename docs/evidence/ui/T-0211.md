# T-0211 - split ui.rs into shell modules with one AppCommand dispatcher

Date: 2026-11-20. Lane: app. Status: lane-complete, awaiting orchestrator review.

Pure refactor; no behaviour or visual change. `pdfxi_app::ui::run` and
`pdfxi_app::ui::PdfxiApp` are unchanged, `crates/pdfxi-app/src/bin/pdfxi-ui.rs`
compiled without edits, and `AppCommand` is re-exported as
`pdfxi_app::ui::AppCommand` for T-0212.

## Modules (physical lines)

`ui.rs` declares `#[path = "shell/mod.rs"] mod shell;`, so the files live under
`crates/pdfxi-app/src/shell/` while remaining descendants of `ui`.

| File | Lines | Responsibility |
|---|---:|---|
| `shell/mod.rs` | 18 | module wiring |
| `shell/commands.rs` | 274 | `AppCommand`, `label()`, `dispatch` |

| `shell/document_view.rs` | 432 | canvas, page pill, rasters and textures |
| `shell/widgets.rs` | 258 | shared shell widgets and caption chrome |
| `shell/command_bar.rs` | 85 | command bar and legacy tab strip |
| `shell/side_panel.rs` | 166 | thumbnails and texture upload |
| `shell/find_bar.rs` | 49 | find bar |
| `shell/empty_state.rs` | 45 | empty-document Home surface |
| `shell/dialogs.rs` | 62 | open dialog, error banner, open-error window |

`ui.rs` no longer draws chrome, canvas, panels, dialogs or widgets. The pure
public geometry helpers and the state/input loop stay so public paths and tests
do not move.

## Routing and honest exceptions

Every `clicked()` site in `ui.rs` and `shell/*.rs` either dispatches or records a
local (`activate`, `close`, `clicked` page, `theme_choice`, `controls_choice`,
`TabAction`) that is dispatched immediately afterwards. Keyboard shortcuts build
`AppCommand`s; `ViewCommand` is translated 1:1.

- Text fields edit their buffers through `egui::TextEdit`, then dispatch.
- Canvas scroll, selection drag and thumbnail-follow are pointer gestures that
  mutate scroll/selection/pending state directly.
- `window_resize_handles` sends `BeginResize` on an edge press.
- `open_dialog_ui` executes the `OpenDialog` command body; `rfd` runs between
  frames, never in a paint callback.
- Texture/raster cache population, OS theme resolution and text extraction are
  per-frame plumbing.
- `apply_view_command` remains a public compatibility method; no UI path uses it.
