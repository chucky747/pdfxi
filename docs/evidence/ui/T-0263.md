## Protect PDF (A-30, O-04 save half)

`crates/pdfxi-app/src/shell/protect_card.rs` holds `ProtectUiState` and
`handle_protect_command`. `AppCommand::Protect` (`label = "protect"`) explains
"Open a document to protect" without a document and otherwise opens the
**Protect PDF** window.

The card has masked user and owner password fields, checkboxes for printing,
copying, annotations and form filling, **Protect and save as...** (default
`<stem>-protected.pdf`), and a **Remove protection...** section with a password
field and file picker.

`protect_to_path` calls
`pdfxi_security::protect_document(&session_document, ProtectOptions::new(user)
.with_permissions(..))` plus `with_owner_password` when the owner field is
non-empty, and writes the bytes. The permission mapping mirrors the checkboxes:
`print` and `print_high_quality` follow Print, `copy` follows Copy, `annotate`
follows Annotate with `modify = annotate` (the library requires annotation
permission to imply modification), `fill_forms` follows Forms, accessibility
stays granted, and assemble stays false. Empty user and owner passwords are the
library's typed configuration error.

`remove_protection_from` reads the chosen file, calls
`remove_protection(&bytes, password)`, writes `<stem>-unprotected.pdf` beside
it, reports `Protection removed; the decrypted copy is at <path>`, and opens
the decrypted copy through `open_document`.

The saved document is checked with
`pdfxi_security::open_encrypted(&bytes, Some(user_password))`: the correct
password opens with the source page count, the role is `PasswordRole::User`,
and `Permission::PRINT`, `COPY`, `ANNOTATE` and `FILL_FORMS` report exactly the
selected grants and denials. Missing and wrong passwords are typed errors.

## Redaction (A-30, O-06)

`crates/pdfxi-app/src/shell/redact_card.rs` holds `RedactUiState` and
`handle_redact_command`. `AppCommand::Redact` (`label = "redact"`) is the entry;
the Tools row **Redact** is gated by `Capability::Protect` and hidden without a
document, so the command is the reachable path in this build.

**Redact current selection** is enabled only when the page selection has quads
(`selection_quads` is now `pub(crate)`). Each quad becomes
`RedactionMark::new(page, rect)`; `apply_redaction` runs on a cloned document,
`verify_redaction(&candidate, secrets, &report)` checks the result, and the
candidate is written with `save()` (a full rewrite, never an incremental append)
to `<stem>-redacted.pdf` beside the source and opened as a new tab. The source
file is never overwritten. The status reports
`Redacted N area(s) on M page(s); verification: clean` or the survivor details.

Checkboxes default from `RedactionRequest::default()`: images are redacted
(`keep_images = false`), intersecting annotations, links and form fields are
removed, and metadata removal is off unless the user turns it on.

**Sanitize and save as...** calls
`pdfxi_security::sanitize_verified::sanitize_document_full` with
`SanitizeRequest::all()`, writes `<stem>-sanitized.pdf`, reports the removed
categories (`document_info`, `xmp_metadata`, ...), and opens the copy.

## Limits

- Redaction acts on the current text selection only; there is no area-drawing
  tool, no search-and-redact, and no review list before applying.
- The redacted and sanitized copies are new files; the source tab is not
  replaced and the redaction is not part of the source tab's undo history.
- Protect uses the active session document, so unsaved edits are included in the
  protected copy only if the session document already holds them.
- No permission editing after protection and no repair of a damaged encryption
  dictionary.
- The Tools Protect/Redact rows are capability-gated off by default; the commands
  and `--tool=protect` reach the cards.
- No capture is claimed; T-0262 captures the installed build.

## API notes

`ProtectOptions` has no `Default`; the builder is used. `RedactionRequest` has
no builder, so the card builds it from the checkbox fields directly.
`RedactionVerification` reports `SurvivorKind` and detail strings, joined for the
status. `SanitizeReport::removed` exposes `category()`.
