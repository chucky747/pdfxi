# T-0264 - Edit PDF tool UI

Status: served for A-17 (a text edit box on a paragraph; the saved file extracts
the new text) and A-23 (add, move, resize, replace and delete text and image
objects on a real page). No feature row is promoted and no capture is claimed.

Claim: app lane, `crates/pdfxi-app/src/**`, `crates/pdfxi-app/tests/**`, this
file and `orchestration/feature-updates/T-0264.toml`. Target directory
`target/lanes/app9`, features `ui,pdfium`.

## Entry and selection

`crates/pdfxi-app/src/shell/edit_tool.rs` holds `EditToolState`,
`EditSelection` (`page`, `object`, `rect`, `label`), `Handle` (NW/NE/SE/SW) and
`DragMode::{Move, Resize(Handle)}`. `AppCommand::EditDocument` (`label =
"edit-document"`) now calls `handle_edit_document_command`: no document gives
`Open a document to edit`; a document activates the tool and sets
`Edit PDF: click an object`; dispatching again deactivates it.

`edit_hit_test(page, x, y)` lists `pdfxi_edit::content_edit::list_objects` for
the page, flips the canvas y (top-left origin) into PDF space with the page
height, and selects the topmost object whose rect contains the point. Empty
space clears the selection with `Edit PDF: no object at that point`.

The canvas hook is in `shell/document_view.rs::canvas_ui` (the pure layout
`canvas.rs` has no egui pointer handling): while the tool is active, a press
starts a move or a handle resize, drag updates the preview, release commits, and
Delete deletes. A selection rectangle and four corner handles are drawn above
the page rasters, after the find highlights.

## Edits

Every mutation clones the session document, calls the matching
`pdfxi_edit::content_edit` function, commits with
`session.edit(|document| { *document = candidate; Ok(()) })`, then
`after_session_edit(id)` - the `comments.rs::commit_annotation` pattern:

- **Move**: `move_object` with the PDF-space delta from the drag.
- **Resize**: `resize_object` whose scales come from the dragged corner; the
  library anchors at the object's lower-left, so the scale math is anchored
  there.
- **Delete**: `delete_object`, selection cleared.
- **Add text**: the card's text at a clamped 220x28 box through `add_text_box`;
  empty text is a typed `Type the text to add first`.
- **In-place text edit**: double-clicking a selected text object opens an inline
  editor prefilled with the object's text; **Apply text** replaces it with
  `replace_object` (or `replace_run_text` for a run) on a clone and commits.
- **Add image**: **Add image** picks a PNG/JPEG (`rfd`), then the next click
  places it with `add_image` at a 120x120 box; `load_image_file` classifies the
  bytes as PNG or JPEG and rejects other input with a typed error.

Read-only tabs and documents whose permissions deny modification are refused
before any mutation. The card shows the selected kind, page and rect, an error
line, and Done/close deactivates the tool. Clicks inside the last-drawn card rect
are ignored by the canvas handler.

## Limits

- Text replacement rewrites the object's text; there is no font picker, size or
  colour control, and no automatic font embedding beyond what the library does.
- Resize is anchored at the object's lower-left, so a north/west handle drag
  grows rather than moving the opposite edge.
- Object ids are positional; deleting a block renumbers later blocks, so the
  selection is cleared rather than kept after a delete.
- No multi-select, grouping, z-order control, undo grouping beyond the session
  revision, or image replacement in place (delete then add).
- The card and handles are plain egui overlays; no snapping or alignment guides.
- No capture is claimed; T-0262 captures the installed build.

## API notes

`screen_to_canvas` and `active_tab_status` are re-exported from `crate::ui`.
`egui::Window::show` returns `Option<InnerResponse>` in this egui version.
`content_edit::resize_object` scales about the lower-left origin.
