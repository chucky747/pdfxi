# T-0242 - comments and markup UI (verified)

Date: 2026-11-20. Lane: app. Status: verified.

Acceptance covered here: **A-15** (Comments rail with a real count badge),
**A-18** (highlight from a text selection), **A-19** (note with thread popup,
author, time, menu; add/reply/edit/delete/resolve; persists) and **A-24** (the
Comment tool), in all four theme/control combinations. **A-32** (XFDF import/
export and shared-folder review) is out of scope and moves to **T-0246**.

All PDF work is `pdfxi_edit::document_annotations`; the shell owns selection,
presentation and the session commit.

## What is real per control

| Control | Behaviour |
|---|---|
| Comments rail | Enabled with a real badge: annotations across every page, refreshed after open, tab switch, undo/redo and every edit. |
| Comment | Arms the note tool; the next page click opens the **Add comment** draft at that PDF point. Save adds a `/Text` note with the display name as author and a unique `/NM`. |
| Highlight | With a selection, adds one `/Highlight` per selected page from the selected spans; without one it shows a short hint. |
| Comments panel | Grouped by page with page label, subtype icon, snippet, author, human date, resolved checkbox and Delete. A row click scrolls to the page and opens the thread. |
| Thread popup | Anchored beside the annotation, sized to content (max 360 pt wide, auto height), clamped inside the window. Contents, author, date, direct replies (`/IRT`), reply box, Resolve/Reopen, Edit, Delete; Escape closes. |
| Undo/redo, save, reopen | Each action is one `DocumentSession::edit`; one undo removes a note or a deleted thread. Changes mark the tab dirty, use the save/close prompt, and persist. |
| Permissions | Read-only tabs and `/P` masks that deny `ANNOTATE` refuse changes. |

`Edit PDF` moved behind a new, still-disabled `Capability::Edit` so enabling
Comments does not surface a dead button (A-17/A-23 belong to T-0233).

## Neutral author, human dates

- `default_display_name()` is `Reader`; the identity popover still edits it.
  Existing settings keep a saved name (tested), missing keys get `Reader`.
- `/M` is parsed (`D:YYYYMMDDHHmmSS` with `Z`, `+HH'mm'`, `-HH'mm'` or no zone)
  and shown as `YYYY-MM-DD HH:MM`. Zoned values use
  `time::UtcOffset::current_local_offset()`; on this Windows host it works
  (22:03Z displayed as 18:03), with a fallback to the recorded offset. Malformed
  strings are shown unchanged. `time` is MIT OR Apache-2.0 and replaced
  `chrono` after RUSTSEC-2026-0543.

## Stale-canvas defect and fix

The main canvas could keep the previous GPU texture after an annotation edit
even though the thumbnail path regenerated. The fix is at the session boundary:

- `PdfxiApp::after_session_edit(id)` is the single post-edit hook (dirty marker,
  canvas, textures, thumbnails, annotation list).
- `force_canvas_reload()` clears the `(path, revision)` key, then the shared
  refresh invalidates `RasterCache`, drops every `LiveTexture` and reloads the
  renderer from `session.bytes()`.
- `LiveTexture` now also records `render_generation`; a texture is re-uploaded
  when the generation changes even if scale and rotation did not, so no second
  cache can serve stale pixels.
- Regression: `highlight_uses_the_selection_quads` asserts that after
  `AddHighlight` the generation advances, `textures` and `raster_cache` are
  empty, and a raster of the app's current renderer contains yellow pixels.
  `writes_annotated_document_for_captures` also renders the saved page at scales
  0.2/0.5/1.0/1.5 and requires the highlight each time.

## Notes and draft API

The old capture-only launch flags, canned strings and dispatch block are
deleted; no app code path creates annotation text from constants. The only annotation launch flag is the view-only
`--open-annotation=N`, which opens the Nth annotation's thread.

The draft flow is public and testable without a canvas click:
`begin_note_draft_at(page, x, y)`, `set_note_draft_text(text)`,
`note_draft_text()`, then the existing `SaveNoteDraft` / `CancelNoteDraft`
commands. No new command variant was needed; `SaveNoteDraft` is now reachable
from the harness, which no longer has it in `PENDING_COVERAGE`.
