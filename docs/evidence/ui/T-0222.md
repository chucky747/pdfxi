# T-0222 Round A - session-backed save, undo/redo, password prompt, permissions

Date: 2026-11-20. Lane: app. Status: review (Round A complete; the bookmarks
panel is Round B).

Every open document now has a `pdfxi_document::DocumentSession` behind its tab.
The canvas rasterizes the session's current bytes, byte-changing edits go
through `session.edit`, and undo, redo and atomic save are real. No UI action
writes a file except Save / Save As, which run through the session's atomic
writer.

## What is real

| # | Item | Status |
|---|---|---|
| 1 | Session per tab; open through `DocumentSession::open_with_password`; renderer loaded from `session.bytes()`; 2 GiB cap on the app open path | **Real**. `PdfiumRenderer::from_bytes(Vec<u8>)` already existed in `pdfxi-render`, so the app passes a copy of the session bytes; the path loaders are untouched. The renderer cache key is `(path, revision_count)`, so edit, undo and redo re-rasterize the current bytes. |
| 2 | Password prompt: masked field, Open / Cancel, wrong password retries with the typed message, Cancel opens no tab and shows the banner; read-only when permissions deny modification | **Real** modal in `shell/dialogs.rs`. The read-only flag comes from `decryption_report().permissions.allows(Permission::MODIFY)`; unencrypted documents and owner-password sessions stay editable. An encrypted document cannot be saved (`SessionError::EncryptedSaveUnsupported`), and every mutating command reports that. |
| 3 | Save, Save As, Undo, Redo, CloseTab with Save / Discard / Cancel; Ctrl+S, Ctrl+Shift+S, Ctrl+Z, Ctrl+Y, Ctrl+Shift+Z; `*` title; external-change dialog; failed save keeps the tab open | **Real**. `plan_close` is the pure decision; `force_close_tab` performs the discard; `save_tab_by_id` raises the conflict dialog on `ExternallyModified` and keeps the tab open on any error. |
| 4 | Mutations through `session.edit`; prove with the Info title, undo/redo, save | **Real** in `set_active_document_title` (used by the test and by the capture-only `--set-title=` launch flag). Rotation, zoom, page and scroll stay view-only per-tab state and deliberately do not touch the session. |
| 5 | Undo/redo buttons only when `can_undo()` / `can_redo()` | **Real** in the command bar; they dispatch `Undo` / `Redo`. |

`crates/pdfxi-app/tests/**` was not modified; the T-0212 harness still passes.

`Save`, `SaveAs`, `Undo`, `Redo`, `SetDocumentTitle(String)`,
`SubmitPassword(String)`, `CancelPasswordPrompt`, `ResolveClose(CloseChoice)`,
`OverwriteDocument`, `DismissSaveConflict`.

Labels: `save`, `save-as`, `undo`, `redo`, `set-document-title`,
`submit-password`, `cancel-password-prompt`, `resolve-close`,
`overwrite-document`, `dismiss-save-conflict`. `CloseChoice` is re-exported from
`pdfxi_app::ui` for the harness. New public accessors: `password_prompt_open`,
`password_prompt_error`, `active_is_read_only`, `can_undo`, `can_redo`,
`save_conflict_open`, `save_conflict_path`.

checks the dirty marker, undo (clean), redo (dirty), Save As to a temp file,
