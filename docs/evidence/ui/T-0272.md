# T-0272 - enable shipped tools and fix the Pages bookmark layout

Status: verified for A-06 and A-33. No feature row is promoted and no capture is
claimed (capture verification is T-0262).

Claim: app lane, `crates/pdfxi-app/src/**`, `crates/pdfxi-app/tests/**`, this
file and `orchestration/feature-updates/T-0272.toml`. Target directory
`target/lanes/app11`, features `ui,pdfium`.

## Root cause

`Capabilities::available()` in `crates/pdfxi-app/src/shell/capabilities.rs`
enabled Documents, Recent, Bookmarks, Files, Starred, Comments, Forms, Signing
and AssistantConnect only. `tool_rows_for` and `command_bar_features` filter
their catalogues with `capabilities.contains(row.capability)`, so the installed
Tools panel omitted every row gated by Edit, Export or Protect: the user could
not reach Edit PDF, Organize Pages, Export PDF, Convert to PDF, Combine Files,
Protect PDF or Redact. The commands themselves (A-23/A-27/A-28/A-29/A-30) were
already implemented; only the reachability registry was stale.

## Capability set before/after

Before:
`Documents, Recent, Bookmarks, Files, Starred, Comments, Forms, Signing,
AssistantConnect`.

After:
`Documents, Recent, Bookmarks, Files, Starred, Comments, Forms, Signing, Edit,
Export, Protect, AssistantConnect`.

`Capability::Print` was **not** added: grep found no `Capability::Print` gate
anywhere. `shell/command_bar.rs` draws the Print button unconditionally and
dispatches `AppCommand::Print`; the keyboard path in `ui.rs` is unconditional
too. Enabling the capability would have no effect, so `available()` documents
that in a comment.

## Tool rows available to an open document

The new test `ui::tests::available_capabilities_list_every_shipped_tool`
asserts the exact ordered label vector from
`tool_rows_for(Capabilities::available(), "")`:

```
Edit PDF, Comment, Fill & Sign, Place signature, Request signature,
Organize Pages, Export PDF, Convert to PDF, Combine Files, Protect PDF,
Redact, AI Assistant, Document properties
```

The ten rows named in the task are the first ten, in the requested order. Three
more rows actually exist and are listed rather than invented: `Redact` (gate
`Protect`, so it flips on with this change), `AI Assistant` (gate
`AssistantConnect`) and `Document properties` (gate `Documents`).

API note: `tools_panel_rows()` on the app additionally hides Fill & Sign unless
the open document carries an AcroForm, and hides document-dependent rows when
no tab is open. The assertion uses the exact function named in the task,
`tool_rows_for`, which is capability/search only.

## Pages bookmark layout (A-33)

`crates/pdfxi-app/src/shell/bookmarks_panel.rs::bookmarks_section_ui` used one
`horizontal_wrapped` row for Add bookmark, Rename, Delete, Move up and Move down
with no reserved rows, so at 1920x1200 the wrapped controls overlapped the
bookmark text and clipped Move up.

The CollapsingHeader body now wraps its content in
`egui::ScrollArea::vertical().id_salt("pages_bookmarks_body").max_height(220.0)`.
Inside it, the count line (`0 bookmarks`, `1 bookmark`, `N bookmarks`) is its
own row, `ui.add_space(4.0)` separates it from the wrapped button row, and the
rename editor and bookmark rows follow below. Commands and button labels are
unchanged.
