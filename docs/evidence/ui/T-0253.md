## What is real

- Three placements, one command: the command-bar pill ("AI Assistant"), the
  Tools panel row and the rail entry dispatch `AppCommand::AiAssistant`
  (label `ai-assistant`), which opens the assistant panel. Opening the panel
  sends nothing; the probe still requires the explicit Connect action.
- Panel states: the short connect card (`Connect to OpenCode`, last endpoint),
  the full Connect screen from T-0252, and the connected conversation.
- Conversation: the question, the answer, "Thinking..." with a spinner, Stop,
  an ask box with an Ask button and Enter, and a redacted error line. Only the
  typed question is sent; no document text is read or sent in Round A.
- Citations: `page 2`, `p. 2`, `[page 2]` and `[p. 2]` are parsed from the
  answer (ASCII case insensitive, whitespace or a colon after the keyword), kept
  in first-appearance order, deduplicated and bounded. A bare `p` is not a
  keyword (`Appendix P 2` does not cite page 2). Each citation is a chip that
  dispatches `AppCommand::AssistantCitation(page)`, which forwards to
  `GoToPage(page - 1)`, so a click navigates the open document; a chip beyond
  the page count is disabled instead of navigating nowhere.
- Stop: cancels the worker flag, returns to idle immediately and leaves the
  question without inventing an answer. The worker result is dropped with the
  receiver, so a late answer cannot appear after Stop.
- Per-document conversation: `AssistantChat::sync_document` resets messages,
  session, error and any running turn when the active `TabId` changes (open,
  switch, close). Returning to a tab does not resurrect the old conversation.
- One T-0251 session per conversation, reused on the next question; the model
  is the one selected or remembered in settings. A model change on an existing
  session is applied with `set_model` before the prompt.
- `--assistant-question=<text>` is a capture/deep-link path only: it opens the
  rail, starts the explicit connect probe and asks once the service is usable.
  Normal panel opening never sets it (`settings::tests::
  assistant_question_flag_is_a_capture_only_override`).
- The UI thread never blocks: the probe and the turn run on worker threads and
  the frame only drains a channel and requests a repaint while busy.

## Dead-control gate (T-0212) fix

The assistant panel called mutating methods directly from click handlers, so the
static scanner flagged six controls. The fix routes every panel action through
`PdfxiApp::dispatch`, not an allowlist entry:

| command | label | dispatch target |
| --- | --- | --- |
| `AppCommand::AssistantConnect` | `assistant-connect` | `begin_assistant_connect` |
| `AppCommand::AssistantAsk` | `assistant-ask` | `begin_assistant_ask` |
| `AppCommand::AssistantStop` | `assistant-stop` | `stop_assistant_turn` |
| `AppCommand::AssistantDisconnect` | `assistant-disconnect` | `disconnect_assistant` |
| `AppCommand::AssistantSelectModel(String)` | `assistant-select-model` | `select_assistant_model` |
| `AppCommand::AssistantPair` | `assistant-pair` | `start_assistant_pair` |

Wired at `assistant_connect.rs` (connect/reconnect/try again, Disconnect, Pair
and check, model rows), `assistant_chat.rs` (connect card, Ask, the single Stop
control, citation chips) and `ui.rs` (the Escape key handler now dispatches
`AssistantStop`). `AiAssistant` still only opens the panel.

`stop_assistant_turn` now reports "Assistant turn stopped" or "No assistant
turn to stop", so the command always has visible feedback and a headless
dispatch proof can observe it.

The module doc in `shell/commands.rs` lists the new variants and labels for the
interaction harness. `tests/ui_controls.rs` is integrator-owned; the harness
records the six variants in `PENDING_COVERAGE`. Five of them can be promoted to
`all_commands()` + `PROVEN_LABELS` with a `status`/`active_rail` proof on a
fresh app; `assistant-select-model` still needs a connected service and stays
pending. The current pending reasons for connect/ask/stop/disconnect predate the
status reporting and are stale.

thinking row and single Stop while a long answer streamed, with no overlap.

## Limits (Round B unless stated)

- No locked session, no `attach_locked_mcp`, no `BudgetedTools` wrapper; the
  service can therefore not call document tools from this panel yet.
- No document text is read or sent; no summary or "key insights" presets. This
  is why the captures use a greeting instead of a document answer.
- No streaming: Round A sends one prompt and polls the message route. The UI
  shows "Thinking..." until the whole answer arrives.
- Session reuse and `set_model` are implemented (one session per conversation,
  model applied before the prompt) but not yet covered by a test: the loopback
  stub answers only the first prompt of a session. Round B replaces the plain
  session with a locked one and adds the test; until then this evidence does not
  claim a proven reuse test.
- SEC-013 is not promoted; the fragment carries no `promoted_rows`.
- `shell/help.rs` still says the assistant is not enabled in this build, and
  `docs/book/src/privacy.md` still describes the panel as inert with no request
  path. Both are false now and are left for the docs task (the T-0253 notes).
- Citation extraction is text-only; there is no coordinate-based citation to a
  passage. A refusal that mentions "page 2" can still produce a chip; Round B's
  document-grounded answers make the chips meaningful.
- The plain Round A session is not the T-0254 locked session, so no document
  tool call has been exercised from this panel yet.
- A stopped turn drops the worker result but does not delete the session it may
  already have created on the local service; the service expires idle sessions
  itself. Round B's locked-session cleanup should add an explicit delete.
- The Escape/Ctrl+Shift+A accelerators are not covered by a headless test; the
  ask/stop/citation commands they call are. `opening_the_panel_sends_nothing`
  polls without a settle window, so a probe queued but not yet accepted could
  false-pass; `dispatch_opens_the_assistant_panel_without_network_io` is the
  independent guard for the same behavior.
