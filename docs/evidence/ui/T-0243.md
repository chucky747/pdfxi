## 2. Model, caching and errors

- On open, tab switch, undo/redo and every form edit the shell calls
  `pdfxi_forms::read_acroform(session.document())` and caches the
  `AcroFormModel` **keyed by the tab and `DocumentSession::revision_count()`**;
  an unchanged revision does no work.
- Values are committed with `pdfxi_forms::set_text` / `set_checkbox` on a clone
  of the session document, then committed as one `session.edit` -- the same
  clone-then-commit shape T-0242 uses for annotations. The library writes `/V`,
  widget `/AS` and regenerates `/AP /N`; the shell never parses or writes a field
  dictionary and never changes library semantics.
- The library documents that `read_acroform` returns the snapshot it was called
  with, so after a commit the cached model is also updated with the value that
  was actually written. A later revision (undo, tab switch, save/reopen) replaces
  it from bytes.
- Typed failures are surfaced, never swallowed: a malformed AcroForm shows the
  `AcroFormError` message in the panel banner; an unknown, read-only or
  wrong-kind field refuses with one sentence and appends no revision; `/XFA` and
  JavaScript actions produce a notice that they are **not** rendered or
  executed. No XFA and no script is ever run.

## 3. Read-only and permission gate

`form_edit_blocker(read_only, fill_allowed)` is a pure, unit-tested gate:

- the tab is read-only (an encrypted document whose permissions deny `MODIFY`), or
- the document `/Perms` mask denies `FILL_IN_FORM` (`Permission::FILL_FORMS`).

Either refusal paints the widgets without interaction, writes a short hint in the
panel and status line, and leaves the tab clean (no session revision).
Field-level `/Ff` read-only is refused by the library
(`AcroFormError::ReadOnlyField`) and is also checked against the cached model
before the edit, so nothing is appended.

## 5. `--tool=` launch flag

`settings::LaunchOptions` gained `tool: Option<LaunchTool>` parsed from
`--tool=<name>` (case-insensitive, last one wins, unknown values ignored):
`edit`, `comment`, `highlight`, `fill`/`fill-sign`/`fill-and-sign`/`forms`,
`sign`, `organize`, `export`, `convert`, `protect`, `ai`/`assistant`.
`fill` maps to `LaunchTool::Fill`, which dispatches the real
`AppCommand::FillAndSign` after the startup document opens -- the same command the
Tools row emits, so a deep link can never do more than the control. With the
capability off or no document, the dispatch takes the ordinary hint path: no
panic, no placeholder. `LaunchTool::as_str()` returns the stable names, which is
the shape T-0262 can use for every installed tool.

## B2. Choice fields

- The widget is drawn at its real /Rect. A click dispatches FocusFormWidget;
  its handler opens a small window anchored at the widget top-right corner. Its
  buttons come from the cached model /Opt entries and each dispatches
  SetFormChoice; Clear dispatches it with value None. No option list is
  hard-coded in the shell.
- Non-editable choices reject a value outside /Opt before a session edit with
  the hint "choice-field only accepts its listed options."; the library
  (set_choice/set_choice_reported) independently enforces the rule and honours
  CHOICE_EDIT. An editable combo additionally exposes a text box, but only when
  the CHOICE_EDIT flag is actually set.
- Proof: choice_fields_select_options_and_persist_with_appearances selects
  three, clears it, reselects it, saves target/lanes/app3/t0243b-out/choice.pdf,

## B4. Tab order and keyboard

- widget_order(&AcroFormModel) returns (name, widget index, kind, on-state)
  in document order then widget order, skipping Button and Signature.
  focus_transition(order, current, forward) starts at the first/last widget
  for an unknown current focus and wraps at both ends. Both are pure and
  unit-tested (widget_order_uses_document_and_widget_order_and_skips_value_less_kinds,
  focus_transition_walks_wraps_and_handles_unknown_focus) with no OS input.
- The canvas consumes Tab and Shift+Tab only while a form widget is focused,
  requests egui focus for the next widget, paints a second accent ring around
  the focused widget, activates checkbox/radio with Enter or Space, and lets
  Escape leave the field. Typed characters go to the focused text (or
  editable-choice) field. dispatched_round_b_form_commands_act proves
  FocusFormWidget opens the real choice popup headlessly.

## B5. Apply and reset

- Apply is rendered only when form_edit_pending() is true - the focused
  text/choice draft differs from the field value - so there is no permanently
  visible no-op button.
- There is no document-level reset API in pdfxi_forms, so the app walks
  AcroFormModel::fields(), reads FormField::default_value and calls the typed
  setter for each kind (set_text, set_checkbox, set_choice, set_radio) on one
  document clone. Each field Result<(), String> is kept; signature/pushbutton
  fields and radio groups with no on-state default are reported as skipped
  rather than silently changed. The clone is committed once through
  DocumentSession::edit.
- reset_restores_every_default_as_one_undo_step fills all four fields, resets
  and asserts Default text, Off, one, A, then proves one Undo restores every
  changed value and one Redo reapplies all defaults.

## B6. Flatten

- Confirmation is two-click: Flatten... arms forms_flatten_confirm and writes
  "Flattening is permanent. Click Confirm flatten."; only the second click
  dispatches FlattenForm. The pure flatten_blocker(read_only, has_form) gate
  plus form_edit_blocker() refuse read-only documents and documents without a
  form. flatten_is_refused_for_a_read_only_document proves the refusal leaves
  the AcroForm intact.
- flatten is called through the same clone-then-commit session path, and its
  FlattenFormReport counts are shown in the status line and panel.
- flatten_removes_all_fields_but_keeps_values_visible asserts the report
  (fields = 4, widgets >= 4, pages >= 1), has_acroform() == false, one Undo
  restores the form and one Redo removes it again, saves flattened.pdf, reopens
  it with zero fields and renders it in PDFium: the text rectangle
  [72 700 272 720] keeps over 40 ink pixels and the choice rectangle
  [72 600 272 620] keeps over 20, so values remain visible after the widgets
  are gone. The test also re-parses the saved bytes and asserts the active
  catalog has no /AcroForm key. A raw ASCII scan of flattened.pdf can still
  find /AcroForm and /Widget strings (and AcroFormCount=1) because the
  session undo-preserving incremental save retains old, now-unreachable
  objects; flatten removes the active form/fields, not every historical byte.
  A full rewrite would drop those objects. We do not claim byte-level removal.

## B7. FDF / XFDF

- Four native rfd dialog commands (pick_file / save_file). A dialog handler
  always forwards to a testable *_at(Option<&Path>) method; with no window it
  passes None and surfaces the typed NoPath error instead of blocking.
  validate_import_path rejects directories and inputs above 8 MiB with typed
  FormsIoError variants; paths are taken only from the dialog result and no
  network is used.
- XFDF uses document_form::export_xfdf(&model) and
  document_form::import_xfdf(&mut candidate, &input) (unknown names fail with
  AcroFormError::UnknownField, one undo step).
- FDF import uses pdfxi_forms::import_fdf and applies each FdfField by the
  target field kind through the document setters; export builds a legacy
  Form::from_fields with Field::new(...).with_value(...), carrying raw /Ff
  flags so NO_EXPORT fields are skipped, then calls fdf::export_fdf.
- Artifacts in target/lanes/app3/t0243b-out/: export.xfdf (336 B),
  export.fdf (222 B) and the typed-failure inputs unknown.xfdf, unknown.fdf.
  xfdf_export_import_round_trips_and_rejects_unknown_fields and
  fdf_export_import_round_trips_every_value_kind assert the bytes and the
  reopened values; file_dialog_commands_report_a_typed_hint_without_a_window
  proves all four headless paths.
- Faithfulness limit: the legacy Form has no per-widget on-state dictionary,
  so FDF export writes a radio group selected name as a single choice array.
  That is the documented closest real API; the round-trip test proves it
  re-imports to the same group value. No field kind is silently dropped.
