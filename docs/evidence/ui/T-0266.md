# T-0266 - Convert to PDF tool UI

Status: partial for A-28. The Convert to PDF window creates real PDFs from
text, Markdown, HTML and PNG/JPEG sources and is tested end to end. Office input
is unavailable because the app has no Office extractor, so those extensions are
absent from the picker rather than a disabled ghost. No feature row is promoted
and no capture is claimed.

Claim: app lane, `crates/pdfxi-app/src/**`, `crates/pdfxi-app/tests/**`, this
file and `orchestration/feature-updates/T-0266.toml`. Target directory
`target/lanes/app9`, features `ui,pdfium`.

## Entry

`AppCommand::ConvertToPdf` (`label = "convert-to-pdf"`) now calls
`handle_convert_command`: it opens the **Convert to PDF** window and sets
`Convert to PDF: choose files, then Convert`. No document is required because
the command creates one. The Tools row stays gated by `Capability::Export`; the
command and `--tool=convert` reach the card in this build.

## Convert card

`ConvertUiState` in `crates/pdfxi-app/src/shell/convert_card.rs`: `open`,
`sources`, `source_names`, `output`, `page_size_letter`, `title`, `error`,
`progress`. The window has:

- **Add files** (`rfd` multi-select filtered to `png`, `jpg`, `jpeg`, `txt`,
  `md`, `html`, `htm`); Office extensions are absent;
- the chosen files with a **Remove** per row;
- an output row with **Choose output** (`save_file`, defaulting to the first
  source stem + `.pdf`);
- an optional title field;
- a fixed `Page size: Letter` line;
- **Convert**, enabled only with at least one source and an output.

Sources are read and classified when added (`load_sources`): UTF-8 `.txt` and
`.md`, `.html`/`.htm` with their parent as the base directory, and `.png` /
`.jpg`/`.jpeg` bytes. An unknown or missing extension is a typed error naming
the supported set and the missing Office extractor. Because sources are loaded
at add time, the list the user sees is exactly what is converted.

## Conversion

`convert_to_path` sends the loaded sources, in order, to
`pdfxi_convert::convert_to_pdf(ConvertInput::from_sources(..),
ConvertOptions::new() with an optional title)`, writes the result with
`ConvertedPdf::write_to`, returns the page count, sets
`Converted N file(s) to a PDF with M page(s) at <path>`, and records the
`PDF converted` notification. Converter and I/O failures set the card error and
`Convert failed: <error>`; the source list is kept.

## Limits

- Office input is unavailable: `pdfxi_convert::office_import` expects a
  caller-supplied bundle, and the app has no `.docx/.xlsx/.pptx` extractor. The
  picker omits those extensions; loading one by another route reports a typed
  unsupported error.
- Page size is fixed to Letter (the library default); margins and font size are
  not exposed.
- Conversion is synchronous on the UI thread with no progress or cancel.
- The result is not opened automatically after conversion.
- The Tools row is still capability-gated; reach it through the command or
  `--tool=convert` until `Capability::Export` is enabled.
- No capture is claimed.

## API notes

`convert_to_pdf`, `ConvertInput`, `ConvertSource`, `ConvertOptions`,
`ConvertedPdf`, `CreateImageFormat` and `ConvertError` match the brief.
Mismatch: `pdfxi_convert::encode_png` emits RGBA (PNG color type 6), but the
converter's image path rejects PNGs with alpha, so the test embeds a known
124-byte RGB PNG instead of calling `encode_png`; the crate has no JPEG encoder
for test input.
