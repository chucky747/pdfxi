# T-0231 - Organize Pages and Combine Files UI

Acceptance items: A-13, A-14, A-26, A-29. Lane: app. No captures and no git.

## What shipped

`crates/pdfxi-app/src/shell/organize_card.rs` adds two windows over the library
page planner in `pdfxi_core::pages`.

Organize Pages - `OrganizeUiState { open, selection, last_output, error }`.
`AppCommand::Organize` opens it on a real document; with no document the status
is "Open a document to organize". While the card is open the Pages-panel
thumbnail click feeds `organize.selection`: plain click replaces, Ctrl toggles,
Shift fills from the nearest selected page; outside the card it navigates.
Buttons: Rotate left, Rotate right, Delete, Move up, Move down, Extract selected,
Split each page. Insert blank page is reported unavailable because
`PageOperation` has no blank/insert variant.

Combine Files - `CombineUiState { open, sources, output, last_output, error }`.
Add files (rfd multi-select PDF), per-row Remove, `save_file` output defaulting
to combined.pdf, Combine. `combine_to_path` reads each source into a `Document`,
applies `PagePlan::merge(docs[1..])` to `docs[0]`, writes the bytes, opens the
result and returns the reopened page count; fewer than two sources is
`CombineError::TooFewSources`.

## API mismatch

A `PagePlan` rebuilds the page tree with fresh object numbers, so its bytes are a
full rewrite and `DocumentSession::edit` rejects them with
`SessionError::RevisionMismatch`. Page edits commit with
`DocumentSession::edit_full` (ADR 0010 point 5) plus `after_session_edit`. The
tab is dirty and save/save-as works, but undo does not cross the rewrite boundary.

## Limits

- No blank-page insert (no library operation); no pointer drag reorder
  (Move up/down over the multi-select instead).
- Combine takes PDFs only; no image conversion into the merge list.
- Page operations clear undo at the `edit_full` rewrite boundary.
- No capture and no git; the claim stays held.
