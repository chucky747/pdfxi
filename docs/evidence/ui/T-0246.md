## Notifications (A-02)

`crates/pdfxi-app/src/shell/notifications.rs` holds `Notification` (`id`,
`title`, `detail`, `unix_time`, `read`), `NotificationStore` and
`NotificationsUiState`. The store is a tab-separated file at
`%APPDATA%\PDFXI\notifications.tsv` on Windows, `$XDG_CONFIG_HOME/PDFXI/notifications.tsv`
or `~/.config/PDFXI/notifications.tsv` elsewhere, with the OS temporary
directory as the last resort. It is capped at 100 entries, oldest dropped; a
missing, unreadable or corrupt file loads empty. Fields escape backslash, tab
and newline, so a tab in a detail cannot forge a column.

`notify_real_event` lazy-loads the store, records one unread entry, saves it, and
swallows a save failure: a notification can never break the action that raised
it. Every entry comes from an action that actually happened:

- **Document opened** - after `library.record_open` in `open_document_session`.
- **Document saved** - the success paths of `save_tab_by_id`,
  `save_active_as` and `save_forced_active`.
- **Export finished** - `export_card::export_to_path` success, detail is the path.
- **Signature requested** - after `send_signature_request_with` records and saves.
- **Signed copy returned** - `mark_returned_signature` when a pending request matched.
- **Print finished** - the `Ok` branch of `poll_print_job`, with the
  `"Printed N page(s)"` line.

`Icon::Bell` in the title bar dispatches `AppCommand::ToggleNotifications`
(`label = "toggle-notifications"`) and shows the unread count while it is above
zero. The window lists each entry with its `YYYY-MM-DD HH:MM UTC` time, an
explicit **No notifications yet.** empty state, and **Mark all read**; it marks
all read when drawn. `PdfxiApp::new()` (the headless/test constructor) installs
a unique temporary store so tests never touch the user file;
`new_for_window()` uses the platform path, and `set_notifications_path` is the
capture/test injection point.

## Shared folder (A-11)

`settings.shared_folder` is chosen in the title-bar gear popup: the current path
(or `not set`), **Choose folder** (`rfd` folder picker) and **Clear**, persisted
immediately through the app's settings path. `set_shared_folder` is the test
injection point.

`shared_panel_ui` lists the folder's PDFs non-recursively through
`SharedFolderSource::new(root).with_recursive(false).with_max_entries(200).with_extension("pdf")`,
validates each child name, sorts case-insensitively, shows the byte size, and
opens a row through `PdfxiApp::open_document`. It shows **No shared folder
chosen**, **This folder is empty**, and a typed error line for a rejected root
(for example a path containing `..`) or a read failure.

## Shared review (A-32)

For an active document whose canonical path is inside the configured folder the
panel shows a **Shared review** block naming `<stem>.xfdf` as `present` or `not
written yet`:

- **Share review comments** (`sync_review_to_shared_folder`) exports the active
  document's annotations with
  `pdfxi_edit::document_annotations::export_xfdf`, writes `<stem>.xfdf.tmp` and
  renames it to `<stem>.xfdf`, and records a "Review comments shared"
  notification.
- **Import review comments** (`import_review_from_shared_folder`) reads the
  sidecar, clones the session document, imports with
  `import_xfdf(&mut candidate, &xml, author)` where the author is the display
  name (fallback `PDFXI reviewer`), commits with `session.edit` followed by
  `after_session_edit`, and reports `Imported N review comment(s)`. Import is
  enabled only when the sidecar exists and the tab is not read-only.

The existing `AppCommand::ImportXfdfDialog` / `ExportXfdfDialog` still import and
export form field values from T-0243.

## Limits

- Notifications are a local log, not a delivery channel; they are not shown as
  desktop toasts and the list is not synced between machines.
- Shared review is file-based: one XFDF sidecar per document, no locking, no
  conflict merge, no author identity check, last writer wins.
- Only annotations travel in the sidecar; form field values use the separate
  XFDF field import/export commands.
- Import checks the tab's read-only flag but not the ANNOTATE permission bit.
- A hand-edited `settings.toml` root containing `..` is rejected with a typed
  panel error rather than normalized.
- No capture is claimed; T-0262 captures the installed build.

## API notes

`export_xfdf` / `import_xfdf` matched the brief. The review owner is the display
name, not the certificate identity. Preferences live in the title-bar gear popup
in this tree, not a separate Preferences window.
