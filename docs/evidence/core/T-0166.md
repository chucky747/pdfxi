## What closes / what honestly remains

- **STD-005**: `pdfxi-core::conformance` now exposes a stable-coded row check
  that validates caller blend-mode names through `BlendMode::parse` and records
  the colour-management requirement for non-separable modes. `transparency.rs`
  gains a repeated-build determinism test for `TransparencyStack::plans`.
  Remaining at row level: pixel compositing (render lane) — reported as an
  honest unsupported operation, not implemented here.
- **STD-006**: `pdfxi-core::structure` adds a bounded structure-role model,
  `/ParentTree`-style index, canonical token round-trip and typed validation
  (root role, role names, node count, depth, malformed/oversized tokens).
  Remaining at row level: embedding the tree into PDF objects and the reading
  order editor (accessibility lane).
- **STD-007/008/009**: `DocumentFacts` + `ConformancePlan` give deterministic,
  sorted reports with stable codes for version, encryption, output intent, XMP,
  fonts, transparency, forbidden catalog entries and tagging facts. Unknown
  facts yield an `Incomplete` verdict rather than a false pass, and
  `ConformanceOperation::Certify` is a typed unsupported operation. The existing
  `pdfxi-standards` subset profiles remain the richer checker and are unchanged.
  Remaining: ICC byte validation and a veraPDF oracle (STD-007/008); full reading
  order and alt-text verification (STD-009). No certification claim is made.
- **STD-010**: `ConformancePlan` for `StandardRow::IncrementalPreservation`
  emits a deterministic report over the structural-preservation facts and lists
  signing and long-term packaging as honest unsupported operations;
  `PreservationOperation::check` gains a stability/typed-error test. Remaining:
  cryptographic signing and archival packaging (security/application lanes).
