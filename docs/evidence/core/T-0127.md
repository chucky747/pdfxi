## What changed

- `crates/pdfxi-core/src/boxes.rs`
  - New public `normalize_rectangle(Rectangle) -> Result<Rectangle>` orders a
    rectangle's edges into a finite, positive-area box (no panics on reversed,
    non-finite or zero-area input).
  - New public `rectangle_intersection(Rectangle, Rectangle) -> Option<Rectangle>`
    clips two rectangles; disjoint, edge-touching and non-finite inputs return
    `None`.
  - New `PageBoxes::normalized() -> Result<PageBoxes>` applies the ISO fallback
    and containment rules to produce a canonical set that always passes
    `PageBoxes::validate`; explicitness flags are preserved so writes do not
    invent dictionary keys.
  - 6 new tests: edge ordering, non-finite/zero-area rejection, clipping and
    disjoint/edge-touching intersections, canonical/idempotent normalization of
    a hostile hierarchy, inherited CropBox parsing, and typed errors for
    malformed MediaBox/TrimBox arrays.
- `crates/pdfxi-core/src/printer_marks.rs` — 3 new tests: the Form XObject's
  BBox/data match the generated stream, marks embedded as a page content stream
  survive a `Document::save` + reparse round-trip byte-for-byte, four ordered
  CMYK swatches, and typed empty geometry when all mark families are disabled.
- `crates/pdfxi-core/src/lib.rs` — re-export the two new public box helpers.
- `crates/pdfxi-standards/src/document_profile.rs` — module docs now state that
  these profiles are a deterministic **subset preflight, not a certification**;
  3 new tests for PDF/A-3b and PDF/E-1 findings, PDF/X-4 page-box findings with
  page locations, and stable canonical report ordering.
- `crates/pdfxi-standards/src/fixup.rs` — 3 new tests for opt-in fixup
  application to a realistic snapshot, deterministic reporting in request
  order, and the version-below-minimum typed error.

15 new tests total (9 in pdfxi-core, 6 in pdfxi-standards).

## Scope / honest status

Both rows remain `in-progress` in the fragment rather than `verified`: the
core-library scope claimed by T-0127 is complete and thoroughly tested, but the
full user-visible rows also require work that belongs to other lanes or later
tasks and cannot be performed under this task's ownership:

- PRINT-007: no UI/CLI box editing or printer-mark placement surface, no
  print-dialog/imposition consumer of the overlay stream, no user-configurable
  mark styles/inks beyond `PrinterMarkOptions`, no mdBook print-production page,
  and no independent reviewer/security sign-off.
- PRINT-001: no byte-level fixup adapter (both `pdfxi-core` and
  `pdfxi-standards` are dependency-free and cannot link each other without an
  integrator-owned manifest change), no ICC payload validation, no veraPDF CI
  oracle, and no UI/CLI exposure. The fixups deliberately operate on a cloned
  `PreflightInput` snapshot and add placeholders, so the profiles are a subset
  preflight, not a certification.
