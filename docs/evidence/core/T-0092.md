## What changed

1. Hybrid-reference files: when a classic section's trailer contains
   `/XRefStm`, the pointed-to `/Type /XRef` stream is parsed as part of the same
   revision and pushed ahead of the classic table in the newest-wins merge, so
   its type-2 entries replace the classic table's free placeholders. The
   pointer is bounds-checked, type-checked and registered for cycle detection.
   The classic trailer's `/Prev` continues the chain; the stream's `/Prev` is a
   fallback when the classic one is absent.
2. Width validation: `/W` fields are individually capped at eight bytes and
   their sum must be in `1..=16`; a zero sum or an oversized row is rejected
   before any allocation or entry decode.
3. Typed public report: `XrefReport`, `XrefSectionReport` and
   `XrefSectionKind` describe each visited section (kind, byte offset, entry
   count, `/Prev` pointer), the merged entry count, whether any section was a
   stream, and the `startxref` offset. Exposed via `inspect_xref(bytes)` and
   `Document::xref_report()`.

Pre-existing behavior exercised by the new tests: `/W` widths 1–4, multiple
`/Index` subsections, `/Size` fallback, FlateDecode with cap-bounded inflation,
PNG predictors 10–15 through `/DecodeParms`, type-0/1/2 entries, `/ObjStm`
member retrieval with header bounds checks, `/Prev` chains mixing classic
tables and streams, newest-wins merging, cycle detection, out-of-range offsets
and out-of-range compressed indexes.

## Limits and assumptions

- `objstm.rs` exposes writers and planners but no reusable reader API, so
  type-2 expansion continues to use the parser's bounds-checked `/ObjStm`
  reader. Compatibility with the `objstm.rs` writer is proven by a real
  save → reopen round-trip rather than by calling a reader from that module.
- For a hybrid file whose classic `/Prev` and stream `/Prev` disagree, the
  classic pointer wins and the stream pointer is used only when the classic
  one is absent. This is deterministic and matches ISO 32000's hybrid layout,
  where both normally point at the same older section.
- The new report is structural only: it is available even when `/Root` or
  `/Pages` is damaged, but it does not validate page-tree semantics.
