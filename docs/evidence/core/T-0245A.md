# T-0245A evidence — document session signing

- Lane: core
- Claim: `orchestration/claims/T-0245A.json` (held; not released)
- Target dir: `target/lanes/core`
- Scope: `crates/pdfxi-document/**` only. No app, orchestration, shared-doc or
  `Cargo.toml` edits. ADR 0010 point 3 is the design basis.

## Public API added

```rust
impl DocumentSession {
    pub fn sign(
        &mut self,
        identity: &SigningIdentity,
        options: &SignOptions,
    ) -> Result<SignatureReport, SessionError>
}
```

New typed error variant (crate-owned, no semantics change in `pdfxi-security`):

```rust
SessionError::EncryptedSignUnsupported
```

`encrypted_fixture` sessions are refused before any byte is produced: a
signature over the decrypted plaintext would not cover the bytes on disk, so it
would be invalid by construction after reopening.

## Behaviour

- Calls `pdfxi_security::sign_pdf` on the session's `pdfxi_core::Document`
  (`crates/pdfxi-document/src/session.rs`).
- Never calls `edit_full` / `Document::save`; the signed file is the original
  session bytes as an exact prefix plus one incremental revision.
- Enforces the same prefix check as `edit`: the returned bytes must start with
  the unchanged session bytes and append a non-empty delta, otherwise the
  document is reloaded and `RevisionMismatch` is returned.
- On success updates `bytes`, reparses and replaces `document`, sets
  `current_digest = sha256(signed)` (so `is_dirty()` is true), pushes one
  `Revision { start_len, delta, before, after }`, and clears `redo`.
- On any error (`sign_pdf`, prefix, reparse) the unchanged bytes are reparsed,
  so the pre-call document, revision history and redo stack are intact.

## Test

`crates/pdfxi-document/tests/signing.rs`

- `session_signs_saves_reopens_and_detects_tampering`
  (`#[ignore]`, matching `crates/pdfxi-security/tests/pfx_signing.rs`, because
  `crates/pdfxi-security/tests/fixtures/pfx/leaf-aes256.pfx` contains a private
  key and `.pfx` files are gitignored; public password `pdfxi-test-pfx`).

Flow on `fixtures/realworld/microsoft-excel-2019-sample.pdf`:

1. Copy to a temp directory, open with `DocumentSession::open`; capture page
   count and page-1 text, assert it contains `amber compass lantern`.
2. Import `leaf-aes256.pfx`, `sign` with a fixed `signing_time_unix`
   (`1_700_000_000`).
3. Assert the report subject contains `PDFXI Test Signing Identity`, the byte
   range starts at 0, `contents_start < contents_end`, the ranges end exactly at
   the signed file length, `appended_bytes == signed_len - original_len`, and
   `session.bytes()[..original_len] == original` (exact prefix).
4. Assert one revision, undo available, redo cleared, session dirty.
5. `save`, reread the file, assert it equals `session.bytes()`; reopen with
   `DocumentSession::open_bytes` and assert page count and page-1 text are
   unchanged.
6. `verify_signature`: `Valid`, `signature_valid`, `bytes_match`,
   `covers_entire_file`, `!appended_after_signature`, `is_fully_valid`, same
   byte range and signing time as the report.
7. Flip one byte at `contents_start / 2` (inside the first signed range):
   `SignatureStatus::Tampered`, `signature_valid` still true, `bytes_match`
   false.
