## Reviewer fix (medium correctness)

Type-2 xref entries carry the object-stream member index in a two-byte `/W`
field. The previous `MAX_OBJECTS_PER_STREAM` of 1,000,000 allowed a stream with
more than 65,536 members, whose zero-based index would silently wrap to zero
and corrupt xref entries. The bound is now `u16::MAX` (65,535):

- `MAX_OBJECTS_PER_STREAM = u16::MAX as usize` — rejects a per-stream limit of
  65,536 and the old 1,000,000 limit with `Error::CannotSerialize`.
- `plan_object_streams` converts every member index through `u16::try_from`
  before building a `PackedObjectRef`, with a typed error naming the field
  width.
- `XrefEntrySpec::Compressed.index` is now `u16`, so the write path cannot
  represent an out-of-range index; `build_document` also converts through
  `u16::try_from` defensively.
- Regression tests: `object_stream_member_limit_rejects_65536_before_xref_index_wraps`
  (no large allocation: validates the bound with an empty object set) and
  `object_stream_at_the_member_limit_keeps_indices_in_range` (65,536 null
  objects split into two streams; all indices stay inside `u16`).
