# T-0384 - AUTO-008 closed as a documented replacement

- Date: 2026-11-24
- Lane: integrator
- Status: replaced (terminal, per ADR 0014)
- Scope: ADR 0009 row `AUTO-008`. The row asked for a WebAssembly plugin host.
  The plan's locked decision allows the documented ADR-replacement path before
  the lane starts, and the repository already has the sandboxed plugin contract
  this row's user-facing surface needs.

## Decision

ADR 0014 records the replacement:

- manifests are admitted only through the deny-by-default `pdfxi plugin plan`
  gate (closed capability set, invocation budget, six deterministic steps);
- every value crossing back is validated against a typed `OutputBudget` through
  `pdfxi plugin output`;
- no WebAssembly runtime is embedded, no `.wasm` is loaded or executed, and the
  CLI never claims to run one; a future WASM host is a new row.

## Evidence

The existing plugin contract tests, unchanged:

```text
cli::plugin_plan_reports_capability_and_budget_gates
cli::plugin_output_validates_types_and_budgets
plugin_output::tests::execution_plan_is_byte_for_byte_deterministic
plugin_output::tests::oversized_text_and_bytes_are_rejected_with_typed_errors
```

```text
$ cargo test -p pdfxi-cli --test cli plugin_
test result: ok. 2 passed; 0 failed; 0 ignored; 0 measured; ... filtered out
```

The plan report denies a filesystem capability and executes nothing; the output
validator rejects over-budget values with typed errors, which is the same
sandbox boundary a WASM host would have to enforce.
