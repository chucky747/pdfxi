- Date: 2026-11-24

## Certificate

`scripts/new-signing-cert.ps1` created a Code Signing certificate in
`Cert:\CurrentUser\My`:

```text
CREATED code-signing certificate thumbprint=95A135FA8A63BFCDBE7AB9E874BA5D743A4783C3 not_after=2029-11-24
```

`scripts/trust-signing-cert.ps1` added the public part to the current user's
Root and TrustedPublisher stores through the .NET `X509Store` API, so the step
works unattended (certutil's Root-store add can open a UI prompt):

```text
TRUSTED thumbprint=95A135FA8A63BFCDBE7AB9E874BA5D743A4783C3 (CurrentUser Root + TrustedPublisher)
trust_exit=0
```

A direct signing smoke on a copy of the release CLI:

```text
sign_status=Valid
sign_msg=Signature verified.
verify_status=Valid
signer=CN=PDFXI Local Build, O=PDFXI
timestamped=True
```

## Package hook

`scripts/package.ps1` signs `pdfxi.exe` and `pdfxi-ui.exe` after the build and
before staging, so the manifest and zip contain the signed bytes. It signs the
Inno Setup executable before writing its `.sha256` sidecar. Each signature is
verified with `Get-AuthenticodeSignature`; a non-`Valid` status throws. With no
thumbprint it prints `SIGNING skipped: PDFXI_SIGN_THUMBPRINT not set (unsigned
build)` and never pretends to have signed.

the unsigned state explicitly.

## Honest scope

This is a local self-signed publisher. It is tamper-evident and locally
verifiable after `scripts/trust-signing-cert.ps1`, but it is **not** a publicly
trusted publisher. Other machines do not trust the certificate and SmartScreen
may still warn there. T-0202 records this distinction; a public OV/EV
certificate is still required for distribution. The 0.1.4 package used for the
signing test is not the final release; 0.1.5 will be signed with the same
certificate.
