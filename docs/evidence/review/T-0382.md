# T-0382 - CREATE-008 real OCR engines reachable from the CLI

- Date: 2026-11-24
- Lane: integrator
- Status: verified
- Scope: ADR 0009 row `CREATE-008`. The searchable-PDF pipeline and the
  `--words` contract existed; every recognition result had to be supplied by
  the caller. `pdfxi create ocr` now recognizes the image itself with a real
  engine.

## Changes

- `crates/pdfxi-cli/src/ocr.rs`
  - `--engine auto|tesseract|windows`. `tesseract` runs the installed Tesseract
    CLI (`tesseract IMAGE stdout -l TAG tsv`) and parses level-5 TSV rows into
    word boxes and confidence. `windows` runs the bundled
    `scripts/windows-ocr.ps1` sidecar over the built-in Windows.Media.Ocr
    engine. `auto` prefers Tesseract and falls back to Windows OCR with one
    actionable error if neither works.
  - The sidecar is embedded with `include_str!` and written to the OS temp
    directory at run time, so an installed CLI does not depend on the
    repository layout. Tesseract's ISO 639-2 tags are mapped to Windows BCP 47
    base tags (`eng` -> `en`, `deu` -> `de`, `chi_sim` -> `zh-Hans`).
  - `--words` is now optional: with it the old caller-supplied path is
    unchanged; without it `--engine` recognizes the image.
- `scripts/windows-ocr.ps1` - WinRT sidecar: reads the image with
  `BitmapDecoder`, runs `OcrEngine`, and prints
  `{"language": "...", "words": [{"text", "x", "y", "width", "height",
  "confidence"}]}`. The WinRT API does not expose per-word confidence, so the
  sidecar reports 100 and this is documented. It exits 3 when no engine or
  language pack exists.
- `crates/pdfxi-cli/src/main.rs` - `render --format jpeg`, so a real page can
  be rasterized to a non-alpha image the OCR engine and the image embedder both
  accept.
- Four parser tests: Tesseract TSV keeps level-5 words with boxes and
  confidence and rejects non-TSV/empty output; the Windows JSON contract parses
  and rejects empty/invalid output; Tesseract tags map to Windows tags.

## Limits

Tesseract is used when installed; the silent installer on this host needs
elevation and was blocked, so the recorded run uses the built-in Windows OCR
engine. The Windows engine exposes no per-word confidence, so its words report
100 and are not filtered by the confidence policy. One image page per command;
Latin-1 invisible text; no deskew or rotation detection.
