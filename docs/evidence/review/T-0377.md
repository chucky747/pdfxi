# T-0377 - REVIEW-007 review tracker reachable from the CLI

- Date: 2026-11-24
- Lane: integrator
- Status: verified
- Scope: ADR 0009 row `REVIEW-007`. The tracker model and participant
  summaries existed in `pdfxi-edit::review`; no CLI or GUI caller existed. This
  adds the CLI caller and a real reply/state write path.

## Changes

- `crates/pdfxi-cli/src/review.rs` (new) - `pdfxi review status FILE [--json]`.
  Loads real PDF bytes, lists annotations on every page, rebuilds threads from
  `/IRT` links (roots are annotations without a parent), maps `/State` into the
  review workflow (`Accepted`/`Marked` -> resolved, `Completed`, `Rejected`,
  `Cancelled`, anything else -> open), and reports the five-status board,
  participant roster and deterministic digest through `ReviewTracker`. Orphan
  replies become their own visible thread instead of being dropped.
- `crates/pdfxi-cli/src/annotate.rs` - `pdfxi annotate reply FILE --out PATH
  --page N --parent NM --text TEXT [--author NAME] [--state accepted|...]
  [--json]`. Writes a real reply with `reply_to` and sets the parent's `/State`
  with `set_state`, so a script can drive the workflow the tracker reads.
- `crates/pdfxi-cli/src/main.rs` - `review` command group and the `reply`
  subcommand wiring.
- Two CLI regression tests: a round trip over a real annotated fixture
  (thread, reply, resolved state, roster, digest) and an empty tracker on a
  document with no annotations.

## Limits

The tracker is derived from the annotations saved in one document. Shared or
email synchronisation, assignment, and a tracker panel in the GUI remain out of
scope; the GUI comments rail still shows threads without the tracker board.
Windows x86_64 is the only verified host.
