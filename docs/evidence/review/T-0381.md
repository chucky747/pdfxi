# T-0381 - VIEW-006 split and tile panes in the GUI

- Date: 2026-11-24
- Lane: integrator
- Status: verified
- Scope: ADR 0009 row `VIEW-006`. The split/tile geometry model and pane state
  existed and were tested, but the GUI had no control and the canvas always
  painted one pane. This connects them.

## Changes

- `crates/pdfxi-app/src/ui.rs`
  - `SplitView` stores the `SplitLayout` plus one scroll offset per pane.
  - `PdfxiApp::split` holds the active split; `set_split` builds a vertical
    (side-by-side) or horizontal (stacked) layout at the default 50% ratio, and
    clears it for a single pane. `split_choice` reports the selected choice for
    the picker.
- `crates/pdfxi-app/src/shell/document_view.rs`
  - `canvas_ui` is now the split-aware wrapper: it resolves the pane geometry
    through `SplitLayout::geometry`, paints the active tab twice with each
    pane's saved scroll offset, saves each pane's scroll back, and fills the
    divider rectangle with the palette border. The old body is
    `canvas_content_ui`, used for the single-pane path and both panes.
- `crates/pdfxi-app/src/shell/commands.rs` - `SplitChoice` (Single pane, Side by
  side, Stacked) and `AppCommand::SetSplit` with the stable name `set-split`.
- `crates/pdfxi-app/src/shell/bottom_bar.rs` - a `Split view` combo next to the
  page-layout picker; it dispatches `SetSplit` and carries an AccessKit label.
- `crates/pdfxi-app/src/ui/widget_tests.rs` -
  `bottom_bar_split_picker_creates_and_clears_two_panes` drives the real combo:
  switches to Side by side and asserts the split is active and the status
  reports it, then switches to Single pane and asserts it cleared.
- `docs/book/src/gui.md` - the navigation section names the Split view picker.

## Limits

Two panes in one window; there are no OS-level top-level windows and no tile
grid larger than 2x2 in the GUI (the model supports it, the picker exposes the
two-pane splits). Windows x86_64 is the only verified host.
