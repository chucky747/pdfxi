# T-0380 - REVIEW-001 note, highlight, underline, strikeout and squiggly in the GUI

- Date: 2026-11-24
- Lane: integrator
- Status: verified
- Scope: ADR 0009 row `REVIEW-001`. Note and highlight were real and already
  reachable from the GUI. Underline and strikeout had library writers but no
  caller; squiggly had only a model variant. This adds all four markup tools to
  the GUI on a real text selection.

## Changes

- `crates/pdfxi-edit/src/document_annotations.rs` - `TextMarkup::Squiggly` and
  the public `add_squiggly` writer. The appearance strokes a small zigzag along
  the bottom edge of each quad (4-96 segments by quad width), so viewers that do
  not synthesise appearances still draw a wavy underline. `line_offset` shares
  the underline baseline.
- `crates/pdfxi-edit/src/lib.rs` - export `add_squiggly`.
- `crates/pdfxi-app/src/shell/comments.rs` - `MarkupKind` (Highlight, Underline,
  Strikeout, Squiggly) with `label`, past-tense status text and a single `apply`
  that calls the matching library writer. `markup_selection(kind)` generalises
  the old `highlight_selection`; a missing selection explains which tool to use
  and adds nothing. The Comments panel now shows four small buttons that
  dispatch `AddHighlight`, `AddUnderline`, `AddStrikeout` and `AddSquiggly`.
- `crates/pdfxi-app/src/shell/commands.rs` - the three new commands with stable
  names `add-underline`, `add-strikeout`, `add-squiggly`.
- Two regression tests: all three new tools create one annotation of the right
  subtype from a real selection with the expected status, and a missing
  selection explains and adds nothing.

## Limits

All five tools apply to an existing text selection and write standard PDF
annotation dictionaries with appearance streams. Freehand pencil, shapes and
stamps remain separate tools. Windows x86_64 is the only verified host.
