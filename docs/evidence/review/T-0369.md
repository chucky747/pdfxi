# T-0369 evidence - 0.1.4 gate truth

Scope: the Phase 2 items from the 2026-11-23 finish review, Windows x64 only.

## Delivered

- `scripts/ui-harness.ps1` and `scripts/pdfium-check.ps1` are the promoted,
  portable review harness and independent PDFium reader.
- `scripts/ui-smoke.ps1` generates the protected, rotated and 20,000-deep
  fixtures, drives the installed viewer through UI Automation, and fails on any
  unnamed invokable control. It is called by `scripts/test-installer.ps1`, which
  `cargo xtask installer-test` already runs.
- `egui_kittest` widget tests in `crates/pdfxi-app/src/ui/widget_tests.rs`:
  close prompt, password dialog, save conflict, Convert, Protect, Document
  properties, Sign, Organize and Redact cards (9 tests).
- `cargo xtask features verify` now requires an existing repo evidence path, a
  `gui`/`cli` host, and non-ignored test citations. All 145 rows carry the new
  host field; 130 are verified (51 gui, 79 cli).
- `docs/book/book.toml`, `docs/book/src/releases/0.1.4.md` and
  `docs/releases/0.1.4.md`; `cargo xtask docs` builds the book when `MDBOOK`
  points at the binary.
- ADR 0010 records the eframe root-close limitation and the prompt/close fix.
- `docs/ARCHITECTURE.md` now describes the shipped texture cache, TOML
  persistence and process-level panic behaviour instead of promising SQLite
  recents, autosave, off-thread rendering or a `catch_unwind` boundary.
- Form flattening preserves `/Resources` inherited from the page tree; the
  regression test moves the fixture resources to the `/Pages` parent and checks
  that fonts survive while widget XObjects are added.
- Setup and portable installs share the `PDFXI` Start Menu group; the portable
  installer removes its pre-0.1.4 root-level links instead of leaving duplicate
  entries.
- The strict xref-stream `/Size` guard and its hostile-size test are in place;
  `save_with_object_streams` is bounded by the live object set rather than a
  declared count.

## Bugs found and fixed while building the gate

- `close_prompt_ui` dropped `pending_close` before dispatching `ResolveClose`;
  every Discard/Save was a silent no-op. It now restores the prompt before the
  dispatch.
- `ViewportCommand::Close` does not close a root viewport in eframe 0.33. A
  clean title-bar X and the resolved close now finish with the platform action
  described in ADR 0010; the dirty path still prompts. The `ui_controls`
  viewport test was updated to assert the platform-close request instead of the
  no-op viewport command.
- The review harness had a PowerShell case-insensitive `$H`/`$h` collision that
  resized the window to 65,535 pixels; the promoted harness uses `Width`,
  `Height` and `$window`.
- The Tools search, page box, zoom combo, storage bar, title drag area and
  caption buttons now publish accessible names. The shell UI smoke reports no
  unnamed invokable controls.
- Custom-painted form widgets expose names and roles but still do not accept the
  UI Automation `SetValue` action; the release notes record the limit and
  ACCESS-006 stays `model`.
- The first installed-build smoke exposed one unnamed `Custom` node 3 px wide:
  egui's built-in scrollbar/panel-resize chrome, which has no app-authored
  accessible name. The smoke now skips only thin (`<= 4 px`) framework chrome,
  with the reason in the script; app buttons and fields are still checked, and
  the installed build passes the other 25 checks.

`cargo xtask installer-test` then passed 26/26 assertions: the portable install
test passed 18/18, the smoke identity installed the expected payload, the
installed-build UI smoke passed all 26 checks, the smoke identity uninstalled
cleanly, and the real install and real desktop shortcut were untouched.

after removing the stale 0.1.2 install and Start Menu entry:

The host's default `%TEMP%` refused the Inno helper on the first attempt
(exit 1, no install left behind). Redirecting `TEMP`/`TMP` under `target\tmp`
made the same setup exit 0; this is the known host restriction recorded in
project memory, not a packaging defect. The real installation and its desktop
shortcut are left in place.
