# T-0371 - local CI replaces GitHub CI

- Date: 2026-11-24
- Lane: integrator
- Status: verified
- Scope: remove the GitHub-CI concept from the plan/testing docs and add the
  complete local gate.

## Changes

- `docs/PLAN.md`: M0 now names the local CI gate (`cargo xtask ci`) instead of
  `CI`.
- `docs/TESTING.md`: the Nightly and Release tiers no longer say `CI`; a new
  "Local CI" section documents the command and the opt-in nightly scheduler.
  The corpus table says "nightly only" instead of "CI only".
- `docs/features.toml`: PLAT-002 no longer cites the nonexistent
  `.github/workflows/ci.yml` and its note no longer refers to GitHub CI.
- `xtask/src/main.rs`: added `cargo xtask ci`. It runs
  `verify` (fmt, clippy, workspace tests, feature tests, `cargo doc -j 1`,
  feature matrix), `docs` (mdBook when `MDBOOK` is available), `bench`,
  `installer-test`, the NVDA screen-reader smoke, and the signature check when
  `PDFXI_SIGN_THUMBPRINT` is set. It writes `target/ci/ci-report.md` and exits
  non-zero on the first failure.
- `scripts/register-local-ci.ps1`: opt-in Windows Task Scheduler wrapper for
  the nightly tier; `-Remove` unregisters, `-At`/`-TaskName` customize it.

No `.github/` directory exists and no workflow was added.

The first run failed because the new signing hook contained
`"failed for $Path: ..."`; PowerShell parsed `$Path:` as a drive-qualified
variable. The message now uses `${Path}`. The second run is the evidence above.

The nightly scheduler script parses cleanly and is opt-in:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/register-local-ci.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/register-local-ci.ps1 -Remove
```

It resolves `cargo.exe` and the repository root at registration time and stores
no machine-specific path in the repository.
