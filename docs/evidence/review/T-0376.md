# T-0376 - STD-007 PDF/A conformance reachable from the CLI

- Date: 2026-11-24
- Lane: integrator
- Status: verified
- Scope: ADR 0009 row `STD-007`. The ICC validator and the profile checks were
  library-only. `pdfxi preflight` and `pdfxi export conformance` are the CLI
  callers; this records real runs on real fixtures and promotes the row on the
  `cli` host.

## Commands

```text
pdfxi preflight <PROFILE> <INPUT> [--fix] [--output PATH] [--json]
pdfxi export conformance <INPUT> --profile <PROFILE> --out <PATH> [--json]
pdfxi color intents <FILE> [--json]
```

`--fix` applies the byte-expressible normalizations and writes a new file; the
recheck drops from three errors to the one finding bytes alone cannot fix:

```text
$ pdfxi preflight PDF/A-2b fixtures\realworld\pdfxi-forms-selfmade.pdf --fix --output target\tmp\std-007\forms-preflight.pdf --json
fix_exit=2
$ pdfxi preflight PDF/A-2b target\tmp\std-007\forms-preflight.pdf --json
  "profile": "PDF/A-2b",
    "error_count": 1,
    "findings": [
        "severity": "error",
```

The normalized file's embedded output intent validates through the colour
command:

```text
$ pdfxi color intents target\tmp\std-007\forms-norm.pdf --json
{
  "file": "target\\tmp\\std-007\\forms-norm.pdf",
```

its own report:

## Limits

Subset preflight only. Font embedding, ICC payload semantics, transparency,
colour spaces, content-stream semantics and certification remain out of scope,
and every report says `certification_claimed: false`. veraPDF is an external
oracle, not a runtime dependency. Windows x86_64 is the only verified host.
