# T-0379 - VIEW-012 presentation mode reachable from the GUI

- Date: 2026-11-24
- Lane: integrator
- Status: verified
- Scope: ADR 0009 row `VIEW-012`. The presentation state machine, layout, key
  mapping and full-screen painter were already implemented in `ui.rs`, but the
  only way to enter the mode was the `--present` launch flag. The bottom bar now
  has a Present control.

## Changes

- `crates/pdfxi-app/src/shell/commands.rs` - `AppCommand::StartPresentation`
  with the stable command name `start-presentation`; dispatch calls
  `apply_launch_presentation(true)`, the same entry point the launch flag uses.
- `crates/pdfxi-app/src/shell/bottom_bar.rs` - a `Present` icon button next to
  Full screen. It dispatches `StartPresentation`.
- `crates/pdfxi-app/src/design.rs` - the `Present` glyph (a screen outline with
  a play triangle).
- `crates/pdfxi-app/src/ui/widget_tests.rs` -
  `bottom_bar_present_button_enters_presentation_mode` renders the real bottom
  bar, clicks the real `Present` control by its AccessKit label and asserts
  `is_presenting()`.
- `docs/book/src/gui.md` - the navigation section names the Present control and
  Escape as the exit.

The GUI mode itself is the existing `update` path: it requests a full-screen
viewport, captures Space/Enter/Page Down/Right/Down/Page Up/Left/Up/Home/End/
Escape/A, ticks auto-advance from `stable_dt`, paints the slide on black from
the page raster cache, and restores the window decoration on exit.

## Matrix and docs

## Limits

Full-screen presentation is a single-window mode on Windows x86_64. Multi-monitor
presenter view, slide transitions animation, and embedded video playback remain
out of scope.
