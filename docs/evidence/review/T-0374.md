# T-0374 - EXPORT-006 reachable from GUI and CLI, including TIFF

- Date: 2026-11-24
- Lane: integrator
- Status: verified
- Scope: ADR 0009 row `EXPORT-006`. The renderer already wrote TIFF; the
  converter, GUI export card and CLI `render` did not reach it.

## Changes

- `crates/pdfxi-convert/src/pdf_export.rs`
  - `ExportFormat::Tiff` added to `ALL`, `implemented()` (with `pdfium`),
    `is_image()`, `extension()` (`tiff`), `media_type()` (`image/tiff`) and
    `label()` (`TIFF image`).
  - The image dispatch maps `Tiff` to `ImageFormat::Tiff`,
    `ColorMode::Rgba`, `AlphaPolicy::Preserve` and emits a single `document`
    part, because the renderer batches every selected page into one IFD chain.
  - New regression test `tiff_export_batches_all_selected_pages_into_one_file`
    exports the three-page `powerpoint-slides.pdf` and asserts one part, a
    little-endian TIFF header, a non-trivial size and `is_single_file()`.
  - The feature-availability test now covers nine formats with `pdfium` and six
    without.
- `crates/pdfxi-app/src/shell/export_card.rs`
  - `ExportChoice::Tiff` added to `ALL` (nine targets), with the label
    `TIFF images (.tiff)`, the `tiff` extension and `ExportFormat::Tiff`.
  - `every_export_choice_writes_real_bytes` asserts the `II*\0` header for the
    new choice.
- `crates/pdfxi-cli/src/main.rs`
  - `pdfxi render --format tiff` added; it reuses
    `pdfxi_render::encode_image` so the CLI writes the same layout as the export
    pipeline, with the TIFF resolution tag derived from `--scale`.
- New CLI regression test `render_writes_a_single_page_tiff_with_the_same_geometry`
  checks the header, the IFD offset, a full tag table, and that the TIFF width
  and height tags equal the PNG raster of the same page.

## Limits

TIFF output is uncompressed and single-IFD-chain; LZW/Deflate compression and
separate-file-per-page TIFF are not implemented. Windows x86_64 remains the only
verified host.
