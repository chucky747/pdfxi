# T-0360 — Explicit ADR-bound replacement notes (`CREATE-011`, `CREATE-012`)

Work item W-4 of the PDFXI close-out. Both rows keep `status = "replaced"`:
ADR 0008 and ADR 0009 declare that retired Adobe-specific integrations are
delivered as local, file-based equivalents, and the replacement is the accepted
terminal state. This task makes that terminal state explicit in the matrix, in
the user guide, and in evidence.

## What was wrong

- `CREATE-011` still said "No CLI exposure in this task." That sentence was
  true for T-0107 but is stale now: `pdfxi watch` converts `.html`/`.htm`
  through `capture_html_markup`, while `capture_html_file` and
  `capture_mhtml` remain library APIs.
- `CREATE-012` described the library adapter but did not say that it has no
  CLI host yet.
- ADR 0008 requires rustdoc **and mdBook** coverage for a `replaced` row; no
  mdBook page documented either replacement, and neither row cited one.

## What changed

- `docs/book/src/tools/convert-to-pdf.md`: new "Retired capture features"
  section documenting the local HTML/MHTML capture adapter and the `.eml`
  ingestion adapter, their host reachability, and the ADR 0008/0009 terminal
  status. No network, browser extension, mail client or active content.
- `docs/features.toml` (via fragment `T-0360`): both rows now cite the book
  page in `docs`; `CREATE-011`'s note names the real CLI reachability; both
  notes say the status is terminal per ADR 0008/0009 and name the local
  replacement.

Statuses and tests are unchanged: the 9 `capture::tests::*` and 9
`email::tests::*` citations still resolve and pass.
