# T-0361 — Retire the print-test skip (W-2)

Close-out work item W-2: the campaign's manual gate transcripts always used
`cargo test --workspace --all-features -- --skip
prints_first_page_through_microsoft_print_to_pdf`. This task establishes the
real state, retires the skip, and records it.

## Findings

1. The standard gate never used the skip. `xtask/src/main.rs` `verify()` runs
   `cargo test --workspace`, then `run_feature_tests()`, which runs
   `cargo test -p pdfxi-app --features ui,pdfium` and
   `cargo test -p pdfxi-render --features pdfium` with no `--skip` and no
   `#[ignore]`. The test is `#[cfg(all(windows, feature = "pdfium"))]`, so the
   default-feature workspace run compiles it out and the feature run executes
   it.
2. The skip was a host-session workaround copied from
   `orchestration/blockers/ENV-gui-session-wedged.md` into evidence transcripts;
   it was never an xtask behaviour.
3. The wedged print path has recovered. The test now passes in both commands.

## Evidence

Standard gate, `cargo xtask verify` (no skip anywhere):

```text
$ cargo test -p pdfxi-app --features ui,pdfium
test print::backend_tests::prints_first_page_through_microsoft_print_to_pdf ... ok
...
FEATURES OK: 145 rows, 143 verified
VERIFY OK
VERIFY_EXIT=0
```

Full workspace with every feature, no skip:

```text
$ cargo test --workspace --all-features
test print::backend_tests::prints_first_page_through_microsoft_print_to_pdf ... ok
...
green_suites=79
tests_passed=4130
NOSKIP_TEST_EXIT=0
```

No `test result: FAILED` and no `failures:` block appears in either log
(`target/tmp/closeout-verify.log`, `target/tmp/closeout-full-noskip.log`).

## Decision

No ADR or feature gate is needed because the test is green again. The skip is
retired: future gate transcripts use the plain commands above. The blocker keeps
only the GUI-window part open (W-6), and its print section is marked resolved.

## Scope

No source, test, or matrix changes. Documentation and blocker accuracy only.
