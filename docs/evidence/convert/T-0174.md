## Delivered

Five new library-contract modules in `crates/pdfxi-convert/src/`, plus
re-exports and crate docs in `lib.rs`. No other crate and no shared file was
edited.

| Module | Rows | What it adds |
|---|---|---|
| `create_assembly.rs` | CREATE-001, CREATE-002 | `PdfAssemblyPlan` joining the print-job envelope and captured page set: media resolution, per-page validation, requested-page reconciliation, fit/scale placement, collated copies, byte-stable summary |
| `office_contract.rs` | CREATE-006 | Envelope validation, canonical adapter target per office kind, path-safe output part names, typed unsupported constructs, strict mode |
| `portfolio_builder.rs` | CREATE-010 | Case-insensitive add/remove/describe/order operations, validation, byte-stable serialized manifest |
| `postscript_contract.rs` | CREATE-013 | `PsAssemblyPlan` with per-page construct counts, media box, ordinal page order, typed unsupported constructs, strict mode |
| `watched_contract.rs` | CREATE-014 | `WatchedConfig::validate` (rooted, traversal-free, safe extensions, nonzero budgets) and a deterministic per-file watched plan |

25 new tests cover determinism, negative validation, typed unsupported
constructs, budget enforcement and collated ordering.

## Status decision

- **CREATE-001, CREATE-002, CREATE-006, CREATE-013, CREATE-014 -> verified.**
  Every capability these rows name that can exist inside the libraries is
  implemented, tested, documented and evidenced. The remainder is host-only
  (native window capture, OS printer driver/spooler, external Office or
  PostScript process, OS watcher loop, CLI/UI wiring) and is listed verbatim in
  each row's notes. This follows the row verification policy recorded in
  `docs/ASSUMPTIONS.md`.
- **CREATE-010 -> in-progress.** The manifest creation/customization contract is
  complete and deterministic, but the actual PDF package assembly
  (`/EmbeddedFiles` name tree, `/Collection` dictionary, embedded file streams)
  is a library-level capability the row names and is still missing. It is queued
  as a follow-up task rather than over-claimed here.
