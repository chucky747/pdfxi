## Why this page set exists

`docs/book/src/security.md` described the security crates as model-only and
stated that the viewer had no password prompt, no production signer, no
document-level redaction and no raster image removal. Every one of those
statements was false against the committed evidence, and the page's blanket
"none of them is available" framing mixed three different states: reachable in
the viewer, implemented and tested at document level with no viewer control, and
not implemented. The rewrite separates them instead of collapsing them.

## Discrepancies resolved during the rewrite

1. **T-0221's settings table says `display_name` defaults to the OS account
   name.** The implementation and its test use the neutral `Reader`
   (`settings.rs` doc comment: "Comments and signatures must not leak the
   platform account name by default";
   `avatar_initials_use_up_to_two_words` asserts `"Reader"`). The page follows the
   implementation and cites it; T-0221's table is stale on that one default.
2. **`docs/ARCHITECTURE.md` Persistence says recents/favourites use SQLite.**
   The shipped app uses `%APPDATA%\PDFXI\library.toml` (T-0221). The page cites
   the shipped file, not the architecture target.
3. **The parent correction said signing and redaction are reachable.** T-0241 and
   T-0237 are document-level `library` results, and the viewer dispatches
   `Sign` and `Protect` to `not_available`
   (`crates/pdfxi-app/src/shell/commands.rs`). The pages therefore state:
   implemented and tested on real documents, no viewer control in this build.
   Calling them reachable would contradict both the shell and `SEC-005`/
   `EDIT-013`. The blanket "none is available" text is still gone.
4. **`security.md` previously claimed form recursion and opaque-rectangle
   painting.** T-0237 does the opposite: no form recursion (fail closed) and
   content removal, not a painted rectangle. The rewritten page states the
   actual behaviour and the fail-closed matrix.

  than describing how it behaves.

  committed evidence file. PFX source files exist uncommitted in
  `crates/pdfxi-security` at the time of writing, but no result, test transcript
  or row change is committed, so the page says PFX is not available and claims
  none of its behaviour.
- **No trust-anchor, RFC 3161 or revocation behaviour in a PDF signature.**
  T-0267 is `queued` and has no evidence file. `SEC-006`/`SEC-007` are `model`
  rows with model-level tests, not a signature-validation pipeline; the page
  claims neither.
- **No claim that a 24-hour fuzz run happened.** Only the deterministic smoke
  runner and the release requirement are documented.
- **No claim about log contents beyond the wrapper message.** T-0202 records the
  message being appended; broader log redaction is not evidenced here.
- **No claim that signing identifies a person.** The evidence has no trust
  anchor and a self-signed test identity only.
- **No claim that redaction output is clean without running the verifier.**
  The page requires the caller to verify and states fail-closed limits.
- **No evidence for a Disconnect control.** None exists; the page says so.
