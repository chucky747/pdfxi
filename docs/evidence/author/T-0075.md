## Notes

- Implementation lives entirely in `crates/pdfxi-accessibility/src/structure.rs`
  and is re-exported from `crates/pdfxi-accessibility/src/lib.rs`. This is the
  crate that owns the validated `A11yTree` (`T-0055`); the workspace rules forbid
  editing the integrator-owned `Cargo.toml` to add a cross-crate dependency, so
  the writer accepts `&A11yTree` directly and defines its own dependency-free
  PDF value intermediate.
- The writer produces `/StructTreeRoot`, ordered `/K` kids, `/StructElem` per
  node, `/ParentTree` + `/ParentTreeNextKey`, `/RoleMap`, `/Alt`, per-page
  `/StructParents`, `/Lang`/`/MarkInfo`/`/ViewerPreferences`, and MCID overlay
  bytes. `compose_page_content` only appends, so existing content bytes are an
  untouched prefix. `read_structure_tree` reconstructs the exact `A11yTree`.
- No `unwrap`/`expect`/`panic` in non-test code, no unsafe, no external deps.
- STD-006 stays `in-progress`: no editor UI or PDF-UA validation oracle yet.
