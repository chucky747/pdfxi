# T-0357 — Flatten host: real annotations into content (`EDIT-012`)

Row promoted: `EDIT-012` (Flatten annotations and form fields) `model` ->
`verified`.

The row had the complete headless flatten model in `pdfxi_edit::flatten`, with
its own note stating the boundary: "Headless flatten backend; /Rotate applied by
the viewer only, AcroForm kept when untouched widgets remain." The model
deliberately has no PDF object store, so nothing user-reachable existed. This
task supplies the writer.

## 1. Host

```text
pdfxi flatten FILE.pdf --out OUT.pdf [--page N] [--keep-widgets-without-appearance]
    [--drop-links] [--dry-run] [--json]
```

What the host does with the real document:

- Parses every page and resolves `/Annots` entries to dictionaries.
- Decodes each annotation's `/AP /N` stream (unfiltered or `FlateDecode`;
  any other filter is a typed error) and registers the appearance bytes, its
  `/BBox`, `/Matrix` and source stream dictionary.
- Projects each annotation into the model's dependency-free `Dict`/`Value`
  form, replacing `/AP /N` with a side-table name so the model can resolve it.
  References and streams become stable markers that keep retention equality
  exact for annotations that stay interactive.
- Runs `pdfxi_edit::flatten::flatten` with the requested page subset, link and
  widget options.
- Writes the result back: the page `/Contents` becomes the flattened stream,
  every emitted appearance is materialized as a real form XObject under a fresh
  page `/Resources /XObject` (preserving the source stream dictionary, so
  `/Group`, `/SMask` and `/Resources` survive), flattened entries are removed
  from `/Annots` while retained entries keep their original objects, and the
  catalog `/AcroForm` is removed when the report says no widget survives.
- Reopens the written file, checks the page count, and verifies that every
  emitted resource exists in the page's `/Resources /XObject`.
- `--dry-run` reports the identical plan and writes nothing.

`/Rotate` is validated but not baked into the placement, exactly as the model
documents: the viewer rotates the whole page.

## Scope

Real annotation and widget appearances are now baked into page content on real
documents: page subsets, retained links, widget removal, AcroForm removal,
materialized form XObjects with their source resources, a verified reopen and a
dry run. Interactive annotation editing, appearance generation for annotations
that have no `/AP` stream, and `/Rotate`-baked placement are not claimed; they
remain viewer/editor behaviour.
