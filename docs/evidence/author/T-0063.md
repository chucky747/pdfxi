## Reviewer follow-up details

- **HIGH** — Restored `orchestration/feature-updates/T-0063.toml` with the same
  `EDIT-008` `in-progress` row, relative paths only, and corrected test list
  (14 tests) and evidence path. `features apply` was not run.
- **MEDIUM** — `PageNumbering::number_for` now returns
  `Result<String, HeaderFooterError>` and uses `i64::try_from` + `checked_add`
  instead of `unwrap_or(i64::MAX)`/`saturating_add`. New
  `HeaderFooterError::PageIndexOutOfRange { index, start }` variant reports
  both unrepresentable indices and offset overflow. `substitute` returns a
  `Result` and `render_overlay` propagates it via `?`, so both use the same
  checked path. Regression tests:
  `number_for_rejects_unrepresentable_and_overflowing_indices` (covers
  `usize::MAX` and `i64::MAX` overflow) and
  `substitute_propagates_numbering_overflow`.
- **LOW** — Module docs and `escape_literal` rustdoc now state that non-ASCII
  is emitted as three-digit octal escapes of raw UTF-8 bytes
  (`é` -> `\303\251`) and that consumers must use a UTF-8-capable encoding or
  pre-encode for WinAnsi standard fonts. Existing test
  `escaped_literal_strings_are_valid_and_deterministic` (`é` -> `\303\251`)
  remains green.

## Known limitations / honest status

- No UI or CLI command wires the new API, so EDIT-008 remains `in-progress`,
  not `verified`.
- Text width for centering/right-alignment is approximated from character
  count and a per-family average advance (no AFM metrics, no new dependency).
- `{date}` is a caller-supplied preformatted string to keep output deterministic.
