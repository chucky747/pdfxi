## Notes

- The permanent-removal contract is explicit about the security boundary:
  `ContentRemover` is the single security-critical step that physically
  rewrites content streams, and its rustdoc names `pdfxi-security` as that
  step's owner in this workspace. `pdfxi-edit` deliberately does **not**
  duplicate the security logic — callers supply a remover through the trait.
  `StreamContentRemover` delegates to this crate's one internal stream rewriter
  for callers without a separate engine.
- `PermanentRemovalPlan::execute` validates metadata, geometry, page bounds,
  and overlap policy before invoking the remover once per page in ascending
  page order. `PermanentRemovalResult::verify` and the free
  `verify_extracted_text` build a `RedactionReport` from caller-supplied
  extracted text, proving marked strings are absent (strict mode fails via
  `check` when residuals remain).
- `RedactionPlan::new`/`add` now deduplicate exact regions after canonical
  sorting, so a repeated mark is applied and painted exactly once.
  `RedactionPlan::validate_geometry` re-checks non-finite coordinates, empty
  rectangles, and blank patterns defensively. `OverlapPolicy::{Allow, Reject}`
  governs partially overlapping rectangles (edge contact is never an overlap);
  `apply` honours it through `RedactionOptions::overlap_policy`.
- `RedactionMetadata` validates optional author/subject (non-blank) and
  `created_unix_ms` (non-negative), with typed `InvalidMetadata` errors and
  stable `Display` wording.
- The fake `DroppingRemover` test proves the contract requires removal, not
  cover: it drops the matched pattern bytes and never paints an opaque box, and
  the verification report confirms the region no longer exposes that text.
- Library-level EDIT-013 is complete. Out of scope for this row and explicitly
  delegated elsewhere: rendering-based verification that rasterised image
  content inside a rectangle is gone (render lane) and UI/CLI exposure of the
  redaction workflow (app lane).
