## What was delivered

- `crates/pdfxi-automation/src/js/` extended with a deterministic interpreter for
  an Acrobat-compatible subset: scalar values, `var`/`let`/`const`, arithmetic,
  comparison and logical operators, `if`/`else`, bounded `while`/`for`,
  functions with call-depth limits, objects and arrays, property access, and a
  documented built-in library (`AFNumber_Format`, `AFNumber_Keystroke`,
  `AFPercent_*`, `AFDate_*`, `util.printf`, and a `this.getField` read/write
  model) in `acrobat.rs`.
- Hard sandbox: no filesystem, network, process, clock, randomness, or host
  globals; bounded steps, call depth, string/array sizes; deterministic results
  independent of wall-clock time; an explicit cancellation flag is honored.
- Typed errors for syntax, unsupported syntax, unknown builtins, step/depth/size
  limits, forbidden globals, and cancellation. Scripts are only executed through
  the explicit evaluation API.

## Safety and scope

- No `unsafe`; no `unwrap`/`expect`/`panic!` in non-test code.
- No new dependencies.
- The interpreter accepts a documented subset; unsupported syntax fails with a
  typed error instead of being silently ignored.
- Host UI (Action Wizard) and document-mutation bindings remain outside this

### Findings fixed

- **HIGH — parser recursion / chain depth.** `parse_unary` now calls `enter()`
  for every recursive unary step and `parse_postfix` holds a depth slot for the
  whole `.`/`[]`/`()` chain (released once the chain ends, including on error
  via `Parser::unwind`). Deep parentheses already flowed through
  `parse_expr`/`parse_primary` `enter()` calls. Regression tests with 50,000 `!`
  operators, a 50,000-link member chain (both `.a` and `[0]`), and 50,000 nested
  parentheses all return `JsError::AstTooDeep` instead of aborting with
  `STATUS_STACK_OVERFLOW`. (An earlier iteration balanced the per-link depth
  immediately and the member-chain test did overflow; the test caught it and
  the chain now accumulates depth.)
- **MEDIUM — printf padding allocation.** `util.printf` computes the projected
  output length with checked arithmetic and returns `JsError::StringTooLarge`
  *before* `std::iter::repeat_n` allocates the padding. A fixed-point precision
  guard was added for the same reason. `util.printf('%999999999d', 1)` and
  `%999999999f` now fail with a typed size error.
- **LOW — Acrobat host borrows.** All nine public `AcrobatContext` accessors
  now use `try_borrow`/`try_borrow_mut`; typed-error `try_*` variants were added,
  and the original signatures remain as non-panicking wrappers. The invariant
  (interpreter borrows are short-lived and host callbacks run outside them) is
  documented on the impl and tested twice: direct contention against held
  borrows, and re-entrant host-callback access during a script run.
- **LOW — feature-matrix test names.** `docs/features.toml` was not edited. The
  matrix's `AUTO-004` row listed three `js::interpreter::tests::*` names that do
  not exist. The fragment uses these real replacements (confirmed by the test
  output above): `js::interpreter::tests::acrobat_number_and_percent_builtins`
  → `js::tests::acrobat_arithmetic_and_calculate_script`,
  `js::tests::af_number_format_end_to_end`, and
  `js::tests::af_percent_format_and_keystroke_end_to_end`;
  `js::interpreter::tests::forbidden_globals_are_rejected` →
  `js::tests::dangerous_globals_are_rejected` and
  `js::tests::forbidden_globals_are_rejected_even_with_a_context`;
  `js::interpreter::tests::cancellation_stops_evaluation` →
  `js::tests::cancellation_is_observed_before_and_during_a_run` and
  `js::tests::cancellation_is_honored_with_a_context`.
- **Cheap JS semantics.** `Number('')` and whitespace-only strings coerce to
  `0`; `isNaN(undefined)` and `isNaN()` return `true`. Existing behavior
  (`isNaN('xyz')` → `true`, `isNaN('')` → `false`) is preserved.
