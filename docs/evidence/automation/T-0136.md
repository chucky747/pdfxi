## Scope and notes

- Implemented in `crates/pdfxi-automation/src/plugin.rs`, re-exported from
  `crates/pdfxi-automation/src/lib.rs`. No other source file was edited.
- `PluginManifest` (id, name, version, api_version, required capabilities) with
  structural validation, ABI compatibility checks, and canonical JSON
  round-trip through the crate's dependency-free `JsonValue`.
- Closed `Capability` allowlist (DocumentText, DocumentMetadata, PageImages,
  ExportBytes). No filesystem/network/process/shell/environment capability;
  such names are rejected with a typed `Forbidden` parse error.
- `CapabilityGrants` is deny by default; `PluginHost` is an audited trait and
  `LocalPluginHost` is a concrete deny-by-default implementation.
- `PluginRegistry` is id-ordered (`BTreeMap`), enforces one plugin per id, bounds
  the plugin count and the serialized manifest size.
- `PluginInvocation` / `InvocationBudget` / `InvocationReport` /
  `InvocationDecision` model allow/deny planning with budget fields
  (fuel/steps, memory bytes, wall-clock ms) and sorted, deduplicated deny
  reasons. `plan_invocation` collects all reasons without executing anything.
- Typed errors (`PluginError`, `CapabilityParseError`); no new dependencies, no
  `unsafe`, and no `unwrap`/`expect`/`panic!` in non-test code (grep confirmed
  all `expect` uses are inside `#[cfg(test)]`).
- Honest status: `in-progress`. This is the local host *contract* only — it does
  not load or execute WebAssembly modules, so it does not fully substitute a
  real WASM plugin host. Remaining scope is recorded in
  `orchestration/feature-updates/T-0136.toml`.
