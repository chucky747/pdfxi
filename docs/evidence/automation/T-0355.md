# T-0355 — Real document runner for Action Wizard sequences (`AUTO-002`)

Row promoted: `AUTO-002` (Batch processing and command sequences) `model` ->
`verified`.

The row already had the complete batch queue (`SequenceBatchQueue`, FIFO order,
state machine, cancellation, failure isolation, idempotence) and the planning /
sandboxed script runner. Its own note recorded the remaining gap honestly:

> Step effects stay behind the injected `SequenceStepRunner` trait with a
> side-effect-free `RecordingRunner` default, so no I/O or real PDF mutation
> occurs.

This task supplies the missing host: a `SequenceStepRunner` that executes the
steps against real parsed documents and writes real output PDFs.

## 1. Host

```text
pdfxi action sequence --input PATH [--input PATH ...] --step STEP [--step ...]
    [--out-dir DIR] [--json]
```

`--step` is ordered and accepts three forms:

- `script:SOURCE` — runs the source in the existing deterministic sandbox with
  the sequence's `ScriptBudget`;
- `metadata:KEY=VALUE` — writes one `/Info` field. Keys are case-insensitive
  aliases: `title`, `author`, `subject`, `keywords`, `creator`, `producer`,
  `creation-date`, `mod-date`;
- `command:strip-metadata` or `command:normalize-boxes` — document commands
  implemented with `pdfxi-core` (`Document::set_info`, `Document::page_boxes` /
  `Document::set_page_boxes`).

Behaviour:

- Every input is validated and parsed **before** the first job runs (readable
  file, size limit, real PDF, resolvable page tree, readable `/Info`).
- Items run in input order through `SequenceBatchQueue::run_all` with the real
  runner; one failing item never stops its siblings.
- Metadata steps accumulate against a per-document `/Info` mirror, because
  `Document::info()` reads the original trailer and cannot see pending
  `set_info` writes.
- Every succeeded item is saved to `<stem>.sequence.pdf` (or beneath
  `--out-dir`), then read back and reparsed; the reported page count comes from
  the reparsed bytes. The input file is never overwritten.
- `--json` reports the sequence name, the step tokens, and per job: id, input,
  terminal state, completed step ids, failing step, failure message, output
  path, byte size and reparsed page count. Text mode prints one line per job
  plus its output line. The command exits non-zero when any item failed.

## 2. Evidence

```text
> pdfxi action sequence --input target\tmp\roomy.pdf --input target\tmp\pages3.pdf
    --step "metadata:title=Quarterly Report" --step "metadata:author=PDFXI Test"
    --step "script:2 + 3;" --step "command:normalize-boxes"
    --out-dir target\tmp\seqout
job-0   target\tmp\roomy.pdf   succeeded  steps=4
        out: target\tmp\seqout\roomy.sequence.pdf (730 bytes)
job-1   target\tmp\pages3.pdf  succeeded  steps=4
        out: target\tmp\seqout\pages3.sequence.pdf (747 bytes)
job-0   target\tmp\roomy.pdf   succeeded  steps=4
job-1   target\tmp\pages3.pdf  succeeded  steps=4
EXIT=0

    --step "metadata:mod-date=D:20261122120000Z" --out-dir target\tmp\seqout --json
```

The written PDF contains both the `/Title` and `/ModDate` entries (checked in the
raw bytes and by reparsing in the test).

A failing step is isolated and reported:

```text
> pdfxi action sequence --input target\tmp\roomy.pdf --step "metadata:colour=red" --json
"state": "failed",
"failed_step": "step-1",
"failure": "unknown metadata key \"colour\"; expected title, author, subject,
            keywords, creator, producer, creation-date or mod-date",
Error: 1 of 1 job(s) failed
EXIT=1
```

Rejections:

```text
> action sequence --step ... (no --input)         -> Error: at least one --input path is required
> action sequence --input ... (no --step)         -> clap: --step is required
> --step swipe:1                                  -> Error: unknown step "swipe:1"
> --step metadata:title                           -> Error: metadata step "title" must be KEY=VALUE
> --step script:                                  -> Error: script step has an empty source
> --step command:                                 -> Error: command step has an empty name
> --input <missing>                               -> Error: input '<path>' is not readable
> --input <not a PDF>                             -> Error: parse '<path>': invalid header
> --input A A (same file twice)                   -> Error: input '<path>' was given more than once
```

## 3. Tests

```text
> cargo test -p pdfxi-cli action_sequence_
action_sequence_applies_real_document_steps ... ok
action_sequence_isolates_failures_and_rejects_bad_input ... ok
test result: ok. 2 passed
```

The first runs two real PDFs (a 612x792 one-page fixture and a three-page
fixture) through metadata, script and `normalize-boxes` steps, asserts both jobs
succeed with four completed steps and correct page counts, then reparses both
outputs and checks `/Title` and `/Author`. It then runs
`metadata:title=Transient` followed by `command:strip-metadata` against the same
input and asserts the output has no title, proving ordered real mutation. The
second drives a sandbox parse error, asserts `failed` / `failed_step=step-1` /
the parse-error message / no output file, then covers each typed rejection and
the non-PDF and duplicate-input cases.

The 12 existing `sequence_batch::tests::*` and 4 existing `action_run_*` tests
remain cited in the matrix and continue to pass.

## Scope

The complete sequence/batch model is now user-reachable on real documents: FIFO
ordering, state machine, failure isolation, sandboxed scripts, `/Info` metadata,
the two documented document commands, saved-and-reparsed outputs and a stable
report. Unbounded custom plugin commands, interactive Action Wizard editing and
network operations remain outside the CLI host boundary and are not claimed.
