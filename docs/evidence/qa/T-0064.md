## Reviewer responses

**MEDIUM — Cargo.lock disclosure.** The earlier claim that Cargo.lock was
"untouched" was inaccurate. Adding `pdfxi-core` as a test-only dev-dependency
caused Cargo to regenerate the integrator-owned lockfile. I did not hand-edit
Cargo.lock. The exact resulting entry (Cargo.lock lines 2511–2515) is:

```toml
[[package]]
name = "pdfxi-testkit"
version = "0.1.0"
dependencies = [
 "pdfxi-core",
]
```

Exact diff: one line added inside the `pdfxi-testkit` package's `dependencies`
array, namely ` "pdfxi-core",`. No versions, checksums, or other packages
changed. The integrator owns this file; no lockfile edit was made in the
reviewer pass.

**LOW — `VOLATILE_DICTIONARY_FIELDS` dead code / overstated claim.** The constant
is now used by a new public `golden::normalize_volatile_fields(body)` function,
called by `PageTreeSnapshot::from_pdf` on each page body before extraction. It
strips exactly the documented `/CreationDate`, `/ModDate`, `/ID` and `/Producer`
key/value pairs (supporting literal/hex strings, arrays, dictionaries, names,
numbers and `N 0 R` references) and copies every other byte verbatim. Docs and
README now state precisely that the snapshot records only object number, the
five box arrays and `/Rotate`; other dictionary entries are out of scope, not
normalized. New test `normalize_volatile_fields_removes_only_documented_keys`
covers the helper directly; renamed `page_tree_snapshot_ignores_documented_volatile_fields`
covers the volatile case; new test `page_tree_snapshot_detects_non_volatile_changes`
proves a changed `/CropBox` coordinate and a changed `/Rotate` both change the
fingerprint.

**NIT — duplicate assertion.** The second user-password assertion is now an
owner-password assertion. A new `TestEncryption::owner_password_matches` reverses
R2 Algorithm 3 (RC4-decrypt `/O` with the owner key to recover the padded user
password, then validate `/U`). Both the unit test and
`encrypted_fixture_handles_documented_password` now assert the documented user
password with `password_matches` and the documented owner password with
`owner_password_matches`, plus negative cases for each.
