## What `-Check` does

`-Check` discovers Git, `rustup`, `cargo`, `rustc`, the linker `gcc` and the
pinned GNU toolchain. It resolves each tool first along a caller-supplied
search path and then in the same fallback locations the installer uses
(`%USERPROFILE%\.cargo\bin`, `%LOCALAPPDATA%\Programs\MinGit\cmd`,
`%LOCALAPPDATA%\Programs\winlibs\bin`), prints a `TOOL ... path=... version=...`
line for each, and prints the toolchain line. It never calls `Ensure-MinGit`,
`Ensure-Rust`, `Ensure-Mingw`, `Invoke-WebRequest`, `Invoke-RestMethod`,
`winget`, `rustup toolchain install`, `git init`, `git config` or
`SetEnvironmentVariable`. Those live only in `Invoke-Install`, which the
dispatch reaches only when neither switch is present. Discovery probes native
tools through `Invoke-ToolCapture`, which scopes `$ErrorActionPreference` to
`Continue` and merges stderr so PowerShell 5.1 does not turn rustup's
informational stderr note into a terminating error.

Optional override environment variables `PDFXI_BOOTSTRAP_CARGO_BIN`,
`PDFXI_BOOTSTRAP_MINGIT` and `PDFXI_BOOTSTRAP_WINLIBS` let `-SelfTest` inject a
sandbox without touching the real installation; they default to the standard
paths.

Acceptance command: `powershell -File scripts/bootstrap.ps1 -Check`

## Deterministic self-tests: `powershell -NoProfile -File scripts/bootstrap.ps1 -SelfTest` — EXIT 0

```text
TEST 1 path_resolution PASS
TEST 2 missing_tool_detection PASS missing=6
TEST 3 version_output PASS version=git version 2.56.0.windows.4
TEST 4 check_mode_no_op PASS exit=1 unchanged=True install_markers=0
TEST 5 check_success_path PASS exit=0
SELFTEST passed=5 failed=0
SELFTEST_EXIT=0
```

The five checks cover the four required areas plus the real-script success
path:

1. `path_resolution` — a stub is found both via an explicit candidate path and
   via a caller-supplied search path, with the expected `Source` marker.
2. `missing_tool_detection` — with no PATH and no candidates, `Resolve-Tool`
   returns not-found and the structured prereq result contains `git` and `gcc`
   in `Missing` (`missing=6` including the toolchain).
3. `version_output` — the pure `Get-VersionLine` parser selects the first
   non-empty line from a noisy output array, and the real local `git` probe
   returns a `git version...` line. No network.
4. `check_mode_no_op` — launches the actual `bootstrap.ps1 -Check` as a child
   with empty candidate roots and empty PATH. It must return exit 1, leave a
   recursive snapshot of the sandbox byte-identical (including a
   `DO-NOT-CHANGE` sentinel), and emit none of the install markers
   (`Installing`, `git init`, `rustup toolchain install`, `Bootstrap complete`,
   `Configuring git`).
5. `check_success_path` — launches the real script with the machine's real
   roots; asserts exit 0, `CHECK result=PASS` and a resolved `git` tool line.

All state is a fresh GUID sandbox under `%TEMP%` that is removed in `finally`.
No test needs network, GUI, sleep, secret or elevation; the whole suite
completes in a few seconds.

## AC-01 coverage: verified here vs. remaining external gap

AC-01 text: *A fresh Windows machine can run `scripts/bootstrap.ps1` without
interactive decisions. The script installs or locates Git, Rust, and a working
linker, then `cargo xtask goal-verify --milestone M0` passes.*

Verified on this machine:

- The discovery/locate half of "installs or locates Git, Rust and a working
  linker": all five tools and the pinned `stable-x86_64-pc-windows-gnu`
  toolchain are located without any PATH precondition and reported with exact
  paths and versions (`CHECK result=PASS`, exit 0).
- Failure behaviour is clear and non-destructive: every missing item is named,
  `expected_at` paths are printed, and the process exits 1 without side
  effects.
- `-Check` is a true no-op: no install, download, PATH/registry change, git
  config change or directory creation (five self-tests plus the direct state
  comparison above).
- The non-interactive property of the check path: no switch prompts and no
  `winget` interactivity are involved.

Not verifiable here (external, and deliberately not attempted):

- **Clean-machine install.** This host already has MinGit, rustup/cargo/rustc
  and WinLibs MinGW installed, so the download/install branches in
  `Ensure-MinGit`, `Ensure-Rust` and `Ensure-Mingw` were not exercised. No
  network or machine modification was permitted for this task. Verifying a
  genuinely fresh Windows image requires a disposable VM in a separate CI job
  that runs the default mode of `bootstrap.ps1` with network access.
- **Elevation.** `winget install` may require an elevated token on some hosts;
  the bootstrap is designed to fall back to user-local MinGit/WinLibs and
  user-local rustup, and `-Check` is elevation-free, but an elevated vs.
  unelevated install matrix cannot be exercised from this autonomous shell.
- **`cargo xtask goal-verify --milestone M0` passing on a fresh machine.**
  That is the second half of AC-01 and is owned by the goal-controller, not by
  this task. It was not run here; the recorded evidence for it belongs to the
  M0 goal-verify task. This task records only the bootstrap discovery gate.

The `-Check` gate is therefore a necessary-but-not-sufficient record for
AC-01. The remaining three bullets above are the AC-01 gap that must be closed
by an external clean-machine CI run.
