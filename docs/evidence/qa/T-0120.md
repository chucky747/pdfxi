## What the harness does

Three deterministic in-memory fixtures (small 1 page / 24-byte marker, medium
100 pages / 24-byte marker, large 500 pages / 48-byte marker) are measured for
`open`, `first_page_render`, `text_extract`, `search_index_build`, `save` and a
`peak_allocation_estimate`. Each operation has 2 warmup and 7 measured runs; the
whole harness runs 3 independent rounds and keeps the best median per metric.
Budgets are scaled from the 500-page values in `docs/TESTING.md` with +25%
headroom; regressions are flagged when a tracked median (baseline >= 1 ms) is
more than 10% above the baseline. Output is stable-shape JSON plus a summary.
`--report` never fails; the default gate and `--check` exit 1 on a breach, a
regression, or an invalid baseline. Details are in `docs/TESTING.md`.

## Variance observation and mitigation

An early default run failed with five >10% "regressions" because one transient
shared-host event made every large-fixture metric about 2× slower than the
baseline in a single process; the next two runs were back at baseline level and
passed (exit 0). Rather than weakening the 10% rule, the harness now runs three
independent measurement rounds per invocation and keeps the best median per
metric. Baseline and gate use the same best-of-3 method, so a sustained
regression still fails while a single spike is suppressed. This is documented in
`docs/TESTING.md` under "Regression gate and variance handling".
