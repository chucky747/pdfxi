## Integrator follow-up: stale-manifest race, robustness test and host load

The integrator observed `cargo xtask corpus smoke` failing in
`CARGO_TARGET_DIR=target/integration` with
`SizeMismatch("crypto/oid.bin")`. Root cause: the check ran in the window between
restoring the pre-existing `crypto/oid.bin`/`random.bin` from `HEAD` and
re-running the generator to refresh `fuzz/corpus/manifest.toml`, so the manifest
briefly still recorded my generated 37-byte `oid.bin` while the file on disk was
the restored 11-byte original. The manifest is now regenerated and contains only
the three `crypto/*-variants.bin` / `der-sequence.bin` generated rows; the
pre-existing `der.bin` (5 B), `oid.bin` (11 B) and `random.bin` (13 B) are restored
byte-for-byte and `git status --porcelain -- fuzz/corpus/crypto` reports no change
for them.

The documented intent is option (b): the manifest describes exactly the generated
seeds and pre-existing hand-seeded files are left untouched but still fed to the
fuzz entry points by `fuzz_smoke`. `verify_corpus` already iterates manifest rows
only (it never walks the directory); I added
`fuzz_seed_corpus::verification_ignores_unlisted_files_but_catches_real_mismatches`
to test that contract explicitly. It asserts the three pre-existing crypto seeds
exist and are absent from the manifest, that a full audit succeeds despite them,
and that a wrong hash, wrong size or missing listed file is still rejected with
`HashMismatch`, `SizeMismatch` or `Missing`. The check was not weakened.
