# T-0354 — Linux build verification (`PLAT-002`)

Row promoted: `PLAT-002` (macOS and Linux desktop builds) `model` ->
`verified`.

The row's own acceptance is the cross-platform build check. The previous
evidence claimed a Windows-hosted `--target x86_64-unknown-linux-gnu` check, but
that path now fails in `ring`'s build script without a Linux C toolchain. This
task verifies the workspace with a **native Linux build** in the installed WSL
Ubuntu 24.04 environment and fixes the portability warnings that only appear
there.

## 1. Portability fixes

- `crates/pdfxi-render/src/win_print.rs`: `Ordering`, `CancellationToken` and
  `PageIndex` are used only by the Windows implementation, so their imports are
  now `#[cfg(windows)]`. The non-Windows API and its `Unsupported` stubs are
  unchanged.
- `crates/pdfxi-app/src/print.rs` (`backend_tests`): the `super::*`, `PathBuf`
  and `AtomicBool` imports are used only by the Windows + `pdfium` print test,
  so they are gated with the same condition.
- `crates/pdfxi-app/Cargo.toml`: `pdfxi-assistant`, `pdfxi-convert`,
  `pdfxi-core`, `pdfxi-document`, `pdfxi-edit`, `pdfxi-forms`,
  `pdfxi-security` and `time` are used only by the `ui` shell modules, so they
  are optional and enabled by `ui` (and `pdfium` for the convert forwarding).
  A default-feature build no longer reports unused dependencies.

## 2. Linux evidence

Environment (WSL):

```text
$ rustc +stable --version
rustc 1.100.0 (0ef1bc386 2026-11-09)
$ cc --version | head -1
cc (Ubuntu 13.3.0-6ubuntu2~24.04.1) 13.3.0
```

Run in the canonical workspace (the repository is not copied):

```text
$ cd /mnt/d/Documents/opencode-work
$ RUSTUP_TOOLCHAIN=stable CARGO_TARGET_DIR=$PWD/target/linux-wsl \
    cargo check --workspace --all-targets
    Checking pdfxi-core v0.1.0 (/mnt/d/Documents/opencode-work/crates/pdfxi-core)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 25.04s
EXIT:0
```

The log contains no `warning:` lines and no errors; every workspace crate and
test target compiles for `x86_64-unknown-linux-gnu` on a real Linux host. The
WSL toolchain is selected with `RUSTUP_TOOLCHAIN=stable` because
`rust-toolchain.toml` pins the Windows GNU channel for the canonical host; the
source tree is unchanged.
