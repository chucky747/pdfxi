# T-0055 — Accessibility tree and reading-order export

Status: verified (task). ACCESS-001 and ACCESS-002 remain in-progress: this task
delivers the tree/export model, not the interactive editor UI or the full
PDF/UA checker.

## Files

- `crates/pdfxi-accessibility/src/tree.rs` (new) — `NodeId`, `BBox` (finite,
  positive extent), `A11yNode`, and `A11yTree` with deterministic depth-first
  traversal (explicit stack, safe for deep trees). Validation rejects duplicate
  ids, unknown children or roots, multiple parents, cycles (iterative
  three-colour DFS, including disconnected cycles), orphan nodes, and
  non-finite/empty boxes. Font-size validation lives in `builder.rs`
  (`TextBlock::new` and `ReadingOrderBuilder::build`), not here.
- `crates/pdfxi-accessibility/src/builder.rs` (new) — `TextBlock` and
  `ReadingOrderBuilder` with canonical sort, same-line merging, vertical-gap
  paragraph splitting, font-size heading detection, and stable ids.
- `crates/pdfxi-accessibility/src/export.rs` (new) — `to_plain_text` in reading
  order with role labels and indentation (explicit stack, safe for deep trees;
  page labels use `saturating_add(1)`), plus `summarize` with role counts and
  alt-text coverage.
- `crates/pdfxi-accessibility/src/lib.rs` — `TagRole::Page`, `Ord` derive, module
  wiring, and re-exports.

No new dependencies; `.opencode` permission mismatch for the app lane was
reported to the integrator.

## Review fixes (second pass)

1. `export.rs` page label no longer uses `node.page + 1` (which overflows in
   debug for `page = usize::MAX`); it uses `saturating_add(1)`. Regression test:
   `export::tests::page_label_saturates_for_max_page`.
2. `A11yTree::traversal` and `to_plain_text` now use explicit stacks instead of
   per-depth recursion. Deep-chain tests (10,000 nodes):
   `tree::tests::deep_chain_traversal_uses_explicit_stack` and
   `export::tests::deep_chain_export_uses_explicit_stack`.
3. Corrected this evidence file's wording: font-size validation is in
   `builder.rs` / `TextBlock::new`, not `tree.rs`.
4. Added `tree::tests::disconnected_cycle_is_rejected`: a three-node cycle with
   no roots (every node in-degree one) asserts `TreeError::Cycle`.
