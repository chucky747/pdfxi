### Rustdoc fix

Integrator verification found `RUSTDOCFLAGS=-D warnings cargo doc
-p pdfxi-app --no-deps --all-features` exiting 101 with:

```
error: unresolved link to `PdfxiApp`
 --> crates/pdfxi-app/src/ui.rs:68
  = note: `-D rustdoc::broken-intra-doc-links` implied by `-D warnings`
```

Cause: the new module-level `//!` doc paragraph linked `[`PdfxiApp`]`, and
module-level docs resolve links in the crate-root scope where `PdfxiApp` is not
in scope. Fixed by using a plain code span `` `PdfxiApp` `` in module docs. The
pre-existing `[`PdfxiApp`]` link at line 438 is inside a function's rustdoc and
already resolves; an explicit `crate::ui::PdfxiApp` target there was tried and
reverted because rustdoc then flagged `redundant-explicit-links`. The final
rustdoc command exits **0** (exact exit code above).

  exposes only page rasters and has no optional-content API, so PDFium cannot yet
  hide/show group content. The `VisibilityPlan` is the documented boundary a

  as `in-progress`.

  non-test code; no new dependencies; no network or GUI in tests.
