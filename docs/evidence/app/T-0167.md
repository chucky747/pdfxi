- `src/open.rs`: added `OpenPhase` (`Loading -> Ready | Failed`), `OpenPhaseState`,
  `OpenPhases` (ordered `BTreeMap` tracker with `begin`/`finish`), `OpenReportEntry`,

## Regression proof for the ordering bug

Before the fix, `LayerModel::position` returned the declaration index while
`LayerState.visible` is indexed by display position. With
`with_order(["oc3", "oc1", "oc2"])` the three following tests fail on the old code
and pass now:

- `position_is_display_index_after_reordered_order` — `position` now agrees with
  `layers` and `get`.
- `set_visible_after_reorder_affects_the_correct_layer` — old code wrote the flag
  of `oc1` instead of `oc2`; the plan now contains only `oc2`.
- `locked_check_after_reorder_uses_the_correct_layer` — old code consulted the
  locked layer's flag via a declaration index and wrongly rejected editing an
  unlocked layer.

## Honest scope / host boundary

Both rows are closed at the **library/model level** only. VIEW-001 still has no OS
printer/spooler adapter: `PrintDispatchPlan` carries the resolved data a host feeds
to `pdfxi_render::print`. VIEW-010 still has no renderer optional-content API:
`OcGroupPlan` / `VisibilityPlan` are the data a host passes to a renderer that
supports per-group visibility. These are the same documented host boundaries that
keep the rows from claiming user-visible UI completion; the model work in this task
is complete and fully tested.
