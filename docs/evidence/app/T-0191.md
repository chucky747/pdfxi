# T-0191 — R2 render-path safety

Date: 2026-11-20. Lane: integrator. Target dir: `target/integration`.

## Delivered

- **Per-raster pixel cap.** `pdfxi_render::MAX_RASTER_PIXELS` (16 Mpx = 64 MiB
  RGBA) plus the pure `clamp_render_scale(width_pt, height_pt, scale, max)`
  helper. The PDFium backend now clamps the effective scale from the real page
  size before rendering, so a large page at high zoom can never request an
  unbounded buffer. The clamp floors at `MIN_RASTER_SCALE` for pathological
  pages and never exceeds the requested scale.
- **Byte-budgeted raster cache.** `RasterCache` now enforces
  `DEFAULT_RASTER_BYTES` (256 MiB) together with the entry limit. The byte
  counter stays accurate across replacement, `invalidate_page` and
  `invalidate_all`, and a single raster larger than the whole budget is not
  retained.
- **Per-frame render budget.** New `RasterCache::ensure_visible_capped` renders
  at most N uncached visible pages per call; `ensure_visible` delegates with an
  unlimited budget so existing callers are unchanged. The GUI uses
  `RASTERS_PER_FRAME = 2`, so a spread showing many pages cannot freeze a frame.
- **Cross-frame cancellation.** `PdfxiApp` holds one `CancellationToken` for
  the open document instead of creating it per frame. `reset_raster_state`
  cancels it, replaces it, and clears the raster cache and GPU textures whenever
  the active document changes or a tab closes. This also fixes a latent
  multi-document bug: rasters are keyed by page/scale/rotation, so without the
  reset a second document could paint the first document's pixels.
