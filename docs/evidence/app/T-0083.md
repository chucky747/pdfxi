# T-0083 — rotate view and page display controls

Status: verified (task and `VIEW-004`). All checks were re-run after the
reviewer's findings were addressed; the exact command output is pasted below.

## Files and attribution

- `crates/pdfxi-app/src/tabs.rs` — **owns the per-tab rotation state**: the
  `DocumentTab::rotation` field plus `set_rotation`, `rotate_clockwise`, and
  `rotate_counterclockwise` methods. New test
  `tabs::tests::rotation_state_is_owned_by_the_tab` asserts this ownership.
- `crates/pdfxi-app/src/state.rs` — **delegates** to the tab's rotation methods
  for the active tab and adds `reset_rotation`, `fit_page`, `fit_width`, and
  `actual_size` (typed `AppError` on a missing active tab).
- `crates/pdfxi-app/src/view.rs` — `Rotation` quarter turns, `combine`,
  `swaps_dimensions`, and the documented rotation-then-zoom composition order.
- `crates/pdfxi-app/src/canvas.rs` — rotation-aware layout (effective page size,
  fit modes, scroll clamping), inverse-rotation hit testing in `page_point`,
  forward overlay mapping in `page_rect_to_canvas`, and `uv_quad_for_rotation`.
- `crates/pdfxi-app/src/commands.rs` — typed `ViewCommand`, `ShortcutKey`, and
  the pure `map_shortcut` table shared by toolbar and keyboard paths.
- `crates/pdfxi-app/src/raster.rs` — `ensure_visible` keys each raster by the
  page's **effective rotation** (`PageGeometry::rotation`), the same value the
  UI uses when painting.
- `crates/pdfxi-app/src/ui.rs` — toolbar/menu actions, status indicator, and
  keyboard dispatch; `paint_rotated_image` uses `egui::epaint::Vertex` and the
  effective-rotation UV quad. No UI action performs blocking I/O.
