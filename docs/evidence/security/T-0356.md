# T-0356 — Timestamp token host (`SEC-006`)

Row promoted: `SEC-006` (Timestamp and signature validation) `model` ->
`verified`.

The row's own boundary note was explicit:

> Host boundaries (not library gaps): online TSA enrollment/request transport,
> revocation/CRL status inside a concrete PDF signature workflow, and the
> trust-manager desktop UI remain host/follow-on adapters.

This task supplies the missing host without claiming network transport: a real
RFC 3161 token mint and validation command over caller-supplied trust material.

## 1. Host

```text
pdfxi timestamp sign CONTENT --out TOKEN.der --key KEY.pem --cert CERT.pem
    [--digest sha256|sha384|sha512] [--policy OID] [--serial N] [--time UNIX]
    [--nonce N] [--ordering] [--json]

pdfxi timestamp verify TOKEN.der --content CONTENT --cert CERT.pem
    [--anchor PEM] [--chain PEM] [--nonce N] [--at UNIX] [--allow-any-eku]
    [--json]
```

- `sign` builds a real CMS `SignedData` token with
  `pdfxi_security::build_timestamp_token`, signing with a caller-supplied
  unencrypted RSA key (PKCS#8 or PKCS#1 PEM) for the supplied certificate. The
  certificate, signer identifier and public key all come from the same
  certificate bytes, so the token always verifies against that certificate.
  This is an offline TSA: no network request and no hidden key is used.
- `verify` runs the full `validate_timestamp_token` pipeline: CMS signature,
  message imprint, future-skew guard, TSA chain at `genTime` with the RFC 3161
  timeStamping EKU, and the optional nonce. Trust anchors default to `--cert`;
  `--chain` supplies intermediates; `--anchor` overrides the anchors; `--at`
  pins the validation clock; `--allow-any-eku` is the documented override for
  non-standard TSA certificates.
- The report prints the exact `TimestampStatus` (`valid`, `imprint-mismatch`,
  `nonce-mismatch`, `timestamp-eku-missing`, `certificate-not-valid-at-gen-time`,
  `untrusted-tsa`, ...) and the conservative `SignatureStatus` mapping, plus
  serial, `genTime`, policy OID, nonce, imprint digest and hex imprint. A token
  that is not `valid` exits non-zero.

No network transport, wall clock is used only as the default validation clock
(`--at` pins it), no hidden trust store, and no revocation check is claimed.

## 3. Tests

```text
> cargo test -p pdfxi-cli timestamp_
timestamp_signs_and_validates_a_real_token ... ok
timestamp_rejects_bad_tokens_and_arguments ... ok
test result: ok. 2 passed
```

The first mints a real token from a generated RSA identity, then asserts:

- the JSON sign report (digest, serial, gen time, nonce, policy, bytes);
- a successful verification reporting `valid` / `valid` with the same serial,
  gen time, nonce and policy, a 64-hex-character SHA-256 imprint and the signer
  subject;
- different content -> `imprint-mismatch` / `tampered`, exit non-zero;
- a different expected nonce -> `nonce-mismatch`;
- omitting `--allow-any-eku` -> `timestamp-eku-missing` (the RFC 3161
  timeStamping EKU is required by default);
- a token minted before the certificate's `notBefore` ->
  `certificate-not-valid-at-gen-time` / `expired`;
- a foreign trust anchor -> `untrusted-tsa` / `unknown`.

The second covers an unsupported digest, a one-arc policy OID, a non-numeric
policy arc, a missing content file, and a garbage token (typed validation
error).

The 9 existing `timestamp_authority::tests::*` and the full RFC 3161
`timestamp::tests::*` suite remain cited in the matrix and continue to pass.

## Scope

Real token minting and full RFC 3161 validation are user-reachable from the CLI
on caller-supplied content and trust material, including imprint, nonce, EKU,
certificate-window and chain decisions with a conservative status mapping.
Online TSA request transport, OCSP/CRL status inside a PDF signature workflow,
and the trust-manager desktop UI remain host/follow-on adapters and are not
claimed.
