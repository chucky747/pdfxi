## New behavior

### SEC-003 — RFC 3394 AES-KW (new `crypto::keywrap` module)

- `aes_key_wrap` / `aes_key_unwrap` built on the existing FIPS 197 AES block
  cipher, with the `A6A6A6A6A6A6A6A6` integrity register check.
- RFC 3394 §4.1/§4.2/§4.3 known-answer vectors (128/192/256-bit KEK, one and two
  64-bit semiblocks of key data) verified exactly.
- Typed errors: `AesKwInvalidKekLength`, `AesKwInvalidKeyDataLength`,
  `AesKwIntegrityCheckFailed`.
- `InMemoryKeyWrapProvider` XOR test double replaced with real AES-KW (wrapped
  CEK is 8 bytes longer and authenticated). `AesKwKeyWrapProvider` added as the
  production provider holding a caller-supplied KEK (RSA/ECDH/KMS boundary).
  Existing `KeyWrapProvider` / `InMemoryKeyWrapProvider` APIs kept compatible.

### SEC-007 — CRL signature verification

- `Crl` now carries a canonical `tbsCertList`, an optional signature algorithm,
  and a signature over it; `to_der` / `from_der` round-trip signed CRLs.
- `Crl::verify_signature(&Certificate, &dyn CertificateVerifier)` checks issuer
  subject, `cRLSign` key usage, algorithm recognition, signature presence, and
  delegates to the shared `CertificateVerifier` path (no network, no host
  clock). Typed errors: `CrlSignatureMissing`, plus existing key-usage and
  unsupported-algorithm variants.
- `RevocationPolicy::verify_crl_signatures` (enabled by `strict()`) makes
  `TrustManager::evaluate` exclude CRLs with invalid/wrong-issuer/missing
  signatures and report `TrustFailureReason::CrlSignatureInvalid`. Reports
  expose `RevocationEvidence::crl_signature_verified()`. Revoked/Good/Unknown/
  Stale statuses and expiry handling remain typed and deterministic.
