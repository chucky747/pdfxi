## 6. Review-finding closure and honesty statement

- **MEDIUM — payload in `Debug`.** `SecurityEnvelope` and
  `OpenedSecurityEnvelope` no longer derive `Debug`. Manual implementations
  print `payload` as `<N bytes>`, permissions as bits, a recipient count, and
  `<redacted>` for tags. `envelope_debug_redacts_payload_bytes` checks all four
  rendered forms against both a distinctive ASCII payload and a non-UTF-8 byte
  run (its decimal Debug representation).
- **MEDIUM — forgeable unkeyed tag.** A caller-supplied HMAC-SHA256 key is now
  supported. `build_authenticated_security_envelope` writes a version-2
  envelope with a keyed tag; `open_security_envelope_with_key` requires a
  non-empty key, rejects unkeyed envelopes, and verifies both tags in constant
  time via the shared `crypto::constant_time_eq`. `EnvelopeReport.integrity`
  makes `Integrity::Unkeyed` vs `Integrity::Authenticated` explicit and the docs
  state that unkeyed permissions are untrusted. Negative tests cover a tampered
  payload and tampered permissions with a recomputed unkeyed tag, a wrong key,
  an empty key, a missing MAC tag, and an unkeyed envelope presented to the
  keyed opener; an authenticated round-trip succeeds. Version-1 envelopes still
  open via `open_security_envelope` (backward compatible).
- **LOW — raw-substring XMP residual detection.** `verify_xmp_scrub` now checks
  `XmpPacket::namespace_uris()`, so a selected URI appearing only as text inside
  an unselected property value is not flagged. The new test first proves the
  URI text is really present in the XML, then asserts a clean verification, and
  still asserts detection when the namespace is genuinely declared.
- No `docs/features.toml` or `orchestration/BOARD.md` edit; feature changes are
  reported in `orchestration/feature-updates/T-0176.toml` with SEC-010 and
  SEC-011 rows kept at `verified` and updated notes/evidence.
- No secrets, keys, or document contents are logged. Reviewer sign-off and
  integrator snapshot remain external orchestration steps.
