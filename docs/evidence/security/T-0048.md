# T-0048 — CMS/PKCS#7 signature creation and validation

Status: verified (task). SEC-005 is verified; SEC-006 stays in-progress until
RFC 3161 timestamps and trust/revocation management land.

## Files

- `crates/pdfxi-security/src/der.rs` — strict, dependency-free ASN.1 DER
  encoder/decoder subset (SEQUENCE, SET, INTEGER, OCTET STRING, NULL, OID,
  UTCTime/GeneralizedTime, context tags) with a bounds-checked reader, canonical
  length/integer/OID rules, and distinct truncation/tag/trailing-byte errors.
- `crates/pdfxi-security/src/cms.rs` — deterministic CMS `SignedData` builder
  and verifier behind the object-safe `SignatureProvider` trait. Emits
  `encapContentInfo`, signer certificate, and DER-sorted signed attributes
  (`contentType`, `messageDigest`, `signingTime`); verification recomputes the
  digest, checks the signed attributes, and maps results to
  `SignatureInfo`/`SignatureStatus`.
- `crates/pdfxi-security/src/error.rs` — DER and CMS error variants.
- `crates/pdfxi-security/src/lib.rs` — module wiring and re-exports.

Keys and certificates stay outside the crate behind `SignatureProvider`. The
in-memory test provider uses a documented small toy key with known-answer
modular-exponentiation vectors; it is test-only and not real RSA security.

## Trust boundary

The verifier checks only cryptographic integrity: the content digest matches the
`messageDigest` signed attribute, and the `SignatureProvider` accepts the
signature over the DER-encoded `signedAttrs` set. A returned
`SignatureStatus::Valid` with `SignatureCoverage::WholeDocument` means exactly
"the CMS signature is cryptographically valid over the signed attributes and the
whole encapsulated/detached content". It does **not** mean the signer is trusted:
no certificate chain is built, no trust anchor or revocation status is consulted,
no identity policy is applied, and the `signingTime` attribute is untrusted
self-asserted metadata rather than an RFC 3161 trusted timestamp. These checks
belong to higher layers. The module and public verifier docs in `cms.rs` state
this trust boundary explicitly; no behavior or feature status was changed by
this wording fix.

## Scope limits

Real X.509 parsing, PDF `ByteRange`/signature-field integration, RFC 3161
timestamps, and trust anchoring are follow-on tasks. No unsafe code and no
`unwrap`/`expect` in library paths.
