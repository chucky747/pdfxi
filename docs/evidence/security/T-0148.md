## Negative / security tests (explicit)

- **Permission widening rejected** — `password_policy::tests::empty_user_password_does_not_widen_permissions`
  asserts an empty open credential gets `PasswordRole::User` and the configured
  mask (not `Permission::ALL`, not owner), and
  `empty_user_password_without_owner_password_is_rejected`,
  `restricted_permissions_without_owner_password_are_rejected`,
  `identical_user_and_owner_passwords_are_rejected`, and
  `invalid_permission_bits_are_typed` cover conflicting states.
- **Sanitize removes, does not merely hide** —
  `sanitize_document::extended_tests::removal_is_structural_not_cosmetic`
  byte-scans the re-parsed output and asserts none of `Secret Title`,
  `secret.txt`, `hidden note`, `app.alert`, `secret value`, `secret private`,
  `secret page`, or `secret info` survive. `full_selection_removes_every_hidden_class_on_real_bytes`
  re-parses the output and verifies an empty inventory for all nine classes.
- **Malformed XMP is typed** — `xmp_scrub::tests::malformed_xmp_is_a_typed_error`
  and `scrub::tests::from_xml_rejects_trailing_content_after_root` require typed
  `ScrubXmpMalformed` / `ScrubInvalid*` results, never panics.
- **Post-scrub verification** — `xmp_scrub::tests::verify_scrub_detects_a_residual_as_a_typed_error`
  verifies the original (unscrubbed) bytes and expects
  `SecurityError::ScrubVerificationFailed` scoped to `ScrubCategory::Xmp`.
- **Secret hygiene** — `password_policy::tests::plan_and_credentials_never_print_secrets`
  asserts `Debug` output of credentials, input, and plan contains no secret text.
