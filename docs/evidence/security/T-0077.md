## Scope, disclosures, and honesty notes

- All acceptance checks pass with zero failures and zero warnings; no new
  external dependencies; no `unsafe`; no `unwrap`/`expect`/`panic!` in library
  (non-test) paths; no secret or document-content logging.
- **TSA EKU behavior (review item 1):** `ValidationPolicy::required_eku` defaults
  to `None`, so a generic chain-trusted TSA without `id-kp-timeStamping` could
  previously reach `Valid`. `validate_timestamp_token` now defaults
  `TimestampPolicy::required_tsa_eku` to `Some(EkuPurpose::TimeStamping)`,
  requires the TSA leaf to carry that purpose, propagates it to issuing CAs via
  a cloned policy, and reports `TimestampStatus::TimestampEkuMissing` (mapped to
  `SignatureStatus::Unknown`). A trusted but non-timestamping TSA can no longer
  be `Valid`. An explicit documented override (another purpose or `None`) is
  supported and tested by `eku_requirement_can_be_explicitly_overridden`.
- **GeneralizedTime limits (review item 2):** RFC 3161 `genTime` accepts
  fractional seconds `.sss...Z` (1â€“9 digits). `der.rs::decode_time_content`
  validates the fraction and discards it; the public time type is whole Unix
  seconds, so sub-second precision is not represented in `TstInfo::gen_time`
  and is not used by skew or nonce checks. `UTCTime` and malformed fractional
  forms are rejected. Both behaviors are documented in the `timestamp` and `der`
  rustdoc and covered by two new tests.
- `Valid` / `SignatureStatus::Valid` is reserved for a token that passes every
  check; the full trust boundary is documented in the `timestamp` module docs.
- Revocation/CRL checks, a trust-manager UI (SEC-007), and wiring validation
  into a concrete PDF signature workflow are out of scope, so the SEC-006
  feature row remains `in-progress`, not `verified`.
- The feature-matrix change is delivered as the restored fragment
  `orchestration/feature-updates/T-0077.toml`; `docs/features.toml` and
  `orchestration/BOARD.md` were not edited by this lane.
