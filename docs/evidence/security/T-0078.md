### Finding (a) — XMP identifier injection fixed

`XmpProperty::new` now validates `prefix` and `local_name` as ASCII XML NCNames
(non-empty, no `:`, first char letter/`_`, remaining chars letter/digit/`_`/`-`/`.`).
Empty values still return `ScrubInvalidFieldIdentifier`; a bad prefix returns the
new typed `ScrubInvalidXmpPrefix`, and a bad local name (including a colon, `<`,
a quote, or a space) returns the new typed `ScrubInvalidXmpLocalName`. Both
`Display` arms were added in `error.rs`. Because the fields are private and every
constructor/deserialisation path goes through `new`, `to_xml` can interpolate
names safely; `namespace_uri` and `value` remain XML-escaped. Negative test:
`hostile_xmp_identifiers_are_rejected_as_typed_errors`.

### Finding (b) — `from_xml` root validation fixed

`from_xml` no longer accepts arbitrary text containing `rdf:RDF`. A bounded,
case-insensitive validator (`validate_rdf_root` + `find_matching_rdf_close`)
skips only a prolog (whitespace, `<?...?>`, `<!--...-->`) and an optional
`x:xmpmeta` wrapper, requires `<rdf:RDF ...>` in document order with a matching
`</rdf:RDF>` close tag, and caps input at 1 MiB, tag count at 50,000, and RDF
nesting depth at 32. Description parsing is confined to the root's element
content. Negative tests: `from_xml_rejects_non_root_rdf_and_malformed_roots`
(text mention, root not at start, nested under `<foo>`, truncated root,
mismatched close) and `from_xml_bounds_huge_nesting_and_oversized_input`.
Positive guard: `from_xml_is_case_insensitive_and_accepts_a_bare_root` and the
pre-existing canonical round-trip test.

### Finding (c) — rustdoc corrected

The module rustdoc no longer claims `to_xml` "always emits well-formed XML" or
that `from_xml` is a general parser. It now states the exact NCName validation,
the `& < > " '` escaping of values/URIs, and the bounded structured-subset
parsing guarantees. `cargo doc` with `-D warnings` passes, so all new intra-doc
links resolve.
