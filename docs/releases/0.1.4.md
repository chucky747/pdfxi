# PDFXI 0.1.4 release notes

PDFXI 0.1.4 is a Windows x64 release. It fixes the blocking defects and the
security/UI findings in the 2026-11-23 finish review, and makes the verification
gates exercise the installed application instead of only the model.

## Fixed

- **Text selection and copy** work on the canvas; the platform Ctrl+C event is
  consumed, and the selection is painted. `V`/`T`/`H`/`Y`/`F`/`M` select a tool
  when no text field has focus.
- **Password-protected files** open after the prompt restores its pending state.
- **Page operations** (rotate, delete, move, extract, merge) carry the catalog:
  bookmarks, forms, labels, metadata, named destinations, tags and optional
  content survive, or are pruned when their page is removed.
- **Closing a dirty window** prompts for every dirty tab. Discard/Save now
  actually resolve the prompt, and the final close reaches the platform.
- **Deep page trees** stop at 64 levels with a typed error instead of a stack
  overflow.
- **Read-only and required form fields** use the correct `/Ff` bits.
- **Redaction** fails closed, refuses encrypted sources, and checks thumbnails,
  UTF-16 strings, form values and bookmark titles before writing.
- **Encryption detection** reads the trailer reference instead of scanning
  bytes; the password/owner paths use owner-first authentication.
- **Advisories**: `url` 2.5.9 and the `p256`/`crypto-bigint` upgrade; `cargo
  deny check` is green.
- **UI**: status line, Ctrl+O, `/EncryptMetadata false`, random `/ID`, form
  editor focus/revert, thumbnail aspect, Pages/bookmarks overflow, HTML help,
  friendly PDFium errors, and accessible names on the shell controls.
- **Flatten**: form flattening preserves `/Resources` inherited from the page
  tree, so existing page text keeps its fonts while widget appearances are
  added.
- **Start Menu**: setup and portable installs now share the `PDFXI` group; the
  portable installer removes its pre-0.1.4 root-level links instead of leaving
  duplicate entries.
- **Matrix honesty**: overstated rows are `library`, `model` or `deferred`;
  `cargo xtask features verify` now requires an existing evidence path, a
  `gui`/`cli` host, and non-ignored test citations.
- **Gate truth**: the UI harness and an independent PDFium checker live under
  `scripts/`; `cargo xtask installer-test` runs the installed-build UI smoke;
  `egui_kittest` covers the close prompt, password dialog, save conflict,
  Convert, Protect, Document properties, Sign, Organize and Redact cards; the
  mdBook and release notes are checked in.
- **Documentation honesty**: `docs/ARCHITECTURE.md` now describes the shipped
  texture cache, TOML persistence and process-level panic behaviour instead of
  promising SQLite recents, autosave, off-thread rendering or a `catch_unwind`
  boundary.

## Verification

- `cargo fmt --all --check`, `cargo clippy --workspace --all-targets
  --all-features -- -D warnings`, `cargo test --workspace`, `cargo doc
  --workspace --no-deps` and `cargo deny check` are green on this release.
- `cargo xtask bench --report` is green: 18/18 metrics, 0 breaches, 0
  regressions. Real-corpus save durability remains the open T-0260B item.
- `cargo xtask features verify` is green for the honest matrix.
- `cargo xtask installer-test` installs the smoke identity, runs the 26-check
  UI smoke against it, and uninstalls.
- The per-user setup installs cleanly from a machine with no previous PDFXI
  installation; `scripts/install.ps1` remains the portable path.

## Known limits

- Windows x86_64 only; Linux and macOS builds are not verified.
- The build and installer are unsigned (T-0202). SmartScreen may warn.
- A 24-hour fuzz campaign has not run on this host (T-0260A).
- The assistant's answers are local-tool grounded but not a substitute for
  reading the document (T-0251 limits).
- Custom-painted form widgets expose accessible names and roles, but do not yet
  accept the UI Automation `SetValue` action; edit them on the canvas. ACCESS-006
  therefore remains `model`, not `verified`.
- Upgrading directly over a 0.1.2 portable install can leave stale uninstall
  metadata. The 0.1.2 uninstaller exits 1 on this host; use
  `scripts/uninstall.ps1` to remove the per-user directory and its matching
  HKCU entry, then run the 0.1.4 setup. `scripts/install.ps1` from the new
  portable archive remains the no-registry path.
- `cargo xtask goal-verify --all` stays red while rows are honestly
  `library`/`model`/`deferred` (ADR 0009); this is intended, not a suppressed
  failure.
- GitHub CI is not used; the verified gate is the local Windows run.
