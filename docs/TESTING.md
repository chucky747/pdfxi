# TESTING

## Test pyramid

| Layer | Location | Budget | Notes |
|---|---|---|---|
| Unit | crate `#[cfg(test)]` | < 30 s total | Pure logic, no I/O |
| Integration | `tests/` per crate | < 60 s total | Generated fixtures |
| Doc tests | rustdoc | < 30 s | Public examples compile |
| Full | `--profile full` | < 15 min | Corpus subsets, OCR, render |
| Nightly | Local scheduled run | < 2 h | veraPDF, fuzz, mutation, full corpus |
| Release | Local release run | 24 h fuzz | No panics on malformed corpus |

## Local CI

There is no GitHub CI. The verified gate is the local Windows run:

```powershell
cargo xtask ci
```

It runs `cargo fmt --all --check`, clippy with warnings denied, the workspace
tests, the feature tests, `cargo doc --workspace --no-deps -j 1`, the feature
matrix, mdBook (when `MDBOOK` is available), the benchmark gate,
`cargo xtask installer-test`, the real NVDA screen-reader smoke against the
installed viewer, and the Authenticode check when
`PDFXI_SIGN_THUMBPRINT` is set. It writes `target/ci/ci-report.md` and exits
non-zero on the first failed step.

The nightly tier is opt-in. Register a Windows Task Scheduler job with:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/register-local-ci.ps1
```

Use `-Remove` to unregister it, `-TaskName` to choose another name, and `-At`
to change the start time. The job runs `cargo xtask ci`; the 24-hour fuzz and
mutation campaigns remain explicit blocked items until the host toolchain can
run them.

## Rules

- No network, GUI, sleeps, or secrets in fast tests.
- One behavior per test; the name states the behavior.
- A bug fix adds a regression test that fails without the fix.
- Fixtures are generated by `pdfxi-testkit` where possible.
- Large corpora are fetched by checksum and never committed.
- Flaky tests are quarantined the same day; a quarantine needs an owner and a
  date.

## Rendering tests

- Render at 72 and 144 DPI.
- Compare against PDFium baselines with SSIM tolerance.
- Store per-platform baselines only when rendering is deterministic.
- Structural assertions (text runs, page boxes, annotation geometry) are
  preferred over pixel-perfect comparisons.

## Security tests

- Encrypted fixtures for revisions 2–6.
- Signature creation and validation with test certificates.
- Redaction verification: extract text and images after redaction and assert
  the removed content is absent.
- JavaScript sandbox escape attempts (filesystem, network, process, time).
- Path traversal for attachments, exports, and memory.

## Tracked benchmark harness (T-0120)

`cargo xtask bench` runs a deterministic, offline harness implemented in
`xtask/src/bench.rs`. It generates three byte-stable, text-only PDF fixtures in
memory -- **small** (1 page), **medium** (100 pages) and **large** (500 pages) --
with page count and marker width controlled by `FixtureSpec`. For each fixture it
measures `open`, `first_page_render` (mock), `text_extract`,
`search_index_build`, `save` and a `peak_allocation_estimate`, then emits
versioned JSON (`schema_version = 1`) to stdout and to
`target/perf/bench-report.json`, plus a human-readable summary.

### Method

1. Every operation runs **2 unmeasured warmup** iterations followed by **7
   measured** iterations. The median is the tracked number; min and max are also
   recorded.
2. The whole harness runs **3 independent rounds** and keeps the best median per
   metric (`best-of-3`). A real regression appears in every round; a transient
   scheduler spike does not.
3. Fixture bytes, JSON field order and all non-timing values are deterministic.
   Only measured numbers vary; the JSON *shape* is stable.
4. Each operation's correctness checksum is verified once before timing, so a
   broken operation fails the harness instead of producing meaningless numbers.

### Explicit budgets

Budgets are derived from the 500-page reference values in the table above. They
scale linearly with page count, are floored at 5 ms for tiny fixtures, then get a
documented **+25% host-variance allowance**. A metric passes when its tracked
median is at or below its budget.

The real-file save measurement in `docs/evidence/acceptance/T-0260B-measure.rs`
adds a **25 ms durability floor** before the +25% allowance. That timed region is
the whole Ctrl+S path including `sync_all` and the rename, so one device flush is
unavoidable; the in-memory harness above never flushes and keeps the 5 ms floor.
This is a floor for a different timed region, not a relaxation of the `save`
metric in `cargo xtask bench`. The 2000 ms absolute row is unchanged.

| Operation | Base @ 500 pages | small (1 p) | medium (100 p) | large (500 p) |
|---|---:|---:|---:|---:|
| open | 1500 ms | 6.25 ms | 375 ms | 1875 ms |
| first-page render (mock) | 150 ms | 6.25 ms | 37.5 ms | 187.5 ms |
| text extraction | 1000 ms | 6.25 ms | 250 ms | 1250 ms |
| search index build | 1000 ms | 6.25 ms | 250 ms | 1250 ms |
| save | 2000 ms | 6.25 ms | 500 ms | 2500 ms |

Peak allocation is estimated as `fixture bytes + save output bytes`, budgeted at
`< 1.5 Ã— file + 512 MiB` per the memory row above.

### Regression gate and variance handling

- A baseline report is committed at `docs/evidence/qa/bench-baseline.json`.
- A tracked timing regresses when its current best-of-3 median exceeds the
  baseline median by **more than 10%**. A metric whose baseline median is below a
  **1 ms noise floor** is informational only: sub-millisecond wall-clock
  measurements are too resolution-limited for a meaningful ratio.
- Budget breaches, tracked regressions, or an unreadable/invalid baseline fail
  the default gate with exit code 1. `--report` is informational and always
  exits 0.
- The baseline is **host-specific**. Regenerate it after changing hosts,
  toolchains, or the harness itself with `cargo xtask bench --update-baseline`.

### Host caveats

- The harness is dependency-free and runs inside the dev-built `xtask` process;
  it is **not** a Criterion or release-profile run. Numbers are reproducible in
  shape, not absolute across machines.
- The renderer is a **mock**: it decodes the first content stream and fills a
  bounded 320Ã—240 RGB buffer. No PDFium binding is linked. If `PDFIUM_PATH` is
  set, its presence is recorded for context only.
- This workspace can run up to five lanes concurrently. The warmup, best-of-3
  rounds and 25% budget headroom absorb ordinary shared-host noise. Sustained
  host load that survives all three rounds is reported as a regression rather
  than silently ignored.

### Commands

```text
cargo xtask bench                    # enforce budgets and >10% regression gate
cargo xtask bench --check            # same gate (compatibility with older scripts)
cargo xtask bench --report           # informational; never exits non-zero
cargo xtask bench --update-baseline  # refresh the committed baseline JSON
```

Evidence for this task: `docs/evidence/qa/T-0120.md`.

## Fuzz seed corpus (T-0144)

The committed seeds in `fuzz/corpus/<target>/` are generated, not hand-written
binary blobs. `crates/pdfxi-testkit/src/seed_corpus.rs` owns a byte-stable
generator for all five targets (`parser`, `filters`, `content`, `forms`,
`crypto`) and renders `fuzz/corpus/manifest.toml`, a SHA-256 descriptor of every
generated seed. The manifest covers exactly the generated seeds; older
hand-seeded files in the target directories are left untouched and are still fed
to the fuzz entry points by `fuzz_smoke`.

Regenerate the corpus and its manifest with the env-gated example. The flag is
required, so an accidental `cargo run` is a no-op:

```powershell
. .\scripts\env.ps1 -Lane qa
$env:PDFXI_GENERATE_FUZZ_SEEDS = '1'
cargo run -p pdfxi-testkit --example generate_fuzz_seeds
Remove-Item Env:\PDFXI_GENERATE_FUZZ_SEEDS
```

Fast tests enforce the corpus contract:

- `fuzz_seed_manifest_hashes_are_valid` (part of `cargo xtask corpus smoke`)
  re-computes the SHA-256 of each listed seed and prints an audit line per seed.
  Run it with `-- --nocapture` to see the hashes.
- `fuzz_seed_corpus.rs` asserts the generated bytes equal the committed files,
  the manifest text is byte-stable, every target is covered, and no seed exceeds
  the 16 KiB fuzz input bound.

`cargo xtask corpus smoke` passes and reports the manifest hashes; evidence for
this task is `docs/evidence/qa/T-0144.md`.

## Budget descriptor and baseline capture (T-0144)

The tracked gate is still `cargo xtask bench` (T-0120). This task adds a
human-readable counterpart, `crates/pdfxi-testkit/perf-budgets.toml`, which
declares the five logical operations named by AC-05's source table and maps each
to the concrete harness metric. `pdfxi_testkit::budget` parses and validates the
descriptor and reproduces the harness's page-count scaling formula (linear,
floored at 5 ms, plus 25% host headroom). Only the *declared* budgets live here;
measured timings come from the harness and are archived in the evidence file.

| Operation | Harness metric | Base @ 500 p | small (1 p) | medium (100 p) | large (500 p) |
|---|---|---:|---:|---:|---:|
| open | `open` | 1500 ms | 6.25 ms | 375 ms | 1875 ms |
| parse | `open` | 1500 ms | 6.25 ms | 375 ms | 1875 ms |
| render | `first_page_render` | 150 ms | 6.25 ms | 37.5 ms | 187.5 ms |
| text-extraction | `text_extract` | 1000 ms | 6.25 ms | 250 ms | 1250 ms |
| search | `search_index_build` | 1000 ms | 6.25 ms | 250 ms | 1250 ms |

`parse` shares the `open` metric because that harness operation validates the
header, `startxref`, xref table and page-tree count -- the structural parse
proxy. `save` and the memory estimate remain tracked by the harness's `save`
and `peak_allocation_estimate` metrics and the committed baseline
(`docs/evidence/qa/bench-baseline.json`).

Reproduce on this host:

```powershell
. .\scripts\env.ps1 -Lane qa
cargo xtask bench                # enforce budgets and >10% regression gate
cargo xtask bench --report       # informational; always exits 0
cargo test -p pdfxi-testkit      # includes budget parser validation tests
```

Host variance: the harness generates fixtures in memory and runs 2 warmup plus
7 measured iterations over 3 independent rounds, keeping the best median per
metric. Budgets include a documented 25% headroom, and a tracked median (baseline
>= 1 ms) regresses only when it exceeds the host-specific baseline by more than
10%. The renderer is a bounded mock, not PDFium; `PDFIUM_PATH` is recorded for
context only. Results are reproducible in *shape*, not as absolute numbers
across machines -- refresh the baseline with `cargo xtask bench --update-baseline`
after changing hosts, toolchains or the harness. See the T-0120 section above
for the full method and caveats.
